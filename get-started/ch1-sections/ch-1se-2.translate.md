# ماجرای این نام چیست؟

نام JavaScript احتمالاً اشتباه‌برانگیزترین و بدفهمیده‌شده‌ترین نام در میان زبان‌های برنامه‌نویسی است.

آیا این زبان به Java مربوط است؟ آیا فقط نسخهٔ اسکریپتی Java است؟ آیا فقط برای نوشتن اسکریپت‌هاست و نه برنامه‌های واقعی؟

حقیقت این است که نام JavaScript محصول ترفندهای بازاریابی است. وقتی برندان آیک برای اولین بار این زبان را طراحی کرد، نام رمز آن Mocha بود. در داخل Netscape، برند LiveScript استفاده می‌شد. اما وقتی نوبت به نام‌گذاری عمومی زبان رسید، «JavaScript» رأی آورد.

چرا؟ چون این زبان در اصل طوری طراحی شده بود که برای مخاطبی که عمدتاً برنامه‌نویس Java بودند جذاب باشد، و چون کلمهٔ «script» در آن زمان برای اشاره به برنامه‌های سبک‌وزن رایج بود. این «اسکریپت»های سبک اولین چیزهایی بودند که داخل صفحات این چیز جدید به نام وب قرار می‌گرفتند!

به عبارت دیگر، JavaScript یک ترفند بازاریابی بود برای قرار دادن این زبان به‌عنوان جایگزینی قابل‌قبول برای نوشتن Java سنگین‌تر و شناخته‌تر آن روزگار. به همین راحتی می‌شد «WebJava» نامیده شود.

شباهت‌های سطحی بین کد JavaScript و کد Java وجود دارد. این شباهت‌ها به‌طور خاص از توسعهٔ مشترک نمی‌آیند، بلکه از هدف‌گیری هر دو زبان برای توسعه‌دهندگانی با انتظارات نحوی از C (و تا حدی C++) ناشی می‌شوند.

مثلاً از `{` برای شروع یک بلوک کد و `}` برای پایان آن استفاده می‌کنیم، درست مثل C/C++ و Java. همچنین از `;` برای پایان یک دستور استفاده می‌کنیم.

از برخی جهات، روابط حقوقی حتی عمیق‌تر از نحو است. Oracle (از طریق Sun)، شرکتی که هنوز Java را مالک است و اداره می‌کند، مالک علامت تجاری رسمی نام «JavaScript» (از طریق Netscape) هم هست. این علامت تجاری تقریباً هرگز اعمال نمی‌شود، و احتمالاً در این مرحله هم نمی‌تواند اعمال شود.

به همین دلایل، برخی پیشنهاد کرده‌اند به جای JavaScript از JS استفاده کنیم. این نام‌گذاری کوتاه بسیار رایج است، حتی اگر نامزد خوبی برای برند رسمی زبان نباشد. در واقع، این کتاب‌ها تقریباً منحصراً از JS برای اشاره به زبان استفاده می‌کنند.

برای فاصله‌انداختن بیشتر زبان از علامت تجاری متعلق به Oracle، نام رسمی زبان مشخص‌شده توسط TC39 و رسمی‌شده توسط سازمان استاندارد ECMA، **ECMAScript** است. و در واقع از سال ۲۰۱۶، نام رسمی زبان با سال انتشار همراه است؛ در زمان نگارش این متن، ECMAScript 2019 است، یا به اختصار ES2019.

به عبارت دیگر، JavaScript/JS که در مرورگر یا Node.js اجرا می‌شود، *یک* پیاده‌سازی از استاندارد ES2019 است.

چه آن را JavaScript، JS، ECMAScript یا ES2019 بنامید، قطعاً گونه‌ای از زبان Java نیست!

> «Java به JavaScript مثل ham به hamster است.» —جرمی کیت، ۲۰۰۹
