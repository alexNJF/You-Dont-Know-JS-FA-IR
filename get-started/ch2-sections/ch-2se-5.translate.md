# مقایسه‌ها

تصمیم‌گیری در برنامه‌ها نیاز به مقایسهٔ مقادیر برای تعیین هویت و رابطهٔ آن‌ها با یکدیگر دارد. جاوااسکریپت چند مکانیزم برای مقایسهٔ مقادیر دارد، پس بیایید دقیق‌تر نگاه کنیم.

## برابر...ish

رایج‌ترین مقایسه در برنامه‌های جاوااسکریپت این سؤال را می‌پرسد: «آیا این مقدار X *همان* مقدار Y است؟» اما «همان» دقیقاً برای جاوااسکریپت چه معنایی دارد؟

به دلایل ارگونومیک و تاریخی، معنا پیچیده‌تر از تطابق نوع *هویت دقیق* واضح است. گاهی مقایسهٔ برابری قصد تطابق *دقیق* دارد، اما گاهی مقایسهٔ مطلوب کمی گسترده‌تر است، اجازهٔ تطابق *مشابه نزدیک* یا *قابل تعویض*. به عبارت دیگر، باید از تفاوت‌های ظریف بین مقایسهٔ **equality** و مقایسهٔ **equivalence** آگاه باشیم.

اگر زمانی با جاوااسکریپت کار کرده و دربارهٔ آن خوانده‌اید، قطعاً عملگر «triple-equals» `===` را دیده‌اید، که «strict equality» هم توصیف می‌شود. درست است؟ قطعاً «strict» یعنی strict، یعنی narrow و *دقیق*.

نه *دقیق*اً.

بله، بیشتر مقادیر شرکت‌کننده در مقایسهٔ برابری `===` با آن شهود *دقیقاً همان* مطابقت می‌کنند. چند مثال در نظر بگیرید:

```js
3 === 3.0;              // true
"yes" === "yes";        // true
null === null;          // true
false === false;        // true

42 === "42";            // false
"hello" === "Hello";    // false
true === 1;             // false
0 === null;             // false
"" === null;            // false
null === undefined;     // false
```

| نکته: |
| :--- |
| راه دیگر توصیف مقایسهٔ برابری `===` این است: «بررسی هم مقدار و هم نوع». در چند مثال که تا به حال دیدیم، مثل `42 === "42"`، *نوع* هر دو مقدار (number، string و غیره) به نظر می‌رسد عامل تشخیص باشد. بیش از این هست، با این حال. **همه** مقایسه‌های مقدار در جاوااسکریپت نوع مقادیر مقایسه‌شده را در نظر می‌گیرند، نه *فقط* عملگر `===`. به‌طور خاص، `===` هر نوع تبدیل نوع (با نام مستعار «coercion») را در مقایسه‌اش ممنوع می‌کند، جایی که سایر مقایسه‌های جاوااسکریپت coercion *اجازه* می‌دهند. |

اما عملگر `===` ظرافت‌هایی دارد، که بسیاری توسعه‌دهندگان جاوااسکریپت از آن نادیده می‌گیرند، به ضررشان. عملگر `===` طوری طراحی شده که در دو مورد مقادیر خاص *دروغ* بگوید: `NaN` و `-0`. در نظر بگیرید:

```js
NaN === NaN;            // false
0 === -0;               // true
```

در مورد `NaN`، عملگر `===` *دروغ* می‌گوید و می‌گوید یک occurrence از `NaN` با `NaN` دیگر برابر نیست. در مورد `-0` (بله، این مقدار واقعی و متمایزی است که می‌توانید عمداً در برنامه‌هایتان استفاده کنید!)، عملگر `===` *دروغ* می‌گوید و می‌گوید با مقدار معمولی `0` برابر است.

از آنجا که *دروغ* دربارهٔ چنین مقایسه‌هایی می‌تواند آزاردهنده باشد، بهترین کار اجتناب از استفادهٔ `===` برای آن‌هاست. برای مقایسه‌های `NaN`، از ابزار `Number.isNaN(..)` استفاده کنید که *دروغ* نمی‌گوید. برای مقایسهٔ `-0`، از ابزار `Object.is(..)` استفاده کنید که آن هم *دروغ* نمی‌گوید. `Object.is(..)` می‌تواند برای بررسی‌های `NaN` غیر-*دروغ* هم استفاده شود، اگر ترجیح می‌دهید. به‌طور طنزآمیز، می‌توانید `Object.is(..)` را «quadruple-equals» `====` در نظر بگیرید، مقایسهٔ واقعاً-واقعاً-strict!

دلایل تاریخی و فنی عمیق‌تری برای این *دروغ*ها وجود دارد، اما این واقعیت را تغییر نمی‌دهد که `===` در *سخت‌گیرانه‌ترین* معنای ممکن در واقع مقایسهٔ *سخت‌گیرانه دقیقاً برابر* نیست.

داستان وقتی مقایسه‌های مقادیر object (غیر-primitive) را در نظر می‌گیریم پیچیده‌تر می‌شود. در نظر بگیرید:

```js
[ 1, 2, 3 ] === [ 1, 2, 3 ];    // false
{ a: 42 } === { a: 42 }         // false
(x => x * 2) === (x => x * 2)   // false
```

چه خبر است؟

ممکن است منطقی به نظر برسد فرض کنیم بررسی برابری *طبیعت* یا *محتوای* مقدار را در نظر می‌گیرد؛ بالاخره `42 === 42` مقدار واقعی `42` را در نظر می‌گیرد و مقایسه می‌کند. اما وقتی به اشیاء می‌رسد، مقایسهٔ آگاه از محتوا معمولاً «structural equality» نامیده می‌شود.

جاوااسکریپت `===` را به‌عنوان *structural equality* برای مقادیر object تعریف نمی‌کند. در عوض، `===` از *identity equality* برای مقادیر object استفاده می‌کند.

در جاوااسکریپت، همهٔ مقادیر object با reference نگه داشته می‌شوند (پیوست A، «Values vs References» را ببینید)، با reference-copy assign و pass می‌شوند، **و** برای بحث فعلی ما، با reference (identity) equality مقایسه می‌شوند. در نظر بگیرید:

```js
var x = [ 1, 2, 3 ];

// assignment با reference-copy است، پس
// y به *همان* آرایهٔ x ارجاع می‌دهد،
// نه کپی دیگری از آن.
var y = x;

y === x;              // true
y === [ 1, 2, 3 ];    // false
x === [ 1, 2, 3 ];    // false
```

در این تکه، `y === x` true است چون هر دو متغیر به همان آرایهٔ اولیه ارجاع می‌دهند. اما مقایسه‌های `=== [1,2,3]` هر دو شکست می‌خورند چون `y` و `x` به ترتیب با آرایه‌های *متفاوت* جدید `[1,2,3]` مقایسه می‌شوند. ساختار و محتوای آرایه در این مقایسه مهم نیست، فقط **هویت reference**.

جاوااسکریپت مکانیزمی برای مقایسهٔ structural equality مقادیر object ارائه نمی‌دهد، فقط مقایسهٔ identity reference. برای انجام مقایسهٔ structural equality، باید خودتان بررسی‌ها را پیاده کنید.

اما مراقب باشید، پیچیده‌تر از آن است که فرض می‌کنید. مثلاً چطور می‌توانید تعیین کنید آیا دو ارجاع تابع «structurally equivalent» هستند؟ حتی stringify کردن برای مقایسهٔ متن کد منبع آن‌ها چیزهایی مثل closure را در نظر نمی‌گیرد. جاوااسکریپت مقایسهٔ structural equality ارائه نمی‌دهد چون تقریباً غیرقابل حل است همهٔ موارد حاشیه‌ای را handle کند!

## مقایسه‌های Coercive

Coercion یعنی تبدیل مقدار یک نوع به نمایش مربوطش در نوع دیگر (تا حد امکان). همان‌طور که در فصل ۴ بحث می‌کنیم، coercion یکی از ستون‌های اصلی زبان جاوااسکریپت است، نه ویژگی اختیاری که بتوان منطقاً از آن اجتناب کرد.

اما جایی که coercion با عملگرهای مقایسه (مثل برابری) برخورد می‌کند، متأسفانه سردرگمی و ناامیدی بیشتر از نه رخ می‌دهد.

کمتر ویژگی جاوااسکریپت در جامعهٔ گسترده‌تر جاوااسکریپت خشم بیشتری نسبت به عملگر `==` جلب می‌کند، که معمولاً «loose equality» نامیده می‌شود. اکثر نوشته‌ها و گفتگوهای عمومی دربارهٔ جاوااسکریپت این عملگر را به‌عنوان طراحی ضعیف و خطرناک/پراز باگ هنگام استفاده در برنامه‌های جاوااسکریپت محکوم می‌کنند. حتی خالق خود زبان، برندان آیک، افسوس خورده که چطور به‌عنوان اشتباه بزرگ طراحی شده.

از آنچه می‌توانم بگویم، بیشتر این ناامیدی از لیست کوتاهی از موارد حاشیه‌ای سردرگم می‌آید، اما مشکل عمیق‌تر تصور نادرست بسیار گسترده است که مقایسه‌ها را بدون در نظر گرفتن نوع مقادیر مقایسه‌شده انجام می‌دهد.

عملگر `==` مقایسهٔ برابری را مشابه نحوهٔ اینکه `===` انجام می‌دهد انجام می‌دهد. در واقع، هر دو عملگر نوع مقادیر مقایسه‌شده را در نظر می‌گیرند. و اگر مقایسه بین همان نوع مقدار باشد، هر دو `==` و `===` **دقیقاً همان کار را می‌کنند، هیچ تفاوتی ندارند.**

اگر نوع مقادیر مقایسه‌شده متفاوت باشند، `==` با `===` در این تفاوت دارد که قبل از مقایسه coercion اجازه می‌دهد. به عبارت دیگر، هر دو می‌خواهند مقادیر با نوع مشابه مقایسه کنند، اما `==` ابتدا تبدیل نوع را اجازه می‌دهد، و وقتی نوع‌ها در هر دو طرف تبدیل شدند، `==` همان کار `===` را می‌کند. به‌جای «loose equality»، عملگر `==` باید «coercive equality» توصیف شود.

در نظر بگیرید:

```js
42 == "42";             // true
1 == true;              // true
```

در هر دو مقایسه، نوع مقادیر متفاوت است، پس `==` باعث می‌شود مقادیر غیر-عدد (`"42"` و `true`) قبل از انجام مقایسه به عدد (`42` و `1` به ترتیب) تبدیل شوند.

فقط آگاه بودن از این طبیعت `==`—که مقایسه‌های عددی اولیه را ترجیح می‌دهد—به شما کمک می‌کند از بیشتر موارد حاشیه‌ای مشکل‌دار اجتناب کنید، مثل دور ماندن از gotchaهایی مثل `"" == 0` یا `0 == false`.

شاید فکر می‌کنید «آها، پس همیشه از هر مقایسهٔ برابری coercive اجتناب می‌کنم (با استفاده از `===` به‌جای آن) تا از آن موارد حاشیه‌ای اجتناب کنم»! اِ، متأسفانه، آن چندان که امید دارید محتمل نیست.

شانس خوبی هست که از عملگرهای مقایسهٔ relational مثل `<`، `>` (و حتی `<=` و `>=`) استفاده کنید.

درست مثل `==`، این عملگرها طوری عمل می‌کنند انگار «strict» هستند اگر نوع‌های مقایسه‌شده relational از قبل مطابقت کنند، اما اگر نوع‌ها متفاوت باشند ابتدا coercion اجازه می‌دهند (معمولاً به عدد).

در نظر بگیرید:

```js
var arr = [ "1", "10", "100", "1000" ];
for (let i = 0; i < arr.length && arr[i] < 500; i++) {
    // 3 بار اجرا می‌شود
}
```

مقایسهٔ `i < arr.length` از coercion «امن» است چون `i` و `arr.length` همیشه عدد هستند. `arr[i] < 500` coercion را فراخوانی می‌کند، با این حال، چون مقادیر `arr[i]` همه string هستند. آن مقایسه‌ها پس می‌شوند `1 < 500`، `10 < 500`، `100 < 500`، و `1000 < 500`. چون آن چهارمی false است، حلقه بعد از تکرار سومش متوقف می‌شود.

این عملگرهای relational معمولاً از مقایسهٔ عددی استفاده می‌کنند، مگر در موردی که **هر دو** مقدار مقایسه‌شده از قبل string هستند؛ در این مورد، از مقایسهٔ الفبایی (dictionary-like) stringها استفاده می‌کنند:

```js
var x = "10";
var y = "9";

x < y;      // true، مراقب باشید!
```

راهی برای اینکه این عملگرهای relational از coercion اجتناب کنند نیست، مگر اینکه هرگز از نوع‌های نامطابقت در مقایسه‌ها استفاده نکنید. شاید به‌عنوان هدف قابل تحسین باشد، اما هنوز احتمالاً به موردی برخورد می‌کنید که نوع‌ها *ممکن* متفاوت باشند.

رویکرد عاقلانه‌تر اجتناب از مقایسه‌های coercive نیست، بلکه پذیرش و یادگیری جزئیات آن‌هاست.

مقایسه‌های coercive در جاهای دیگر جاوااسکریپت هم رخ می‌دهند، مثل شرطی‌ها (`if` و غیره)، که در پیوست A، «Coercive Conditional Comparison» مرور می‌کنیم.
