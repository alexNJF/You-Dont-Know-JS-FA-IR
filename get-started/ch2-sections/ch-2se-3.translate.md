# اعلان و استفاده از متغیرها

برای صریح بودن دربارهٔ چیزی که ممکن است در بخش قبلی واضح نبوده: در برنامه‌های جاوااسکریپت، مقادیر می‌توانند یا به‌عنوان literal (مثل بسیاری از مثال‌های قبلی) ظاهر شوند، یا در متغیرها نگه داشته شوند؛ متغیرها را فقط ظروف مقادیر در نظر بگیرید.

متغیرها باید اعلان (ایجاد) شوند تا استفاده شوند. اشکال نحو مختلفی برای اعلان متغیرها (با نام مستعار «identifiers») وجود دارد، و هر شکل رفتارهای ضمنی متفاوتی دارد.

مثلاً دستور `var` را در نظر بگیرید:

```js
var myName = "Kyle";
var age;
```

کلمهٔ کلیدی `var` متغیری را برای استفاده در آن بخش برنامه اعلان می‌کند، و به‌طور اختیاری اجازهٔ assign اولیهٔ مقدار را می‌دهد.

کلمهٔ کلیدی مشابه دیگر `let` است:

```js
let myName = "Kyle";
let age;
```

کلمهٔ کلیدی `let` تفاوت‌هایی با `var` دارد، که واضح‌ترین آن این است که `let` دسترسی محدودتری به متغیر نسبت به `var` اجازه می‌دهد. این «block scoping» نامیده می‌شود در مقابل scoping معمولی یا تابعی.

در نظر بگیرید:

```js
var adult = true;

if (adult) {
    var myName = "Kyle";
    let age = 39;
    console.log("Shhh, this is a secret!");
}

console.log(myName);
// Kyle

console.log(age);
// Error!
```

تلاش برای دسترسی به `age` خارج از دستور `if` منجر به خطا می‌شود، چون `age` به block `if` محدود بود، در حالی که `myName` نبود.

Block-scoping برای محدود کردن گستردگی اعلان‌های متغیر در برنامه‌هایمان بسیار مفید است، که به جلوگیری از تداخل تصادفی نام‌های آن‌ها کمک می‌کند.

اما `var` هنوز مفید است چون «این متغیر توسط scope گسترده‌تر (کل تابع) دیده می‌شود» را منتقل می‌کند. هر دو شکل اعلان می‌توانند در هر بخش خاص برنامه مناسب باشند، بسته به شرایط.

| نکته: |
| :--- |
| بسیار رایج است پیشنهاد شود از `var` به نفع `let` (یا `const`!) اجتناب شود، عمدتاً به‌خاطر سردرگمی درک‌شده دربارهٔ نحوهٔ کار رفتار scoping `var` از ابتدای جاوااسکریپت. معتقدم این توصیه بیش از حد محدودکننده و در نهایت بی‌فایده است. فرض می‌کند نمی‌توانید یک ویژگی را یاد بگیرید و درست در ترکیب با ویژگی‌های دیگر استفاده کنید. معتقدم *می‌توانید* و *باید* هر ویژگی موجود را یاد بگیرید و در جای مناسب استفاده کنید! |

شکل سوم اعلان `const` است. مثل `let` است اما محدودیت اضافی دارد که باید در لحظهٔ اعلان مقدار داده شود، و نمی‌توان بعداً مقدار متفاوتی re-assign کرد.

در نظر بگیرید:

```js
const myBirthday = true;
let age = 39;

if (myBirthday) {
    age = age + 1;    // OK!
    myBirthday = false;  // Error!
}
```

ثابت `myBirthday` اجازهٔ re-assign ندارد.

متغیرهای اعلان‌شده با `const` «تغییرناپذیر» نیستند، فقط نمی‌توان re-assign کرد. استفاده از `const` با مقادیر object توصیه نمی‌شود، چون آن مقادیر هنوز می‌توانند تغییر کنند حتی اگر متغیر نتواند re-assign شود. این منجر به سردرگمی بالقوه در آینده می‌شود، پس فکر می‌کنم عاقلانه است از موقعیت‌هایی مثل این اجتناب کنید:

```js
const actors = [
    "Morgan Freeman", "Jennifer Aniston"
];

actors[2] = "Tom Cruise";   // OK :(
actors = [];                // Error!
```

بهترین استفادهٔ معنایی از `const` وقتی است که مقدار اولیهٔ ساده‌ای دارید که می‌خواهید نام مفیدی به آن بدهید، مثل استفاده از `myBirthday` به‌جای `true`. این برنامه‌ها را خوان‌تر می‌کند.

| نکته: |
| :--- |
| اگر فقط با مقادیر primitive از `const` استفاده کنید، از هر سردرگمی re-assignment (غیرمجاز) در مقابل mutation (مجاز) اجتناب می‌کنید! این امن‌ترین و بهترین راه استفاده از `const` است. |

علاوه بر `var` / `let` / `const`، اشکال نحوی دیگری هستند که identifiers (متغیرها) را در scopeهای مختلف اعلان می‌کنند. مثلاً:

```js
function hello(myName) {
    console.log(`Hello, ${ myName }.`);
}

hello("Kyle");
// Hello, Kyle.
```

identifier `hello` در scope بیرونی ایجاد می‌شود، و همچنین به‌طور خودکار مرتبط می‌شود تا به تابع ارجاع دهد. اما پارامتر نام‌دار `myName` فقط داخل تابع ایجاد می‌شود، و بنابراین فقط در scope آن تابع قابل دسترسی است. `hello` و `myName` به‌طور کلی مثل اعلان‌شده با `var` رفتار می‌کنند.

نحو دیگر که متغی را اعلان می‌کند clause `catch` است:

```js
try {
    someError();
}
catch (err) {
    console.log(err);
}
```

`err` متغی block-scoped است که فقط داخل clause `catch` وجود دارد، انگار با `let` اعلان شده باشد.
