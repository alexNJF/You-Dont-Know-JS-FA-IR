# Closure

شاید بدون اینکه متوجه شوید، تقریباً هر توسعه‌دهندهٔ جاوااسکریپت از closure استفاده کرده. در واقع، closure یکی از فراگیرترین قابلیت‌های برنامه‌نویسی در اکثریت زبان‌هاست. حتی ممکن است به اندازهٔ متغیرها یا حلقه‌ها برای فهمیدن مهم باشد؛ اینقدر بنیادین است.

با این حال، نوعی پنهان، تقریباً جادویی احساس می‌شود. و اغلب با اصطلاحات بسیار انتزاعی یا بسیار غیررسمی دربارهٔ آن صحبت می‌شود، که کمکی به دقیقاً مشخص کردن آنچه هست نمی‌کند.

باید بتوانیم تشخیص دهیم closure کجا در برنامه‌ها استفاده می‌شود، چون وجود یا عدم closure گاهی علت باگ‌ها (یا حتی علت مشکلات عملکرد) است.

پس بیایید closure را به‌طور عملی و concrete تعریف کنیم:

> Closure وقتی است که یک تابع متغیرها را از خارج scope خود به خاطر می‌آورد و به دسترسی ادامه می‌دهد، حتی وقتی تابع در scope متفاوتی اجرا می‌شود.

دو ویژگی تعریفی اینجا می‌بینیم. اول، closure بخشی از طبیعت یک تابع است. اشیاء closure نمی‌گیرند، توابع می‌گیرند. دوم، برای مشاهدهٔ closure، باید تابع را در scope متفاوتی از جایی که در اصل تعریف شده اجرا کنید.

در نظر بگیرید:

```js
function greeting(msg) {
    return function who(name) {
        console.log(`${ msg }, ${ name }!`);
    };
}

var hello = greeting("Hello");
var howdy = greeting("Howdy");

hello("Kyle");
// Hello, Kyle!

hello("Sarah");
// Hello, Sarah!

howdy("Grant");
// Howdy, Grant!
```

اول، تابع بیرونی `greeting(..)` اجرا می‌شود، instanceای از تابع داخلی `who(..)` ایجاد می‌کند؛ آن تابع روی متغیر `msg` بسته می‌شود، که پارامتر از scope بیرونی `greeting(..)` است. وقتی آن تابع داخلی برگردانده می‌شود، ارجاعش به متغیر `hello` در scope بیرونی assign می‌شود. سپس `greeting(..)` را بار دوم فراخوانی می‌کنیم، instance تابع داخلی جدیدی با closure جدید روی `msg` جدید ایجاد می‌کنیم، و آن ارجاع را برای assign به `howdy` برمی‌گردانیم.

وقتی تابع `greeting(..)` اجرایش تمام می‌شود، معمولاً انتظار داریم همهٔ متغیرهایش garbage collected شوند (از حافظه حذف شوند). انتظار داریم هر `msg` برود، اما نمی‌روند. دلیل closure است. چون instanceهای تابع داخلی هنوز زنده‌اند (به ترتیب به `hello` و `howdy` assign شده‌اند)، closureهایشان هنوز متغیرهای `msg` را حفظ می‌کنند.

این closureها snapshot مقدار متغیر `msg` نیستند؛ لینک مستقیم و حفظ خود متغیر هستند. یعنی closure در واقع می‌تواند به‌مرور زمان به‌روزرسانی‌ها به این متغیرها را مشاهده (یا ایجاد!) کند.

```js
function counter(step = 1) {
    var count = 0;
    return function increaseCount(){
        count = count + step;
        return count;
    };
}

var incBy1 = counter(1);
var incBy3 = counter(3);

incBy1();       // 1
incBy1();       // 2

incBy3();       // 3
incBy3();       // 6
incBy3();       // 9
```

هر instance از تابع داخلی `increaseCount()` روی هر دو متغیر `count` و `step` از scope تابع بیرونی `counter(..)` بسته می‌شود. `step` به‌مرور زمان ثابت می‌ماند، اما `count` در هر فراخوانی آن تابع داخلی به‌روز می‌شود. چون closure روی متغیرهاست و نه فقط snapshotهای مقادیر، این به‌روزرسانی‌ها حفظ می‌شوند.

Closure هنگام کار با کد asynchronous رایج‌ترین است، مثل callbackها. در نظر بگیرید:

```js
function getSomeData(url) {
    ajax(url,function onResponse(resp){
        console.log(
            `Response (from ${ url }): ${ resp }`
        );
    });
}

getSomeData("https://some.url/wherever");
// Response (from https://some.url/wherever): ...
```

تابع داخلی `onResponse(..)` روی `url` بسته می‌شود، و بنابراین آن را تا زمانی که فراخوانی Ajax برگردد و `onResponse(..)` را اجرا کند حفظ و به خاطر می‌آورد. حتی با وجود اینکه `getSomeData(..)` بلافاصله تمام می‌شود، متغیر پارامتر `url` در closure تا زمانی که لازم است زنده نگه داشته می‌شود.

ضروری نیست scope بیرونی تابع باشد—معمولاً هست، اما همیشه نه—فقط اینکه حداقل یک متغیر در scope بیرونی باشد که از تابع داخلی دسترسی شود:

```js
for (let [idx,btn] of buttons.entries()) {
    btn.addEventListener("click",function onClick(){
       console.log(`Clicked on button (${ idx })!`);
    });
}
```

چون این حلقه از اعلان‌های `let` استفاده می‌کند، هر تکرار متغیرهای block-scoped (با نام مستعار محلی) جدید `idx` و `btn` می‌گیرد؛ حلقه همچنین هر بار تابع داخلی جدید `onClick(..)` ایجاد می‌کند. آن تابع داخلی روی `idx` بسته می‌شود، آن را تا زمانی که handler کلیک روی `btn` تنظیم شده حفظ می‌کند. پس وقتی هر دکمه کلیک می‌شود، handlerش می‌تواند مقدار index مرتبطش را چاپ کند، چون handler متغیر `idx` مربوطش را به خاطر می‌آورد.

به خاطر داشته باشید: این closure روی مقدار (مثل `1` یا `3`) نیست، بلکه روی خود متغیر `idx` است.

Closure یکی از رایج‌ترین و مهم‌ترین الگوهای برنامه‌نویسی در هر زبانی است. اما به‌ویژه برای جاوااسکریپت درست است؛ تصور انجام هر کار مفیدی بدون استفاده از closure به شکلی یا شکلی دیگر سخت است.
