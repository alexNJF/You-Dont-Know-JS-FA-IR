# تکرار

از آنجا که برنامه‌ها اساساً برای پردازش داده (و تصمیم‌گیری روی آن داده) ساخته می‌شوند، الگوهای استفاده‌شده برای قدم‌زدن در داده تأثیر بزرگی بر خوانایی برنامه دارند.

الگوی iterator دهه‌هاست وجود دارد، و رویکرد «استاندارد» برای مصرف داده از منبع یک *chunk* در هر بار پیشنهاد می‌کند. ایده این است که تکرار منبع داده—handle کردن تدریجی مجموعهٔ داده با پردازش بخش اول، سپس بعدی، و غیره—رایج‌تر و مفیدتر است تا handle کردن کل مجموعه یک‌جا.

ساختار داده‌ای را تصور کنید که query `SELECT` پایگاه دادهٔ relational را نشان می‌دهد، که معمولاً نتایج را به‌صورت ردیف‌ها سازماندهی می‌کند. اگر این query فقط یک یا چند ردیف داشت، می‌توانستید کل مجموعهٔ نتیجه را یک‌جا handle کنید، و هر ردیف را به متغیر محلی assign کنید، و هر عملیات مناسب روی آن داده انجام دهید.

اما اگر query ۱۰۰ یا ۱۰۰۰ (یا بیشتر!) ردیف داشته باشد، برای برخورد با این داده به پردازش تکراری نیاز دارید (معمولاً یک حلقه).

الگوی iterator ساختار داده‌ای به نام «iterator» تعریف می‌کند که ارجاعی به منبع دادهٔ زیرین (مثل ردیف‌های نتیجهٔ query) دارد، که متدی مثل `next()` در معرض می‌گذارد. فراخوانی `next()` قطعهٔ بعدی داده را برمی‌گرداند (یعنی یک «record» یا «row» از query پایگاه داده).

همیشه نمی‌دانید چند قطعه داده باید از آن تکرار کنید، پس الگو معمولاً تکمیل را با مقداری خاص یا exception نشان می‌دهد وقتی از کل مجموعه عبور کردید و *از انتها گذشتید*.

اهمیت الگوی iterator در پایبندی به روش *استاندارد* پردازش تکراری داده است، که کد تمیزتر و ساده‌تر برای فهم ایجاد می‌کند، در مقابل اینکه هر ساختار/منبع داده روش سفارشی خودش برای handle کردن داده‌اش را تعریف کند.

بعد از سال‌ها تلاش‌های مختلف جامعهٔ جاوااسکریپت حول تکنیک‌های تکرار توافق‌شده، ES6 پروتکل خاصی برای الگوی iterator مستقیماً در زبان استاندارد کرد. پروتکل متد `next()` را تعریف می‌کند که بازگشتش objectی به نام *iterator result* است؛ object دارای propertyهای `value` و `done` است، که `done` booleanی است که تا تکمیل تکرار روی منبع دادهٔ زیرین `false` است.

## مصرف Iteratorها

با پروتکل تکرار ES6 در جای خود، قابل کار است منبع داده را یک مقدار در هر بار مصرف کنیم، بعد از هر فراخوانی `next()` برای `done` بودن `true` برای توقف تکرار بررسی کنیم. اما این رویکرد نسبتاً دستی است، پس ES6 چند مکانیزم (نحو و API) برای مصرف استاندارد این iteratorها هم شامل کرد.

یکی از این مکانیزم‌ها حلقهٔ `for..of` است:

```js
// با فرض iterator منبع داده‌ای:
var it = /* .. */;

// روی نتایجش یکی یکی حلقه بزن
for (let val of it) {
    console.log(`Iterator value: ${ val }`);
}
// Iterator value: ..
// Iterator value: ..
// ..
```

| :--- |
| معادل حلقهٔ دستی را اینجا حذف می‌کنیم، اما قطعاً خوانایی کمتری نسبت به حلقهٔ `for..of` دارد! |

مکانیزم دیگر که اغلب برای مصرف iteratorها استفاده می‌شود عملگر `...` است. این عملگر در واقع دو شکل متقارن دارد: *spread* و *rest* (یا *gather*، همان‌طور که ترجیح می‌دهم). شکل *spread* consumer iterator است.

برای *spread* کردن یک iterator، باید *چیزی* برای spread کردنش در آن داشته باشید. دو امکان در جاوااسکریپت وجود دارد: آرایه یا لیست argument برای فراخوانی تابع.

spread آرایه:

```js
// iterator را در آرایه spread کن،
// با هر مقدار تکرارشده در
// موقعیت عنصر آرایه.
var vals = [ ...it ];
```

spread فراخوانی تابع:

```js
// iterator را در تابع spread کن،
// فراخوانی با هر مقدار تکرارشده
// در موقعیت argument.
doSomethingUseful( ...it );
```

در هر دو مورد، شکل iterator-spread از `...` از پروتکل مصرف iterator (همان حلقهٔ `for..of`) پیروی می‌کند تا همهٔ مقادیر موجود را از iterator بگیرد و در context گیرنده (آرایه، لیست argument) قرار دهد (با نام مستعار spread).

## Iterableها

پروتکل مصرف iterator از نظر فنی برای مصرف *iterable*ها تعریف شده؛ iterable مقداری است که می‌توان روی آن iterate کرد.

پروتکل به‌طور خودکار instance iterator را از iterable ایجاد می‌کند، و *فقط آن instance iterator* را تا تکمیل مصرف می‌کند. یعنی یک iterable می‌تواند بیش از یک بار مصرف شود؛ هر بار، instance iterator جدیدی ایجاد و استفاده می‌شود.

پس iterableها را کجا پیدا می‌کنیم؟

ES6 انواع ساختار داده/مجموعهٔ پایه در جاوااسکریپت را به‌عنوان iterable تعریف کرد. این شامل stringها، آرایه‌ها، mapها، setها و غیره می‌شود.

در نظر بگیرید:

```js
// آرایه iterable است
var arr = [ 10, 20, 30 ];

for (let val of arr) {
    console.log(`Array value: ${ val }`);
}
// Array value: 10
// Array value: 20
// Array value: 30
```

از آنجا که آرایه‌ها iterable هستند، می‌توانیم با مصرف iterator از طریق عملگر spread `...` آرایه را shallow-copy کنیم:

```js
var arrCopy = [ ...arr ];
```

همچنین می‌توانیم کاراکترهای string را یکی یکی iterate کنیم:

```js
var greeting = "Hello world!";
var chars = [ ...greeting ];

chars;
// [ "H", "e", "l", "l", "o", " ",
//   "w", "o", "r", "l", "d", "!" ]
```

ساختار دادهٔ `Map` از اشیاء به‌عنوان کلید استفاده می‌کند، مقدار (از هر نوع) را با آن object مرتبط می‌کند. Mapها تکرار پیش‌فرض متفاوتی از آنچه اینجا دیدیم دارند، به این معنا که تکرار فقط روی مقادیر map نیست بلکه روی *entry*هایش است. یک *entry* یک tuple (آرایهٔ ۲ عنصری) است که هم کلید و هم مقدار را شامل می‌شود.

در نظر بگیرید:

```js
// با فرض دو عنصر DOM، `btn1` و `btn2`

var buttonNames = new Map();
buttonNames.set(btn1,"Button 1");
buttonNames.set(btn2,"Button 2");

for (let [btn,btnName] of buttonNames) {
    btn.addEventListener("click",function onClick(){
        console.log(`Clicked ${ btnName }`);
    });
}
```

در حلقهٔ `for..of` روی تکرار پیش‌فرض map، از نحو `[btn,btnName]` (به نام «array destructuring») برای تجزیهٔ هر tuple مصرف‌شده به جفت‌های کلید/مقدار مربوط (`btn1` / `"Button 1"` و `btn2` / `"Button 2"`) استفاده می‌کنیم.

هر کدام از iterableهای built-in در جاوااسکریپت تکرار پیش‌فرضی در معرض می‌گذارند، که احتمالاً با شهود شما مطابقت دارد. اما می‌توانید در صورت نیاز تکرار خاص‌تری هم انتخاب کنید. مثلاً اگر می‌خواهیم فقط مقادیر map بالا را مصرف کنیم، می‌توانیم `values()` را فراخوانی کنیم تا iterator فقط-مقادیر بگیریم:

```js
for (let btnName of buttonNames.values()) {
    console.log(btnName);
}
// Button 1
// Button 2
```

یا اگر index *و* مقدار را در تکرار آرایه می‌خواهیم، می‌توانیم با متد `entries()` iterator entries بسازیم:

```js
var arr = [ 10, 20, 30 ];

for (let [idx,val] of arr.entries()) {
    console.log(`[${ idx }]: ${ val }`);
}
// [0]: 10
// [1]: 20
// [2]: 30
```

در بیشتر موارد، همهٔ iterableهای built-in در جاوااسکریپت سه شکل iterator در دسترس دارند: فقط-کلیدها (`keys()`)، فقط-مقادیر (`values()`)، و entries (`entries()`).

فراتر از فقط استفاده از iterableهای built-in، می‌توانید اطمینان حاصل کنید ساختارهای دادهٔ خودتان به پروتکل تکرار پایبند باشند؛ انجام این کار یعنی به قابلیت مصرف دادهٔ خود با حلقه‌های `for..of` و عملگر `...` opt-in می‌کنید. «استاندارد کردن» روی این پروتکل یعنی کدی که به‌طور کلی قابل تشخیص‌تر و خوانا‌تر است.
