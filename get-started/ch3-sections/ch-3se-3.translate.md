# کلمهٔ کلیدی `this`

یکی از قدرتمندترین مکانیزم‌های جاوااسکریپت همچنین یکی از بدفهمیده‌شده‌ترین‌هاست: کلمهٔ کلیدی `this`. یک تصور نادرست رایج این است که `this` یک تابع به خود تابع اشاره می‌کند. به‌خاطر نحوهٔ کار `this` در زبان‌های دیگر، تصور نادرست دیگر این است که `this` به instanceای که متد به آن تعلق دارد اشاره می‌کند. هر دو نادرست‌اند.

همان‌طور که قبلاً بحث شد، وقتی تابعی تعریف می‌شود، از طریق closure به scope احاطه‌کننده‌اش *متصل* می‌شود. Scope مجموعه قوانینی است که نحوهٔ resolve شدن ارجاع به متغیرها را کنترل می‌کند.

اما توابع ویژگی دیگری علاوه بر scope دارند که بر آنچه می‌توانند دسترسی داشته باشند تأثیر می‌گذارد. این ویژگی بهترین توصیف به‌عنوان *execution context* است، و از طریق کلمهٔ کلیدی `this` به تابع در معرض است.

Scope استاتیک است و مجموعهٔ ثابتی از متغیرهای موجود در لحظه و مکان تعریف تابع را شامل می‌شود، اما *context* اجرای تابع پویا است، کاملاً وابسته به **نحوهٔ فراخوانی آن** (صرف‌نظر از جایی که تعریف یا حتی فراخوانی شده).

`this` ویژگی ثابت تابع بر اساس تعریف تابع نیست، بلکه ویژگی پویایی است که هر بار تابع فراخوانی می‌شود تعیین می‌شود.

یک راه فکر کردن به *execution context* این است که object ملموسی است که propertyهایش در حین اجرا در دسترس تابع قرار می‌گیرند. آن را با scope مقایسه کنید، که می‌توان آن را هم *object* در نظر گرفت؛ با این تفاوت که *scope object* داخل موتور جاوااسکریپت پنهان است، همیشه برای آن تابع یکسان است، و *property*هایش به شکل متغیرهای identifier موجود داخل تابع هستند.

```js
function classroom(teacher) {
    return function study() {
        console.log(
            `${ teacher } says to study ${ this.topic }`
        );
    };
}
var assignment = classroom("Kyle");
```

تابع بیرونی `classroom(..)` هیچ ارجاعی به کلمهٔ کلیدی `this` ندارد، پس مثل هر تابع دیگری که تا به حال دیدیم است. اما تابع داخلی `study()` به `this` ارجاع می‌دهد، که آن را تابع آگاه از `this` می‌کند. به عبارت دیگر، تابعی است که به *execution context* خود وابسته است.

| نکته: |
| :--- |
| `study()` همچنین روی متغیر `teacher` از scope بیرونی بسته می‌شود. |

تابع داخلی `study()` برگردانده‌شده توسط `classroom("Kyle")` به متغیری به نام `assignment` assign می‌شود. پس چطور می‌توان `assignment()` (با نام مستعار `study()`) را فراخوانی کرد؟

```js
assignment();
// Kyle says to study undefined  -- اوه :(
```

در این تکه، `assignment()` را به‌عنوان تابع ساده و معمولی فراخوانی می‌کنیم، بدون ارائهٔ هیچ *execution context*.

چون این برنامه در حالت strict نیست (فصل ۱، «Strictly Speaking» را ببینید)، توابع آگاه از context که **بدون هیچ context مشخصی** فراخوانی می‌شوند context را به object سراسری (`window` در مرورگر) پیش‌فرض می‌کنند. چون متغیر سراسری به نام `topic` وجود ندارد (و بنابراین چنین propertyای روی object سراسری نیست)، `this.topic` به `undefined` resolve می‌شود.

حالا در نظر بگیرید:

```js
var homework = {
    topic: "JS",
    assignment: assignment
};

homework.assignment();
// Kyle says to study JS
```

کپی ارجاع تابع `assignment` به‌عنوان property روی object `homework` تنظیم شده، و سپس به‌عنوان `homework.assignment()` فراخوانی می‌شود. یعنی `this` برای آن فراخوانی تابع object `homework` خواهد بود. بنابراین، `this.topic` به `"JS"` resolve می‌شود.

در نهایت:

```js
var otherHomework = {
    topic: "Math"
};

assignment.call(otherHomework);
// Kyle says to study Math
```

راه سوم فراخوانی تابع با متد `call(..)` است، که object (`otherHomework` اینجا) را برای تنظیم ارجاع `this` برای فراخوانی تابع می‌گیرد. ارجاع property `this.topic` به `"Math"` resolve می‌شود.

همان تابع آگاه از context با سه روش مختلف فراخوانی شده، هر بار پاسخ متفاوتی برای objectی که `this` به آن ارجاع می‌دهد می‌دهد.

مزیت توابع آگاه از `this`—و context پویای آن‌ها—قابلیت استفادهٔ انعطاف‌پذیرتر مجدد از یک تابع با داده از اشیاء مختلف است. تابعی که روی scope بسته می‌شود هرگز نمی‌تواند به scope یا مجموعه متغیرهای متفاوتی ارجاع دهد. اما تابعی که آگاهی context `this` پویا دارد می‌تواند برای کارهای خاص بسیار مفید باشد.
