# Abstract Relational Comparison

هرچند این بخش از coercion *implicit* اغلب خیلی کمتر توجه می‌گیرد، مهم است به آنچه در مقایسه‌های `a < b` رخ می‌دهد فکر کنیم (مشابه بررسی عمیق `a == b`).

الگوریتم «Abstract Relational Comparison» در بخش ۱۱٫۸٫۵ ES5 در اصل خود را به دو بخش تقسیم می‌کند: چه کنیم اگر مقایسه هر دو مقدار `string` را شامل شود (نیمهٔ دوم)، یا چیز دیگر (نیمهٔ اول).

**توجه:** الگوریتم فقط برای `a < b` تعریف شده. پس `a > b` به‌صورت `b < a` پردازش می‌شود.

الگوریتم اول coercion یعنی `ToPrimitive` را روی هر دو مقدار فراخوانی می‌کند، و اگر نتیجهٔ برگشتی هر فراخوانی `string` نبود، هر دو مقدار با قوانین عملیات `ToNumber` به مقدارهای `number` coerce می‌شوند و به‌صورت عددی مقایسه می‌شوند.

مثلاً:

```js
var a = [ 42 ];
var b = [ "43" ];

a < b;	// true
b < a;	// false
```

**توجه:** هشدارهای مشابه برای `-0` و `NaN` اینجا هم مثل الگوریتم `==` که قبلاً بحث شد اعمال می‌شوند.

با این حال، اگر هر دو مقدار برای مقایسهٔ `<` برابر `string` باشند، مقایسهٔ واژه‌نگارانه (الفبایی طبیعی) ساده روی کاراکترها انجام می‌شود:

```js
var a = [ "42" ];
var b = [ "043" ];

a < b;	// false
```

`a` و `b` به `number` coerce *نمی‌شوند*، چون هر دو بعد از coercion یعنی `ToPrimitive` روی آن دو `array` به `string` تبدیل می‌شوند. پس `"42"` کاراکتر به کاراکتر با `"043"` مقایسه می‌شود، از کاراکترهای اول یعنی `"4"` و `"0"`. چون `"0"` از نظر واژه‌نگارانه *کوچک‌تر از* `"4"` است، مقایسه `false` برمی‌گرداند.

دقیقاً همان رفتار و استدلال برای این هم برقرار است:

```js
var a = [ 4, 2 ];
var b = [ 0, 4, 3 ];

a < b;	// false
```

اینجا `a` می‌شود `"4,2"` و `b` می‌شود `"0,4,3"`، و آن‌ها از نظر واژه‌نگارانه مثل قطعهٔ قبلی مقایسه می‌شوند.

این چطور:

```js
var a = { b: 42 };
var b = { b: 43 };

a < b;	// ??
```

`a < b` برابر `false` است، چون `a` می‌شود `[object Object]` و `b` می‌شود `[object Object]`، و پس واضح است که `a` از نظر واژه‌نگارانه کوچک‌تر از `b` نیست.

اما عجیب این که:

```js
var a = { b: 42 };
var b = { b: 43 };

a < b;	// false
a == b;	// false
a > b;	// false

a <= b;	// true
a >= b;	// true
```

چرا `a == b` برابر `true` نیست؟ آن‌ها همان مقدار `string` (`"[object Object]"`) هستند، پس به نظر می‌رسد باید برابر باشند، درست؟ نه. بحث قبلی دربارهٔ نحوهٔ کار `==` با ارجاع‌های `object` را به یاد بیاورید.

اما پس چطور `a <= b` و `a >= b` نتیجهٔ `true` می‌دهند، اگر `a < b` **و** `a == b` **و** `a > b` همه `false` باشند؟

چون مشخصات می‌گوید برای `a <= b` در واقع اول `b < a` را ارزیابی می‌کند و بعد نتیجه را نفی می‌کند. چون `b < a` *هم* `false` است، نتیجهٔ `a <= b` برابر `true` است.

احتمالاً کاملاً خلاف توضیحی است که تا الان از `<=` داده‌اید، که احتمالاً تحت‌اللفظی بوده: «کوچک‌تر *یا* برابر.» JS دقیق‌تر `<=` را «بزرگ‌تر نیست» در نظر می‌گیرد (`!(a > b)` که JS به‌صورت `!(b < a)` رفتار می‌کند). علاوه بر این، `a >= b` با در نظر گرفتن اول آن به‌صورت `b <= a` و بعد اعمال همان استدلال توضیح داده می‌شود.

متأسفانه «مقایسهٔ رابطه‌ای strict» مثل برابری وجود ندارد. به عبارت دیگر، راهی برای جلوگیری از coercion *implicit* در مقایسه‌های رابطه‌ای مثل `a < b` نیست، جز اینکه قبل از مقایسه صریحاً مطمئن شوید `a` و `b` از یک type هستند.

همان استدلال بحث سلامت `==` در مقابل `===` را به کار ببرید. اگر coercion مفید و نسبتاً امن است، مثل مقایسهٔ `42 < "43"`، **استفاده کنید**. از طرف دیگر، اگر باید در مقایسهٔ رابطه‌ای امن باشید، اول مقدارها را *صریحاً coerce* کنید، قبل از استفاده از `<` (یا همتایانش).

```js
var a = [ 42 ];
var b = "043";

a < b;						// false -- string comparison!
Number( a ) < Number( b );	// true -- number comparison!
```
