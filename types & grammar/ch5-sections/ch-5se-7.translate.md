# `switch`

بیایید کوتاه statement `switch` را بررسی کنیم، نوعی خلاصهٔ نحوی برای زنجیرهٔ statementهای `if..else if..else..`.

```js
switch (a) {
	case 2:
		// do something
		break;
	case 42:
		// do another thing
		break;
	default:
		// fallback to here
}
```

همان‌طور که می‌بینید، یک بار `a` را ارزیابی می‌کند، بعد مقدار حاصل را با هر expression در `case` (اینجا فقط expressionهای مقدار ساده) مقایسه می‌کند. اگر تطابقی پیدا شود، اجرا در آن `case` تطابق‌یافته شروع می‌شود، و یا تا رسیدن به `break` ادامه می‌یابد یا تا رسیدن به انتهای بلوک `switch`.

این مقدار شاید تعجب‌آور نباشد، اما چند quirk دربارهٔ `switch` هست که شاید قبلاً متوجه نشده باشید.

اول، تطابقی که بین expression `a` و هر expression در `case` رخ می‌دهد با الگوریتم `===` یکسان است (فصل ۴ را ببینید). اغلب `switch`ها با مقدارهای مطلق در statementهای `case` به کار می‌روند، همان‌طور که بالا نشان داده شد، پس تطابق سخت مناسب است.

با این حال، ممکن است بخواهید برابری coercion (یعنی `==`، فصل ۴ را ببینید) را اجازه دهید، و برای این کار باید کمی statement `switch` را «هک» کنید:

```js
var a = "42";

switch (true) {
	case a == 10:
		console.log( "10 or '10'" );
		break;
	case a == 42:
		console.log( "42 or '42'" );
		break;
	default:
		// never gets here
}
// 42 or '42'
```

این کار می‌کند چون بند `case` می‌تواند هر expression داشته باشد (نه فقط مقدارهای ساده)، یعنی نتیجهٔ آن expression را با expression تست (`true`) به‌طور سخت تطابق می‌دهد. چون `a == 42` اینجا به `true` نتیجه می‌دهد، تطابق برقرار می‌شود.

علیرغم `==`، خود تطابق `switch` هنوز سخت است، بین `true` و `true` اینجا. اگر expression در `case` به چیزی truthy اما نه به‌طور سخت `true` نتیجه می‌داد (فصل ۴ را ببینید)، کار نمی‌کرد. اگر مثلاً در expressionتان از یک «operator منطقی» مثل `||` یا `&&` استفاده کنید می‌تواند گاز بگیرد:

```js
var a = "hello world";
var b = 10;

switch (true) {
	case (a || b == 10):
		// never gets here
		break;
	default:
		console.log( "Oops" );
}
// Oops
```

چون نتیجهٔ `(a || b == 10)` برابر `"hello world"` است و نه `true`، تطابق سخت شکست می‌خورد. در این مورد، راه‌حل این است که expression را صریحاً به `true` یا `false` وادار کنید، مثل `case !!(a || b == 10):` (فصل ۴ را ببینید).

در آخر، بند `default` اختیاری است، و لزوماً نباید در انتها باشد (هرچند این قرارداد قوی است). حتی در بند `default`، همان قواعد دربارهٔ رسیدن به `break` یا نرسیدن اعمال می‌شود:

```js
var a = 10;

switch (a) {
	case 1:
	case 2:
		// never gets here
	default:
		console.log( "default" );
	case 3:
		console.log( "3" );
		break;
	case 4:
		console.log( "4" );
}
// default
// 3
```

| NOTE: |
| :--- |
| همان‌طور که قبلاً دربارهٔ `break`های دارای label بحث شد، `break` داخل بند `case` هم می‌تواند دارای label باشد. |

نحوهٔ پردازش این قطعه این است که اول از همهٔ تطابق بندهای `case` عبور می‌کند، تطابقی پیدا نمی‌کند، بعد برمی‌گردد به بند `default` و اجرا را شروع می‌کند. چون آنجا `break` نیست، در بلوک `case 3` که قبلاً رد شده ادامه اجرا می‌دهد، تا به آن `break` برخورد کند.

در حالی که این نوع منطق دور-و-بری در جاوااسکریپت واضحاً ممکن است، تقریباً هیچ شانسی نیست که کد معقول یا قابل‌فهم بسازد. اگر دیدید می‌خواهید چنین جریان منطق دایره‌ای بسازید بسیار شک‌کننده باشید، و اگر واقعاً می‌کنید، حتماً کامنت‌های کافی برای توضیح کارتان بگذارید!
