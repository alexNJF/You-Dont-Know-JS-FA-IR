# Function Arguments

مثال دیگر نقض TDZ را می‌توان با مقدارهای پیش‌فرض پارامتر ES6 دید (عنوان *ES6 & Beyond* این مجموعه را ببینید):

```js
var b = 3;

function foo( a = 42, b = a + b + 5 ) {
	// ..
}
```

ارجاع `b` در انتساب در TDZ برای پارامتر `b` اتفاق می‌افتد (نه کشیدن ارجاع بیرونی `b`)، پس خطا پرتاب می‌کند. با این حال، `a` در انتساب درست است چون تا آن زمان از TDZ پارامتر `a` گذشته.

وقتی از مقدارهای پیش‌فرض پارامتر ES6 استفاده می‌کنید، مقدار پیش‌فرض به پارامتر اعمال می‌شود اگر یا آرگومان را حذف کنید، یا مقدار `undefined` به‌جایش پاس دهید:

```js
function foo( a = 42, b = a + 1 ) {
	console.log( a, b );
}

foo();					// 42 43
foo( undefined );		// 42 43
foo( 5 );				// 5 6
foo( void 0, 7 );		// 42 7
foo( null );			// null 1
```

| NOTE: |
| :--- |
| `null` در expression `a + 1` به مقدار `0` coercion می‌شود. فصل ۴ را برای اطلاعات بیشتر ببینید. |

از منظر مقدارهای پیش‌فرض پارامتر ES6، بین حذف یک آرگومان و پاس دادن مقدار `undefined` فرقی نیست. با این حال، در بعضی موارد راهی برای تشخیص تفاوت وجود دارد:

```js
function foo( a = 42, b = a + 1 ) {
	console.log(
		arguments.length, a, b,
		arguments[0], arguments[1]
	);
}

foo();					// 0 42 43 undefined undefined
foo( 10 );				// 1 10 11 10 undefined
foo( 10, undefined );	// 2 10 11 10 undefined
foo( 10, null );		// 2 10 null 10 null
```

حتی با اینکه مقدارهای پیش‌فرض پارامتر به پارامترهای `a` و `b` اعمال می‌شوند، اگر در آن slotها آرگومانی پاس داده نشده باشد، آرایهٔ `arguments` entry نخواهد داشت.

برعکس، اگر صریحاً آرگومان `undefined` پاس دهید، یک entry در آرایهٔ `arguments` برای آن آرگومان وجود خواهد داشت، اما `undefined` خواهد بود و (الزاماً) با مقدار پیش‌فرضی که به متغیر پارامتر نام‌دار برای همان slot اعمال شد یکی نیست.

در حالی که مقدارهای پیش‌فرض پارامتر ES6 می‌توانند واگرایی بین slot آرایهٔ `arguments` و متغیر پارامتر نام‌دار متناظر ایجاد کنند، همین disjointedness می‌تواند به‌صورت های trick در ES5 هم رخ دهد:

```js
function foo(a) {
	a = 42;
	console.log( arguments[0] );
}

foo( 2 );	// 42 (linked)
foo();		// undefined (not linked)
```

اگر آرگومان پاس دهید، slot `arguments` و پارامتر نام‌دار به هم وصل می‌شوند تا همیشه همان مقدار را داشته باشند. اگر آرگومان را حذف کنید، چنین اتصالی رخ نمی‌دهد.

اما در حالت `strict`، اتصال در هر صورت وجود ندارد:

```js
function foo(a) {
	"use strict";
	a = 42;
	console.log( arguments[0] );
}

foo( 2 );	// 2 (not linked)
foo();		// undefined (not linked)
```

تقریباً قطعاً ایدهٔ بدی است که به چنین اتصالی تکیه کنید، و در واقع خود اتصال یک انتزاع نشتی است که جزئیات پیاده‌سازی زیرین موتور را افشا می‌کند، نه یک ویژگی درست طراحی‌شده.

استفاده از آرایهٔ `arguments` منسوخ شده (به‌ویژه به نفع پارامترهای rest با `...` در ES6 — عنوان *ES6 & Beyond* این مجموعه را ببینید)، اما این یعنی بد نیست.

قبل از ES6، `arguments` تنها راه گرفتن آرایهٔ همهٔ آرگومان‌های پاس‌داده‌شده برای پاس دادن به توابع دیگر است، که بسیار مفید است. می‌توانید پارامترهای نام‌دار را با آرایهٔ `arguments` هم مخلوط کنید و امن باشید، به‌شرطی که یک قانون ساده را رعایت کنید: **هرگز هم به پارامتر نام‌دار و هم به slot متناظر `arguments` در همان زمان ارجاع ندهید.** اگر از آن روش بد دوری کنید، هرگز رفتار اتصال نشتی را افشا نمی‌کنید.

```js
function foo(a) {
	console.log( a + arguments[1] ); // safe!
}

foo( 10, 32 );	// 42
```
