# Errors

جاوااسکریپت نه‌تنها *زیرنوع*های مختلف خطا دارد (`TypeError`، `ReferenceError`، `SyntaxError` و غیره)، بلکه grammar خطاهای معینی را تعریف می‌کند که در زمان compile اعمال می‌شوند، در مقایسه با بقیهٔ خطاهایی که در زمان اجرا رخ می‌دهند.

به‌طور خاص، مدتهاست شرایط معین زیادی وجود دارد که باید گرفته و به‌عنوان «early errors» (در حین کامپایل) گزارش شوند. هر خطای syntax مستقیم یک early error است (مثلاً `a = ,`)، اما grammar چیزهایی را هم تعریف می‌کند که از نظر نحوی معتبرند اما به‌هرحال ممنوع‌اند.

چون اجرای کدتان هنوز شروع نشده، این خطاها با `try..catch` قابل گرفتن نیستند؛ فقط parse/کامپایل برنامه را شکست می‌دهند.

| TIP: |
| :--- |
| در مشخصات الزامی دربارهٔ نحوهٔ دقیق گزارش خطا توسط مرورگرها (و ابزارهای توسعه‌دهنده) وجود ندارد. پس ممکن است در مثال‌های خطای زیر در مرورگرهای مختلف تفاوت ببینید، در اینکه چه زیرنوع خطایی گزارش می‌شود یا متن پیام خطای شامل چه خواهد بود. |

یک مثال ساده با syntax داخل یک literal عبارت باقاعده است. از نظر syntax JS اینجا اشکالی نیست، اما regex نامعتبر early error پرتاب می‌کند:

```js
var a = /+foo/;		// Error!
```

هدف یک انتساب باید یک identifier باشد (یا یک expression destructuring در ES6 که یک یا چند identifier تولید می‌کند)، پس مقداری مثل `42` در آن موقعیت غیرقانونی است و می‌توان فوراً گزارش داد:

```js
var a;
42 = a;		// Error!
```

حالت `strict` در ES5 حتی early errorهای بیشتری تعریف می‌کند. مثلاً، در حالت `strict`، نام پارامترهای تابع نمی‌توانند تکراری باشند:

```js
function foo(a,b,a) { }					// just fine

function bar(a,b,a) { "use strict"; }	// Error!
```

یک early error دیگر حالت `strict` این است که یک object literal بیش از یک property با همان نام داشته باشد:

```js
(function(){
	"use strict";

	var a = {
		b: 42,
		b: 43
	};			// Error!
})();
```

| NOTE: |
| :--- |
| از نظر معنایی، چنین خطاهایی از نظر فنی *syntax* error نیستند بلکه بیشتر *grammar* error هستند — قطعه‌های بالا از نظر نحوی معتبرند. اما چون نوع `GrammarError` وجود ندارد، بعضی مرورگرها به‌جایش از `SyntaxError` استفاده می‌کنند. |

### Using Variables Too Early

ES6 مفهومی جدید (صادقانه بگوییم با نام گیج‌کننده) به نام TDZ («Temporal Dead Zone») تعریف می‌کند.

TDZ به جاهایی در کد اشاره دارد که هنوز نمی‌توان به یک متغیر ارجاع داد، چون به مقداردهی الزامی خود نرسیده.

واضح‌ترین مثال با block-scoping با `let` در ES6 است:

```js
{
	a = 2;		// ReferenceError!
	let a;
}
```

انتساب `a = 2` به متغیر `a` (که واقعاً به بلوک `{ .. }` block-scoped است) قبل از مقداردهی توسط اعلام `let a` دسترسی دارد، پس در TDZ برای `a` است و خطا پرتاب می‌کند.

جالبی اینکه، در حالی که `typeof` استثنایی برای امن بودن با متغیرهای اعلام‌نشده دارد (فصل ۱ را ببینید)، برای ارجاع‌های TDZ چنین استثنای امنیتی وجود ندارد:

```js
{
	typeof a;	// undefined
	typeof b;	// ReferenceError! (TDZ)
	let b;
}
```
