# Host Objects

قواعد خوب پوشش‌داده‌شدهٔ نحوهٔ رفتار متغیرها در JS وقتی به متغیرهایی می‌رسد که به‌طور خودکار تعریف می‌شوند، یا به‌طور دیگر توسط محیطی که کدتان را میزبانی می‌کند (مرورگر و غیره) ساخته و به JS داده می‌شوند — به‌اصطلاح «host objects» (که هم `object`های built-in و هم `function`ها را شامل می‌شود) استثنا دارند.

مثلاً:

```js
var a = document.createElement( "div" );

typeof a;								// "object" -- as expected
Object.prototype.toString.call( a );	// "[object HTMLDivElement]"

a.tagName;								// "DIV"
```

`a` فقط یک `object` نیست، بلکه یک host object خاص است چون المان DOM است. مقدار داخلی `[[Class]]` متفاوتی دارد (`"HTMLDivElement"`) و با propertyهای از پیش‌تعریف‌شده (و اغلب غیرقابل‌تغییر) می‌آید.

یک quirk دیگر قبلاً در بخش «Falsy Objects» فصل ۴ پوشش داده شد: بعضی objectها می‌توانند وجود داشته باشند اما وقتی به `boolean` coercion شوند (گیج‌کننده) به‌جای `true` مورد انتظار به `false` coercion می‌شوند.

تنوع‌های رفتاری دیگر با host objectها که باید از آن‌ها آگاه باشید می‌تواند شامل شود:

* نداشتن دسترسی به built-inهای معمولی `object` مثل `toString()`
* غیرقابل بازنویسی بودن
* داشتن propertyهای از پیش‌تعریف‌شدهٔ فقط‑خواندنی معین
* داشتن متدهایی که نمی‌توان `this` آن‌ها را به objectهای دیگر override کرد
* و بیشتر...

Host objectها برای کار کردن کد JS با محیط اطرافش حیاتی‌اند. اما مهم است وقتی با یک host object تعامل می‌کنید متوجه باشید و در فرض رفتارهایش احتیاط کنید، چون اغلب با `object`های معمولی JS مطابقت ندارند.

یک مثال notable از host object که احتمالاً مرتب با آن تعامل دارید شیء `console` و توابع مختلفش (`log(..)`، `error(..)` و غیره) است. شیء `console` توسط *محیط میزبان* به‌طور خاص داده می‌شود تا کدتان بتواند برای کارهای خروجی مرتبط با توسعه با آن تعامل کند.

در مرورگرها، `console` به نمایش کنسول ابزارهای توسعه‌دهنده وصل می‌شود، در حالی که در node.js و محیط‌های JS سمت سرور دیگر، `console` معمولاً به جریان‌های standard-output (`stdout`) و standard-error (`stderr`) فرایند سیستم محیط جاوااسکریپت وصل است.
