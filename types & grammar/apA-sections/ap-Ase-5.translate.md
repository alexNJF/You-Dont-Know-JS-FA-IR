# `<script>`s

بیشتر وب‌سایت‌ها/اپلیکیشن‌های دیده‌شده در مرورگر بیش از یک فایل دارند که کدشان را در بر می‌گیرد، و رایج است چند یا چندین المان `<script src=..></script>` در صفحه داشته باشید که این فایل‌ها را جدا لود می‌کنند، و حتی چند المان `<script> .. </script>` کد درون‌خطی هم.

اما آیا این فایل‌ها/قطعه‌های کد جدا برنامه‌های جدا هستند یا با هم یک برنامهٔ JS؟

واقعیت (شاید تعجب‌آور) این است که در بیشتر، اما نه همه، جنبه‌ها بیشتر مثل برنامه‌های JS مستقل عمل می‌کنند.

یک چیز که *به اشتراک می‌گذارند* شیء واحد `global` (`window` در مرورگر) است، یعنی چند فایل می‌توانند کدشان را به آن namespace مشترک اضافه کنند و همه با هم تعامل کنند.

پس، اگر یک المان `script` یک تابع سراسری `foo()` تعریف کند، وقتی `script` دوم بعداً اجرا شود، می‌تواند به `foo()` دسترسی داشته باشد و فراخوانی کند انگار خودش تابع را تعریف کرده.

اما *hoisting* scope متغیر سراسری (عنوان *Scope & Closures* این مجموعه را ببینید) از این مرزها عبور نمی‌کند، پس کد زیر کار نمی‌کند (چون اعلام `foo()` هنوز اعلام نشده)، صرف‌نظر از اینکه المان‌های `<script> .. </script>` درون‌خطی باشند (همان‌طور که نشان داده شده) یا فایل‌های `<script src=..></script>` لودشدهٔ خارجی:

```html
<script>foo();</script>

<script>
  function foo() { .. }
</script>
```

اما هر یک از این‌ها *کار می‌کرد*:

```html
<script>
  foo();
  function foo() { .. }
</script>
```

یا:

```html
<script>
  function foo() { .. }
</script>

<script>foo();</script>
```

همچنین، اگر در یک المان `script` (درون‌خطی یا خارجی) خطا رخ دهد، به‌عنوان یک برنامهٔ JS مستقل جدا شکست می‌خورد و متوقف می‌شود، اما هر `script` بعدی (هنوز با `global` مشترک) بدون مانع اجرا می‌شود.

می‌توانید المان‌های `script` را به‌طور پویا از کدتان بسازید و در DOM صفحه تزریق کنید، و کد داخل آن‌ها اساساً مثل لود عادی در یک فایل جدا رفتار می‌کند:

```js
var greeting = "Hello World";

var el = document.createElement( "script" );

el.text = "function foo(){ alert( greeting );\
 } setTimeout( foo, 1000 );";

document.body.appendChild( el );
```

| NOTE: |
| :--- |
| البته، اگر قطعهٔ بالا را امتحان می‌کردید اما به‌جای تنظیم `el.text` روی محتوای کد، `el.src` را روی یک URL فایل تنظیم می‌کردید، یک المان `<script src=..></script>` لودشدهٔ خارجی به‌طور پویا می‌ساختید. |

یک تفاوت بین کد در بلوک کد درون‌خطی و همان کد در فایل خارجی این است که در بلوک کد درون‌خطی، توالی کاراکترهای `</script>` نمی‌تواند با هم ظاهر شوند، چون (صرف‌نظر از محل ظاهر) به‌عنوان پایان بلوک کد تفسیر می‌شود. پس، از کدی مثل این بر حذر باشید:

```html
<script>
  var code = "<script>alert( 'Hello World' )</script>";
</script>
```

بی‌ضرر به نظر می‌رسد، اما `</script>` داخل literal `string` بلوک script را به‌طور غیرعادی خاتمه می‌دهد و خطا می‌دهد. رایج‌ترین راه‌حل:

```js
"</sc" + "ript>";
```

همچنین، مراقب باشید کد داخل فایل خارجی با set کاراکتر (UTF-8، ISO-8859-8 و غیره) سرو می‌شود (یا پیش‌فرض) تفسیر می‌شود، اما همان کد در المان `script` درون‌خطی در صفحهٔ HTML با set کاراکتر صفحه (یا پیش‌فرض آن) تفسیر می‌شود.

| WARNING: |
| :--- |
| attribute `charset` روی المان‌های script درون‌خطی کار نمی‌کند. |

یک روش منسوخ دیگر با المان‌های `script` درون‌خطی شامل کردن کامنت‌های سبک HTML یا X(HT)ML دور کد درون‌خطی است، مثل:

```html
<script>
<!--
alert( "Hello" );
//-->
</script>

<script>
<!--//--><![CDATA[//><!--
alert( "World" );
//--><!]]>
</script>
```

هر دو الان کاملاً غیرضروری‌اند، پس اگر هنوز می‌کنید، دست بردارید!

| NOTE: |
| :--- |
| هر دو `<!--` و `-->` (کامنت‌های سبک HTML) در واقع به‌عنوان delimiterهای کامنت تک‌خطی معتبر در جاوااسکریپت مشخص شده‌اند (`var x = 2; <!-- valid comment` و `--> another valid line comment`) (بخش «Web ECMAScript» قبلی را ببینید)، صرفاً به‌خاطر این تکنیک قدیمی. اما هرگز استفاده نکنید. |
