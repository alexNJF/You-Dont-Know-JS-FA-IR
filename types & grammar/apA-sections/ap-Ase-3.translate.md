# Global DOM Variables

احتمالاً می‌دانید که اعلام یک متغیر در scope سراسری (با یا بدون `var`) نه‌تنها یک متغیر سراسری می‌سازد، بلکه آینهٔ آن را هم: یک property با همان نام روی شیء `global` (`window` در مرورگر).

اما آنچه شاید کمتر شناخته باشد این است که (به‌خاطر رفتار مرورگر legacy) ساختن المان‌های DOM با attributeهای `id` متغیرهای سراسری با همان نام‌ها می‌سازد. مثلاً:

```html
<div id="foo"></div>
```

و:

```js
if (typeof foo == "undefined") {
	foo = 42;		// will never run
}

console.log( foo );	// HTML element
```

شاید عادت دارید تست‌های متغیر سراسری (با بررسی `typeof` یا `.. in window`) را با این فرض مدیریت کنید که فقط کد JS چنین متغیرهایی می‌سازد، اما همان‌طور که می‌بینید محتوای صفحهٔ HTML میزبانتان هم می‌تواند آن‌ها را بسازد، که به‌راحتی می‌تواند منطق بررسی وجودتان را به هم بریزد اگر مراقب نباشید.

این یک دلیل دیگر است که باید در صورت امکان از متغیرهای سراسری دوری کنید، و اگر مجبورید، از متغیرهایی با نام‌های یکتا استفاده کنید که احتمال برخورد نداشته باشند. اما باید مطمئن شوید با محتوای HTML و هر کد دیگر هم برخورد نکنید.
