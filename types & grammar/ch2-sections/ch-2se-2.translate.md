# Strings

باور رایج این است که `string`ها در اصل فقط `array` کاراکترها هستند. هرچند پیاده‌سازی زیرپوستی ممکن است از `array` استفاده کند یا نکند، مهم است بدانیم که `string`های JavaScript واقعاً با `array` کاراکترها یکی نیستند. شباهت بیشتر سطحی است.

مثلاً این دو مقدار را در نظر بگیرید:

```js
var a = "foo";
var b = ["f","o","o"];
```

رشته‌ها شباهت سطحی به `array`ها دارند — شبیه آرایه، مثل بالا — مثلاً هر دو property به‌نام `length`، متد `indexOf(..)` (نسخهٔ آرایه فقط از ES5) و متد `concat(..)` دارند:

```js
a.length;							// 3
b.length;							// 3

a.indexOf( "o" );					// 1
b.indexOf( "o" );					// 1

var c = a.concat( "bar" );			// "foobar"
var d = b.concat( ["b","a","r"] );	// ["f","o","o","b","a","r"]

a === c;							// false
b === d;							// false

a;									// "foo"
b;									// ["f","o","o"]
```

پس هر دو در اصل «آرایهٔ کاراکترها» هستند؟ **دقیقاً نه**:

```js
a[1] = "O";
b[1] = "O";

a; // "foo"
b; // ["f","O","o"]
```

`string`های JavaScript immutable هستند، در حالی که `array`ها قابل تغییرند. علاوه بر این، شکل دسترسی `a[1]` به موقعیت کاراکتر همیشه در JavaScript معتبر نبود. نسخه‌های قدیمی IE این سینتکس را اجازه نمی‌دادند (اما الان می‌دهند). به‌جایش روش *درست* همیشه `a.charAt(1)` بوده است.

نتیجهٔ دیگر immutable بودن `string`ها این است که هیچ‌کدام از متدهای `string` که محتوا را عوض می‌کنند درجا تغییر نمی‌دهند، بلکه باید `string` جدید بسازند و برگردانند. در مقابل، خیلی از متدهایی که محتوای `array` را عوض می‌کنند واقعاً *درجا* تغییر می‌دهند.

```js
c = a.toUpperCase();
a === c;	// false
a;			// "foo"
c;			// "FOO"

b.push( "!" );
b;			// ["f","O","o","!"]
```

همچنین خیلی از متدهای `array` که در کار با `string`ها می‌توانند مفید باشند روی خود `string`ها موجود نیستند، اما می‌توانیم متدهای غیرتغییردهندهٔ `array` را روی `string`مان «قرض» بگیریم:

```js
a.join;			// undefined
a.map;			// undefined

var c = Array.prototype.join.call( a, "-" );
var d = Array.prototype.map.call( a, function(v){
	return v.toUpperCase() + ".";
} ).join( "" );

c;				// "f-o-o"
d;				// "F.O.O."
```

مثال دیگر: معکوس کردن یک `string` (اتفاقاً سؤال رایج مصاحبهٔ JavaScript!). `array`ها متد تغییردهندهٔ درجا `reverse()` دارند، اما `string`ها ندارند:

```js
a.reverse;		// undefined

b.reverse();	// ["!","o","O","f"]
b;				// ["!","o","O","f"]
```

متأسفانه این «قرض گرفتن» با تغییردهنده‌های `array` کار نمی‌کند، چون `string`ها immutable هستند و بنابراین درجا قابل تغییر نیستند:

```js
Array.prototype.reverse.call( a );
// still returns a String object wrapper (see Chapter 3)
// for "foo" :(
```

راه‌حل دیگر (یا به‌قولی hack) این است که `string` را به `array` تبدیل کنید، عملیات موردنظر را انجام دهید، بعد دوباره به `string` برگردانید.

```js
var c = a
	// split `a` into an array of characters
	.split( "" )
	// reverse the array of characters
	.reverse()
	// join the array of characters back to a string
	.join( "" );

c; // "oof"
```

اگر زشت به نظر می‌رسد، هست. با این حال *جواب می‌دهد* برای `string`های ساده؛ پس اگر به چیزی سریع و کثیف نیاز دارید، اغلب چنین رویکردی کار را راه می‌اندازد.

**هشدار:** مراقب باشید! این روش برای `string`هایی که کاراکترهای پیچیده (یونیکد) دارند (نمادهای astral، کاراکترهای چندبایتی و غیره) **جواب نمی‌دهد**. برای چنین عملیاتی به ابزارهای کتابخانه‌ای دقیق‌تر و آگاه از یونیکد نیاز دارید. به کار Mathias Bynens مراجعه کنید: *Esrever* (https://github.com/mathiasbynens/esrever).

نگاه دیگر: اگر بیشتر کارهایتان روی «رشته»ها آن‌ها را در عمل *آرایهٔ کاراکترها* فرض می‌کند، شاید بهتر باشد واقعاً آن‌ها را به‌صورت `array` ذخیره کنید نه `string`. احتمالاً از دردسر تبدیل هر بار از `string` به `array` خلاص می‌شوید. هر وقت به نمایش `string` نیاز داشتید می‌توانید روی `array` *کاراکترها* متد `join("")` را فراخوانی کنید.
