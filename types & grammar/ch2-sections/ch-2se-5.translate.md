# Value vs. Reference

در خیلی زبان‌های دیگر، مقدارها بسته به سینتکسی که استفاده می‌کنید یا با کپی مقدار یا با کپی ارجاع انتساب/ارسال می‌شوند.

مثلاً در C++ اگر بخواهید متغیر `number` را به تابعی بفرستید و مقدار آن متغیر به‌روز شود، می‌توانید پارامتر تابع را مثلاً `int& myNum` اعلان کنید؛ وقتی متغیری مثل `x` را بفرستید، `myNum` **ارجاع به `x`** خواهد بود. ارجاع‌ها شبیه شکل خاصی از pointer هستند که به متغیر دیگری (مثل یک *alias*) اشاره می‌کنند. اگر پارامتر ارجاعی اعلان نکنید، مقدار ارسالی *همیشه* کپی می‌شود، حتی اگر یک object پیچیده باشد.

در JavaScript pointer وجود ندارد و ارجاع‌ها کمی متفاوت کار می‌کنند. نمی‌توانید از یک متغیر JS به متغیر دیگری ارجاع داشته باشید. چنین چیزی ممکن نیست.

یک ارجاع در JS به یک (مقدار) **مشترک** اشاره می‌کند؛ پس اگر ۱۰ ارجاع متفاوت داشته باشید، همگی ارجاع‌های متمایز به یک مقدار مشترک هستند؛ **هیچ‌کدام ارجاع/pointer به دیگری نیست.**

علاوه بر این، در JavaScript هیچ نشانهٔ سینتکسی برای کنترل انتساب/ارسال بر اساس مقدار در مقابل ارجاع وجود ندارد. به‌جایش، *type* مقدار *به‌تنهایی* تعیین می‌کند که آن مقدار با کپی مقدار انتساب/ارسال می‌شود یا با کپی ارجاع.

بیایید نشان دهیم:

```js
var a = 2;
var b = a; // `b` همیشه کپی مقدار داخل `a` است
b++;
a; // 2
b; // 3

var c = [1,2,3];
var d = c; // `d` ارجاع به مقدار مشترک `[1,2,3]` است
d.push( 4 );
c; // [1,2,3,4]
d; // [1,2,3,4]
```

مقدارهای ساده (یعنی scalar primitives) *همیشه* با کپی مقدار انتساب/ارسال می‌شوند: `null`، `undefined`، `string`، `number`، `boolean` و `symbol` در ES6.

مقدارهای مرکب — `object`ها (شامل `array`ها و همهٔ wrapperهای object با boxing — فصل ۳ را ببینید) و `function`ها — در انتساب یا ارسال *همیشه* کپی از ارجاع ایجاد می‌کنند.

در قطعهٔ بالا، چون `2` یک scalar primitive است، `a` یک کپی اولیه از آن مقدار را نگه می‌دارد و `b` *کپی* دیگری از مقدار انتساب می‌گیرد. وقتی `b` را عوض می‌کنید، به هیچ وجه مقدار داخل `a` را عوض نمی‌کنید.

اما **هم `c` و هم `d`** ارجاع‌های جدا به همان مقدار مشترک `[1,2,3]` هستند که یک مقدار مرکب است. مهم است بدانید نه `c` و نه `d` بیشتر «مالک» مقدار `[1,2,3]` نیستند — هر دو فقط ارجاع‌های برابر به آن مقدارند. پس وقتی از هر ارجاع برای تغییر (`.push(4)`) خود مقدار مشترک `array` استفاده می‌کنید، فقط همان یک مقدار مشترک تحت تأثیر است و هر دو ارجاع به مقدار تغییر یافتهٔ جدید `[1,2,3,4]` اشاره می‌کنند.

چون ارجاع‌ها به خود مقدارها اشاره می‌کنند نه به متغیرها، نمی‌توانید از یک ارجاع برای عوض کردن جایی که ارجاع دیگر به آن اشاره می‌کند استفاده کنید:

```js
var a = [1,2,3];
var b = a;
a; // [1,2,3]
b; // [1,2,3]

// later
b = [4,5,6];
a; // [1,2,3]
b; // [4,5,6]
```

وقتی انتساب `b = [4,5,6]` را می‌کنیم، هیچ کاری برای تأثیر روی *جایی* که `a` هنوز به آن اشاره می‌کند (`[1,2,3]`) نمی‌کنیم. برای آن کار، `b` باید pointer به `a` می‌بود نه ارجاع به `array` — اما چنین قابلیتی در JS وجود ندارد!

رایج‌ترین جایی که این گیجی پیش می‌آید پارامترهای تابع است:

```js
function foo(x) {
	x.push( 4 );
	x; // [1,2,3,4]

	// later
	x = [4,5,6];
	x.push( 7 );
	x; // [4,5,6,7]
}

var a = [1,2,3];

foo( a );

a; // [1,2,3,4]  not  [4,5,6,7]
```

وقتی آرگومان `a` را می‌فرستیم، کپی ارجاع `a` به `x` انتساب می‌شود. `x` و `a` ارجاع‌های جدا به همان مقدار `[1,2,3]` هستند. حالا داخل تابع می‌توانیم از آن ارجاع برای تغییر خود مقدار (`push(4)`) استفاده کنیم. اما وقتی انتساب `x = [4,5,6]` را می‌کنیم، این به هیچ وجه جایی که ارجاع اولیهٔ `a` به آن اشاره می‌کند را عوض نمی‌کند — هنوز به مقدار (حالا تغییر یافته) `[1,2,3,4]` اشاره می‌کند.

راهی نیست که با ارجاع `x` جایی که `a` به آن اشاره می‌کند را عوض کنیم. فقط می‌توانستیم محتوای مقدار مشترکی که هر دو `a` و `x` به آن اشاره می‌کنند را تغییر دهیم.

برای اینکه `a` محتوای `[4,5,6,7]` را بگیرد، نمی‌توانید `array` جدید بسازید و انتساب دهید — باید مقدار `array` موجود را تغییر دهید:

```js
function foo(x) {
	x.push( 4 );
	x; // [1,2,3,4]

	// later
	x.length = 0; // empty existing array in-place
	x.push( 4, 5, 6, 7 );
	x; // [4,5,6,7]
}

var a = [1,2,3];

foo( a );

a; // [4,5,6,7]  not  [1,2,3,4]
```

همان‌طور که می‌بینید، `x.length = 0` و `x.push(4,5,6,7)` `array` جدید نمی‌ساختند، بلکه `array` مشترک موجود را تغییر می‌دادند. پس البته `a` به محتوای جدید `[4,5,6,7]` اشاره می‌کند.

یادتان باشد: نمی‌توانید مستقیم کپی-مقدار در مقابل ارجاع را کنترل/override کنید — آن معناشناسی کاملاً توسط type مقدار زیرین تعیین می‌شود.

برای ارسال مؤثر یک مقدار مرکب (مثل `array`) با کپی مقدار، باید دستی کپی بسازید تا ارجاع ارسالی هنوز به اصلی اشاره نکند. مثلاً:

```js
foo( a.slice() );
```

`slice(..)` بدون پارامتر به‌طور پیش‌فرض یک کپی (سطحی) کاملاً جدید از `array` می‌سازد. پس فقط ارجاع به `array` کپی‌شده را می‌فرستیم و بنابراین `foo(..)` نمی‌تواند محتوای `a` را تحت تأثیر قرار دهد.

برای برعکس — ارسال یک مقدار scalar primitive طوری که به‌روزرسانی‌های مقدارش دیده شود، تقریباً مثل ارجاع — باید مقدار را در یک مقدار مرکب دیگر (`object`، `array` و غیره) بپیچید که *می‌تواند* با کپی ارجاع ارسال شود:

```js
function foo(wrapper) {
	wrapper.a = 42;
}

var obj = {
	a: 2
};

foo( obj );

obj.a; // 42
```

اینجا `obj` به‌عنوان wrapper برای property اسکالر primitive به‌نام `a` عمل می‌کند. وقتی به `foo(..)` فرستاده می‌شود، کپی ارجاع `obj` فرستاده و به پارامتر `wrapper` انتساب می‌شود. حالا می‌توانیم از ارجاع `wrapper` برای دسترسی به object مشترک و به‌روز کردن propertyاش استفاده کنیم. بعد از اتمام تابع، `obj.a` مقدار به‌روزشدهٔ `42` را می‌بیند.

شاید به ذهنتان برسد که اگر می‌خواستید ارجاع به یک مقدار scalar primitive مثل `2` بفرستید، می‌توانستید مقدار را در wrapper شیء `Number` (فصل ۳) boxing کنید.

درست است که کپی ارجاع به این شیء `Number` *به* تابع فرستاده می‌شود، اما متأسفانه داشتن ارجاع به object مشترک توان تغییر مقدار primitive مشترک را به شما نمی‌دهد، آن‌طور که شاید انتظار دارید:

```js
function foo(x) {
	x = x + 1;
	x; // 3
}

var a = 2;
var b = new Number( a ); // or equivalently `Object(a)`

foo( b );
console.log( b ); // 2, not 3
```

مشکل این است که مقدار scalar primitive زیرین *قابل تغییر نیست* (همین‌طور برای `String` و `Boolean`). اگر یک شیء `Number` مقدار scalar primitive یعنی `2` را نگه دارد، آن شیء `Number` هرگز نمی‌تواند طوری عوض شود که مقدار دیگری نگه دارد؛ فقط می‌توانید یک شیء `Number` کاملاً جدید با مقدار متفاوت بسازید.

وقتی `x` در عبارت `x + 1` به کار می‌رود، مقدار scalar primitive یعنی `2` به‌طور خودکار از شیء `Number` unbox (استخراج) می‌شود، پس خط `x = x + 1` به‌طور بسیار ظریف `x` را از ارجاع مشترک به شیء `Number` به نگه‌داشتن فقط مقدار scalar primitive یعنی `3` (نتیجهٔ عملیات `2 + 1`) تغییر می‌دهد. بنابراین `b` در بیرون هنوز به شیء `Number` تغییرنیافته/immutable اصلی که مقدار `2` را نگه می‌دارد اشاره می‌کند.

می‌توانید روی شیء `Number` property اضافه کنید (فقط مقدار primitive درونی را نتوانید عوض کنید)، پس می‌توانید به‌طور غیرمستقیم از طریق آن propertyهای اضافه اطلاعات مبادله کنید.

این چندان رایج نیست؛ احتمالاً بیشتر توسعه‌دهندگان آن را روش خوبی نمی‌دانند.

به‌جای استفاده از wrapper object یعنی `Number` به این شکل، احتمالاً خیلی بهتر است از رویکرد wrapper object دستی (`obj`) در قطعهٔ قبلی استفاده کنید. این به معنی نبودن استفادهٔ هوشمندانه از wrapperهای object مثل `Number` نیست — فقط این که در بیشتر موارد احتمالاً شکل مقدار scalar primitive را ترجیح دهید.

ارجاع‌ها خیلی قدرتمندند، اما گاهی سر راهتان قرار می‌گیرند و گاهی جایی به آن‌ها نیاز دارید که وجود ندارند. تنها کنترلی که روی رفتار ارجاع در مقابل کپی-مقدار دارید type خود مقدار است، پس باید با انتخاب typeهای مقداری که استفاده می‌کنید به‌طور غیرمستقیم بر رفتار انتساب/ارسال تأثیر بگذارید.
