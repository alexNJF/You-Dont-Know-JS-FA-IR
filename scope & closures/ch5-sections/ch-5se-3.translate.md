# حالا می‌توانم ببینم

تکه کدهای قبلی تا حدی آکادمیک و مصنوعی ساخته شده بودند برای نشان دادن *استفاده از closure*. اما قول دادم چیزی بیش از فقط یک اسباب‌بازی cool جدید. قول دادم closure چیزی است که همه‌جا دور و بر شما در کد موجودتان است. بیایید اکنون آن حقیقت را *ببینیم*.

```js
function wait(message) {

	setTimeout( function timer(){
		console.log( message );
	}, 1000 );

}

wait( "Hello, closure!" );
```

تابع درونی (به‌نام `timer`) را به `setTimeout(..)` منتقل می‌کنیم. اما `timer` closure scope روی scope مربوط به `wait(..)` دارد، در واقع ارجاع به متغیر `message` را نگه می‌دارد و استفاده می‌کند.

هزار میلی‌ثانیه بعد از اجرای `wait(..)`، و scope درونی آن باید مدتها پیش رفته باشد، آن تابع درونی `timer` هنوز closure روی آن scope دارد.

در اعماق guts موتور *Engine*، ابزار built-in `setTimeout(..)` ارجاعی به پارامتری دارد، احتمالاً `fn` یا `func` یا چیزی شبیه آن نامیده می‌شود. *Engine* می‌رود آن تابع را فراخوانی کند، که فراخوانی تابع درونی `timer` ماست، و ارجاع lexical scope هنوز سالم است.

**Closure.**

یا اگر از نظر jQuery (یا هر فریمورک JS) هستید:

```js
function setupBot(name,selector) {
	$( selector ).click( function activator(){
		console.log( "Activating: " + name );
	} );
}

setupBot( "Closure Bot 1", "#bot_1" );
setupBot( "Closure Bot 2", "#bot_2" );
```

مطمئن نیستم چه نوع کدی می‌نویسید، اما من به‌طور منظم کدی می‌نویسم که مسئول کنترل کل ارتش global drone از closure botهاست، پس این کاملاً واقع‌گرایانه است!

(برخی) شوخی کنار، اساساً *هر زمان* و *هر کجا* توابع (که به lexical scopeهای مربوط خود دسترسی دارند) را به‌عنوان مقادیر درجهٔ اول برخورد می‌کنید و آن‌ها را منتقل می‌کنید، احتمالاً آن توابع را در حال اعمال closure می‌بینید. چه timerها، event handlerها، درخواست‌های Ajax، پیام‌رسانی cross-window، web workerها، یا هر یک از کارهای asynchronous (یا synchronous!) دیگر، وقتی *تابع callback* منتقل می‌کنید، آمادهٔ sling کردن closure باشید!

**توجه:** فصل ۳ الگوی IIFE را معرفی کرد. در حالی که اغلب گفته می‌شود IIFE (به‌تنهایی) مثالی از closure مشاهده‌شده است، با تعریف بالا تا حدی مخالفم.

```js
var a = 2;

(function IIFE(){
	console.log( a );
})();
```

این کد «کار می‌کند»، اما به‌طور سخت‌گیرانه مشاهدهٔ closure نیست. چرا؟ چون تابع (که اینجا «IIFE» نامیدیم) خارج از lexical scope خود اجرا نمی‌شود. هنوز همان‌جا در همان scope اعلامش فراخوانی می‌شود (scope محصور/global که `a` را هم نگه می‌دارد). `a` از طریق جستجوی عادی lexical scope پیدا می‌شود، نه واقعاً از طریق closure.

در حالی که closure ممکن است از نظر فنی در زمان اعلام رخ دهد، *به‌طور سخت‌گیرانه* قابل مشاهده نیست، و پس، همان‌طور که می‌گویند، *درخت در جنگل می‌افتد و کسی نیست بشنود.*

اگرچه IIFE خودش مثالی از closure نیست، قطعاً scope ایجاد می‌کند، و یکی از رایج‌ترین ابزارهایی است که برای ایجاد scope که می‌توان روی آن close کرد استفاده می‌کنیم. پس IIFEها قطعاً به closure بسیار مرتبط هستند، حتی اگر خودشان closure اعمال نکنند.

همین الان این کتاب را بگذارید، خوانندهٔ عزیز. کاری برایتان دارم. بروید برخی کد JavaScript اخیر خود را باز کنید. به دنبال توابع-به‌عنوان-مقدار بگردید و مشخص کنید کجا از closure استفاده می‌کنید و شاید قبلاً نمی‌دانستید.

صبر می‌کنم.

حالا... می‌بینید!
