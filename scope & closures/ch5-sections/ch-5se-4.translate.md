# حلقه‌ها + Closure

رایج‌ترین مثال متعارف برای نشان دادن closure حلقهٔ فروتن for را شامل می‌شود.

```js
for (var i=1; i<=5; i++) {
	setTimeout( function timer(){
		console.log( i );
	}, i*1000 );
}
```

**توجه:** Linterها اغلب وقتی توابع داخل حلقه‌ها می‌گذارید شکایت می‌کنند، چون اشتباهات عدم فهم closure **آنقدر در میان توسعه‌دهندگان رایج است**. اینجا نحوهٔ صحیح انجام آن را با leverage کردن قدرت کامل closure توضیح می‌دهیم. اما آن ظرافت اغلب بر linterها گم می‌شود و صرف‌نظر از اینکه واقعاً می‌دانید چه می‌کنید شکایت می‌کنند.

روح این تکه کد این است که معمولاً *انتظار* داریم رفتار این باشد که اعداد «۱»، «۲»، .. «۵» یکی یکی، هر کدام در ثانیه، چاپ شوند.

در واقع، اگر این کد را اجرا کنید، «۶» پنج بار چاپ می‌شود، در فواصل یک‌ثانیه‌ای.

**ها؟**

اول، بیایید توضیح دهیم `6` از کجا می‌آید. شرط خاتمهٔ حلقه وقتی است که `i` *نه* `<=5` باشد. اولین بار که چنین است وقتی `i` برابر ۶ است. پس خروجی مقدار نهایی `i` بعد از خاتمهٔ حلقه را منعکس می‌کند.

این در نگاه دوم در واقع واضح به نظر می‌رسد. توابع callback تایمر همگی مدتها بعد از تکمیل حلقه اجرا می‌شوند. در واقع، همان‌طور که تایمرها می‌روند، حتی اگر `setTimeout(.., 0)` در هر تکرار بود، تمام آن توابع callback همچنان به‌طور سخت‌گیرانه بعد از تکمیل حلقه اجرا می‌شدند و بنابراین هر بار `6` چاپ می‌کردند.

اما پرسش عمیق‌تری در کار است. چه چیزی *از کد ما کم است* تا واقعاً طوری که معنایی implied کرده‌ایم رفتار کند؟

آنچه کم است این است که سعی می‌کنیم *imply* کنیم هر تکرار حلقه «کپی» خودش از `i` را در زمان تکرار «capture» می‌کند. اما، نحوهٔ کار scope، هر پنج آن توابع، هرچند در هر تکرار حلقه جداگانه تعریف شده‌اند، همگی **روی همان global scope مشترک close می‌کنند** که در واقع فقط یک `i` در آن دارد.

این‌طور که بگوییم، *قطعاً* تمام توابع ارجاعی به همان `i` به اشتراک می‌گذارند. چیزی دربارهٔ ساختار حلقه تمایل به گیج کردن ما دارد که فکر کنیم چیز پیچیده‌تری در کار است. نیست. تفاوتی با این ندارد که هر پنج callback تایمر فقط یکی پس از دیگری، بدون حلقه، اعلام شده بودند.

خب، پس برگردیم به پرسش سوزانمان. چه کم است؟ به closured scope بیشتر ~~cowbell~~ نیاز داریم. به‌طور خاص، به closured scope جدیدی برای هر تکرار حلقه نیاز داریم.

در فصل ۳ یاد گرفتیم IIFE با اعلام تابع و اجرای فوری آن scope ایجاد می‌کند.

بیایید امتحان کنیم:

```js
for (var i=1; i<=5; i++) {
	(function(){
		setTimeout( function timer(){
			console.log( i );
		}, i*1000 );
	})();
}
```

کار می‌کند؟ امتحان کنید. باز هم صبر می‌کنم.

تعلیق را برایتان تمام می‌کنم. **نه.** اما چرا؟ اکنون واضحاً lexical scope بیشتری داریم. هر تابع callback تایمر در واقع روی scope هر-تکرار خودش که به‌ترتیب توسط هر IIFE ایجاد شده close می‌کند.

کافی نیست scope برای close کردن داشته باشیم **اگر آن scope خالی باشد**. دقیق نگاه کنید. IIFE ما فقط scope خالی do-nothing است. به *چیزی* داخلش برای مفید بودن برای ما نیاز دارد.

به متغیر خودش، با کپی مقدار `i` در هر تکرار نیاز دارد.

```js
for (var i=1; i<=5; i++) {
	(function(){
		var j = i;
		setTimeout( function timer(){
			console.log( j );
		}, j*1000 );
	})();
}
```

**یوریکا! کار می‌کند!**

تنوع جزئی که برخی ترجیح می‌دهند:

```js
for (var i=1; i<=5; i++) {
	(function(j){
		setTimeout( function timer(){
			console.log( j );
		}, j*1000 );
	})( i );
}
```

البته، چون این IIFEها فقط توابع هستند، می‌توانیم `i` را منتقل کنیم و می‌توانیم آن را `j` بنامیم اگر ترجیح دهیم، یا حتی دوباره `i` بنامیم. در هر صورت، کد حالا کار می‌کند.

استفاده از IIFE داخل هر تکرار scope جدیدی برای هر تکرار ایجاد کرد که به توابع callback تایمر ما فرصت close کردن روی scope جدید برای هر تکرار داد، یکی که متغیری با مقدار صحیح هر-تکرار برای دسترسی ما داشت.

مشکل حل شد!

### بازبینی Block Scoping

با دقت به تحلیل راه‌حل قبلی نگاه کنید. از IIFE برای ایجاد scope هر-تکرار استفاده کردیم. به عبارت دیگر، در واقع به **block scope** هر-تکرار نیاز داشتیم. فصل ۳ اعلام `let` را نشان داد که بلوک را hijack می‌کند و متغیر را همان‌جا در بلوک اعلام می‌کند.

**اساساً بلوک را به scope تبدیل می‌کند که می‌توانیم روی آن close کنیم.** پس کد awesome زیر «فقط کار می‌کند»:

```js
for (var i=1; i<=5; i++) {
	let j = i; // yay, block-scope for closure!
	setTimeout( function timer(){
		console.log( j );
	}, j*1000 );
}
```

*اما، این همه نیست!* (با بهترین صدای Bob Barker). رفتار خاصی برای اعلام‌های `let` استفاده‌شده در سر حلقهٔ for تعریف شده. این رفتار می‌گوید متغیر نه فقط یک بار برای حلقه بلکه **هر تکرار** اعلام می‌شود. و، مفیدانه، در هر تکرار بعدی با مقدار از انتهای تکرار قبلی مقداردهی اولیه می‌شود.

```js
for (let i=1; i<=5; i++) {
	setTimeout( function timer(){
		console.log( i );
	}, i*1000 );
}
```

چقدر cool است؟ Block scoping و closure دست‌به‌دست هم، تمام مشکلات جهان را حل می‌کنند. نمی‌دانم شما چطور، اما این من را یک JavaScripter خوشحال می‌کند.
