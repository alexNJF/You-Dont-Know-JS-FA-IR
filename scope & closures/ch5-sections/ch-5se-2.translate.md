# جزئیات

خب، کافی از اغراق و ارجاع‌های بی‌حیا به فیلم.

این تعریف down-n-dirty از آنچه برای فهم و تشخیص closure باید بدانید:

> Closure وقتی است که تابعی بتواند lexical scope خود را به خاطر بیاورد و به آن دسترسی داشته باشد حتی وقتی آن تابع خارج از lexical scope خود اجرا می‌شود.

بیایید با کمی کد برای نشان دادن آن تعریف برویم.

```js
function foo() {
	var a = 2;

	function bar() {
		console.log( a ); // 2
	}

	bar();
}

foo();
```

این کد باید از بحث‌های Nested Scope آشنا به نظر برسد. تابع `bar()` *دسترسی* به متغیر `a` در scope محصور بیرونی دارد به‌خاطر قوانین جستجوی lexical scope (در این مورد، ارجاع جستجوی RHS).

آیا این «closure» است؟

خب، از نظر فنی... *شاید*. اما با تعریف what-you-need-to-know بالا... *دقیقاً نه*. فکر می‌کنم دقیق‌ترین راه توضیح ارجاع `bar()` به `a` از طریق قوانین جستجوی lexical scope است، و آن قوانین *فقط* (مهم!) **بخشی** از آنچه closure است هستند.

از منظر صرفاً آکادمیک، گفته می‌شود تابع `bar()` در تکه بالا *closure* روی scope مربوط به `foo()` دارد (و در واقع حتی روی بقیه scopeهایی که به آن‌ها دسترسی دارد، مثل global scope در مورد ما). به‌عبارت کمی متفاوت، گفته می‌شود `bar()` روی scope مربوط به `foo()` close می‌کند. چرا؟ چون `bar()` داخل `foo()` تو در تو ظاهر شده. ساده و روشن.

اما closure تعریف‌شده به این شکل مستقیماً *قابل مشاهده* نیست، و در آن تکه closure را *اعمال* نمی‌بینیم. lexical scope را واضح می‌بینیم، اما closure همچنان نوعی سایهٔ مرموز و متغیر پشت کد می‌ماند.

پس کدی را در نظر بگیریم که closure را کاملاً روشن می‌کند:

```js
function foo() {
	var a = 2;

	function bar() {
		console.log( a );
	}

	return bar;
}

var baz = foo();

baz(); // 2 -- Whoa, closure was just observed, man.
```

تابع `bar()` دسترسی lexical scope به scope درونی `foo()` دارد. اما سپس، `bar()`، خود تابع، را *به‌عنوان* مقدار منتقل می‌کنیم. در این مورد، خود شیء تابعی که `bar` به آن ارجاع می‌دهد را `return` می‌کنیم.

بعد از اجرای `foo()`، مقداری که برگرداند (تابع درونی `bar()`) را به متغیری به‌نام `baz` انتساب می‌دهیم، و سپس واقعاً `baz()` را فراخوانی می‌کنیم، که البته فراخوانی تابع درونی `bar()` ماست، فقط با ارجاع شناسهٔ متفاوت.

`bar()` قطعاً اجرا می‌شود. اما در این مورد، *خارج* از lexical scope اعلام‌شدهٔ خود اجرا می‌شود.

بعد از اجرای `foo()`، معمولاً انتظار داریم کل scope درونی `foo()` از بین برود، چون می‌دانیم *Engine* از *Garbage Collector* استفاده می‌کند که می‌آید و حافظه را آزاد می‌کند وقتی دیگر استفاده نمی‌شود. چون به نظر می‌رسد محتوای `foo()` دیگر استفاده نمی‌شود، طبیعی به نظر می‌رسد که *gone* در نظر گرفته شوند.

اما «جادوی» closure اجازهٔ این را نمی‌دهد. آن scope درونی در واقع *هنوز* «در استفاده» است و بنابراین از بین نمی‌رود. چه کسی استفاده می‌کند؟ **خود تابع `bar()`**.

به‌واسطهٔ جایی که اعلام شد، `bar()` closure lexical scope روی آن scope درونی `foo()` دارد که آن scope را برای ارجاع `bar()` در هر زمان بعد زنده نگه می‌دارد.

**`bar()` هنوز ارجاعی به آن scope دارد و آن ارجاع closure نامیده می‌شود.**

پس، چند میکروثانیه بعد، وقتی متغیر `baz` فراخوانی می‌شود (فراخوانی تابع درونی که ابتدا `bar` نامیدیم)، به‌درستی *دسترسی* به lexical scope زمان نوشتن دارد، پس می‌تواند به متغیر `a` دسترسی داشته باشد همان‌طور که انتظار داریم.

تابع در جایی کاملاً خارج از lexical scope زمان نوشتن خود فراخوانی می‌شود. **Closure** به تابع اجازه می‌دهد به lexical scope تعریف‌شده در زمان نوشتن ادامهٔ دسترسی داشته باشد.

البته، هر یک از راه‌های مختلفی که توابع می‌توانند *به‌عنوان* مقدار *منتقل* شوند و در واقع در مکان‌های دیگر فراخوانی شوند، همگی مثال‌هایی از مشاهده/اعمال closure هستند.

```js
function foo() {
	var a = 2;

	function baz() {
		console.log( a ); // 2
	}

	bar( baz );
}

function bar(fn) {
	fn(); // look ma, I saw closure!
}
```

تابع درونی `baz` را به `bar` منتقل می‌کنیم و آن تابع درونی (اکنون `fn` نامیده شده) را فراخوانی می‌کنیم، و وقتی چنین می‌کنیم، closure آن روی scope درونی `foo()` با دسترسی به `a` مشاهده می‌شود.

این انتقال‌های توابع می‌توانند غیرمستقیم هم باشند.

```js
var fn;

function foo() {
	var a = 2;

	function baz() {
		console.log( a );
	}

	fn = baz; // assign `baz` to global variable
}

function bar() {
	fn(); // look ma, I saw closure!
}

foo();

bar(); // 2
```

هر تسهیلاتی که برای *انتقال* تابع درونی خارج از lexical scope خود استفاده کنیم، ارجاع scope به جایی که در اصل اعلام شد را حفظ می‌کند، و هرکجا اجرا کنیم، آن closure اعمال می‌شود.
