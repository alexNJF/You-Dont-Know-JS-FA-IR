# شما جاوااسکریپت را نمی‌دانید: Scope و Closures - ویرایش اول
# Scope پویا

در فصل ۲، «Dynamic Scope» را در مقایسه با مدل «Lexical Scope» بحث کردیم، که نحوهٔ کار scope در JavaScript (و در واقع اکثر زبان‌های دیگر) است.

به‌طور خلاصه Dynamic Scope را بررسی می‌کنیم تا مقایسه را محکم کنیم. اما مهم‌تر، Dynamic Scope در واقع خویشاوند نزدیک مکانیزم دیگری (`this`) در JavaScript است که در عنوان «*this & Object Prototypes*» این مجموعه کتاب پوشش داده شد.

همان‌طور که در فصل ۲ دیدیم، lexical scope مجموعه قوانینی دربارهٔ نحوهٔ جستجوی متغیر توسط *Engine* و جایی که آن را پیدا می‌کند است. ویژگی کلیدی lexical scope این است که در زمان نوشتن، وقتی کد نوشته می‌شود تعریف می‌شود (با فرض اینکه با `eval()` یا `with` دور نزنید).

Dynamic Scope به نظر می‌رسد imply می‌کند، و به دلایل خوب، که مدلی وجود دارد که scope می‌تواند به‌طور پویا در runtime تعیین شود، نه به‌طور ایستا در زمان نوشتن. در واقع چنین است. بیایید با کد نشان دهیم:

```js
function foo() {
	console.log( a ); // 2
}

function bar() {
	var a = 3;
	foo();
}

var a = 2;

bar();
```

Lexical scope می‌گوید ارجاع RHS به `a` در `foo()` به متغیر global `a` حل می‌شود که منجر به خروجی مقدار `2` می‌شود.

Dynamic Scope، در مقابل، به چگونگی و محل اعلام توابع و scopeها اهمیت نمی‌دهد، بلکه **از کجا فراخوانی می‌شوند** اهمیت می‌دهد. به عبارت دیگر، زنجیره scope بر اساس call-stack است، نه تو در تو بودن scopeها در کد.

پس اگر JavaScript Dynamic Scope داشت، وقتی `foo()` اجرا می‌شود، **از نظر تئوری** کد زیر به‌جای آن منجر به خروجی `3` می‌شد.

```js
function foo() {
	console.log( a ); // 3  (not 2!)
}

function bar() {
	var a = 3;
	foo();
}

var a = 2;

bar();
```

چطور ممکن است؟ چون وقتی `foo()` نمی‌تواند ارجاع متغیر برای `a` را حل کند، به‌جای بالا رفتن از زنجیره scope تو در تو (lexical)، در call-stack بالا می‌رود تا ببیند `foo()` *از کجا* فراخوانی شده. چون `foo()` از `bar()` فراخوانی شده، متغیرهای در scope برای `bar()` را چک می‌کند و `a` با مقدار `3` آنجا پیدا می‌کند.

عجیب؟ احتمالاً الان چنین فکر می‌کنید.

اما فقط به‌خاطر این است که احتمالاً فقط با کدی کار کرده‌اید که lexically scoped است. پس dynamic scoping غریب به نظر می‌رسد. اگر فقط با زبانی dynamically scoped کد نوشته بودید، طبیعی به نظر می‌رسید و lexical scope عجیب می‌بود.

برای روشن بودن، JavaScript **در واقع Dynamic Scope ندارد**. Lexical Scope دارد. ساده و روشن. اما مکانیزم `this` نوعی شبیه Dynamic Scope است.

مقایسهٔ کلیدی: **lexical scope زمان نوشتن است، در حالی که Dynamic Scope (و `this`!) زمان اجرا هستند**. Lexical Scope به *جایی که تابع اعلام شد* اهمیت می‌دهد، اما Dynamic Scope به جایی که تابع *از آن فراخوانی شد* اهمیت می‌دهد.

در نهایت: `this` به *نحوهٔ فراخوانی* تابع اهمیت می‌دهد، که نشان می‌دهد مکانیزم `this` چقدر به ایدهٔ dynamic scoping مرتبط است. برای کاوش بیشتر دربارهٔ `this`، عنوان «*this & Object Prototypes*» را بخوانید.
