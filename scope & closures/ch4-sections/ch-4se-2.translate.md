# کامپایلر دوباره دست به کار می‌شود

برای پاسخ به این پرسش، باید به فصل ۱ و بحثمان دربارهٔ کامپایلرها برگردیم. به یاد دارید که *Engine* در واقع کد JavaScript شما را قبل از تفسیر کامپایل می‌کند. بخشی از فاز کامپایل یافتن و ارتباط تمام اعلام‌ها با scopeهای مناسبشان بود. فصل ۲ نشان داد که این قلب Lexical Scope است.

پس بهترین راه فکر کردن این است که تمام اعلام‌ها، هم متغیرها و هم توابع، اول پردازش می‌شوند، قبل از اجرای هر بخشی از کد شما.

وقتی `var a = 2;` می‌بینید، احتمالاً آن را یک دستور می‌دانید. اما JavaScript در واقع آن را دو دستور می‌داند: `var a;` و `a = 2;`. دستور اول، اعلام، در فاز کامپایل پردازش می‌شود. دستور دوم، انتساب، **در جای خود** برای فاز اجرا باقی می‌ماند.

پس تکه اول ما باید طوری برخورد شود که انگار این‌طور handle می‌شود:

```js
var a;
```
```js
a = 2;

console.log( a );
```

...جایی که بخش اول کامپایل و بخش دوم اجرا است.

به‌طور مشابه، تکه دوم ما در واقع این‌طور پردازش می‌شود:

```js
var a;
```
```js
console.log( a );

a = 2;
```

پس یک راه فکر کردن، به‌نوعی استعاری، دربارهٔ این فرایند این است که اعلام‌های متغیر و تابع از جایی که در جریان کد ظاهر می‌شوند به بالای کد «منتقل» می‌شوند. این به نام «Hoisting» منجر می‌شود.

به عبارت دیگر، **تخم مرغ (اعلام) قبل از مرغ (انتساب) می‌آید**.

**توجه:** فقط خود اعلام‌ها hoist می‌شوند، در حالی که هر انتساب یا منطق اجرایی دیگر *در جای خود* باقی می‌ماند. اگر hoisting منطق اجرایی کد ما را بازچین می‌کرد، می‌توانست havoc ایجاد کند.

```js
foo();

function foo() {
	console.log( a ); // undefined

	var a = 2;
}
```

اعلام تابع `foo` (که در این مورد *شامل* مقدار ضمنی آن به‌عنوان تابع واقعی است) hoist می‌شود، طوری که فراخوانی در خط اول قادر به اجرا است.

همچنین مهم است که hoisting **per-scope** است. پس در حالی که تکه‌های قبلی ساده‌سازی شده بودند که فقط global scope داشتند، تابع `foo(..)` که اکنون بررسی می‌کنیم خودش نشان می‌دهد که `var a` به بالای `foo(..)` hoist می‌شود (نه، واضح است، به بالای برنامه). پس برنامه را می‌توان شاید دقیق‌تر این‌طور تفسیر کرد:

```js
function foo() {
	var a;

	console.log( a ); // undefined

	a = 2;
}

foo();
```

اعلام‌های تابع hoist می‌شوند، همان‌طور که دیدیم. اما function expressionها hoist نمی‌شوند.

```js
foo(); // not ReferenceError, but TypeError!

var foo = function bar() {
	// ...
};
```

شناسهٔ متغیر `foo` hoist شده و به scope محصور (global) این برنامه متصل شده، پس `foo()` به‌عنوان `ReferenceError` شکست نمی‌خورد. اما `foo` هنوز مقداری ندارد (مثل اینکه اگر اعلام تابع واقعی به‌جای expression بود). پس `foo()` سعی می‌کند مقدار `undefined` را فراخوانی کند که عملیات غیرقانونی `TypeError` است.

همچنین به یاد دارید که حتی اگر named function expression است، نام شناسه در scope محصور در دسترس نیست:

```js
foo(); // TypeError
bar(); // ReferenceError

var foo = function bar() {
	// ...
};
```

این تکه با hoisting دقیق‌تر تفسیر می‌شود:

```js
var foo;

foo(); // TypeError
bar(); // ReferenceError

foo = function() {
	var bar = ...self...
	// ...
}
```
