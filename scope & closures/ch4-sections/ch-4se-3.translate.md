# توابع اول

هم اعلام‌های تابع و هم اعلام‌های متغیر hoist می‌شوند. اما جزئی ظریف (که *می‌تواند* در کد با اعلام‌های «تکراری» متعدد ظاهر شود) این است که توابع اول hoist می‌شوند و سپس متغیرها.

در نظر بگیرید:

```js
foo(); // 1

var foo;

function foo() {
	console.log( 1 );
}

foo = function() {
	console.log( 2 );
};
```

به‌جای `2`، `1` چاپ می‌شود! این تکه توسط *Engine* این‌طور تفسیر می‌شود:

```js
function foo() {
	console.log( 1 );
}

foo(); // 1

foo = function() {
	console.log( 2 );
};
```

توجه کنید که `var foo` اعلام تکراری (و بنابراین نادیده گرفته شده) بود، حتی اگر قبل از اعلام `function foo()...` می‌آمد، چون اعلام‌های تابع قبل از متغیرهای عادی hoist می‌شوند.

در حالی که اعلام‌های متعدد/تکراری `var` به‌طور مؤثر نادیده گرفته می‌شوند، اعلام‌های تابع بعدی *بر* قبلی‌ها override می‌کنند.

```js
foo(); // 3

function foo() {
	console.log( 1 );
}

var foo = function() {
	console.log( 2 );
};

function foo() {
	console.log( 3 );
}
```

در حالی که همهٔ این ممکن است چیزی بیش از اطلاعات جالب آکادمیک به نظر نرسد، این واقعیت را برجسته می‌کند که تعریف‌های تکراری در همان scope ایدهٔ واقعاً بدی است و اغلب به نتایج گیج‌کننده منجر می‌شود.

اعلام‌های تابعی که داخل بلوک‌های عادی ظاهر می‌شوند معمولاً به scope محصور hoist می‌شوند، نه conditional همان‌طور که این کد implies می‌کند:

```js
foo(); // "b"

var a = true;
if (a) {
   function foo() { console.log( "a" ); }
}
else {
   function foo() { console.log( "b" ); }
}
```

با این حال، مهم است که بدانید این رفتار قابل اعتماد نیست و در نسخه‌های آیندهٔ JavaScript ممکن است تغییر کند، پس احتمالاً بهتر است از اعلام توابع در بلوک‌ها اجتناب کنید.
