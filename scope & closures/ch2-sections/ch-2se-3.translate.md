# خلاصه

Lexical scope یعنی scope با تصمیمات زمان نوشتن دربارهٔ محل اعلام توابع تعریف می‌شود. فاز lexing کامپایل اساساً می‌تواند بداند تمام شناسه‌ها کجا و چگونه اعلام شده‌اند، و بنابراین پیش‌بینی کند چگونه در حین اجرا جستجو می‌شوند.

دو مکانیزم در JavaScript می‌توانند lexical scope را «دور بزنند»: `eval(..)` و `with`. اولی می‌تواند lexical scope موجود را (در زمان اجرا) با ارزیابی رشته‌ای از «کد» که یک یا چند اعلام دارد تغییر دهد. دومی اساساً یک lexical scope کاملاً جدید (باز هم در زمان اجرا) با برخورد با ارجاع شیء *به‌عنوان* «scope» و ویژگی‌های آن شیء به‌عنوان شناسه‌های scoped ایجاد می‌کند.

معایب این مکانیزم‌ها این است که توانایی *Engine* برای انجام بهینه‌سازی‌های compile-time دربارهٔ جستجوی scope را شکست می‌دهد، چون *Engine* باید بدبینانه فرض کند چنین بهینه‌سازی‌هایی نامعتبر خواهند بود. کد *قطعاً* کندتر اجرا می‌شود در نتیجه استفاده از هر ویژگی. **از آن‌ها استفاده نکنید.**
