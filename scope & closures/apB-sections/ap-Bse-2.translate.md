# بلوک‌های ضمنی در برابر صریح

در فصل ۳، برخی pitfalls بالقوه برای نگهداری/refactorability کد هنگام معرفی block-scoping شناسایی کردیم. آیا راه دیگری برای بهره‌برداری از block scope وجود دارد اما این downside را کاهش دهد؟

این شکل جایگزین `let` را در نظر بگیرید، به‌نام «let block» یا «let statement» (در مقابل «let declarations» قبلی).

```js
let (a = 2) {
	console.log( a ); // 2
}

console.log( a ); // ReferenceError
```

به‌جای hijack ضمنی بلوک موجود، let-statement بلوک صریحی برای scope binding خود ایجاد می‌کند. نه تنها بلوک صریح بیشتر برجسته می‌شود و شاید در refactoring کد قوی‌تر عمل کند، بلکه با اجبار دستوری تمام اعلام‌ها به بالای بلوک کد تمیزتری تولید می‌کند. این کار نگاه کردن به هر بلوک و دانستن چه چیزی به آن scope شده و چه چیزی نه را آسان‌تر می‌کند.

به‌عنوان الگو، رویکرد بسیاری افراد در function-scoping را منعکس می‌کند وقتی دستی تمام اعلام‌های `var` خود را به بالای تابع منتقل/hoist می‌کنند. let-statement آن‌ها را از روی قصد آنجا در بالای بلوک می‌گذارد، و اگر از اعلام‌های `let` پراکنده در همه جا استفاده نکنید، اعلام‌های block-scoping شما تا حدی آسان‌تر برای شناسایی و نگهداری هستند.

اما مشکلی وجود دارد. شکل let-statement در ES6 گنجانده نشده. کامپایلر رسمی Traceur هم آن شکل کد را قبول نمی‌کند.

دو گزینه داریم. می‌توانیم با نحو معتبر ES6 و کمی انضباط کد قالب‌بندی کنیم:

```js
/*let*/ { let a = 2;
	console.log( a );
}

console.log( a ); // ReferenceError
```

اما ابزارها برای حل مشکلات ما هستند. پس گزینهٔ دیگر نوشتن بلوک‌های let statement صریح و گذاشتن ابزار برای تبدیل آن‌ها به کد معتبر و کار است.

پس ابزاری به‌نام «let-er» [^note-let_er] ساختم که دقیقاً این مسئله را حل می‌کند. *let-er* یک transpiler کد build-step است، اما تنها وظیفه‌اش یافتن شکل‌های let-statement و transpile کردن آن‌هاست. بقیهٔ کدتان را، از جمله هر let-declarations، دست‌نخورده می‌گذارد. می‌توانید با خیال راحت *let-er* را به‌عنوان اولین مرحلهٔ transpiler ES6 استفاده کنید و سپس در صورت نیاز کد را از چیزی مثل Traceur عبور دهید.

علاوه بر این، *let-er* پرچم پیکربندی `--es6` دارد که وقتی روشن شود (پیش‌فرض خاموش)، نوع کد تولیدشده را تغییر می‌دهد. به‌جای hack polyfill ES3 با `try/catch`، *let-er* تکهٔ ما را می‌گرفت و کاملاً سازگار با ES6 و غیر-hacky تولید می‌کرد:

```js
{
	let a = 2;
	console.log( a );
}

console.log( a ); // ReferenceError
```

پس می‌توانید همین الان استفاده از *let-er* را شروع کنید و تمام محیط‌های pre-ES6 را هدف بگیرید، و وقتی فقط ES6 برایتان مهم است، می‌توانید پرچم را اضافه کنید و فوراً فقط ES6 را هدف بگیرید.

و مهم‌تر از همه، **می‌توانید شکل let-statement ترجیحی و صریح‌تر را استفاده کنید** حتی اگر بخش رسمی هیچ نسخهٔ ES نیست (هنوز).
