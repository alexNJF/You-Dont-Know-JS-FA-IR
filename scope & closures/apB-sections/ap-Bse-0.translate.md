# شما جاوااسکریپت را نمی‌دانید: Scope و Closures - ویرایش اول
# Polyfill کردن Block Scope

در فصل ۳، Block Scope را کاوش کردیم. دیدیم که `with` و بند `catch` هر دو مثال‌های کوچک block scope هستند که از حداقل معرفی ES3 در JavaScript وجود داشته‌اند.

اما معرفی `let` در ES6 است که در نهایت قابلیت block-scoping کامل و بدون قید به کدمان می‌دهد. چیزهای هیجان‌انگیز زیادی، هم از نظر عملکردی و هم از نظر سبک کد، وجود دارد که block scope امکان‌پذیر می‌کند.

اما اگر می‌خواستیم block scope را در محیط‌های pre-ES6 استفاده کنیم؟

این کد را در نظر بگیرید:

```js
{
	let a = 2;
	console.log( a ); // 2
}

console.log( a ); // ReferenceError
```

این در محیط‌های ES6 عالی کار می‌کند. اما آیا می‌توانیم pre-ES6 انجام دهیم؟ `catch` پاسخ است.

```js
try{throw 2}catch(a){
	console.log( a ); // 2
}

console.log( a ); // ReferenceError
```

واو! کدی زشت و عجیب به نظر می‌رسد. `try/catch` می‌بینیم که به نظر می‌رسد به‌زور خطا پرتاب می‌کند، اما «خطا»یی که پرتاب می‌کند فقط مقدار `2` است، و سپس اعلام متغیری که آن را دریافت می‌کند در بند `catch(a)` است. ذهن: منفجر شد.

درست است، بند `catch` block-scoping دارد، یعنی می‌تواند به‌عنوان polyfill برای block scope در محیط‌های pre-ES6 استفاده شود.

«اما...»، می‌گویید. «...هیچ‌کس نمی‌خواهد کد زشتی مثل آن بنویسد!» درست است. هیچ‌کس (برخی از) کد خروجی کامپایلر CoffeeScript را هم نمی‌نویسد. نکته این نیست.

نکته این است که ابزارها می‌توانند کد ES6 را transpile کنند تا در محیط‌های pre-ES6 کار کند. می‌توانید با block-scoping کد بنویسید و از چنین قابلیتی بهره ببرید، و بگذارید ابزار build-step تولید کدی کند که واقعاً هنگام deploy *کار* کند.

این در واقع مسیر ترجیحی مهاجرت برای تمام (ahem، اکثر) ES6 است: استفاده از transpiler کد برای گرفتن کد ES6 و تولید کد سازگار با ES5 در حین انتقال از pre-ES6 به ES6.
