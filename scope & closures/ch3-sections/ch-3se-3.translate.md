# توابع به‌عنوان Scope

دیده‌ایم که می‌توانیم هر تکه کدی را برداریم و تابعی دور آن بپیچیم، و این به‌طور مؤثر هر اعلام متغیر یا تابع محصور را از scope بیرونی داخل scope درونی آن تابع «پنهان» می‌کند.

مثلاً:

```js
var a = 2;

function foo() { // <-- insert this

	var a = 3;
	console.log( a ); // 3

} // <-- and this
foo(); // <-- and this

console.log( a ); // 2
```

در حالی که این تکنیک «کار می‌کند»، لزوماً خیلی ایده‌آل نیست. چند مشکل ایجاد می‌کند. اول اینکه باید تابع نام‌دار `foo()` اعلام کنیم، یعنی خود نام شناسهٔ `foo` scope محصور (global در این مورد) را «آلوده» می‌کند. همچنین باید صریحاً تابع را با نام (`foo()`) فراخوانی کنیم تا کد پوشانده شده واقعاً اجرا شود.

ایده‌آل‌تر می‌بود اگر تابع نیازی به نام نداشت (یا بهتر بگوییم، نام scope محصور را آلوده نمی‌کرد)، و اگر تابع می‌توانست خودکار اجرا شود.

خوشبختانه، JavaScript راه‌حلی برای هر دو مشکل ارائه می‌دهد.

```js
var a = 2;

(function foo(){ // <-- insert this

	var a = 3;
	console.log( a ); // 3

})(); // <-- and this

console.log( a ); // 2
```

بیایید ببینیم اینجا چه اتفاقی می‌افتد.

اول، توجه کنید که دستور تابع پوشاننده با `(function...` به‌جای فقط `function...` شروع می‌شود. در حالی که ممکن است جزئی جزئی به نظر برسد، در واقع تغییر بزرگی است. به‌جای برخورد با تابع به‌عنوان اعلام استاندارد، تابع به‌عنوان function-expression برخورد می‌شود.

**توجه:** ساده‌ترین راه تشخیص اعلام در برابر expression موقعیت کلمهٔ «function» در دستور است (نه فقط یک خط، بلکه یک دستور مجزا). اگر «function» اولین چیز در دستور باشد، پس اعلام تابع است. در غیر این صورت، function expression است.

تفاوت کلیدی که اینجا بین اعلام تابع و function expression می‌توانیم مشاهده کنیم مربوط به جایی است که نامش به‌عنوان شناسه bind می‌شود.

دو تکه قبلی را مقایسه کنید. در تکهٔ اول، نام `foo` در scope محصور bind شده و مستقیماً با `foo()` فراخوانی می‌کنیم. در تکهٔ دوم، نام `foo` در scope محصور bind نشده، بلکه فقط داخل تابع خودش bind شده است.

به عبارت دیگر، `(function foo(){ .. })` به‌عنوان expression یعنی شناسهٔ `foo` *فقط* در scope جایی که `..` نشان می‌دهد پیدا می‌شود، نه در scope بیرونی. پنهان کردن نام `foo` داخل خودش یعنی scope محصور را به‌طور غیرضروری آلوده نمی‌کند.

### گمنام در برابر نام‌دار

احتمالاً بیشتر با function expressionها به‌عنوان پارامترهای callback آشنا هستید، مثل:

```js
setTimeout( function(){
	console.log("I waited 1 second!");
}, 1000 );
```

این «anonymous function expression» نامیده می‌شود، چون `function()...` نام شناسه روی آن ندارد. Function expressionها می‌توانند گمنام باشند، اما اعلام‌های تابع نمی‌توانند نام را حذف کنند — که دستور JS غیرقانونی می‌بود.

Anonymous function expressionها سریع و آسان برای تایپ هستند، و بسیاری کتابخانه‌ها و ابزارها تمایل به تشویق این سبک idiomatic کد دارند. با این حال، چند draw-back برای در نظر گرفتن دارند:

1. توابع گمنام نام مفیدی برای نمایش در stack trace ندارند، که می‌تواند دیباگ را سخت‌تر کند.

2. بدون نام، اگر تابع نیاز به ارجاع به خودش دارد، برای بازگشت و غیره، متأسفانه ارجاع **منسوخ** `arguments.callee` لازم است. مثال دیگر نیاز به self-reference وقتی است که تابع event handler می‌خواهد بعد از fire شدن خودش را unbind کند.

3. توابع گمنام نامی را که اغلب در ارائهٔ کد خواناتر/قابل‌فهم‌تر مفید است حذف می‌کنند. نام توصیفی به self-document کردن کد مورد نظر کمک می‌کند.

**Inline function expression**ها قدرتمند و مفید هستند — پرسش گمنام در برابر نام‌دار از آن کم نمی‌کند. ارائهٔ نام برای function expression شما به‌طور مؤثر تمام این draw-backها را حل می‌کند، اما downside ملموسی ندارد. بهترین روش این است که همیشه function expressionهای خود را نام بدهید:

```js
setTimeout( function timeoutHandler(){ // <-- Look, I have a name!
	console.log( "I waited 1 second!" );
}, 1000 );
```

### فراخوانی فوری Function Expressionها

```js
var a = 2;

(function foo(){

	var a = 3;
	console.log( a ); // 3

})();

console.log( a ); // 2
```

حالا که تابع را به‌واسطهٔ پیچیدن در جفت `( )` به‌عنوان expression داریم، می‌توانیم آن تابع را با اضافه کردن `()` دیگر در انتها اجرا کنیم، مثل `(function foo(){ .. })()`. جفت `( )` محصور اول تابع را expression می‌کند، و `()` دوم تابع را اجرا می‌کند.

این الگو آنقدر رایج است که چند سال پیش جامعه روی اصطلاحی برای آن توافق کرد: **IIFE**، که مخفف **I**mmediately **I**nvoked **F**unction **E**xpression است.

البته، IIFEها لزوماً نیازی به نام ندارند — رایج‌ترین شکل IIFE استفاده از anonymous function expression است. در حالی که قطعاً کمتر رایج است، نام دادن به IIFE تمام مزایای قبلی نسبت به anonymous function expressionها را دارد، پس روش خوبی برای اتخاذ است.

```js
var a = 2;

(function IIFE(){

	var a = 3;
	console.log( a ); // 3

})();

console.log( a ); // 2
```

تنوع جزئی در شکل سنتی IIFE وجود دارد که برخی ترجیح می‌دهند: `(function(){ .. }())`. دقیق نگاه کنید تا تفاوت را ببینید. در شکل اول، function expression در `( )` پیچیده شده و جفت فراخوانی `()` در بیرون سمت راست آن است. در شکل دوم، جفت فراخوانی `()` به داخل جفت `( )` پوشانندهٔ بیرونی منتقل شده است.

این دو شکل از نظر عملکرد یکسان هستند. **فقط انتخاب سبکی است که ترجیح می‌دهید.**

تنوع دیگر IIFEها که کاملاً رایج است استفاده از این واقعیت است که آن‌ها در واقع فقط فراخوانی تابع هستند و آرگومان(ها) منتقل می‌کنند.

مثلاً:

```js
var a = 2;

(function IIFE( global ){

	var a = 3;
	console.log( a ); // 3
	console.log( global.a ); // 2

})( window );

console.log( a ); // 2
```

ارجاع شیء `window` را منتقل می‌کنیم، اما پارامتر را `global` می‌نامیم تا delineation سبکی واضح برای ارجاع‌های global در برابر non-global داشته باشیم. البته، می‌توانید هر چیزی از scope محصور که می‌خواهید منتقل کنید و پارامتر(ها) را هر نامی که مناسب است بگذارید. این بیشتر فقط انتخاب سبکی است.

کاربرد دیگر این الگو به نگرانی (طاقچهٔ جزئی) می‌پردازد که شناسهٔ پیش‌فرض `undefined` ممکن است مقدارش به‌اشتباه بازنویسی شود و نتایج غیرمنتظره ایجاد کند. با نام دادن پارامتر `undefined` اما منتقل نکردن هیچ مقداری برای آن آرگومان، می‌توانیم تضمین کنیم شناسهٔ `undefined` در واقع مقدار undefined در بلوک کد است:

```js
undefined = true; // setting a land-mine for other code! avoid!

(function IIFE( undefined ){

	var a;
	if (a === undefined) {
		console.log( "Undefined is safe here!" );
	}

})();
```

تنوع دیگر IIFE ترتیب چیزها را معکوس می‌کند، جایی که تابع برای اجرا دوم داده می‌شود، *بعد از* فراخوانی و پارامترهایی که به آن منتقل می‌شوند. این الگو در پروژهٔ UMD (Universal Module Definition) استفاده می‌شود. برخی آن را کمی تمیزتر برای فهم می‌یابند، هرچند کمی verboseتر است.

```js
var a = 2;

(function IIFE( def ){
	def( window );
})(function def( global ){

	var a = 3;
	console.log( a ); // 3
	console.log( global.a ); // 2

});
```

Function expression مربوط به `def` در نیمهٔ دوم تکه تعریف شده و سپس به‌عنوان پارامتر (همچنین `def` نامیده شده) به تابع `IIFE` تعریف‌شده در نیمهٔ اول تکه منتقل می‌شود. در نهایت، پارامتر `def` (تابع) فراخوانی می‌شود و `window` به‌عنوان پارامتر `global` منتقل می‌شود.
