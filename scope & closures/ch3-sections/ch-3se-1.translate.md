# Scope از توابع

رایج‌ترین پاسخ به آن پرسش‌ها این است که JavaScript scope مبتنی بر تابع دارد. یعنی هر تابعی که اعلام می‌کنید برای خودش حباب ایجاد می‌کند، اما هیچ ساختار دیگری scope حباب خودش را ایجاد نمی‌کند. همان‌طور که به‌زودی خواهیم دید، این کاملاً درست نیست.

اما اول، بیایید scope تابع و پیامدهایش را کاوش کنیم.

این کد را در نظر بگیرید:

```js
function foo(a) {
	var b = 2;

	// some code

	function bar() {
		// ...
	}

	// more code

	var c = 3;
}
```

در این تکه، حباب scope مربوط به `foo(..)` شامل شناسه‌های `a`، `b`، `c` و `bar` است. **مهم نیست** *کجا* در scope اعلام ظاهر شود، متغیر یا تابع به حباب scope محصور تعلق دارد، صرف‌نظر. در فصل بعد خواهیم دید دقیقاً *چگونه* کار می‌کند.

`bar(..)` حباب scope خودش را دارد. global scope هم همین‌طور، که فقط یک شناسه به آن متصل است: `foo`.

چون `a`، `b`، `c` و `bar` همگی به حباب scope مربوط به `foo(..)` تعلق دارند، خارج از `foo(..)` قابل دسترسی نیستند. یعنی کد زیر همگی منجر به خطاهای `ReferenceError` می‌شوند، چون شناسه‌ها برای global scope در دسترس نیستند:

```js
bar(); // fails

console.log( a, b, c ); // all 3 fail
```

با این حال، تمام این شناسه‌ها (`a`، `b`، `c`، `foo` و `bar`) *داخل* `foo(..)` قابل دسترسی هستند، و در واقع داخل `bar(..)` هم در دسترس هستند (با فرض اینکه اعلام‌های شناسهٔ shadow داخل `bar(..)` نباشد).

Scope تابع ایدهٔ اینکه تمام متغیرها به تابع تعلق دارند و می‌توان در کل تابع استفاده و استفادهٔ مجدد کرد (و در واقع حتی برای scopeهای تو در تو قابل دسترسی هستند) را تشویق می‌کند. این رویکرد طراحی می‌تواند بسیار مفید باشد و قطعاً می‌تواند از طبیعت «پویا»ٔ متغیرهای JavaScript برای گرفتن مقادیر انواع مختلف در صورت نیاز استفاده کامل کند.

از سوی دیگر، اگر احتیاط دقیق نکنید، متغیرهای موجود در کل scope می‌توانند به برخی pitfalls غیرمنتظره منجر شوند.
