# زیرنوع‌های شیء

انواع مختلف زیرنوع‌های تخصصی شیء در جاوااسکریپت وجود دارد. اما تاکنون، دو مورد رایج‌ترین که با آن‌ها تعامل خواهید داشت آرایه‌ها و `function`ها هستند.

| NOTE: |
| :--- |
| با «زیرنوع» منظور notion نوع مشتق‌شده‌ای است که رفتارها را از نوع والد به ارث برده اما سپس آن رفتارها را تخصصی یا گسترش داده است. به عبارت دیگر، مقادیر این زیرنوع‌ها کاملاً شیء هستند، اما *فراتر از* شیء هم هستند. |

### آرایه‌ها

آرایه‌ها اشیائی هستند که به‌طور خاص برای **ایندکس‌شدهٔ عددی** در نظر گرفته شده‌اند، به‌جای استفاده از مکان‌های ویژگی نام‌دار رشته. آن‌ها هنوز شیء هستند، پس ویژگی نام‌دار مثل `favoriteNumber` قانونی است. اما بسیار ناپسند است که ویژگی‌های نام‌دار را در آرایه‌های ایندکس‌شدهٔ عددی مخلوط کنید.

آرایه‌ها ترجیحاً با نحو literal (مشابه اشیاء) تعریف می‌شوند، اما با براکت‌های مربعی `[ .. ]` به‌جای آکولادهای `{ .. }`:

```js
myList = [ 23, 42, 109 ];
```

جاوااسکریپت هر ترکیبی از انواع مقدار در آرایه‌ها را مجاز می‌داند، از جمله اشیاء، آرایه‌های دیگر، توابع و غیره. همان‌طور که احتمالاً می‌دانید، آرایه‌ها «zero-indexed» هستند، یعنی اولین عنصر آرایه در ایندکس `0` است، نه `1`:

```js
myList = [ 23, 42, 109 ];

myList[0];      // 23
myList[1];      // 42
```

به خاطر بسپارید که هر نام ویژگی رشته روی شیء که «شبیه» عدد صحیح است — بتواند به‌درستی به عدد صحیح عددی coerce شود — در واقع مثل ویژگی عدد صحیح (یعنی integer index) treat می‌شود. همین برای آرایه‌ها هم صادق است. همیشه باید `42` را به‌عنوان integer index (یعنی نام ویژگی) استفاده کنید، اما اگر رشتهٔ `"42"` را استفاده کنید، جاوااسکریپت فرض می‌کند منظورتان آن به‌عنوان عدد صحیح بوده و آن کار را برایتان انجام می‌دهد.

```js
// "2" اینجا به‌عنوان integer index کار می‌کند، اما توصیه نمی‌شود
myList["2"];    // 109
```

یک استثنا برای «قانون» «بدون ویژگی نام‌دار روی آرایه‌ها» این است که همهٔ آرایه‌ها به‌طور خودکار ویژگی `length` را expose می‌کنند که به‌طور خودکار با «طول» آرایه به‌روز نگه داشته می‌شود.

```js
myList = [ 23, 42, 109 ];

myList.length;   // 3

// مقدار دیگر را به انتهای لیست "push" کنید
myList.push("Hello");

myList.length;   // 4
```

| WARNING: |
| :--- |
| بسیاری از توسعه‌دهندگان جاوااسکریپت به‌اشتباه معتقدند `length` آرایه اساساً *getter* است (بخش «Accessor Properties» قبلی این فصل را ببینید)، اما نیست. نتیجه این است که این توسعه‌دهندگان احساس می‌کنند دسترسی به این ویژگی «گران» است — انگار جاوااسکریپت باید length را on-the-fly دوباره محاسبه کند — و بنابراین کارهایی مثل capture/store کردن طول آرایه قبل از حلقهٔ non-mutating روی آن انجام می‌دهند. این قبلاً از نظر عملکرد «best practice» بود. اما حداقل ۱۰ سال است که در واقع anti-pattern شده، چون موتور جاوااسکریپت در مدیریت ویژگی `length` کارآمدتر از کد جاوااسکریپت ما در تلاش برای «هوشمندتر» بودن از موتور برای اجتناب از فراخوانی چیزی که فکر می‌کنیم *getter* است. کارآمدتر است بگذاریم موتور جاوااسکریپت کارش را بکند و فقط هر زمان و هر قدر لازم است به ویژگی دسترسی یابیم. |

#### Empty Slots

آرایه‌های جاوااسکریپت همچنین «نقص» واقعاً بدی در طراحی‌شان دارند به نام «empty slots». اگر ایندکسی از آرایه را بیش از یک موقعیت فراتر از انتهای فعلی آرایه انتساب دهید، جاوااسکریپت slotهای بین را «خالی» می‌گذارد به‌جای انتساب خودکار آن‌ها به `undefined` همان‌طور که ممکن است انتظار داشته باشید:

```js
myList = [ 23, 42, 109 ];
myList.length;              // 3

myList[14] = "Hello";
myList.length;              // 15

myList;                     // [ 23, 42, 109, empty x 11, "Hello" ]

// شبیه slot واقعی با
// مقدار واقعی `undefined` در آن،
// اما مراقب باشید، ترفند است!
myList[9];                  // undefined
```

ممکن است بپرسید چرا empty slotها اینقدر بد هستند؟ یک دلیل: APIهایی در جاوااسکریپت مثل `map(..)` آرایه وجود دارند که empty slotها به‌طور غافل‌گیرکننده رد می‌شوند! هرگز، هرگز عمداً empty slot در آرایه‌هایتان ایجاد نکنید. این بی‌تردید یکی از «بخش‌های بد» جاوااسکریپت است.

### توابع

چیز خاص زیادی دربارهٔ توابع اینجا ندارم بگویم، جز اشاره به اینکه آن‌ها هم زیرنوع‌های شیء هستند. این یعنی علاوه بر قابل اجرا بودن، می‌توانند ویژگی‌های نام‌دار هم به آن‌ها اضافه یا از آن‌ها دسترسی شود.

توابع دو ویژگی از پیش تعریف‌شده دارند که ممکن است با آن‌ها تعامل کنید، به‌طور خاص برای اهداف meta-programming:

```js
function help(opt1,opt2,...remainingOpts) {
    // ..
}

help.name;          // "help"
help.length;        // 2
```

`length` تابع تعداد پارامترهای صریحاً تعریف‌شدهٔ آن است، تا اما بدون شامل پارامتری که یا مقدار پیش‌فرض تعریف شده دارد (مثلاً `param = 42`) یا «rest parameter» (مثلاً `...remainingOpts`).

#### اجتناب از تنظیم ویژگی‌های شیء-تابع

باید از انتساب ویژگی روی اشیاء تابع اجتناب کنید. اگر به دنبال ذخیرهٔ اطلاعات اضافی مرتبط با تابع هستید، از `Map(..)` (یا `WeakMap(..)`) جدا با شیء تابع به‌عنوان کلید و اطلاعات اضافی به‌عنوان مقدار استفاده کنید.

```js
extraInfo = new Map();

extraInfo.set(help,"this is some important information");

// بعداً:
extraInfo.get(help);   // "this is some important information"
```
