# زنجیرهٔ `[[Prototype]]`

یکی از مهم‌ترین اما کم‌واضح‌ترین ویژگی‌های شیء (بخشی از MOP) «prototype chain» نامیده می‌شود؛ نماد رسمی مشخصات جاوااسکریپت `[[Prototype]]` است. مطمئن شوید این `[[Prototype]]` را با ویژگی عمومی به نام `prototype` اشتباه نگیرید. علیرغم نام‌گذاری، این‌ها مفاهیم متمایزی هستند.

`[[Prototype]]` یک linkage داخلی است که شیء به‌طور پیش‌فرض هنگام ایجادش می‌گیرد و به شیء دیگری اشاره می‌کند. این linkage ویژگی مخفی و اغلب ظریف شیء است، اما تأثیرات عمیقی بر نحوهٔ تعاملات با شیء دارد. «chain» نامیده می‌شود چون یک شیء به شیء دیگر لینک می‌شود، که به نوبهٔ خود به شیء دیگری لینک می‌شود، ... و همین‌طور ادامه. *انتهای* یا *بالای* این زنجیره وجود دارد، جایی که linkage متوقف می‌شود و دیگر جایی برای رفتن نیست. بیشتر به زودی.

چند مورد از implications linkage `[[Prototype]]` را در فصل ۱ دیدیم. مثلاً به‌طور پیش‌فرض، همهٔ اشیاء به شیء built-in به نام `Object.prototype` `[[Prototype]]`-linked هستند.

| WARNING: |
| :--- |
| خود آن نام `Object.prototype` می‌تواند گیج‌کننده باشد، چون از ویژگی به نام `prototype` استفاده می‌کند. `[[Prototype]]` و `prototype` چطور مرتبط‌اند!؟ این سؤال‌ها/گیجی را کمی متوقف کنید، چون بعداً در این فصل به تفاوت‌های `[[Prototype]]` و `prototype` برمی‌گردیم و توضیح می‌دهیم. برای لحظه، فقط وجود این شیء built-in مهم اما عجیب‌نام `Object.prototype` را فرض کنید. |

بیایید کدی را در نظر بگیریم:

```js
myObj = {
    favoriteNumber: 42
};
```

این باید از فصل ۱ آشنا به نظر برسد. اما آنچه در این کد *نمی‌بینید* این است که آن شیء به‌طور خودکار (از طریق `[[Prototype]]` داخلیش) به آن شیء built-in اما عجیب‌نام `Object.prototype` لینک شده بود.

وقتی کارهایی مثل این می‌کنیم:

```js
myObj.toString();                             // "[object Object]"

myObj.hasOwnProperty("favoriteNumber");   // true
```

از این linkage داخلی `[[Prototype]]` بهره می‌بریم، بدون اینکه واقعاً متوجه شویم. چون `myObj` ویژگی‌های `toString` یا `hasOwnProperty` تعریف‌شده رویش ندارد، آن دسترسی‌های ویژگی در واقع دسترسی را **DELEGATING** می‌کنند تا جستجویش را در امتداد زنجیرهٔ `[[Prototype]]` ادامه دهد.

چون `myObj` به شیء به نام `Object.prototype` `[[Prototype]]`-linked است، جستجوی ویژگی‌های `toString` و `hasOwnProperty` روی آن شیء ادامه می‌یابد؛ و در واقع، این متدها آنجا پیدا می‌شوند!

قابلیت `myObj.toString` برای دسترسی به ویژگی `toString` حتی با اینکه واقعاً آن را ندارد، معمولاً «inheritance» نامیده می‌شود، یا به‌طور خاص‌تر «prototypal inheritance». ویژگی‌های `toString` و `hasOwnProperty` همراه با بسیاری دیگر، «inherited properties» روی `myObj» گفته می‌شوند.

| NOTE: |
| :--- |
| با استفاده از کلمهٔ «inheritance» اینجا نارضایتی زیادی دارم — باید «delegation» نامیده شود! — اما این همان چیزی است که اکثر مردم به آن اشاره می‌کنند، پس با اکراه موافقت می‌کنیم و فعلاً همان اصطلاحات را استفاده می‌کنیم (اگرچه تحت اعتراض، با گیومه «»). اعتراضاتم را برای پیوست این کتاب نگه می‌دارم. |

`Object.prototype` چند ویژگی و متد built-in دارد که همهٔ آن‌ها توسط هر شیئی که به `Object.prototype` `[[Prototype]]`-linked است (مستقیم یا غیرمستقیم از طریق linkage شیء دیگر) «به ارث برده می‌شوند».

برخی ویژگی‌های «به‌ارث‌برده» رایج از `Object.prototype` شامل این‌هاست:

* `constructor`
* `__proto__`
* `toString()`
* `valueOf()`
* `hasOwnProperty(..)`
* `isPrototypeOf(..)`

`hasOwnProperty(..)` را به خاطر بسپارید که قبلاً دیدیم بررسی boolean برای اینکه آیا ویژگی خاصی (با نام رشته) owned توسط شیء است به ما می‌دهد:

```js
myObj = {
    favoriteNumber: 42
};

myObj.hasOwnProperty("favoriteNumber");   // true
```

همیشه تا حدی بدشانسی (سازماندهی معنایی، تداخل نام‌گذاری و غیره) به‌حساب آمده که ابزار مهمی مثل `hasOwnProperty(..)` روی زنجیرهٔ `[[Prototype]]` Object به‌عنوان متد instance گنجانده شده، به‌جای تعریف به‌عنوان ابزار استاتیک.

از ES2022، جاوااسکریپت بالاخره نسخهٔ استاتیک این ابزار را اضافه کرد: `Object.hasOwn(..)`.

```js
myObj = {
    favoriteNumber: 42
};

Object.hasOwn(myObj,"favoriteNumber");   // true
```

این شکل اکنون گزینهٔ ترجیحی‌تر و قوی‌تر به‌حساب می‌آید و شکل متد instance (`hasOwnProperty(..)`) اکنون عموماً باید اجتناب شود.

متأسفانه و ناسازگارانه، (هنوز، در زمان نوشتن) ابزارهای استاتیک متناظر مثل `Object.isPrototype(..)` (به‌جای متد instance `isPrototypeOf(..)`) وجود ندارد. اما حداقل `Object.hasOwn(..)` وجود دارد، پس پیشرفت است.

### ایجاد شیء با `[[Prototype]]` متفاوت

به‌طور پیش‌فرض، هر شیئی که در برنامه‌هایتان ایجاد می‌کنید به آن شیء `Object.prototype` `[[Prototype]]`-linked خواهد بود. با این حال، می‌توانید شیء با linkage متفاوت این‌طور ایجاد کنید:

```js
myObj = Object.create(differentObj);
```

متد `Object.create(..)` آرگومان اولش را به‌عنوان مقدار برای تنظیم `[[Prototype]]` شیء تازه ایجادشده می‌گیرد.

یک downside این رویکرد این است که از نحو literal `{ .. }` استفاده نمی‌کنید، پس در ابتدا هیچ محتوایی برای `myObj` تعریف نمی‌کنید. معمولاً سپس باید ویژگی‌ها را یکی‌یکی با `=` تعریف کنید.

| NOTE: |
| :--- |
| آرگومان دوم اختیاری `Object.create(..)` — مثل آرگومان دوم `Object.defineProperties(..)` که قبلاً بحث شد — شیء با ویژگی‌هایی است که descriptorها را برای تعریف اولیهٔ شیء جدید نگه می‌دارند. در عمل در دنیای واقعی، این شکل به‌ندرت استفاده می‌شود، احتمالاً چون مشخص کردن descriptorهای کامل به‌جای فقط جفت‌های نام/مقدار awkwardتر است. اما ممکن است در برخی موارد محدود به کار بیاید. |

به‌طور جایگزین اما کمتر ترجیحی، می‌توانید از نحو literal `{ .. }` همراه با ویژگی خاص (و عجیب‌نما!) استفاده کنید:

```js
myObj = {
    __proto__: differentObj,

    // .. بقیهٔ تعریف شیء
};
```

| WARNING: |
| :--- |
| ویژگی عجیب‌نما `__proto__` بیش از ۲۰ سال در برخی موتورهای جاوااسکریپت بوده، اما فقط از ES6 (در ۲۰۱۵) در جاوااسکریپت استاندارد شده. حتی هنوز، در Appendix B مشخصات[^specApB] اضافه شد که ویژگی‌هایی را لیست می‌کند که TC39 با اکراه شامل می‌کند چون به‌طور محبوب در موتورهای جاوااسکریپت مبتنی بر مرورگر وجود دارند و بنابراین واقعیت de-facto هستند حتی اگر از TC39 سرچشمه نگرفته‌اند. این ویژگی بنابراین توسط spec «تضمین» شده که در همهٔ موتورهای جاوااسکریپت مبتنی بر مرورگر conforming وجود دارد، اما لزوماً تضمین نشده که در موتورهای جاوااسکریپت مستقل دیگر کار کند. Node.js از موتور جاوااسکریپت (v8) مرورگر Chrome استفاده می‌کند، پس Node.js به‌طور پیش‌فرض/تصادفی `__proto__` را می‌گیرد. هنگام استفاده از `__proto__` مراقب باشید که از همهٔ محیط‌های موتور جاوااسکریپتی که کدتان در آن اجرا می‌شود آگاه باشید. |

چه از `Object.create(..)` استفاده کنید چه `__proto__`، شیء ایجادشدهٔ مورد نظر معمولاً به شیء متفاوتی از `Object.prototype` پیش‌فرض `[[Prototype]]`-linked خواهد بود.

#### Linkage `[[Prototype]]` خالی

بالا ذکر کردیم که زنجیرهٔ `[[Prototype]]` باید جایی متوقف شود تا جستجوها برای همیشه ادامه نیابند. `Object.prototype` معمولاً بالای/انتهای هر زنجیرهٔ `[[Prototype]]` است، چون `[[Prototype]]` خودش `null` است و بنابراین جایی دیگر برای ادامهٔ جستجو نیست.

با این حال، می‌توانید اشیاء با مقدار `null` خودشان برای `[[Prototype]]` هم تعریف کنید، مثل:

```js
emptyObj = Object.create(null);
// یا: emptyObj = { __proto__: null }

emptyObj.toString;   // undefined
```

ایجاد شیء بدون linkage `[[Prototype]]` به `Object.prototype` می‌تواند بسیار مفید باشد. مثلاً همان‌طور که در فصل ۱ ذکر شد، سازه‌های `in` و `for..in` زنجیرهٔ `[[Prototype]]` را برای ویژگی‌های به‌ارث‌برده مشورت می‌کنند. اما این ممکن است نامطلوب باشد، چون ممکن است نخواهید چیزی مثل `"toString" in myObj` با موفقیت resolve شود.

علاوه بر این، شیء با `[[Prototype]]` خالی از هر برخورد تصادفی «inheritance» بین نام ویژگی‌های خودش و آن‌هایی که از جای دیگر «به ارث می‌برد» در امان است. این انواع اشیاء (مفید!) گاهی در اصطلاحات رایج «dictionary objects» نامیده می‌شوند.

### `[[Prototype]]` در مقابل `prototype`

آن نام ویژگی عمومی `prototype` در نام/مکان این شیء خاص `Object.prototype` را متوجه شدید؟ موضوعش چیست؟

`Object` تابع `Object(..)` است؛ به‌طور پیش‌فرض، همهٔ توابع (که خودشان شیء هستند!) چنین ویژگی `prototype` رویشان دارند که به شیء اشاره می‌کند.

و اینجاست که تداخل نام بین `[[Prototype]]` و `prototype` واقعاً گاز می‌گیرد. ویژگی `prototype` روی تابع هیچ linkage که خود تابع تجربه می‌کند تعریف نمی‌کند. در واقع، توابع (به‌عنوان شیء) linkage `[[Prototype]]` داخلی خودشان را جای دیگر دارند — بیشتر در یک ثانیه.

بلکه، ویژگی `prototype` روی تابع به شیء اشاره می‌کند که باید *به آن لینک شود* توسط هر شیء دیگری که هنگام فراخوانی آن تابع با کلمهٔ کلیدی `new` ایجاد می‌شود:

```js
myObj = {};

// اساساً همان است که:
myObj = new Object();
```

چون نحو literal شیء `{ .. }` اساساً همان فراخوانی `new Object()` است، شیء built-in به نام/مکان‌دار در `Object.prototype` به‌عنوان مقدار `[[Prototype]]` داخلی برای شیء جدیدی که ایجاد و `myObj` نام می‌گذاریم استفاده می‌شود.

فوف! صحبت از موضوعی که فقط به خاطر تداخل نام بین `[[Prototype]]` و `prototype` به‌طور قابل توجهی گیج‌کننده‌تر شده!

----

اما توابع خودشان (به‌عنوان شیء!) به کجا لینک می‌شوند، از نظر `[[Prototype]]`؟ آن‌ها به `Function.prototype` لینک می‌شوند، شیء built-in دیگر، واقع در ویژگی `prototype` روی تابع `Function(..)`.

به عبارت دیگر، می‌توانید توابع خودشان را تصور کنید که با فراخوانی `new Function(..)` «ایجاد» شده‌اند و سپس به شیء `Function.prototype` `[[Prototype]]`-linked شده‌اند. این شیء ویژگی‌ها/متدهایی دارد که همهٔ توابع به‌طور پیش‌فرض «به ارث می‌برند»، مثل `toString()` (برای serialize رشتهٔ کد منبع تابع) و `call(..)` / `apply(..)` / `bind(..)` (بعداً در این کتاب توضیح می‌دهیم).
