# دسترسی به ویژگی‌ها

دسترسی به ویژگی شیء موجود ترجیحاً با operator `.` انجام می‌شود:

```js
myObj.favoriteNumber;    // 42
myObj.isDeveloper;       // true
```

اگر امکان دسترسی این‌طور وجود دارد، قویاً پیشنهاد می‌شود همین کار را بکنید.

اگر نام ویژگی کاراکترهایی دارد که در شناسه‌ها نمی‌توانند ظاهر شوند، مثل اعداد ابتدایی یا فاصلهٔ خالی، می‌توان به‌جای `.` از براکت‌های `[ .. ]` استفاده کرد:

```js
myObj["2 nicknames"];    // [ "getify", "ydkjs" ]
```

```js
anotherObj[42];          // "<-- این نام ویژگی..."
anotherObj["41"];        // "<-- این نام ویژگی..."
```

هرچند «نام‌های» ویژگی عددی به‌عنوان عدد باقی می‌مانند، دسترسی به ویژگی از طریق براکت‌های `[ .. ]` نمایش رشته را به عدد coerce می‌کند (مثلاً `"42"` به معادل عددی `42`) و سپس ویژگی عددی مرتبط را بر این اساس دسترسی می‌کند.

مشابه literal شیء، نام ویژگی برای دسترسی می‌تواند از طریق براکت‌های `[ .. ]` محاسبه شود. عبارت می‌تواند یک شناسهٔ ساده باشد:

```js
propName = "41";
anotherObj[propName];
```

در واقع، آنچه بین براکت‌های `[ .. ]` قرار می‌دهید می‌تواند هر عبارت دلخواه جاوااسکریپت باشد، نه فقط شناسه‌ها یا مقادیر literal مثل `42` یا `"isDeveloper"`. جاوااسکریپت ابتدا عبارت را ارزیابی می‌کند و مقدار حاصل سپس به‌عنوان نام ویژگی برای جستجو روی شیء استفاده می‌شود:

```js
function howMany(x) {
    return x + 1;
}

myObj[`${ howMany(1) } nicknames`];   // [ "getify", "ydkjs" ]
```

در این قطعه، عبارت یک `` `template string literal` `` محدودشده با back-tick با عبارت درونه‌گذاری‌شدهٔ فراخوانی تابع `howMany(1)` است. نتیجهٔ کلی آن عبارت مقدار رشتهٔ `"2 nicknames"` است که سپس به‌عنوان نام ویژگی برای دسترسی استفاده می‌شود.

### Object Entries

می‌توانید لیستی از ویژگی‌های یک شیء به‌صورت آرایه‌ای از tupleها (زیرآرایه‌های دو عنصری) حاوی نام و مقدار ویژگی بگیرید:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

Object.entries(myObj);
// [ ["favoriteNumber",42], ["isDeveloper",true], ["firstName","Kyle"] ]
```

اضافه‌شده در ES6، `Object.entries(..)` این لیست entries را بازیابی می‌کند — فقط ویژگی‌های owned و enumerable؛ بخش «Property Descriptors» فصل بعد را ببینید — از شیء مبدأ.

چنین لیستی را می‌توان loop/iterate کرد و احتمالاً ویژگی‌ها را به شیء موجود دیگر انتساب داد. با این حال، امکان ایجاد شیء جدید از لیست entries با `Object.fromEntries(..)` (اضافه‌شده در ES2019) هم وجود دارد:

```js
myObjShallowCopy = Object.fromEntries( Object.entries(myObj) );

// رویکرد جایگزین برای آنچه قبلاً بحث شد:
// myObjShallowCopy = { ...myObj };
```

### Destructuring

رویکرد دیگر دسترسی به ویژگی‌ها از طریق object destructuring (اضافه‌شده در ES6) است. destructuring را به‌عنوان تعریف «الگویی» تصور کنید که ساختار مورد انتظار یک مقدار شیء را توصیف می‌کند، و سپس از جاوااسکریپت بخواهید آن «الگو» را دنبال کند تا به‌طور سیستماتیک به محتویات مقدار شیء دسترسی یابد.

نتیجهٔ نهایی object destructuring شیء دیگر نیست، بلکه یک یا چند انتساب به targetهای دیگر (متغیرها و غیره) از مقادیر شیء مبدأ است.

این کد pre-ES6 را تصور کنید:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

const favoriteNumber = (
    myObj.favoriteNumber !== undefined ? myObj.favoriteNumber : 42
);
const isDev = myObj.isDeveloper;
const firstName = myObj.firstName;
const lname = (
    myObj.lastName !== undefined ? myObj.lastName : "--missing--"
);
```

آن دسترسی‌های مقادیر ویژگی و انتساب‌ها به شناسه‌های دیگر عموماً «manual destructuring» نامیده می‌شوند. برای استفاده از نحو declarative object destructuring، ممکن است این‌طور باشد:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

const { favoriteNumber = 12 } = myObj;
const {
    isDeveloper: isDev,
    firstName: firstName,
    lastName: lname = "--missing--"
} = myObj;

favoriteNumber;   // 42
isDev;            // true
firstName;        // "Kyle"
lname;            // "--missing--"
```

همان‌طور که نشان داده شد، `{ .. }` object destructuring شبیه تعریف مقدار literal شیء است، اما در سمت چپ operator `=` ظاهر می‌شود به‌جای سمت راست جایی که عبارت مقدار شیء ظاهر می‌شد. این باعث می‌شود `{ .. }` در سمت چپ الگوی destructuring باشد به‌جای تعریف شیء دیگر.

destructuring `{ favoriteNumber } = myObj` به جاوااسکریپت می‌گوید ویژگی به نام `favoriteNumber` روی شیء پیدا کند و مقدارش را به شناسهٔ هم‌نام انتساب دهد. نمونهٔ واحد شناسهٔ `favoriteNumber` در الگو شبیه «concise properties» است که قبلاً در این فصل بحث شد: اگر مبدأ (نام ویژگی) و هدف (شناسه) یکسان باشند، می‌توانید یکی را حذف کنید و فقط یک بار لیست کنید.

بخش `= 12` به جاوااسکریپت می‌گوید `12` را به‌عنوان مقدار پیش‌فرض برای انتساب به `favoriteNumber` ارائه دهد، اگر شیء مبدأ یا ویژگی `favoriteNumber` نداشته باشد یا ویژگی مقدار `undefined` نگه دارد.

در الگوی destructuring دوم، الگوی `isDeveloper: isDev` به جاوااسکریپت دستور می‌دهد ویژگی به نام `isDeveloper` روی شیء مبدأ پیدا کند و مقدارش را به شناسهٔ `isDev` انتساب دهد. نوعی «تغییر نام» مبدأ به هدف است. در مقابل، `firstName: firstName` مبدأ و هدف انتساب را ارائه می‌دهد اما redundant است چون یکسان‌اند؛ یک `firstName` اینجا کافی بود و عموماً ترجیح داده می‌شود.

`lastName: lname = "--missing--"` هم تغییر نام مبدأ-هدف و هم مقدار پیش‌فرض (اگر ویژگی مبدأ `lastName` وجود نداشته یا `undefined` باشد) را ترکیب می‌کند.

قطعهٔ بالا object destructuring را با اعلان‌های متغیر ترکیب می‌کند — در این مثال `const` استفاده شده، اما `var` و `let` هم کار می‌کنند — اما ذاتاً مکانیزم اعلان نیست. destructuring دربارهٔ دسترسی و انتساب (مبدأ به هدف) است، پس می‌تواند روی targetهای موجود عمل کند به‌جای اعلان موارد جدید:

```js
let fave;

// ( ) اطراف اینجا نحو لازم است،
// وقتی declarator استفاده نمی‌شود
({ favoriteNumber: fave } = myObj);

fave;  // 42
```

نحو object destructuring عموماً برای سبک declarative و خواناتر نسبت به معادل‌های imperative سنگین pre-ES6 ترجیح داده می‌شود. اما در destructuring زیاده‌روی نکنید. گاهی فقط `x = someObj.x` کاملاً کافی است!

### دسترسی شرطی به ویژگی

اخیراً (در ES2020)، ویژگی‌ای به نام «optional chaining» به جاوااسکریپت اضافه شد که قابلیت‌های دسترسی به ویژگی (به‌ویژه دسترسی تو در تو) را تقویت می‌کند. شکل اصلی operator مرکب دو کاراکتری `?.` است، مثل `A?.B`.

این operator ارجاع سمت چپ (`A`) را بررسی می‌کند که آیا null'ish (`null` یا `undefined`) است. اگر چنین باشد، بقیهٔ عبارت دسترسی به ویژگی short-circuit می‌شود (رد می‌شود) و `undefined` به‌عنوان نتیجه برگردانده می‌شود (حتی اگر `null` بود که واقعاً مواجه شد!). وگرنه، `?.` ویژگی را درست مثل operator `.` معمولی دسترسی می‌کند.

مثلاً:

```js
myObj?.favoriteNumber
```

اینجا، بررسی null'ish روی `myObj` انجام می‌شود، یعنی دسترسی به ویژگی `favoriteNumber` فقط اگر مقدار در `myObj` non-null'ish باشد انجام می‌شود. توجه کنید که تأیید نمی‌کند `myObj` واقعاً شیء واقعی نگه می‌دارد، فقط non-nullish است. با این حال، همهٔ مقادیر non-nullish می‌توانند «به‌طور امن» (بدون exception جاوااسکریپت) از طریق operator `.` «دسترسی» شوند، حتی اگر ویژگی مطابق برای بازیابی نباشد.

راحت است فکر کنید بررسی null'ish روی ویژگی `favoriteNumber` است. اما یک راه برای روشن نگه داشتن این است که به خاطر بسپارید `?` در سمتی است که بررسی امنیت انجام می‌شود، در حالی که `.` در سمتی است که فقط در صورت عبور بررسی non-null'ish ارزیابی می‌شود.

معمولاً operator `?.` در دسترسی‌های تو در تو که ممکن است ۳ سطح یا بیشتر باشند استفاده می‌شود، مثل:

```js
myObj?.address?.city
```

عملیات معادل با operator `?.` این‌طور می‌شد:

```js
(myObj != null && myObj.address != null) ? myObj.address.city : undefined
```

باز هم به خاطر بسپارید که هیچ بررسی روی ویژگی راست‌ترین (`city`) اینجا انجام نشده است.

همچنین، `?.` نباید به‌طور جهانی به‌جای هر operator `.` در برنامه‌هایتان استفاده شود. باید تلاش کنید بدانید آیا دسترسی `.` موفق می‌شود یا نه قبل از دسترسی، هر زمان ممکن. فقط وقتی از `?.` استفاده کنید که ماهیت مقادیر در حال دسترسی تابع شرایطی است که قابل پیش‌بینی/کنترل نیست.

مثلاً، در قطعهٔ قبلی، استفادهٔ `myObj?.` احتمالاً اشتباه است، چون واقعاً نباید باشد که زنجیرهٔ دسترسی به ویژگی را روی متغیری شروع کنید که شاید حتی شیء سطح بالا نگه ندارد (علاوه بر محتوایش که ممکن است در شرایط خاص ویژگی‌های خاصی نداشته باشد).

در عوض، استفادهٔ بیشتر شبیه این را توصیه می‌کنم:

```js
myObj.address?.city
```

و آن عبارت فقط باید در بخشی از برنامه استفاده شود که مطمئن هستید `myObj` حداقل شیء معتبر نگه می‌دارد (چه ویژگی `address` با زیرشیء داشته باشد چه نه).

شکل دیگر operator «optional chaining» `?.[` است که وقتی دسترسی به ویژگی که می‌خواهید شرطی/امن کنید نیاز به براکت `[ .. ]` دارد.

```js
myObj["2 nicknames"]?.[0];   // "getify"
```

همهٔ آنچه دربارهٔ رفتار `?.` گفته شد برای `?.[` هم صادق است.

| WARNING: |
| :--- |
| شکل سوم این ویژگی به نام «optional call» وجود دارد که از `?.(` به‌عنوان operator استفاده می‌کند. برای انجام بررسی non-null'ish روی ویژگی قبل از اجرای مقدار تابع در ویژگی استفاده می‌شود. مثلاً به‌جای `myObj.someFunc(42)` می‌توانید `myObj.someFunc?.(42)` بنویسید. `?.(` بررسی می‌کند که `myObj.someFunc` non-null'ish باشد قبل از فراخوانی آن (با بخش `(42)`). هرچند ممکن است ویژگی مفیدی به نظر برسد، فکر می‌کنم به اندازهٔ کافی خطرناک است که اجتناب کامل از این شکل/سازه را توجیه کند.<br><br>نگرانی من این است که `?.(` طوری به نظر می‌رسد که گویی مطمئن می‌شویم تابع «قابل فراخوانی» است قبل از فراخوانی، در حالی که در واقع فقط بررسی non-null'ish می‌کنیم. برخلاف `?.` که می‌تواند دسترسی «امن» `.` به مقدار non-null'ish که شیء هم نیست اجازه دهد، بررسی non-null'ish `?.(` به همین شکل «امن» نیست. اگر ویژگی مورد نظر هر مقدار non-null'ish غیرتابعی مثل `true` یا `"Hello"` داشته باشد، بخش فراخوانی `(42)` اجرا می‌شود و با این حال exception جاوااسکریپت پرتاب می‌کند. پس به عبارت دیگر، این شکل متأسفانه وانمود می‌کند «امن‌تر» از آنچه هست است و بنابراین باید در اساساً همهٔ شرایط اجتناب شود. اگر مقدار ویژگی می‌تواند *تابع نباشد*، بررسی کامل‌تری برای function'ness آن قبل از فراخوانی انجام دهید. وانمود نکنید `?.(` این کار را برایتان می‌کند، وگرنه خوانندگان/نگهدارندگان آیندهٔ کدتان (از جمله خود آینده‌تان!) احتمالاً پشیمان می‌شوند. |

### دسترسی به ویژگی‌ها روی غیراشیاء

ممکن است ضد شهودی به نظر برسد، اما عموماً می‌توانید به ویژگی‌ها/متدها از مقادیری که خودشان شیء نیستند دسترسی کنید:

```js
fave = 42;

fave;              // 42
fave.toString();   // "42"
```

اینجا، `fave` مقدار primitive عددی `42` نگه می‌دارد. پس چطور می‌توانیم `.toString` برای دسترسی به ویژگی از آن انجام دهیم و سپس `()` برای فراخوانی تابع نگه‌داشته‌شده در آن ویژگی؟

این موضوعی بسیار عمیق‌تر از آنچه در این کتاب می‌پردازیم است؛ کتاب ۴ «Types و Grammar» این مجموعه را برای بیشتر ببینید. با این حال، به‌عنوان نگاهی سریع: اگر دسترسی به ویژگی (`.` یا `[ .. ]`) روی مقدار non-object و non-null'ish انجام دهید، جاوااسکریپت به‌طور پیش‌فرض (موقتاً!) مقدار را به نمایش object-wrapped coerce می‌کند و دسترسی به ویژگی روی آن شیء implicitly instantiated را اجازه می‌دهد.

این فرایند معمولاً «boxing» نامیده می‌شود، یعنی قرار دادن مقدار در «جعبه» (ظرف شیء).

پس در قطعهٔ بالا، فقط برای لحظه‌ای که `.toString` روی مقدار `42` دسترسی می‌شود، جاوااسکریپت این مقدار را در شیء `Number` box می‌کند و سپس دسترسی به ویژگی را انجام می‌دهد.

توجه کنید که `null` و `undefined` را می‌توان object-ify کرد با فراخوانی `Object(null)` / `Object(undefined)`. با این حال، جاوااسکریپت این مقادیر null'ish را به‌طور خودکار box نمی‌کند، پس دسترسی به ویژگی روی آن‌ها شکست می‌خورد (همان‌طور که قبلاً در بخش «Conditional Property Access» بحث شد).

| NOTE: |
| :--- |
| Boxing همتایی دارد: unboxing. مثلاً موتور جاوااسکریپت object wrapper — مثل شیء `Number` پیچیده‌شده دور `42` — ایجادشده با `Number(42)` یا `Object(42)` را باز می‌کند تا primitive زیربنایی `42` را بازیابی کند، هر زمان عملیات ریاضی (مثل `*` یا `-`) با چنین شیئی مواجه شود. رفتار unboxing خارج از محدودهٔ بحث ماست اما به‌طور کامل در عنوان «Types و Grammar» مذکور پوشش داده شده است. |
