# تعریف ویژگی‌ها

درون آکولادهای literal شیء، ویژگی‌ها (نام و مقدار) را با جفت‌های `propertyName: propertyValue` تعریف می‌کنید، مثل این:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};
```

مقادیری که به ویژگی‌ها انتساب می‌دهید می‌توانند literal باشند، همان‌طور که نشان داده شد، یا با عبارت محاسبه شوند:

```js
function twenty() { return 20; }

myObj = {
    favoriteNumber: (twenty() + 1) * 2,
};
```

عبارت `(twenty() + 1) * 2` بلافاصله ارزیابی می‌شود و نتیجه (`42`) به‌عنوان مقدار ویژگی انتساب داده می‌شود.

توسعه‌دهندگان گاهی می‌پرسند آیا راهی برای تعریف عبارت برای مقدار ویژگی وجود دارد که عبارت «lazy» باشد، یعنی در زمان انتساب محاسبه نشود بلکه بعداً تعریف شود. جاوااسکریپت عبارت lazy ندارد، پس تنها راه این است که عبارت در یک تابع پیچیده شود:

```js
function twenty() { return 20; }
function myNumber() { return (twenty() + 1) * 2; }

myObj = {
    favoriteNumber: myNumber   // توجه کنید، نه `myNumber()` به‌عنوان فراخوانی تابع
};
```

در این حالت، `favoriteNumber` مقدار عددی نگه نمی‌دارد، بلکه ارجاع به تابع نگه می‌دارد. برای محاسبهٔ نتیجه، آن ارجاع تابع باید صریحاً اجرا شود.

### شبیه JSON؟

ممکن است متوجه شوید که نحو literal شیء که تاکنون دیده‌ایم شبیه نحو مرتبط «JSON» (JavaScript Object Notation) است:

```json
{
    "favoriteNumber": 42,
    "isDeveloper": true,
    "firstName": "Kyle"
}
```

بزرگ‌ترین تفاوت‌های بین literalهای شیء جاوااسکریپت و JSON این است که برای اشیاء تعریف‌شده به‌عنوان JSON:

1. نام ویژگی‌ها باید با کاراکترهای `"` دوبل‌کوتیشن در گیومه قرار گیرند

2. مقادیر ویژگی‌ها باید literal باشند (یا primitive، یا شیء، یا آرایه)، نه عبارت‌های دلخواه جاوااسکریپت

در برنامه‌های جاوااسکریپت، literal شیء نیازی به نام‌های ویژگی در گیومه ندارد — *می‌توانید* آن‌ها را در گیومه بگذارید (`'` یا `"` مجاز است)، اما معمولاً اختیاری است. با این حال کاراکترهایی هستند که در نام ویژگی معتبرند اما بدون گیومهٔ اطراف نمی‌توان آن‌ها را قرار داد؛ مثلاً اعداد ابتدایی یا فاصلهٔ خالی:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle",
    "2 nicknames": [ "getify", "ydkjs" ]
};
```

یک تفاوت جزئی دیگر این است که نحو JSON — یعنی متنی که *به‌عنوان* JSON parse می‌شود، مثل از فایل `.json` — سخت‌گیرتر از جاوااسکریپت عمومی است. مثلاً جاوااسکریپت کامنت‌ها (`// ..` و `/* .. */`) و ویرگول‌های trailing در عبارت‌های شیء و آرایه را مجاز می‌داند؛ JSON هیچ‌کدام از این‌ها را مجاز نمی‌داند. خوشبختانه JSON هنوز فاصلهٔ خالی دلخواه را مجاز می‌داند.

### نام‌های ویژگی

نام‌های ویژگی در literalهای شیء تقریباً همیشه به‌عنوان مقادیر رشته treat/coerce می‌شوند. یک استثنا برای «نام‌های» ویژگی عدد صحیح (یا «شبیه عدد صحیح») است:

```js
anotherObj = {
    42:       "<-- این نام ویژگی به‌عنوان عدد صحیح treat می‌شود",
    "41":     "<-- ...و این یکی هم",

    true:     "<-- این نام ویژگی به‌عنوان رشته treat می‌شود",
    [myObj]:  "<-- ...و این یکی هم"
};
```

نام ویژگی `42` به‌عنوان نام ویژگی عدد صحیح (یعنی index) treat می‌شود؛ مقدار رشتهٔ `"41"` هم به همین شکل treat می‌شود چون *شبیه* عدد صحیح است. در مقابل، مقدار `true` به نام ویژگی رشتهٔ `"true"` تبدیل می‌شود و ارجاع شناسهٔ `myObj` که با `[ .. ]` اطرافش *محاسبه* می‌شود، مقدار شیء را به رشته coerce می‌کند (معمولاً پیش‌فرض `"[object Object]"`).

| WARNING: |
| :--- |
| اگر واقعاً نیاز دارید از شیء به‌عنوان کلید/نام ویژگی استفاده کنید، هرگز به این coercion رشتهٔ محاسبه‌شده تکیه نکنید؛ رفتارش غافل‌گیرکننده است و تقریباً مطمئناً آنچه انتظار دارید نیست، پس احتمال باگ برنامه بالاست. در عوض از ساختار دادهٔ تخصصی‌تر به نام `Map` (اضافه‌شده در ES6) استفاده کنید که اشیاء استفاده‌شده به‌عنوان «نام» ویژگی بدون تغییر باقی می‌مانند به‌جای coercion به مقدار رشته. |

همان‌طور که با `[myObj]` بالا، می‌توانید هر **نام ویژگی** را (متمایز از محاسبهٔ مقدار ویژگی) در زمان تعریف literal شیء *محاسبه* کنید:

```js
anotherObj = {
    ["x" + (21 * 2)]: true
};
```

عبارت `"x" + (21 * 2)` که باید داخل براکت‌های `[ .. ]` ظاهر شود بلافاصله محاسبه می‌شود و نتیجه (`"x42"`) به‌عنوان نام ویژگی استفاده می‌شود.

### Symbolها به‌عنوان نام ویژگی

ES6 نوع مقدار primitive جدیدی به نام `Symbol` اضافه کرد که اغلب به‌عنوان نام ویژگی خاص برای ذخیره و بازیابی مقادیر ویژگی استفاده می‌شود. آن‌ها با فراخوانی تابع `Symbol(..)` (**بدون** کلمهٔ کلیدی `new`) ایجاد می‌شوند که رشتهٔ توضیح اختیاری فقط برای اهداف دیباگ دوستانه‌تر می‌پذیرد؛ اگر مشخص شود، توضیح برای برنامهٔ جاوااسکریپت غیرقابل دسترسی است و بنابراین برای هیچ هدف دیگری جز خروجی دیباگ استفاده نمی‌شود.

```js
myPropSymbol = Symbol("optional, developer-friendly description");
```

| NOTE: |
| :--- |
| Symbolها شبیه اعداد یا رشته‌ها هستند، با این تفاوت که مقدارشان برای برنامهٔ جاوااسکریپت *opaque* و در آن به‌طور سراسری یکتا است. به عبارت دیگر، می‌توانید Symbolها را ایجاد و استفاده کنید، اما جاوااسکریپت اجازه نمی‌دهد چیزی دربارهٔ مقدار زیربنایی بدانید یا کاری با آن بکنید؛ آن به‌عنوان جزئیات پیاده‌سازی مخفی توسط موتور جاوااسکریپت نگه داشته می‌شود. |

نام‌های ویژگی محاسبه‌شده، همان‌طور که قبلاً توضیح داده شد، نحوهٔ تعریف نام ویژگی Symbol روی literal شیء هستند:

```js
myPropSymbol = Symbol("optional, developer-friendly description");

anotherObj = {
    [myPropSymbol]: "Hello, symbol!"
};
```

نام ویژگی محاسبه‌شده برای تعریف ویژگی روی `anotherObj` مقدار primitive واقعی Symbol (هرچه باشد) خواهد بود، نه رشتهٔ توضیح اختیاری (`"optional, developer-friendly description"`).

چون Symbolها در برنامهٔ شما به‌طور سراسری یکتا هستند، **هیچ** شانسی برای برخورد تصادفی وجود ندارد که یک بخش برنامه تصادفاً نام ویژگی مشابه بخش دیگری که سعی در تعریف/انتساب کرده تعریف کند.

Symbolها برای قلاب زدن به رفتارهای پیش‌فرض خاص اشیاء هم مفیدند و آن را با جزئیات بیشتر در «Extending the MOP» فصل بعد پوشش می‌دهیم.

### ویژگی‌های مختصر

هنگام تعریف literal شیء، رایج است از نام ویژگی استفاده کنید که با شناسهٔ موجود در scope که مقدار مورد نظرتان را نگه می‌دارد یکسان است.

```js
coolFact = "the first person convicted of speeding was going 8 mph";

anotherObj = {
    coolFact: coolFact
};
```

| NOTE: |
| :--- |
| همان می‌شد تعریف نام ویژگی در گیومه `"coolFact": coolFact`، اما توسعه‌دهندگان جاوااسکریپت به‌ندرت نام ویژگی‌ها را در گیومه می‌گذارند مگر ضرورتاً. در واقع، idiomatic است که از گیومه اجتناب کنید مگر لازم باشد، پس discouraged است آن‌ها را unnecessarily قرار دهید. |

در این وضعیت، که نام ویژگی و شناسهٔ عبارت مقدار یکسان‌اند، می‌توانید بخش نام ویژگی تعریف ویژگی را حذف کنید، به‌عنوان تعریف «concise property»:

```js
coolFact = "the first person convicted of speeding was going 8 mph";

anotherObj = {
    coolFact   // <-- میانبر ویژگی مختصر
};
```

نام ویژگی `"coolFact"` (رشته) است و مقدار انتساب‌داده‌شده به ویژگی آنچه در متغیر `coolFact` در آن لحظه است: `"the first person convicted of speeding was going 8 mph"`.

در ابتدا این میانبر راحتی ممکن است گیج‌کننده به نظر برسد. اما با آشنا شدن با این ویژگی بسیار رایج و محبوب، احتمالاً آن را برای تایپ (و خواندن!) کمتر ترجیح می‌دهید.

### متدهای مختصر

میانبر مشابه دیگر تعریف توابع/متدها در literal شیء با شکل مختصرتر است:

```js
anotherObj = {
    // ویژگی تابع استاندارد
    greet: function() { console.log("Hello!"); },

    // ویژگی تابع/متد مختصر
    greet2() { console.log("Hello, friend!"); }
};
```

در حین صحبت از ویژگی‌های متد مختصر، می‌توانیم توابع generator (ویژگی دیگر ES6) هم تعریف کنیم:

```js
anotherObj = {
    // به‌جای:
    //   greet3: function*() { yield "Hello, everyone!"; }

    // متد generator مختصر
    *greet3() { yield "Hello, everyone!"; }
};
```

و هرچند چندان رایج نیست، متدها/generatorهای مختصر حتی می‌توانند نام‌های در گیومه یا محاسبه‌شده داشته باشند:

```js
anotherObj = {
    "greet-4"() { console.log("Hello, audience!"); },

    // نام محاسبه‌شدهٔ مختصر
    [ "gr" + "eet 5" ]() { console.log("Hello, audience!"); },

    // نام generator محاسبه‌شدهٔ مختصر
    *[ "ok, greet 6".toUpperCase() ]() { yield "Hello, audience!"; }
};
```

### Object Spread

راه دیگر تعریف ویژگی‌ها در زمان ایجاد literal شیء با شکلی از نحو `...` است — از نظر فنی operator نیست، اما قطعاً شبیه یکی به نظر می‌رسد — که اغلب «object spread» نامیده می‌شود.

وقتی `...` داخل literal شیء استفاده شود، محتویات (ویژگی‌ها، یعنی جفت‌های کلید/مقدار) شیء دیگر را در شیء در حال تعریف «spread» می‌کند:

```js
anotherObj = {
    favoriteNumber: 12,

    ...myObj,   // object spread، کپی shallow از `myObj`

    greeting: "Hello!"
}
```

spread کردن ویژگی‌های `myObj` shallow است، یعنی فقط ویژگی‌های سطح بالا را از `myObj` کپی می‌کند؛ هر مقداری که آن ویژگی‌ها نگه می‌دارند صرفاً انتساب داده می‌شود. اگر هر یک از آن مقادیر ارجاع به اشیاء دیگر باشند، خود ارجاع‌ها انتساب داده می‌شوند (با کپی)، اما مقادیر شیء زیربنایی *تکرار* نمی‌شوند — پس به ارجاع‌های چندگانهٔ مشترک به همان شیء(ها) می‌رسید.

می‌توانید object spreading را مثل حلقهٔ `for` تصور کنید که از ویژگی‌ها یکی‌یکی عبور می‌کند و انتساب به سبک `=` از شیء مبدأ (`myObj`) به شیء هدف (`anotherObj`) انجام می‌دهد.

همچنین، این عملیات‌های تعریف ویژگی را «به ترتیب» از بالا به پایین literal شیء در نظر بگیرید. در قطعهٔ بالا، چون `myObj` ویژگی `favoriteNumber` دارد، object spread در نهایت انتساب `favoriteNumber: 12` از خط قبل را بازنویسی می‌کند. علاوه بر این، اگر `myObj` ویژگی `greeting` داشت که کپی می‌شد، خط بعد (`greeting: "Hello!"`) آن تعریف ویژگی را override می‌کرد.

| NOTE: |
| :--- |
| Object spread فقط ویژگی‌های *owned* (مستقیم روی شیء) که *enumerable* (مجاز به شمارش/لیست) هستند را کپی می‌کند. ویژگی را تکرار نمی‌کند — یعنی واقعاً ویژگی‌های دقیق ویژگی را mimic نمی‌کند — بلکه کپی به سبک انتساب ساده انجام می‌دهد. جزئیات بیشتر در بخش «Property Descriptors» فصل بعد. |

کاربرد رایج `...` object spread برای انجام تکرار *shallow* شیء است:

```js
myObjShallowCopy = { ...myObj };
```

به خاطر داشته باشید نمی‌توانید `...` را در مقدار شیء موجود spread کنید؛ نحو `...` object spread فقط می‌تواند داخل literal شیء `{ .. }` که شیء جدید ایجاد می‌کند ظاهر شود. برای کپی shallow مشابه اما با APIها به‌جای نحو، بخش «Object Entries» بعداً در این فصل را ببینید (با پوشش `Object.entries(..)` و `Object.fromEntries(..)`).

اما اگر می‌خواهید ویژگی‌های شیء را (به‌صورت shallow) در شیء *موجود* کپی کنید، بخش «Assigning Properties» بعداً در این فصل را ببینید (با پوشش `Object.assign(..)`).

### کپی عمیق شیء

همچنین، چون `...` تکرار عمیق کامل شیء انجام نمی‌دهد، object spread عموماً فقط برای تکرار اشیائی مناسب است که مقادیر سادهٔ primitive نگه می‌دارند، نه ارجاع به اشیاء دیگر.

تکرار عمیق شیء عملیاتی فوق‌العاده پیچیده و ظریف است. تکرار مقداری مثل `42` واضح و سرراست است، اما تکرار تابع (که نوع خاصی از شیء است، با ارجاع نگه داشته می‌شود) یا تکرار ارجاع شیء خارجی (نه کاملاً در جاوااسکریپت) مثل المان DOM چه معنایی دارد؟ و اگر شیء ارجاع‌های circular دارد (مثل جایی که شیء تو در تو ارجاعی به شیء اجدادی بیرونی برمی‌گرداند) چه می‌شود؟ نظرات متنوعی دربارهٔ نحوهٔ برخورد با همهٔ این corner caseها وجود دارد و بنابراین هیچ استاندارد واحدی برای تکرار عمیق شیء وجود ندارد.

برای تکرار عمیق شیء، رویکردهای استاندارد این‌ها بوده‌اند:

1. استفاده از ابزار کتابخانه که نظر خاصی دربارهٔ نحوهٔ برخورد با رفتارها/ظرایف تکرار اعلام می‌کند.

2. استفاده از ترفند round-trip `JSON.parse(JSON.stringify(..))` — این فقط درست «کار می‌کند» اگر ارجاع circular نباشد و اگر مقادیری در شیء نباشد که با JSON به‌درستی serialize نشوند (مثل توابع).

اخیراً، گزینهٔ سومی اضافه شده. این ویژگی جاوااسکریپت نیست، بلکه API همراهی است که محیط‌هایی مثل پلتفرم وب به جاوااسکریپت ارائه می‌دهند. اشیاء اکنون با `structuredClone(..)`[^structuredClone] قابل کپی عمیق هستند.

```js
myObjCopy = structuredClone(myObj);
```

الگوریتم زیربنایی این ابزار built-in از تکرار ارجاع‌های circular پشتیبانی می‌کند، و همچنین **انواع بسیار بیشتری** از مقادیر نسبت به ترفند round-trip `JSON`. با این حال، این الگوریتم هنوز محدودیت‌هایی دارد، از جمله عدم پشتیبانی از کلون کردن توابع یا المان‌های DOM.
