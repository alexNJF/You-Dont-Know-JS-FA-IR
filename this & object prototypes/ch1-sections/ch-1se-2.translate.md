# سردرگمی‌ها

به‌زودی توضیح خواهیم داد که `this` *واقعاً* چگونه کار می‌کند، اما اول باید چند تصور غلط دربارهٔ نحوهٔ *عدم* کارکردش را برطرف کنیم.

نام «this» وقتی توسعه‌دهندگان سعی می‌کنند خیلی تحت‌اللفظی به آن فکر کنند سردرگمی ایجاد می‌کند. دو معنا اغلب فرض می‌شوند، اما هر دو نادرست‌اند.

### خود تابع

اولین وسوسهٔ رایج این است که فرض کنیم `this` به خود تابع اشاره می‌کند. حداقل از نظر دستوری استنباط معقولی است.

چرا بخواهید از داخل یک تابع به خودش ارجاع دهید؟ رایج‌ترین دلایل چیزهایی مثل بازگشت (فراخوانی تابع از داخل خودش) یا داشتن یک event handler که بتواند در اولین فراخوانی خودش را unbind کند هستند.

توسعه‌دهندگان تازه‌کار با مکانیزم‌های JS اغلب فکر می‌کنند که ارجاع به تابع به‌عنوان یک object (همهٔ توابع در جاوااسکریپت object هستند!) به آن‌ها اجازه می‌دهد *state* (مقادیر در propertyها) را بین فراخوانی‌های تابع ذخیره کنند. اگرچه این قطعاً ممکن است و کاربردهای محدودی دارد، بقیهٔ کتاب الگوهای زیادی برای *مکان‌های بهتر* ذخیرهٔ state علاوه بر function object شرح خواهد داد.

اما برای لحظه‌ای، آن الگو را بررسی می‌کنیم تا نشان دهیم چطور `this` به تابع اجازهٔ گرفتن ارجاع به خودش را نمی‌دهد، آن‌طور که ممکن بود فرض کنیم.

این کد را در نظر بگیرید، که سعی می‌کنیم تعداد فراخوانی‌های تابع (`foo`) را شمارش کنیم:

```js
function foo(num) {
	console.log( "foo: " + num );

	// keep track of how many times `foo` is called
	this.count++;
}

foo.count = 0;

var i;

for (i=0; i<10; i++) {
	if (i > 5) {
		foo( i );
	}
}
// foo: 6
// foo: 7
// foo: 8
// foo: 9

// how many times was `foo` called?
console.log( foo.count ); // 0 -- WTF?
```

`foo.count` *هنوز* `0` است، حتی با وجود اینکه چهار دستور `console.log` به‌وضوح نشان می‌دهند که `foo(..)` در واقع چهار بار فراخوانی شده. ناامیدی از تفسیر *خیلی تحت‌اللفظی* از معنای `this` (در `this.count++`) ناشی می‌شود.

وقتی کد `foo.count = 0` را اجرا می‌کند، در واقع propertyای به نام `count` به function object یعنی `foo` اضافه می‌کند. اما برای ارجاع `this.count` داخل تابع، `this` در واقع اصلاً به آن function object اشاره *نمی‌کند*، و بنابراین با وجود یکسان بودن نام propertyها، objectهای ریشه متفاوت‌اند و سردرگمی پیش می‌آید.

**یادداشت:** یک توسعه‌دهندهٔ مسئول *باید* در این نقطه بپرسد: «اگر من یک property به نام `count` را افزایش می‌دادم اما آنی نبود که انتظار داشتم، کدام `count` را *افزایش می‌دادم*؟» در واقع، اگر عمیق‌تر کاوش کند، می‌فهمد که به‌طور تصادفی یک متغیر سراسری `count` ساخته (برای *چگونگی* آن فصل ۲ را ببینید!) و الان مقدارش `NaN` است. البته وقتی این نتیجهٔ عجیب را شناسایی کرد، آنگاه مجموعهٔ دیگری از سؤال‌ها پیش می‌آید: «چطور سراسری شد، و چرا به‌جای یک مقدار شمارش درست به `NaN` رسید؟» (فصل ۲ را ببینید).

به‌جای توقف در این نقطه و کندوکاو در اینکه چرا ارجاع `this` *انتظار* ما را برآورده نمی‌کند و پاسخ به آن سؤال‌های سخت اما مهم، بسیاری از توسعه‌دهندگان به‌کل از موضوع دوری می‌کنند و به راه‌حل دیگری مثل ساختن object دیگری برای نگه‌داشتن propertyی `count` متوسل می‌شوند:

```js
function foo(num) {
	console.log( "foo: " + num );

	// keep track of how many times `foo` is called
	data.count++;
}

var data = {
	count: 0
};

var i;

for (i=0; i<10; i++) {
	if (i > 5) {
		foo( i );
	}
}
// foo: 6
// foo: 7
// foo: 8
// foo: 9

// how many times was `foo` called?
console.log( data.count ); // 4
```

اگرچه درست است که این رویکرد مسئله را «حل» می‌کند، متأسفانه فقط مسئلهٔ واقعی را نادیده می‌گیرد — نداشتن درک از معنای `this` و نحوهٔ کارش — و به‌جای آن به منطقهٔ امن مکانیزم آشناتر برمی‌گردد: lexical scope.

**یادداشت:** Lexical scope مکانیزمی کاملاً درست و مفید است؛ به هیچ وجه استفاده از آن را کوچک نمی‌شم (عنوان *«Scope & Closures»* این سری کتاب را ببینید). اما مدام *حدس زدن* دربارهٔ نحوهٔ استفاده از `this` و معمولاً *اشتباه بودن*، دلیل خوبی برای عقب‌نشینی به lexical scope و هرگز یاد نگرفتن *چرایی* گریز `this` از دست شما نیست.

برای ارجاع به function object از داخل خودش، خود `this` معمولاً کافی نخواهد بود. عموماً به ارجاعی به function object از طریق یک شناسهٔ واژگانی (متغیر) که به آن اشاره می‌کند نیاز دارید.

این دو تابع را در نظر بگیرید:

```js
function foo() {
	foo.count = 4; // `foo` refers to itself
}

setTimeout( function(){
	// anonymous function (no name), cannot
	// refer to itself
}, 10 );
```

در تابع اول، که «تابع نام‌دار» نامیده می‌شود، `foo` ارجاعی است که می‌توان از داخل خودش برای ارجاع به تابع استفاده کرد.

اما در مثال دوم، تابع callback پاس‌داده‌شده به `setTimeout(..)` شناسهٔ نام ندارد (به‌اصطلاح «تابع گمنام») و بنابراین راه درستی برای ارجاع به خود function object وجود ندارد.

**یادداشت:** ارجاع قدیمی اما اکنون منسوخ و ناپسند `arguments.callee` داخل یک تابع *همچنین* به function object تابع در حال اجرا اشاره می‌کند. این ارجاع معمولاً تنها راه دسترسی به object تابع گمنام از داخل خودش است. با این حال بهترین رویکرد این است که اصلاً از توابع گمنام استفاده نکنید، حداقل برای آن‌هایی که به self-reference نیاز دارند، و به‌جای آن از یک تابع نام‌دار (expression) استفاده کنید. `arguments.callee` منسوخ است و نباید استفاده شود.

پس راه‌حل دیگر برای مثال جاری ما می‌توانست استفاده از شناسهٔ `foo` به‌عنوان ارجاع به function object در هر جا باشد، و اصلاً از `this` استفاده نکنیم، که *کار می‌کند*:

```js
function foo(num) {
	console.log( "foo: " + num );

	// keep track of how many times `foo` is called
	foo.count++;
}

foo.count = 0;

var i;

for (i=0; i<10; i++) {
	if (i > 5) {
		foo( i );
	}
}
// foo: 6
// foo: 7
// foo: 8
// foo: 9

// how many times was `foo` called?
console.log( foo.count ); // 4
```

با این حال، آن رویکرد به‌طور مشابه درک *واقعی* از `this` را دور می‌زند و کاملاً به lexical scoping متغیر `foo` متکی است.

روش دیگر برای نزدیک شدن به مسئله این است که `this` را وادار کنیم در واقع به function object یعنی `foo` اشاره کند:

```js
function foo(num) {
	console.log( "foo: " + num );

	// keep track of how many times `foo` is called
	// Note: `this` IS actually `foo` now, based on
	// how `foo` is called (see below)
	this.count++;
}

foo.count = 0;

var i;

for (i=0; i<10; i++) {
	if (i > 5) {
		// using `call(..)`, we ensure the `this`
		// points at the function object (`foo`) itself
		foo.call( foo, i );
	}
}
// foo: 6
// foo: 7
// foo: 8
// foo: 9

// how many times was `foo` called?
console.log( foo.count ); // 4
```

**به‌جای دوری از `this`، آن را بپذیریم.** به‌زودی *چگونگی* کار چنین تکنیک‌هایی را کامل‌تر توضیح خواهیم داد، پس اگر هنوز کمی سردرگم هستید نگران نباشید!

### محدودهٔ آن

رایج‌ترین تصور غلط بعدی دربارهٔ معنای `this` این است که به‌نحوی به scope تابع اشاره می‌کند. سؤال حیله‌ای است، چون از یک نظر حقیقتی در کار است، اما از نظر دیگر کاملاً گمراه‌کننده است.

برای وضوح، `this` به هیچ وجه به **lexical scope** تابع اشاره *نمی‌کند*. درست است که درونی، scope به‌نوعی مثل یک object با property برای هر شناسهٔ موجود است. اما «object» scope برای کد جاوااسکریپت قابل دسترسی نیست. بخش درونی پیاده‌سازی *Engine* است.

این کد را در نظر بگیرید که سعی می‌کند (و ناموفق است!) از مرز عبور کند و از `this` برای ارجاع ضمنی به lexical scope تابع استفاده کند:

```js
function foo() {
	var a = 2;
	this.bar();
}

function bar() {
	console.log( this.a );
}

foo(); //undefined
```

بیش از یک اشتباه در این قطعه هست. هرچند ممکن است ساختگی به نظر برسد، کدی که می‌بینید خلاصهٔ کد واقعی است که در انجمن‌های کمک عمومی ردوبدل شده. تصویر خوبی (اگر غم‌انگیز نباشد) از میزان گمراه‌کنندگی فرضیات دربارهٔ `this` است.

اول، تلاشی برای ارجاع به تابع `bar()` از طریق `this.bar()` شده. تقریباً قطعاً *اتفاقی* است که کار می‌کند، اما به‌زودی *چگونگی* آن را توضیح خواهیم داد. طبیعی‌ترین راه فراخوانی `bar()` حذف `this.` جلو و فقط ارجاع واژگانی به شناسه بود.

با این حال، توسعه‌دهنده‌ای که چنین کدی می‌نویسد سعی دارد از `this` برای ایجاد پلی بین lexical scopeهای `foo()` و `bar()` استفاده کند تا `bar()` به متغیر `a` در scope درونی `foo()` دسترسی داشته باشد. **چنین پلی ممکن نیست.** نمی‌توانید از ارجاع `this` برای جستجو در یک lexical scope استفاده کنید. ممکن نیست.

هر بار که احساس کردید دارید جستجوهای lexical scope را با `this` مخلوط می‌کنید، به خود یادآوری کنید: *هیچ پلی وجود ندارد*.
