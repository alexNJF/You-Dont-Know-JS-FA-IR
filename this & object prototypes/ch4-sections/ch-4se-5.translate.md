# خلاصه (TL;DR)

Classها یک الگوی طراحی‌اند. بسیاری زبان‌ها نحو فراهم می‌کنند که طراحی نرم‌افزار طبیعی مبتنی بر class را ممکن می‌کند. JS هم نحو مشابهی دارد، اما **خیلی متفاوت** از آنچه با classها در آن زبان‌های دیگر عادت دارید رفتار می‌کند.

**Class یعنی کپی.**

وقتی classهای سنتی instantiate می‌شوند، کپی رفتار از class به instance اتفاق می‌افتد. وقتی classها به ارث برده می‌شوند، کپی رفتار از والد به فرزند هم اتفاق می‌افتد.

Polymorphism (داشتن توابع متفاوت در چند سطح زنجیرهٔ inheritance با همان نام) ممکن است به نظر برسد دلالت بر لینک ارجاعی نسبی از فرزند به والد دارد، اما هنوز فقط نتیجهٔ رفتار کپی است.

جاوااسکریپت **به‌طور خودکار** کپی (آن‌طور که classها دلالت می‌کنند) بین objectها ایجاد **نمی‌کند**.

الگوی mixin (هم explicit و هم implicit) اغلب برای *نوعی* شبیه‌سازی رفتار کپی class استفاده می‌شود، اما این معمولاً به نحو زشت و شکننده مثل explicit pseudo-polymorphism (`OtherObj.methodName.call(this, ...)`) منجر می‌شود که اغلب به کد سخت‌تر برای فهم و نگهداری می‌انجامد.

Explicit mixinها همچنین دقیقاً مثل *کپی* class نیستند، چون objectها (و توابع!) فقط referenceهای مشترک تکرارشده دارند، نه خود objectها/توابع تکرارشده. توجه نکردن به چنین ظرافتی منبع انواع gotchaهاست.

به‌طور کلی، جعل class در JS اغلب مین‌های بیشتری برای کدنویسی آینده می‌گذارد تا حل مسئله‌های *واقعی* فعلی.
