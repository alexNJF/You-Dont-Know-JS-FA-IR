# `[[Prototype]]`

Objectها در جاوااسکریپت یک property داخلی دارند که در مشخصات با `[[Prototype]]` نشان داده می‌شود و به‌سادگی ارجاعی به object دیگر است. تقریباً همهٔ objectها در زمان ساخت برای این property مقدار غیر-`null` می‌گیرند.

**یادداشت:** به‌زودی می‌بینیم *ممکن* است object لینک `[[Prototype]]` خالی داشته باشد، هرچند تا حدی کمتر رایج است.

در نظر بگیرید:

```js
var myObject = {
	a: 2
};

myObject.a; // 2
```

ارجاع `[[Prototype]]` برای چه استفاده می‌شود؟ در فصل ۳ عملیات `[[Get]]` را که وقتی به property روی object مثل `myObject.a` ارجاع می‌دهید فراخوانی می‌شود بررسی کردیم. برای آن عملیات پیش‌فرض `[[Get]]`، اولین قدم بررسی این است که آیا خود object property یعنی `a` رویش دارد، و اگر بله استفاده می‌شود.

**یادداشت:** ES6 Proxies خارج از محدودهٔ بحث ما در این کتاب است (در کتاب بعدی سری پوشش داده می‌شود!)، اما همهٔ آنچه اینجا دربارهٔ رفتار معمول `[[Get]]` و `[[Put]]` می‌گوییم اگر `Proxy` در کار باشد اعمال نمی‌شود.

اما آنچه اگر `a` **روی** `myObject` **نباشد** اتفاق می‌افتد توجه ما را اکنون به لینک `[[Prototype]]` object جلب می‌کند.

عملیات پیش‌فرض `[[Get]]` اگر نتواند property درخواستی را مستقیماً روی object پیدا کند به دنبال **لینک** `[[Prototype]]` object می‌رود.

```js
var anotherObject = {
	a: 2
};

// create an object linked to `anotherObject`
var myObject = Object.create( anotherObject );

myObject.a; // 2
```

**یادداشت:** به‌زودی توضیح می‌دهیم `Object.create(..)` چه می‌کند و چطور عمل می‌کند. فعلاً فرض کنید objectی با لینک `[[Prototype]]` که بررسی می‌کنیم به object مشخص‌شده می‌سازد.

پس `myObject` داریم که اکنون به `anotherObject` با `[[Prototype]]` لینک است. واضح است `myObject.a` واقعاً وجود ندارد، اما با این حال دسترسی property موفق است (به‌جای آن روی `anotherObject` پیدا می‌شود) و در واقع مقدار `2` را پیدا می‌کند.

اما اگر `a` روی `anotherObject` هم پیدا نمی‌شد، زنجیرهٔ `[[Prototype]]` آن، اگر غیرخالی باشد، دوباره مشورت و دنبال می‌شد.

این فرایند تا وقتی ادامه می‌یابد که یا نام property منطبق پیدا شود، یا زنجیرهٔ `[[Prototype]]` تمام شود. اگر تا انتهای زنجیره هیچ property منطبقی *هرگز* پیدا نشود، نتیجهٔ برگشتی عملیات `[[Get]]` برابر `undefined` است.

مشابه این فرایند جستجوی زنجیرهٔ `[[Prototype]]`، اگر از حلقهٔ `for..in` برای تکرار روی object استفاده کنید، هر property که از طریق زنجیره قابل دسترسی باشد (و همچنین `enumerable` باشد — فصل ۳ را ببینید) شمارش می‌شود. اگر از عملگر `in` برای تست وجود property روی object استفاده کنید، `in` کل زنجیرهٔ object را بررسی می‌کند (صرف‌نظر از *enumerability*).

```js
var anotherObject = {
	a: 2
};

// create an object linked to `anotherObject`
var myObject = Object.create( anotherObject );

for (var k in myObject) {
	console.log("found: " + k);
}
// found: a

("a" in myObject); // true
```

پس زنجیرهٔ `[[Prototype]]` به‌صورت یک لینک در هر زمان وقتی جستجوی property را به روش‌های مختلف انجام می‌دهید مشورت می‌شود. جستجو وقتی property پیدا شد یا زنجیره تمام شد متوقف می‌شود.

### `Object.prototype`

اما زنجیرهٔ `[[Prototype]]` دقیقاً *کجا* «تمام» می‌شود؟

انتهای بالای هر زنجیرهٔ `[[Prototype]]` *معمولی* built-in یعنی `Object.prototype` است. این object انواع ابزارهای مشترک استفاده‌شده در سراسر JS را شامل می‌شود، چون همهٔ objectهای معمولی (built-in، نه افزونهٔ خاص میزبان) در جاوااسکریپت «از» (به‌اصطلاح در بالای زنجیرهٔ `[[Prototype]]` خود دارند) object یعنی `Object.prototype` نزول می‌کنند.

بعضی ابزارهای اینجا که ممکن است با آن‌ها آشنا باشید شامل `.toString()` و `.valueOf()` هستند. در فصل ۳ یکی دیگر معرفی کردیم: `.hasOwnProperty(..)`. و تابع دیگر روی `Object.prototype` که ممکن است آشنا نباشید اما بعداً در این فصل به آن می‌پردازیم `.isPrototypeOf(..)` است.

### تنظیم و Shadowing کردن Propertyها

برگردیم به فصل ۳، گفتیم set کردن property روی object ظریف‌تر از فقط اضافه کردن property جدید به object یا تغییر مقدار property موجود بود. اکنون این وضعیت را کامل‌تر بازمی‌بینیم.

```js
myObject.foo = "bar";
```

اگر object یعنی `myObject` از قبل property دسترسی دادهٔ معمولی به نام `foo` مستقیماً رویش دارد، انتساب به‌سادگی تغییر مقدار property موجود است.

اگر `foo` از قبل مستقیماً روی `myObject` نباشد، زنجیرهٔ `[[Prototype]]` پیمایش می‌شود، درست مثل عملیات `[[Get]]`. اگر `foo` در هیچ جای زنجیره پیدا نشود، property یعنی `foo` با مقدار مشخص‌شده مستقیماً به `myObject` اضافه می‌شود، همان‌طور که انتظار می‌رود.

با این حال، اگر `foo` از قبل جایی بالاتر در زنجیره حاضر باشد، رفتار ظریف (و شاید غیرمنتظره) با انتساب `myObject.foo = "bar"` می‌تواند اتفاق بیفتد. به‌زودی آن را بیشتر بررسی می‌کنیم.

اگر نام property یعنی `foo` هم روی خود `myObject` و هم در سطح بالاتر زنجیرهٔ `[[Prototype]]` که از `myObject` شروع می‌شود تمام شود، *shadowing* نامیده می‌شود. property یعنی `foo` مستقیماً روی `myObject` هر property یعنی `foo` که بالاتر در زنجیره ظاهر می‌شود را *shadow* می‌کند، چون جستجوی `myObject.foo` همیشه property یعنی `foo` که پایین‌ترین در زنجیره است را پیدا می‌کند.

همان‌طور که اشاره کردیم، shadow کردن `foo` روی `myObject` آن‌قدرها که به نظر می‌رسد ساده نیست. اکنون سه سناریو برای انتساب `myObject.foo = "bar"` وقتی `foo` **مستقیماً** روی `myObject` نیست اما **در** سطح بالاتر زنجیرهٔ `[[Prototype]]` یعنی `myObject` **هست** بررسی می‌کنیم:

1. اگر property دسترسی‌دهندهٔ دادهٔ معمولی (فصل ۳ را ببینید) به نام `foo` در هر جای بالاتر زنجیرهٔ `[[Prototype]]` پیدا شود، **و به‌عنوان فقط-خواندنی علامت‌گذاری نشده (`writable:false`)** آنگاه property جدیدی به نام `foo` مستقیماً به `myObject` اضافه می‌شود و به **property سایه‌انداخته‌شده** منجر می‌شود.
2. اگر `foo` بالاتر در زنجیرهٔ `[[Prototype]]` پیدا شود اما **فقط-خواندنی (`writable:false`) علامت‌گذاری شده**، هم set کردن آن property موجود و هم ساخت property سایه‌انداخته‌شده روی `myObject` **ممنوع‌اند**. اگر کد در `strict mode` اجرا شود، error پرتاب می‌شود. وگرنه set کردن مقدار property بی‌سر و صدا نادیده گرفته می‌شود. در هر صورت **shadowing اتفاق نمی‌افتد**.
3. اگر `foo` بالاتر در زنجیرهٔ `[[Prototype]]` پیدا شود و setter باشد (فصل ۳ را ببینید)، setter همیشه فراخوانی می‌شود. هیچ `foo` به (به‌اصطلاح shadow روی) `myObject` اضافه نمی‌شود، و setter یعنی `foo` هم بازتعریف نمی‌شود.

بیشتر توسعه‌دهندگان فرض می‌کنند انتساب property (`[[Put]]`) همیشه اگر property از قبل بالاتر در زنجیرهٔ `[[Prototype]]` وجود داشته باشد به shadowing منجر می‌شود، اما همان‌طور که می‌بینید فقط در یکی (#۱) از سه وضعیت توصیف‌شده درست است.

اگر می‌خواهید در موارد #۲ و #۳ `foo` را shadow کنید، نمی‌توانید از انتساب `=` استفاده کنید، بلکه باید از `Object.defineProperty(..)` (فصل ۳ را ببینید) برای اضافه کردن `foo` به `myObject` استفاده کنید.

**یادداشت:** مورد #۲ ممکن است غیرمنتظره‌ترین از سه تای باشد. وجود property *فقط-خواندنی* از ساخت ضمنی (shadow) property هم‌نام در سطح پایین‌تر زنجیرهٔ `[[Prototype]]` جلوگیری می‌کند. دلیل این محدودیت عمدتاً تقویت توهم propertyهای به‌ارث‌بردهٔ class است. اگر `foo` در سطح بالاتر زنجیره را به‌عنوان به‌ارث‌برده (کپی‌شده به پایین) به `myObject` در نظر بگیرید، پس اعمال طبیعت غیرقابل‌نوشتن آن property یعنی `foo` روی `myObject` معقول است. اما اگر توهم را از واقعیت جدا کنید و تشخیص دهید که چنین کپی inheritance *واقعاً* اتفاق نیفتاده (فصل‌های ۴ و ۵ را ببینید)، کمی غیرطبیعی است که `myObject` فقط به‌خاطر داشتن `foo` غیرقابل‌نوشتن روی object دیگر از داشتن property یعنی `foo` منع شود. حتی عجیب‌تر اینکه این محدودیت فقط به انتساب `=` اعمال می‌شود اما هنگام استفاده از `Object.defineProperty(..)` اعمال نمی‌شود.

Shadowing با **method**ها به *explicit pseudo-polymorphism* زشت منجر می‌شود (فصل ۴ را ببینید) اگر بین آن‌ها نیاز به delegation داشته باشید. معمولاً shadowing پیچیده‌تر و ظریف‌تر از ارزشش است، **پس در صورت امکان سعی کنید از آن اجتناب کنید**. فصل ۶ را برای الگوی طراحی جایگزین ببینید که among other things shadowing را به نفع جایگزین‌های تمیزتر منع می‌کند.

Shadowing حتی می‌تواند به‌طور ضمنی به روش‌های ظریف اتفاق بیفتد، پس اگر می‌خواهید از آن اجتناب کنید باید مراقب باشید. در نظر بگیرید:

```js
var anotherObject = {
	a: 2
};

var myObject = Object.create( anotherObject );

anotherObject.a; // 2
myObject.a; // 2

anotherObject.hasOwnProperty( "a" ); // true
myObject.hasOwnProperty( "a" ); // false

myObject.a++; // oops, implicit shadowing!

anotherObject.a; // 2
myObject.a; // 3

myObject.hasOwnProperty( "a" ); // true
```

هرچند ممکن است به نظر برسد `myObject.a++` باید (از طریق delegation) property یعنی `anotherObject.a` را *در جا* جستجو و فقط افزایش دهد، به‌جای آن عملیات `++` معادل `myObject.a = myObject.a + 1` است. نتیجه این است که `[[Get]]` property یعنی `a` را از طریق `[[Prototype]]` جستجو می‌کند تا مقدار فعلی `2` را از `anotherObject.a` بگیرد، مقدار را یکی افزایش می‌دهد، سپس `[[Put]]` مقدار `3` را به property سایه‌انداخته‌شدهٔ جدید یعنی `a` روی `myObject` انتساب می‌دهد. اوه!

وقتی با propertyهای delegate‌شده‌ای که تغییر می‌دهید سروکار دارید خیلی مراقب باشید. اگر می‌خواستید `anotherObject.a` را افزایش دهید، تنها راه درست `anotherObject.a++` است.
