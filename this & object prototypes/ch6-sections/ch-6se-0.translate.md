# شما جاوااسکریپت را نمی‌دانید: this و Object Prototypes - ویرایش اول
# تفویض رفتار (Behavior Delegation)

در فصل ۵ مکانیزم `[[Prototype]]` را به‌تفصیل بررسی کردیم و *چرا* گیج‌کننده و نامناسب است (علیرغم تلاش‌های بی‌شمار برای نزدیک به دو دهه) که آن را «class» یا «inheritance» توصیف کنیم. نه فقط نحو نسبتاً طولانی (`.prototype` پراکنده در کد) بلکه انواع gotchaها (مثل resolve غافل‌گیرکنندهٔ `.constructor` یا نحو pseudo-polymorphic زشت) را پیمودیم. گونه‌های رویکرد «mixin» را کاوش کردیم که بسیاری برای تلاش هموار کردن چنین نواحی خشن استفاده می‌کنند.

واکنش رایج در این نقطه این است که بپرسیم چرا باید برای کاری به‌ظاهر این‌قدر ساده این‌قدر پیچیده باشد. حالا که پرده را کنار زدیم و دیدیم چقدر کثیف می‌شود، تعجبی نیست که بیشتر توسعه‌دهندگان JS هرگز این عمق را نمی‌روند و به‌جای آن چنین آشفتگی را به کتابخانهٔ «class» واگذار می‌کنند تا برایشان handle کند.

امیدوارم تا الان راضی نباشید فقط از کنار این جزئیات بگذرید و آن‌ها را به کتابخانهٔ «جعبه سیاه» بسپارید. بیایید حالا بکاویم چطور *می‌توان و باید* به مکانیزم object یعنی `[[Prototype]]` در JS فکر کرد، به **روشی بسیار ساده‌تر و مستقیم‌تر** از سردرگمی classها.

به‌عنوان مرور کوتاه نتیجه‌گیری‌هایمان از فصل ۵، مکانیزم `[[Prototype]]` لینک داخلی است که روی یک object وجود دارد و به object دیگری ارجاع می‌دهد.

این لینک وقتی اعمال می‌شود که علیه object اول ارجاع property/method ساخته شود و چنین property/methodی وجود نداشته باشد. در آن صورت لینک `[[Prototype]]` به engine می‌گوید property/method را روی object لینک‌شده جستجو کند. به‌نوبهٔ خود، اگر آن object نتواند جستجو را برآورده کند، `[[Prototype]]` آن دنبال می‌شود و همین‌طور. این سری لینک‌ها بین objectها چیزی به نام «prototype chain» را تشکیل می‌دهد.

به عبارت دیگر، مکانیزم واقعی، ذات آنچه برای قابلیتی که می‌توانیم در جاوااسکریپت بهره بگیریم مهم است، **همه دربارهٔ objectهایی است که به objectهای دیگر لینک شده‌اند.**

آن مشاهدهٔ واحد بنیادی و حیاتی برای فهم انگیزه‌ها و رویکردهای بقیهٔ این فصل است!
