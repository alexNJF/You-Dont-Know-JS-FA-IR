# نوع

Objectها بلوک ساختمانی کلی‌اند که بخش زیادی از JS روی آن‌ها ساخته شده. آن‌ها یکی از ۶ نوع اصلی (که در مشخصات «زبان‌گونه» نامیده می‌شوند) در JS هستند:

* `string`
* `number`
* `boolean`
* `null`
* `undefined`
* `object`

توجه کنید که *primitiveهای ساده* (`string`، `number`، `boolean`، `null` و `undefined`) **خودشان** `object` **نیستند**. `null` گاهی نوع object نامیده می‌شود، اما این تصور غلط از یک باگ در زبان ناشی می‌شود که باعث می‌شود `typeof null` رشتهٔ `"object"` را به‌اشتباه (و گیج‌کننده) برگرداند. در واقع، `null` نوع اولیهٔ خودش است.

**ادعای رایج اما نادرست این است که «همه‌چیز در جاوااسکریپت یک object است». این به‌وضوح درست نیست.**

در مقابل، *چند* زیرنوع object خاص وجود دارد که می‌توانیم آن‌ها را *primitiveهای پیچیده* بنامیم.

`function` زیرنوعی از object است (از نظر فنی، یک «object قابل فراخوانی»). گفته می‌شود توابع در JS «درجهٔ اول» هستند چون اساساً فقط objectهای معمولی‌اند (با معناشناسی رفتار قابل فراخوانی روی آن‌ها)، و بنابراین مثل هر object سادهٔ دیگر قابل برخورد هستند.

آرایه‌ها هم شکلی از objectها هستند، با رفتار اضافی. سازماندهی محتوا در آرایه‌ها کمی ساختاریافته‌تر از objectهای کلی است.

### Built-in Objectها

چند زیرنوع object دیگر وجود دارد، که معمولاً built-in object نامیده می‌شوند. برای بعضی از آن‌ها، نام‌شان به نظر می‌رساند مستقیماً به همتای primitive ساده مربوط‌اند، اما در واقع رابطهٔ آن‌ها پیچیده‌تر است، که به‌زودی بررسی می‌کنیم.

* `String`
* `Number`
* `Boolean`
* `Object`
* `Function`
* `Array`
* `Date`
* `RegExp`
* `Error`

این built-inها ظاهر نوع واقعی، حتی class، را دارند اگر به شباهت با زبان‌های دیگر مثل class یعنی `String` در جاوا تکیه کنید.

اما در JS، این‌ها در واقع فقط توابع داخلی‌اند. هر یک از این توابع داخلی می‌تواند به‌عنوان constructor استفاده شود (یعنی فراخوانی تابع با عملگر `new` — فصل ۲ را ببینید)، با نتیجهٔ object *ساخته‌شده*ٔ جدید از زیرنوع مورد نظر. مثلاً:

```js
var strPrimitive = "I am a string";
typeof strPrimitive;							// "string"
strPrimitive instanceof String;					// false

var strObject = new String( "I am a string" );
typeof strObject; 								// "object"
strObject instanceof String;					// true

// inspect the object sub-type
Object.prototype.toString.call( strObject );	// [object String]
```

در فصل بعدی به‌تفصیل خواهیم دید که بخش `Object.prototype.toString...` دقیقاً چطور کار می‌کند، اما به‌طور خلاصه می‌توانیم زیرنوع داخلی را با قرض گرفتن متد پیش‌فرض پایهٔ `toString()` بررسی کنیم، و می‌بینید که نشان می‌دهد `strObject` objectی است که در واقع توسط constructor یعنی `String` ساخته شده.

مقدار اولیهٔ `"I am a string"` object نیست، یک literal اولیه و مقدار تغییرناپذیر است. برای انجام عملیات روی آن، مثل بررسی طولش، دسترسی به محتوای کاراکترهای تکی و غیره، به object یعنی `String` نیاز است.

خوشبختانه، زبان وقتی لازم باشد به‌طور خودکار primitive یعنی `"string"` را به object یعنی `String` coerce می‌کند، یعنی تقریباً هرگز نیازی به ساختن صریح شکل Object نیست. **ترجیح قوی** اکثریت جامعهٔ JS استفاده از شکل literal برای مقدار است، در صورت امکان، به‌جای شکل object ساخته‌شده.

در نظر بگیرید:

```js
var strPrimitive = "I am a string";

console.log( strPrimitive.length );			// 13

console.log( strPrimitive.charAt( 3 ) );	// "m"
```

در هر دو مورد، property یا متدی روی primitive رشته فراخوانی می‌کنیم و engine به‌طور خودکار آن را به object یعنی `String` coerce می‌کند تا دسترسی به property/متد کار کند.

همین نوع coercion بین primitive یعنی literal عددی `42` و object wrapper یعنی `new Number(42)` اتفاق می‌افتد، وقتی از متدهایی مثل `42.359.toFixed(2)` استفاده می‌کنید. همین‌طور برای objectهای `Boolean` از primitiveهای `"boolean"`.

`null` و `undefined` شکل object wrapper ندارند، فقط مقادیر اولیهٔ خودشان. در مقابل، مقادیر `Date` *فقط* با شکل object ساخته‌شدهٔ خودشان قابل ساخت‌اند، چون همتای شکل literal ندارند.

`Object`ها، `Array`ها، `Function`ها و `RegExp`ها (عبارت‌های منظم) همگی object هستند صرف‌نظر از استفاده از شکل literal یا ساخته‌شده. شکل ساخته‌شده در بعضی موارد گزینه‌های بیشتری در ساخت نسبت به همتای شکل literal ارائه می‌دهد. چون objectها به هر دو صورت ساخته می‌شوند، شکل literal ساده‌تر تقریباً به‌طور جهانی ترجیح داده می‌شود. **فقط در صورت نیاز به گزینه‌های اضافی از شکل ساخته‌شده استفاده کنید.**

objectهای `Error` به‌ندرت صریحاً در کد ساخته می‌شوند، اما معمولاً وقتی exception پرتاب می‌شود به‌طور خودکار ساخته می‌شوند. می‌توان با شکل ساخته‌شدهٔ `new Error(..)` ساخت، اما اغلب لازم نیست.
