# تکرار

حلقهٔ `for..in` روی فهرست propertyهای enumerable روی object (شامل زنجیرهٔ `[[Prototype]]` آن) تکرار می‌کند. اما اگر به‌جای آن بخواهید روی مقادیر تکرار کنید چه؟

با آرایه‌های با index عددی، تکرار روی مقادیر معمولاً با حلقهٔ استاندارد `for` انجام می‌شود، مثل:

```js
var myArray = [1, 2, 3];

for (var i = 0; i < myArray.length; i++) {
	console.log( myArray[i] );
}
// 1 2 3
```

این تکرار روی مقادیر نیست، بلکه تکرار روی indexهاست، که بعد از index برای ارجاع به مقدار استفاده می‌کنید، مثل `myArray[i]`.

ES5 چند helper تکرار برای آرایه‌ها هم اضافه کرد، از جمله `forEach(..)`، `every(..)` و `some(..)`. هر یک از این helperها تابع callback برای اعمال به هر عنصر آرایه می‌پذیرند، فقط در نحوهٔ پاسخ به مقدار برگشتی از callback فرق می‌کنند.

`forEach(..)` روی همهٔ مقادیر آرایه تکرار می‌کند و هر مقدار برگشتی callback را نادیده می‌گیرد. `every(..)` تا انتها ادامه می‌دهد *یا* callback مقدار `false` (یا «falsy») برگرداند، در حالی که `some(..)` تا انتها ادامه می‌دهد *یا* callback مقدار `true` (یا «truthy») برگرداند.

این مقادیر برگشتی خاص داخل `every(..)` و `some(..)` تا حدی مثل دستور `break` داخل حلقهٔ معمولی `for` عمل می‌کنند، چون تکرار را قبل از رسیدن به انتها زود متوقف می‌کنند.

اگر روی object با حلقهٔ `for..in` تکرار کنید، باز هم فقط به‌طور غیرمستقیم به مقادیر می‌رسید، چون در واقع فقط روی propertyهای enumerable object تکرار می‌کند و دسترسی دستی به propertyها برای گرفتن مقادیر را به شما می‌گذارد.

**یادداشت:** در مقابل تکرار روی indexهای آرایه به‌صورت مرتب عددی (حلقهٔ `for` یا iteratorهای دیگر)، ترتیب تکرار روی propertyهای object **تضمین نشده** است و ممکن است بین engineهای مختلف JS فرق کند. **به هیچ ترتیب مشاهده‌شده‌ای** برای چیزی که به سازگاری بین محیط‌ها نیاز دارد تکیه نکنید، چون هر توافق مشاهده‌شده غیرقابل اعتماد است.

اما اگر بخواهید مستقیماً روی مقادیر تکرار کنید به‌جای indexهای آرایه (یا propertyهای object) چه؟ مفیدانه، ES6 نحو حلقهٔ `for..of` برای تکرار روی آرایه‌ها (و objectها، اگر object iterator سفارشی خودش را تعریف کند) اضافه می‌کند:

```js
var myArray = [ 1, 2, 3 ];

for (var v of myArray) {
	console.log( v );
}
// 1
// 2
// 3
```

حلقهٔ `for..of` یک iterator object درخواست می‌کند (از تابع داخلی پیش‌فرض معروف به `@@iterator` در اصطلاح مشخصات) از *چیز* قابل تکرار، و حلقه سپس روی مقادیر برگشتی متوالی از فراخوانی متد `next()` آن iterator object تکرار می‌کند، یک بار برای هر تکرار حلقه.

آرایه‌ها `@@iterator` داخلی دارند، پس `for..of` به‌راحتی روی آن‌ها کار می‌کند، همان‌طور که نشان داده شد. اما بیایید آرایه را دستی با `@@iterator` داخلی تکرار کنیم تا ببینیم چطور کار می‌کند:

```js
var myArray = [ 1, 2, 3 ];
var it = myArray[Symbol.iterator]();

it.next(); // { value:1, done:false }
it.next(); // { value:2, done:false }
it.next(); // { value:3, done:false }
it.next(); // { done:true }
```

**یادداشت:** به *internal property* یعنی `@@iterator` یک object با `Symbol` ES6 دسترسی پیدا می‌کنیم: `Symbol.iterator`. قبلاً در فصل معناشناسی `Symbol` را به‌طور خلاصه ذکر کردیم (بخش «Computed Property Names» را ببینید)، پس همان استدلال اینجا اعمال می‌شود. همیشه می‌خواهید چنین propertyهای خاص را با ارجاع نام `Symbol` ارجاع دهید نه با مقدار خاصی که ممکن است نگه دارد. همچنین، با وجود دلالت نام، `@@iterator` **خود iterator object نیست**، بلکه **تابعی است که** iterator object را برمی‌گرداند — جزئی ظریف اما مهم!

همان‌طور که قطعهٔ بالا نشان می‌دهد، مقدار برگشتی از فراخوانی `next()` یک iterator به شکل `{ value: .. , done: .. }` است، که `value` مقدار تکرار فعلی و `done` یک `boolean` است که نشان می‌دهد آیا چیز بیشتری برای تکرار هست.

توجه کنید مقدار `3` با `done:false` برگشت، که در نگاه اول عجیب به نظر می‌رسد. باید `next()` را بار چهارم فراخوانی کنید (که حلقهٔ `for..of` در قطعهٔ قبل به‌طور خودکار انجام می‌دهد) تا `done:true` بگیرید و بدانید واقعاً تکرار تمام شده. دلیل این عجیب‌بودن خارج از محدودهٔ بحث ماست، اما از معناشناسی توابع generator ES6 می‌آید.

در حالی که آرایه‌ها در حلقه‌های `for..of` به‌طور خودکار تکرار می‌شوند، objectهای معمولی **`@@iterator` داخلی ندارند**. دلایل این حذف عمدی پیچیده‌تر از آن است که اینجا بررسی کنیم، اما به‌طور کلی بهتر بود پیاده‌سازیی که می‌توانست برای انواع آیندهٔ objectها مشکل‌ساز باشد شامل نشود.

*ممکن* است `@@iterator` پیش‌فرض خودتان را برای هر objectی که می‌خواهید روی آن تکرار کنید تعریف کنید. مثلاً:

```js
var myObject = {
	a: 2,
	b: 3
};

Object.defineProperty( myObject, Symbol.iterator, {
	enumerable: false,
	writable: false,
	configurable: true,
	value: function() {
		var o = this;
		var idx = 0;
		var ks = Object.keys( o );
		return {
			next: function() {
				return {
					value: o[ks[idx++]],
					done: (idx > ks.length)
				};
			}
		};
	}
} );

// iterate `myObject` manually
var it = myObject[Symbol.iterator]();
it.next(); // { value:2, done:false }
it.next(); // { value:3, done:false }
it.next(); // { value:undefined, done:true }

// iterate `myObject` with `for..of`
for (var v of myObject) {
	console.log( v );
}
// 2
// 3
```

**یادداشت:** از `Object.defineProperty(..)` برای تعریف `@@iterator` سفارشی خود استفاده کردیم (اغلب تا بتوانیم آن را non-enumerable کنیم)، اما با استفاده از `Symbol` به‌عنوان *computed property name* (قبلاً در این فصل پوشش داده شد)، می‌توانستیم مستقیم اعلان کنیم، مثل `var myObject = { a:2, b:3, [Symbol.iterator]: function(){ /* .. */ } }`.

هر بار حلقهٔ `for..of` متد `next()` را روی iterator object مربوط به `myObject` فراخوانی می‌کند، اشاره‌گر داخلی جلو می‌رود و مقدار بعدی را از فهرست propertyهای object برمی‌گرداند (یادداشت قبلی دربارهٔ ترتیب تکرار روی propertyها/مقادیر object را ببینید).

تکراری که نشان دادیم تکرار سادهٔ مقدار-به-مقدار است، اما البته می‌توانید تکرارهای دلخواه پیچیده برای ساختارهای دادهٔ سفارشی خود تعریف کنید، هرطور مناسب دیدید. iteratorهای سفارشی ترکیب‌شده با حلقهٔ `for..of` ES6 ابزار نحوی قدرتمند جدیدی برای دستکاری objectهای تعریف‌شدهٔ کاربر هستند.

مثلاً، فهرستی از objectهای `Pixel` (با مقادیر مختصات `x` و `y`) می‌تواند ترتیب تکرارش را بر اساس فاصلهٔ خطی از مبدأ `(0,0)` تعیین کند، یا نقطه‌هایی که «خیلی دور» هستند را فیلتر کند، و غیره. تا وقتی iterator شما مقادیر برگشتی مورد انتظار `{ value: .. }` از فراخوانی‌های `next()` و یک `{ done: true }` بعد از اتمام تکرار را برگرداند، `for..of` ES6 می‌تواند روی آن تکرار کند.

در واقع، می‌توانید حتی iteratorهای «بی‌نهایت» بسازید که هرگز «تمام» نمی‌شوند و همیشه مقدار جدیدی برمی‌گردانند (مثل عدد تصادفی، مقدار افزایش‌یافته، شناسهٔ یکتا و غیره)، اگرچه احتمالاً از چنین iteratorهایی با حلقهٔ `for..of` نامحدود استفاده نمی‌کنید، چون هرگز تمام نمی‌شود و برنامه را hang می‌کند.

```js
var randoms = {
	[Symbol.iterator]: function() {
		return {
			next: function() {
				return { value: Math.random() };
			}
		};
	}
};

var randoms_pool = [];
for (var n of randoms) {
	randoms_pool.push( n );

	// don't proceed unbounded!
	if (randoms_pool.length === 100) break;
}
```

این iterator اعداد تصادفی را «برای همیشه» تولید می‌کند، پس فقط ۱۰۰ مقدار بیرون می‌کشیم تا برنامه hang نشود.
