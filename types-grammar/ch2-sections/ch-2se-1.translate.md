## تغییرناپذیری اولیه

همهٔ مقادیر اولیه immutable هستند، یعنی هیچ‌چیز در برنامهٔ JS نمی‌تواند به محتوای مقدار دست یابد و آن را به هیچ شکلی تغییر دهد.

```js
myAge = 42;

// بعداً:

myAge = 43;
```

عبارت `myAge = 43` مقدار را تغییر نمی‌دهد. مقدار متفاوت `43` را به `myAge` دوباره انتساب می‌دهد و کاملاً مقدار قبلی `42` را جایگزین می‌کند.

مقادیر جدید از طریق عملیات‌های مختلف هم ایجاد می‌شوند، اما باز هم این‌ها مقدار اصلی را تغییر نمی‌دهند:

```js
42 + 1;             // 43

"Hello" + "!";      // "Hello!"
```

مقادیر `43` و `"Hello!"` مقادیر جدید و متمایز از مقادیر قبلی `42` و `"Hello"` هستند.

حتی مقدار رشته که به‌نظر صرفاً آرایه‌ای از کاراکترها است — و محتوای آرایه معمولاً mutable است — immutable است:

```js
greeting = "Hello.";

greeting[5] = "!";

console.log(greeting);      // Hello.
```

| WARNING: |
| :--- |
| در حالت غیر strict، انتساب به ویژگی فقط‌خواندنی (مثل `greeting[5] = ..`) ساکتانه شکست می‌خورد. در حالت strict، انتساب ممنوع استثنا پرتاب می‌کند. |

ماهیت immutable بودن مقادیر اولیه *به هیچ وجه* تحت تأثیر نحوهٔ اعلان متغیر یا ویژگی شیء نگه‌دارندهٔ مقدار نیست. مثلاً، چه `const`، `let` یا `var` برای اعلان متغیر `greeting` بالا استفاده شود، مقدار رشتهٔ نگه‌داشته‌شده immutable است.

`const` مقادیر immutable ایجاد نمی‌کند، متغیرهایی اعلان می‌کند که نمی‌توان دوباره انتساب داد (یعنی انتساب‌های immutable) — عنوان «Scope & Closures» این مجموعه را برای اطلاعات بیشتر ببینید.

ویژگی روی شیء ممکن است فقط‌خواندنی علامت‌گذاری شود — با ویژگی توصیف‌گر `writable: false`، همان‌طور که در عنوان «اشیاء و کلاس‌ها» این مجموعه بحث شد. اما این هنوز بر ماهیت مقدار تأثیری ندارد، فقط بر جلوگیری از انتساب مجدد ویژگی.

### Primitives با ویژگی‌ها؟

علاوه بر این، ویژگی‌ها *نمی‌توانند* به هیچ مقدار اولیه‌ای اضافه شوند:

```js
greeting = "Hello.";

greeting.isRendered = true;

greeting.isRendered;        // undefined
```

این قطعه به‌نظر می‌رسد ویژگی `isRendered` را به مقدار در `greeting` اضافه می‌کند، اما این انتساب ساکتانه شکست می‌خورد (حتی در حالت strict).

دسترسی ویژگی به هیچ وجه روی مقادیر اولیهٔ nullish یعنی `null` و `undefined` مجاز نیست. اما ویژگی‌ها *می‌توانند* روی همهٔ مقادیر اولیهٔ دیگر دسترسی شوند — بله، ضدشهودی به‌نظر می‌رسد.

مثلاً، همهٔ مقادیر رشته ویژگی فقط‌خواندنی `length` دارند:

```js
greeting = "Hello.";

greeting.length;            // 6
```

`length` قابل تنظیم نیست، اما می‌توان دسترسی داشت و تعداد code-unitهای ذخیره‌شده در مقدار را نشان می‌دهد (ببینید «JS Character Encodings» در فصل ۱)، که اغلب یعنی تعداد کاراکترها در رشته.

| NOTE: |
| :--- |
| تقریباً. برای اکثر کاراکترهای استاندارد درست است؛ یک کاراکتر یک code-point است که یک code-unit است. با این حال، همان‌طور که در فصل ۱ توضیح داده شد، کاراکترهای یونیکد گسترش‌یافته بالای code-point `65535` به‌صورت دو code-unit (surrogate halves) ذخیره می‌شوند. بنابراین، برای هر چنین کاراکتری، `length` عدد `2` را در شمارشش شامل می‌کند، حتی اگر کاراکتر بصری به‌عنوان یک نماد چاپ شود. |

مقادیر اولیهٔ غیر nullish همچنین چند متد استاندارد داخلی دارند که می‌توان به آن‌ها دسترسی داشت:

```js
greeting = "Hello.";

greeting.toString();    // "Hello." <-- تکراری
greeting.valueOf();     // "Hello."
```

علاوه بر این، اکثر انواع مقدار اولیه متدهای خاص خود را با رفتارهای ذاتی آن نوع تعریف می‌کنند. این‌ها را بعداً در این فصل پوشش می‌دهیم.

| NOTE: |
| :--- |
| همان‌طور که قبلاً به‌طور خلاصه در فصل ۱ ذکر شد، از نظر فنی، این نوع دسترسی‌های ویژگی/متد روی مقادیر اولیه توسط رفتار اجباری ضمنی به‌نام *auto-boxing* تسهیل می‌شوند. این را به‌تفصیل در «Automatic Objects» در فصل ۳ پوشش می‌دهیم. |
