## مقادیر Symbol

نوع `symbol` مقادیر ویژهٔ مات به‌نام «symbols» را شامل می‌شود. این مقادیر فقط توسط تابع `Symbol(..)` قابل ساخت هستند:

```js
secret = Symbol("my secret");
```

| WARNING: |
| :--- |
| درست مثل `BigInt(..)`، تابع `Symbol(..)` باید بدون کلمهٔ کلیدی `new` فراخوانی شود. |

رشتهٔ `"my secret"` فرستاده‌شده به فراخوانی تابع `Symbol(..)` *خود* مقدار symbol نیست، حتی اگر به‌نظر برسد. فقط برچسب توصیفی اختیاری است، فقط برای اهداف دیباگ برای سود توسعه‌دهنده استفاده می‌شود.

مقدار زیربنایی برگشتی از `Symbol(..)` نوع خاصی از مقدار است که در برابر بررسی برنامه/توسعه‌دهنده از هر چیزی دربارهٔ نمایش زیربنایی‌اش مقاومت می‌کند. منظورم از «مات» همین است.

| NOTE: |
| :--- |
| می‌توانید symbols را طوری فکر کنید انگار اعداد integer یکنواخت فزاینده هستند — در واقع، شبیه نحوهٔ پیاده‌سازی حداقل برخی موتورهای JS است. اما موتور JS هرگز هیچ نمایشی از مقدار زیربنایی symbol را به هیچ شکلی که شما یا برنامه ببینید افشا نخواهد کرد. |

Symbols توسط موتور JS تضمین می‌شوند که یکتا باشند (فقط در خود برنامه)، و غیرقابل حدس هستند. به عبارت دیگر، مقدار symbol تکراری هرگز در برنامه قابل ساخت نیست.

شاید در این نقطه تعجب کنید symbols برای چه استفاده می‌شوند؟

یک کاربرد معمول به‌عنوان مقادیر «ویژه» است که توسعه‌دهنده از هر مقدار دیگری که ممکن است تصادفاً برخورد کند متمایز می‌کند. مثلاً:

```js
EMPTY = Symbol("not set yet");
myNickname = EMPTY;

// بعداً:

if (myNickname == EMPTY) {
    // ..
}
```

اینجا مقدار ویژهٔ `EMPTY` تعریف کرده و `myNickname` را با آن مقداردهی اولیه کرده‌ام. بعداً بررسی می‌کنم آیا هنوز آن مقدار ویژه است و سپس در صورت مثبت عملی انجام می‌دهم. شاید نمی‌خواستم از `null` یا `undefined` برای چنین اهدافی استفاده کنم، چون توسعه‌دهندهٔ دیگری ممکن است بتواند یکی از آن مقادیر داخلی رایج را بفرستد. `EMPTY` در مقابل اینجا مقدار یکتا و غیرقابل حدسی است که فقط من تعریف کرده و کنترل و دسترسی دارم.

شاید حتی رایج‌تر، symbols اغلب به‌عنوان ویژگی‌های (متا-)ویژه روی اشیاء استفاده می‌شوند:

```js
myInfo = {
    name: "Kyle Simpson",
    nickname: "getify",
    age: 42
};

// بعداً:
PRIVATE_ID = Symbol("private unique ID, don't touch!");

myInfo[PRIVATE_ID] = generateID();
```

مهم است توجه کنید ویژگی‌های symbol هنوز به‌طور عمومی روی هر شیء قابل مشاهده هستند؛ *واقعاً* خصوصی نیستند. اما به‌عنوان ویژه و جدا از مجموعهٔ عادی ویژگی‌های شیء رفتار می‌شوند. شبیه است به اگر به‌جای آن کرده بودم:

```js
Object.defineProperty(myInfo,"__private_id_dont_touch",{
    value: generateID(),
    enumerable: false,
});
```

فقط طبق قرارداد، اکثر توسعه‌دهندگان می‌دانند اگر نام ویژگی با `_` (یا حتی بیشتر، `__`!) پیشوند داشته باشد، یعنی «شبه‌خصوصی» است و به حال خود بگذارند مگر واقعاً قرار است دسترسی داشته باشند.

Symbols اساساً همان use-case را خدمت می‌کنند، اما کمی ارگونومیک‌تر از رویکرد پیشوندگذاری.

### Well-Known Symbols (WKS)

JS مجموعه‌ای از symbols از پیش تعریف‌شده دارد، به‌نام *well-known symbols* (WKS)، که قلاب‌های متا‑برنامه‌نویسی ویژهٔ خاصی روی اشیاء را نشان می‌دهند. این symbols به‌عنوان ویژگی‌های استاتیک روی شیء تابع `Symbol` ذخیره می‌شوند. مثلاً:

```js
myInfo = {
    // ..
};

String(myInfo);         // [object Object]

myInfo[Symbol.toStringTag] = "my-info";
String(myInfo);         // [object my-info]
```

`Symbol.toStringTag` یک well-known symbol برای دسترسی و بازنویسی نمایش رشتهٔ پیش‌فرض یک شیء ساده (`"[object Object]"`) است، جایگزینی بخش `"Object"` با مقدار متفاوت (مثلاً `"my-info"`).

کتاب «اشیاء و کلاس‌ها» از این مجموعه را برای اطلاعات بیشتر دربارهٔ Well-Known Symbols و متا‑برنامه‌نویسی ببینید.

### ثبات Symbol سراسری

اغلب می‌خواهید مقادیر symbol را خصوصی نگه دارید، مثلاً داخل scope ماژول. اما گاهی می‌خواهید آن‌ها را افشا کنید تا در همهٔ فایل‌های برنامهٔ JS به‌طور سراسری قابل دسترسی باشند.

به‌جای فقط attaching آن‌ها به‌عنوان متغیرهای سراسری (یعنی ویژگی‌ها روی شیء `globalThis`)، JS namespace *سراسری* جایگزینی برای ثبت symbols ارائه می‌دهد:

```js
// بازیابی اگر قبلاً ثبت شده،
// در غیر این صورت ثبت
PRIVATE_ID = Symbol.for("private-id");

// جای دیگر:

privateIDKey = Symbol.keyFor(PRIVATE_ID);
privateIDKey;           // "private-id"

// جای دیگر:

// بازیابی symbol از ثبات تحت
// کلید مشخص‌شده
privateIDSymbol = Symbol.for(privateIDKey);
```

مقدار فرستاده‌شده به `Symbol.for(..)` *همان* فرستاده‌شده به `Symbol(..)` نیست. `Symbol.for(..)` کلید *یکتا* برای ثبت symbol تحت آن در ثبات سراسری انتظار دارد، در حالی که `Symbol(..)` اختیاری برچسب توصیفی (نه لزوماً یکتا) می‌پذیرد.

اگر ثبات symbol تحت آن *key* مشخص‌شده نداشته باشد، symbol جدید (بدون برچسب توصیفی) ساخته و خودکار آنجا ثبت می‌شود. در غیر این صورت، `Symbol.for(..)` هر symbol قبلاً ثبت‌شده تحت آن *key* را برمی‌گرداند.

در جهت مخالف، اگر خود مقدار symbol را دارید و می‌خواهید *key* ثبت‌شده‌اش را بازیابی کنید، `Symbol.keyFor(..)` خود symbol را به‌عنوان ورودی می‌گیرد و *key* را (در صورت وجود) برمی‌گرداند. این مفید است در صورتی که راحت‌تر باشد مقدار رشتهٔ *key* را به‌جای خود symbol رد و بدل کنید.

### شیء یا Primitive؟

برخلاف primitives دیگر مثل `42` که می‌توانید چند کپی از همان مقدار بسازید، symbols *واقعاً* بیشتر شبیه مراجع شیء خاص عمل می‌کنند چون همیشه کاملاً یکتا هستند (برای اهداف انتساب مقدار و مقایسهٔ برابری). مشخصات همچنین تابع `Symbol()` را تحت بخش «اشیاء بنیادی» دسته‌بندی می‌کند، تابع را «constructor» می‌خواند و حتی ویژگی `prototype` آن را تعریف می‌کند.

با این حال، همان‌طور که قبلاً ذکر شد، نمی‌توان از `new` با `Symbol(..)` استفاده کرد؛ این شبیه «constructor» `BigInt()` است. ما به‌وضوح می‌دانیم مقادیر `bigint` primitives هستند، پس مقادیر `symbol` به‌نظر از همان *نوع* هستند.

و در «اصطلاحات و تعاریف» مشخصات، symbol به‌عنوان مقدار اولیه فهرست شده است. [^PrimitiveValues] علاوه بر این، خود مقادیر در برنامه‌های JS به‌عنوان primitives به‌جای اشیاء استفاده می‌شوند. مثلاً، symbols عمدتاً به‌عنوان کلید در اشیاء استفاده می‌شوند — می‌دانیم اشیاء نمی‌توانند از مقادیر شیء دیگر به‌عنوان کلید استفاده کنند! — همراه با رشته‌ها که آن‌ها هم primitives هستند.

همان‌طور که قبلاً ذکر شد، برخی موتورهای JS حتی symbols را به‌صورت داخلی به‌عنوان integerهای یکنواخت فزایندهٔ یکتا (primitives!) پیاده‌سازی می‌کنند.

در نهایت، همان‌طور که در بالای این فصل توضیح داده شد، می‌دانیم مقادیر اولیه *اجازهٔ* تنظیم ویژگی روی آن‌ها را ندارند، اما *auto-boxed* می‌شوند (ببینید «اشیاء خودکار» در فصل ۳) به‌صورت داخلی به نوع object-wrapper متناظر برای تسهیل دسترسی ویژگی/متد. Symbols همهٔ این رفتارهای دقیق را دنبال می‌کنند، مثل همهٔ primitives دیگر.

با توجه به همهٔ این‌ها، فکر می‌کنم symbols *خیلی بیشتر* شبیه primitives هستند تا اشیاء، پس این‌طور در این کتاب ارائه می‌دهم.
