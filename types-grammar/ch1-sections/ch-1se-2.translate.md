## مقادیر خالی

هر دو نوع `null` و `undefined` معمولاً خالی بودن یا عدم وجود مقدار را نشان می‌دهند.

متأسفانه، نوع مقدار `null` نتیجهٔ `typeof` غیرمنتظره‌ای دارد. به‌جای `"null"`، می‌بینیم:

```js
typeof null;            // "object"
```

نه، این به معنای آن نیست که `null` به‌نحوی نوع خاصی از شیء است. فقط میراث روزهای اولیهٔ JS است که به‌خاطر کدهای زیادی که در دنیا می‌شکست نمی‌توان تغییرش داد.

نوع `undefined` هم برای مقادیر صریح `undefined` و هم هر جایی که مقدار به‌ظاهر گم‌شده‌ای مواجه می‌شود گزارش می‌شود:

```js
typeof undefined;               // "undefined"

var whatever;

typeof whatever;                // "undefined"
typeof nonExistent;             // "undefined"

whatever = {};
typeof whatever.missingProp;    // "undefined"

whatever = [];
typeof whatever[10];            // "undefined"
```

| NOTE: |
| :--- |
| عبارت `typeof nonExistent` به متغیر اعلام‌نشدهٔ `nonExistent` اشاره می‌کند. معمولاً دسترسی به مرجع متغیر اعلام‌نشده استثنا ایجاد می‌کند، اما عملگر `typeof` قابلیت ویژهٔ دسترسی امن حتی به شناسه‌های غیرموجود را دارد و به‌جای پرتاب استثنا آرام `"undefined"` برمی‌گرداند. |

با این حال، هر نوع «خالی» دقیقاً یک مقدار دارد، به همان نام. پس `null` تنها مقدار در نوع مقدار `null` است و `undefined` تنها مقدار در نوع مقدار `undefined` است.

### Null'ish

از نظر معنایی، هر دو نوع `null` و `undefined` خالی بودن عمومی یا عدم وجود مقدار مثبت و معنادار دیگر را نشان می‌دهند.

| NOTE: |
| :--- |
| عملیات‌های JS که به‌یک‌سان رفتار می‌کنند چه `null` یا `undefined` مواجه شوند، «null'ish» (یا «nullish») نامیده می‌شوند. حدس می‌زنم «undefined'ish» عجیب به‌نظر برسد! |

برای بسیاری از JS، به‌ویژه کدی که توسعه‌دهندگان می‌نویسند، این دو مقدار *nullish* قابل تعویض هستند؛ تصمیم استفاده/انتساب عمدی `null` یا `undefined` در هر سناریو به وضعیت بستگی دارد و به عهدهٔ توسعه‌دهنده است.

JS قابلیت‌های متعددی برای کمک به رفتار یکسان با دو مقدار nullish ارائه می‌دهد.

مثلاً، عملگر `==` (مقایسهٔ برابری اجباری) به‌طور خاص `null` و `undefined` را برابر اجباری می‌داند، اما با هیچ مقدار دیگر در زبان نه. بنابراین، بررسی `.. == null` امن است اگر بخواهید بررسی کنید آیا مقدار دقیقاً `null` یا `undefined` است:

```js
if (greeting == null) {
    // greeting nullish/خالی است
}
```

افزودن (اخیر) دیگر به JS عملگر `??` (nullish-coalescing) است:

```js
who = myName ?? "User";

// معادل:
who = (myName != null) ? myName : "User";
```

همان‌طور که معادل سه‌تایی نشان می‌دهد، `??` بررسی می‌کند آیا `myName` غیر nullish است، و اگر باشد، مقدارش را برمی‌گرداند. در غیر این صورت، عملوند دیگر را برمی‌گرداند (اینجا `"User"`).

همراه با `??`، JS عملگر `?.` (nullish conditional-chaining) را هم اضافه کرد:

```js
record = {
    shippingAddress: {
        street: "123 JS Lane",
        city: "Browserville",
        state: "XY"
    }
};

console.log( record?.shippingAddress?.street );
// 123 JS Lane

console.log( record?.billingAddress?.street );
// undefined
```

عملگر `?.` مقدار بلافاصله قبل (سمت چپ) را بررسی می‌کند، و اگر nullish باشد، متوقف می‌شود و مقدار `undefined` برمی‌گرداند. در غیر این صورت، دسترسی ویژگی `.` را روی آن مقدار انجام می‌دهد و با عبارت ادامه می‌دهد.

فقط برای روشنی: `record?.` یعنی «قبل از دسترسی ویژگی `.`، `record` را برای nullish بررسی کن». همچنین `billingAddress?.` یعنی «قبل از دسترسی ویژگی `.`، `billingAddress` را برای nullish بررسی کن».

| WARNING: |
| :--- |
| برخی توسعه‌دهندگان JS معتقدند `?.` جدیدتر از `.` برتر است و باید تقریباً همیشه به‌جای `.` استفاده شود. من این دیدگاه را نادرست می‌دانم. اولاً، شلوغی بصری اضافه می‌کند که فقط وقتی باید انجام شود که سودش را می‌برید. ثانیاً، باید از خالی بودن مقداری آگاه و برایش برنامه‌ریزی کنید تا استفاده از `?.` توجیه شود. اگر همیشه انتظار دارید مقدار غیر nullish در عبارتی وجود داشته باشد، استفاده از `?.` برای دسترسی به ویژگی روی آن نه‌تنها غیرضروری/اتلافی است، بلکه احتمالاً باگ‌های آینده را می‌پوشاند جایی که فرض حضور مقدار شکست خورده اما `?.` آن را پوشاند. مثل هر ویژگی در JS، از `.` جایی که مناسب‌تر است و از `?.` جایی که مناسب‌تر است استفاده کنید. هرگز یکی را جایگزین دیگری نکنید وقتی دیگری مناسب‌تر است. |

همچنین شکل کمی عجیب `?.[` از عملگر وجود دارد، نه `?[`، برای وقتی که باید به‌جای دسترسی `.` از دسترسی سبک `[ .. ]` استفاده کنید:

```js
record?.["shipping" + "Address"]?.state;    // XY
```

تنوع دیگر، «optional-call» نامیده می‌شود، `?.(` است، و برای فراخوانی شرطی تابع اگر مقدار غیر nullish باشد استفاده می‌شود:

```js
// به‌جای:
//   if (someFunc) someFunc(42);
//
// یا:
//   someFunc && someFunc(42);

someFunc?.(42);
```

عملگر `?.(` به‌نظر می‌رسد بررسی می‌کند آیا `someFunc(..)` تابع معتبری است که قابل فراخوانی است. اما نیست! فقط بررسی می‌کند مقدار قبل از تلاش برای فراخوانی غیر nullish باشد. اگر نوع مقدار دیگری غیر nullish اما غیرتابع باشد، تلاش اجرا همچنان با استثنای `TypeError` شکست می‌خورد.

| WARNING: |
| :--- |
| به‌خاطر آن gotcha، من *کاملاً این شکل عملگر را دوست ندارم* و به هر کسی هشدار می‌دهم هرگز استفاده نکند. فکر می‌کنم ویژگی ضعیف طراحی‌شده‌ای است که بیشتر ضرر (به خود JS و برنامه‌ها) می‌زند تا سود. تعداد کمی ویژگی JS هستند که تا این حد بگویم «هرگز استفاده نکن». اما این یکی از *بخش‌های بد* واقعی زبان است، به نظر من. |

### Distinct'ish

مهم است به یاد داشته باشید که `null` و `undefined` *واقعاً* انواع متمایز هستند و بنابراین `null` می‌تواند به‌طور محسوب با `undefined` متفاوت باشد. می‌توانید با دقت برنامه‌هایی بسازید که بیشتر آن‌ها را غیرقابل تشخیص رفتار کنند. اما این نیاز به دقت و انضباط از سوی توسعه‌دهنده دارد. از نظر JS، آن‌ها بیشتر متمایز هستند.

مواردی وجود دارد که `null` و `undefined` رفتار متفاوتی را توسط زبان ایجاد می‌کنند، که مهم است به یاد داشته باشید. همهٔ موارد را اینجا جامع پوشش نمی‌دهیم، اما یک مثال:

```js
function greet(msg = "Hello") {
    console.log(msg);
}

greet();            // Hello
greet(undefined);   // Hello
greet("Hi");        // Hi

greet(null);        // null
```

بند `= ..` روی پارامتر «پیش‌فرض پارامتر» نامیده می‌شود. فقط وقتی فعال می‌شود و مقدار پیش‌فرضش را به پارامتر اختصاص می‌دهد که آرگومان در آن موقعیت گم باشد یا دقیقاً مقدار `undefined` باشد. اگر `null` بفرستید، آن بند فعال نمی‌شود و `null` به پارامتر اختصاص داده می‌شود.

راه *درست* یا *غلط* برای استفاده از `null` یا `undefined` در برنامه وجود ندارد. پس نتیجه: هنگام انتخاب یکی یا دیگری دقت کنید. و اگر آن‌ها را قابل تعویض استفاده می‌کنید، بیشتر دقت کنید.
