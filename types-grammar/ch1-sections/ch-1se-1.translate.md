## انواع مقدار

JS انواع را به متغیرها یا ویژگی‌ها اعمال نمی‌کند — آنچه من «انواع نگه‌دارنده» می‌نامم — بلکه خود مقادیر دارای نوع هستند — آنچه من «انواع مقدار» می‌نامم.

زبان هفت نوع مقدار اولیهٔ (غیرشیء) داخلی ارائه می‌دهد: [^PrimitiveValues]

* `undefined`
* `null`
* `boolean`
* `number`
* `bigint`
* `symbol`
* `string`

این انواع مقدار مجموعه‌هایی از یک یا چند مقدار مشخص را تعریف می‌کنند، هر کدام با مجموعه‌ای از رفتارهای مشترک برای همهٔ مقادیر هر نوع.

### Type-Of

نوع مقدار هر مقداری را می‌توان با عملگر `typeof` بررسی کرد، که همیشه یک مقدار `string` برمی‌گرداند که نوع مقدار JS زیربنایی را نشان می‌دهد:

```js
typeof true;            // "boolean"

typeof 42;              // "number"

typeof 42n;             // "bigint"

typeof Symbol("42");    // "symbol"
```

وقتی عملگر `typeof` به‌جای مقدار، روی متغیر استفاده می‌شود، نوع مقدار *مقدار داخل متغیر* را گزارش می‌دهد:

```js
greeting = "Hello";
typeof greeting;        // "string"
```

خود متغیرهای JS نوع ندارند. آن‌ها هر مقدار دلخواهی را نگه می‌دارند که خودش نوع مقدار دارد.

### غیرشیء؟

چه چیزی به‌طور خاص هفت نوع مقدار اولیه را از انواع مقدار شیء (و زیرنوع‌ها) متمایز می‌کند؟ چرا نباید همهٔ آن‌ها را اساساً *اشیاء* در نظر بگیریم؟

در نظر بگیرید:

```js
myName = "Kyle";

myName.nickname = "getify";

console.log(myName.nickname);           // undefined
```

این قطعه به‌نظر می‌رسد که ساکتانه در افزودن ویژگی `nickname` به رشتهٔ اولیه شکست خورده است. در ظاهر، ممکن است دلالت کند که primitives واقعاً اشیاء هستند، همان‌طور که بسیاری طی سال‌ها (اشتباه) ادعا کرده‌اند.

| WARNING: |
| :--- |
| ممکن است کسی آن شکست ساکت را نمونه‌ای از *auto-boxing* توضیح دهد (ببینید «اشیاء خودکار» در فصل ۳)، جایی که primitive ضمنی به شیء wrapper نمونهٔ `String` تبدیل می‌شود هنگام تلاش برای انتساب ویژگی، و سپس این شیء داخلی پس از اتمام عبارت دور انداخته می‌شود. در واقع، من دقیقاً همین را در ویرایش اول این کتاب گفتم. اما اشتباه بودم؛ اوه! |

چیز عمیق‌تری در کار است، همان‌طور که در این نسخه از قطعهٔ قبلی می‌بینیم:

```js
"use strict";

myName = "Kyle";

myName.nickname = "getify";
// TypeError: Cannot create property 'nickname'
// on string 'Kyle'
```

جالبه! در حالت strict، JS محدودیتی اعمال می‌کند که تنظیم ویژگی جدید روی مقدار اولیه را ممنوع می‌کند، گویی آن را ضمنی به شیء جدید ارتقا می‌دهد.

در مقابل، در حالت غیر strict، JS اجازه می‌دهد نقض بدون ذکر بماند. چرا؟ چون حالت strict در ES5.1 (۲۰۱۱) به زبان اضافه شد، بیش از ۱۵ سال بعد، و چنین تغییری برنامه‌های موجود را می‌شکست اگر نسبت به اعلان حالت strict جدید حساس تعریف نمی‌شد.

پس چه نتیجه‌ای می‌گیریم دربارهٔ تمایز بین primitives و اشیاء؟ Primitives مقادیری هستند که *اجازهٔ داشتن ویژگی ندارند*؛ فقط اشیاء چنین اجازه‌ای دارند.

| TIP: |
| :--- |
| به‌نظر می‌رسد این تمایز خاص با عباراتی مثل `"hello".length` تناقض دارد؛ حتی در حالت strict، مقدار مورد انتظار `5` را برمی‌گرداند. پس قطعاً *به‌نظر می‌رسد* که رشته ویژگی `length` دارد! اما، همان‌طور که قبلاً ذکر شد، توضیح درست *auto-boxing* است؛ این موضوع را در «اشیاء خودکار» در فصل ۳ پوشش می‌دهیم. |
