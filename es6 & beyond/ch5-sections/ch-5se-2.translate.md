# Mapها

اگر تجربه‌ی زیادی در JS داشته باشید، می‌دانید آبجکت‌ها سازوکار اصلی ساخت ساختار داده‌ی نامرتبِ کلید/مقدار هستند که به آن map هم می‌گویند. با این حال، ضعف بزرگِ استفاده از آبجکت به‌عنوان map این است که نمی‌توانید مقدار غیررشته‌ای را به‌عنوان کلید استفاده کنید.

مثلاً:

```js
var m = {};

var x = { id: 1 },
	y = { id: 2 };

m[x] = "foo";
m[y] = "bar";

m[x];							// "bar"
m[y];							// "bar"
```

اینجا چه اتفاقی افتاده؟ هر دو آبجکت `x` و `y` به `"[object Object]"` رشته‌ای می‌شوند، پس فقط همان یک کلید در `m` ست می‌شود.

بعضی‌ها map تقلبی را با نگهداری یک آرایه‌ی موازی از کلیدهای غیررشته‌ای کنار آرایه‌ی مقدارها پیاده‌سازی کرده‌اند، مثل:

```js
var keys = [], vals = [];

var x = { id: 1 },
	y = { id: 2 };

keys.push( x );
vals.push( "foo" );

keys.push( y );
vals.push( "bar" );

keys[0] === x;					// true
vals[0];						// "foo"

keys[1] === y;					// true
vals[1];						// "bar"
```

طبعاً دوست ندارید خودتان این آرایه‌های موازی را مدیریت کنید، پس می‌توانید یک ساختار داده با متدهایی تعریف کنید که این مدیریت را پشت‌صحنه انجام دهد. جدا از زحمت پیاده‌سازی، ضعف اصلی این است که دسترسی دیگر O(1) نیست و O(n) می‌شود.

اما از ES6 به بعد دیگر نیازی به این کارها نیست! کافی است از `Map(..)` استفاده کنید:

```js
var m = new Map();

var x = { id: 1 },
	y = { id: 2 };

m.set( x, "foo" );
m.set( y, "bar" );

m.get( x );						// "foo"
m.get( y );						// "bar"
```

تنها نکته این است که برای set/get نمی‌توانید از سینتکس براکت `[ ]` استفاده کنید. اما `get(..)` و `set(..)` کاملاً مناسب هستند.

برای حذف یک عضو از map، از عملگر `delete` استفاده نکنید؛ از متد `delete(..)` استفاده کنید:

```js
m.set( x, "foo" );
m.set( y, "bar" );

m.delete( y );
```

با `clear()` می‌توانید کل map را خالی کنید. برای گرفتن طول map (یعنی تعداد کلیدها)، از ویژگی `size` استفاده کنید (نه `length`):

```js
m.set( x, "foo" );
m.set( y, "bar" );
m.size;							// 2

m.clear();
m.size;							// 0
```

سازنده‌ی `Map(..)` می‌تواند یک iterable هم بگیرد (بخش «Iteratorها» در فصل ۳) که باید فهرستی از آرایه‌ها تولید کند؛ آیتم اول هر آرایه کلید است و آیتم دوم مقدار. این فرمت تکرار دقیقاً مثل خروجی متد `entries()` است که در بخش بعد توضیح داده می‌شود. پس کپی گرفتن از map ساده است:

```js
var m2 = new Map( m.entries() );

// same as:
var m2 = new Map( m );
```

چون نمونه‌ی map خودش iterable است و iterator پیش‌فرضش همان `entries()` است، فرم دومِ کوتاه‌تر ترجیح داده می‌شود.

البته می‌توانید فهرست *entries* را دستی به سازنده‌ی `Map(..)` بدهید (آرایه‌ای از آرایه‌های کلید/مقدار):

```js
var x = { id: 1 },
	y = { id: 2 };

var m = new Map( [
	[ x, "foo" ],
	[ y, "bar" ]
] );

m.get( x );						// "foo"
m.get( y );						// "bar"
```

### مقدارهای Map

برای گرفتن فهرست مقدارهای map، از `values(..)` استفاده کنید که یک iterator برمی‌گرداند. در فصل‌های ۲ و ۳ روش‌های مختلف پردازش ترتیبی iterator (شبیه آرایه) را دیدیم، مثل عملگر spread یعنی `...` و حلقه‌ی `for..of`. همچنین بخش «Arrays» در فصل ۶، متد `Array.from(..)` را با جزئیات توضیح می‌دهد. مثال:

```js
var m = new Map();

var x = { id: 1 },
	y = { id: 2 };

m.set( x, "foo" );
m.set( y, "bar" );

var vals = [ ...m.values() ];

vals;							// ["foo","bar"]
Array.from( m.values() );		// ["foo","bar"]
```

همان‌طور که در بخش قبل گفتیم، می‌توانید روی entriesهای map با `entries()` (یا iterator پیش‌فرض map) پیمایش کنید:

```js
var m = new Map();

var x = { id: 1 },
	y = { id: 2 };

m.set( x, "foo" );
m.set( y, "bar" );

var vals = [ ...m.entries() ];

vals[0][0] === x;				// true
vals[0][1];						// "foo"

vals[1][0] === y;				// true
vals[1][1];						// "bar"
```

### کلیدهای Map

برای گرفتن فهرست کلیدها، از `keys()` استفاده کنید که iterator کلیدهای map را برمی‌گرداند:

```js
var m = new Map();

var x = { id: 1 },
	y = { id: 2 };

m.set( x, "foo" );
m.set( y, "bar" );

var keys = [ ...m.keys() ];

keys[0] === x;					// true
keys[1] === y;					// true
```

برای بررسی وجود یک کلید مشخص در map، از `has(..)` استفاده کنید:

```js
var m = new Map();

var x = { id: 1 },
	y = { id: 2 };

m.set( x, "foo" );

m.has( x );						// true
m.has( y );						// false
```

Mapها عملاً اجازه می‌دهند یک اطلاعات اضافه (value) را به یک آبجکت (key) وصل کنید، بدون این‌که آن اطلاعات را واقعاً روی خود آبجکت قرار دهید.

هرچند هر نوع مقداری می‌تواند کلید map باشد، معمولاً از آبجکت‌ها برای کلید استفاده می‌کنید، چون رشته‌ها و primitiveهای دیگر از قبل می‌توانند کلید آبجکت معمولی باشند. یعنی تا وقتی نیاز ندارید بعضی/همه‌ی کلیدها آبجکت باشند، احتمالاً آبجکت معمولی برای map کافی است؛ در غیر این صورت map مناسب‌تر است.

**هشدار:** اگر از یک آبجکت به‌عنوان کلید map استفاده کنید و بعد آن آبجکت را discard کنید (همه‌ی referenceها unset شوند) تا GC حافظه‌اش را پس بگیرد، خود map همچنان entry مربوطه را نگه می‌دارد. باید entry را از map حذف کنید تا واجد شرایط GC شود. در بخش بعد WeakMap را می‌بینیم که برای کلیدهای آبجکتی و GC گزینه‌ی بهتری است.
