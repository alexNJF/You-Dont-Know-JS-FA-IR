# WeakMapها

WeakMapها گونه‌ای از map هستند که بیشتر رفتار بیرونی مشابهی دارند، اما در لایه‌ی زیرین، نحوه‌ی تخصیص حافظه (به‌خصوص GC) در آن‌ها متفاوت است.

WeakMap فقط آبجکت را به‌عنوان کلید می‌پذیرد. این آبجکت‌ها به‌صورت *weak* نگه داشته می‌شوند؛ یعنی اگر خود آبجکت GC شود، entry آن در WeakMap هم حذف می‌شود. البته این رفتار مستقیماً قابل مشاهده نیست، چون تنها وقتی یک آبجکت GC می‌شود که دیگر هیچ referenceی به آن نباشد -- و وقتی referenceی ندارید، دیگر آبجکتی هم ندارید که بررسی کنید آیا در WeakMap هست یا نه.

غیر از این موضوع، API مربوط به WeakMap شبیه map است، ولی محدودتر:

```js
var m = new WeakMap();

var x = { id: 1 },
	y = { id: 2 };

m.set( x, "foo" );

m.has( x );						// true
m.has( y );						// false
```

WeakMap نه ویژگی `size` دارد، نه متد `clear()`، و نه iteratorی روی کلیدها، مقدارها یا entryها ارائه می‌دهد. پس حتی اگر reference مربوط به `x` را unset کنید و با GC entry آن از `m` حذف شود، راهی برای دیدن مستقیم این اتفاق ندارید. باید به جاوااسکریپت اعتماد کنید!

WeakMapها مثل Map، امکان soft-associate کردن اطلاعات با یک آبجکت را می‌دهند. اما زمانی خیلی مفیدند که آن آبجکت کاملاً تحت کنترل شما نیست، مثل یک عنصر DOM. اگر آبجکتی که به‌عنوان کلید map استفاده می‌کنید ممکن است حذف شود و باید در آن حالت GC شود، WeakMap گزینه‌ی مناسب‌تری است.

نکته‌ی مهم: WeakMap فقط *کلیدها* را weak نگه می‌دارد، نه مقدارها را. مثال:

```js
var m = new WeakMap();

var x = { id: 1 },
	y = { id: 2 },
	z = { id: 3 },
	w = { id: 4 };

m.set( x, y );

x = null;						// { id: 1 } is GC-eligible
y = null;						// { id: 2 } is GC-eligible
								// only because { id: 1 } is

m.set( z, w );

w = null;						// { id: 4 } is not GC-eligible
```

به همین دلیل، از نظر من نام بهتر برای WeakMap می‌توانست «WeakKeyMap» باشد.
