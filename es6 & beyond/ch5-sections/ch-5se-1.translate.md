# TypedArrayها

همان‌طور که در کتاب *Types & Grammar* از این مجموعه گفتیم، JS مجموعه‌ای از typeهای داخلی مثل `number` و `string` دارد. طبیعی است اگر با دیدن قابلیتی به نام «typed array» فکر کنیم یعنی آرایه‌ای از یک نوع مشخص مقدار، مثلاً آرایه‌ای فقط از رشته‌ها.

اما typed arrayها در واقع بیشتر برای دسترسی ساخت‌یافته به داده‌ی باینری با معناشناسی شبیه آرایه هستند (دسترسی اندیسی و ...). «type» در این نام به «view»ای اشاره دارد که روی سطل بیت‌ها قرار می‌گیرد؛ یعنی نگاشتی از این‌که بیت‌ها باید به شکل آرایه‌ای از اعداد صحیح علامت‌دار ۸ بیتی، ۱۶ بیتی و ... دیده شوند.

این سطل بیت‌ها را چطور می‌سازیم؟ نامش «buffer» است و مستقیم‌ترین روش ساختنش سازنده‌ی `ArrayBuffer(..)` است:

```js
var buf = new ArrayBuffer( 32 );
buf.byteLength;							// 32
```

`buf` حالا یک بافر باینری ۳۲ بایتی (۲۵۶ بیتی) است که از قبل با `0` مقداردهی شده. خود buffer به‌تنهایی تعامل خاصی به شما نمی‌دهد، جز این‌که بتوانید ویژگی `byteLength` آن را ببینید.

**نکته‌ی کاربردی:** چند قابلیت وب از array buffer استفاده می‌کنند یا آن را برمی‌گردانند؛ مثل `FileReader#readAsArrayBuffer(..)`، `XMLHttpRequest#send(..)` و `ImageData` (داده‌ی canvas).

اما روی همین array buffer می‌توانید یک «view» قرار دهید که به شکل typed array است. مثال:

```js
var arr = new Uint16Array( buf );
arr.length;							// 16
```

`arr` یک typed array از اعداد صحیح بدون علامت ۱۶ بیتی است که روی بافر ۲۵۶ بیتی `buf` نگاشت شده، یعنی ۱۶ عنصر دارید.

### Endianness

خیلی مهم است بدانید `arr` با تنظیم endianness پلتفرمی که JS روی آن اجرا می‌شود نگاشت می‌شود (big-endian یا little-endian). این می‌تواند مسئله‌ساز شود اگر داده‌ی باینری با یک endianness تولید شود اما روی پلتفرمی با endianness مخالف تفسیر شود.

Endianness یعنی بایت کم‌ارزش‌تر (مجموعه‌ی ۸ بیت) در یک عدد چندبایتی -- مثل همان عدد صحیح بدون علامت ۱۶ بیتی که قبل‌تر ساختیم -- سمت راست بایت‌های عدد قرار بگیرد یا سمت چپ.

مثلاً عدد ده‌دهی `3085` را تصور کنید که برای نمایش، به ۱۶ بیت نیاز دارد. اگر فقط یک ظرف ۱۶ بیتی داشته باشید، نمایش باینری آن `0000110000001101` (هگز `0c0d`) است، فارغ از endianness.

اما اگر `3085` با دو عدد ۸ بیتی نمایش داده شود، endianness به‌شدت روی ذخیره‌سازی در حافظه اثر می‌گذارد:

* `0000110000001101` / `0c0d` (big endian)
* `0000110100001100` / `0d0c` (little endian)

اگر بیت‌های `3085` را به‌صورت `0000110100001100` از یک سیستم little-endian دریافت کنید، اما روی آن در یک سیستم big-endian view بگذارید، به‌جای آن مقدار، `3340` (ده‌دهی) و `0d0c` (شانزدهی) می‌بینید.

امروزه little endian روی وب رایج‌تر است، ولی قطعاً مرورگرهایی هم هستند که این‌طور نیست. مهم است endianness هر دو طرف تولیدکننده و مصرف‌کننده‌ی یک قطعه داده‌ی باینری را بدانید.

از MDN، این یک روش سریع برای تست endianness در جاوااسکریپت است:

```js
var littleEndian = (function() {
	var buffer = new ArrayBuffer( 2 );
	new DataView( buffer ).setInt16( 0, 256, true );
	return new Int16Array( buffer )[0] === 256;
})();
```

`littleEndian` یا `true` می‌شود یا `false`؛ در اکثر مرورگرها باید `true` باشد. این تست از `DataView(..)` استفاده می‌کند که کنترل low-level و ریزدانه‌تری برای دسترسی (set/get) به بیت‌های view روی buffer می‌دهد. پارامتر سوم متد `setInt16(..)` در مثال بالا برای این است که به `DataView` بگویید در آن عملیات از کدام endianness استفاده کند.

**هشدار:** endianness ذخیره‌سازی باینری زیرین در array buffer را با نحوه‌ی نمایش یک عدد وقتی در برنامه‌ی JS دیده می‌شود اشتباه نگیرید. مثلاً `(3085).toString(2)` مقدار `"110000001101"` را برمی‌گرداند که با فرض چهار `"0"` در ابتدا، ظاهراً big-endian به نظر می‌رسد. در واقع این نمایش بر اساس یک view واحد ۱۶ بیتی است، نه یک view از دو بایت ۸ بیتی. تست `DataView` بالا بهترین روش برای تشخیص endianness محیط JS شماست.

### چند View

یک buffer می‌تواند چند view هم‌زمان داشته باشد. مثل:

```js
var buf = new ArrayBuffer( 2 );

var view8 = new Uint8Array( buf );
var view16 = new Uint16Array( buf );

view16[0] = 3085;
view8[0];						// 13
view8[1];						// 12

view8[0].toString( 16 );		// "d"
view8[1].toString( 16 );		// "c"

// swap (as if endian!)
var tmp = view8[0];
view8[0] = view8[1];
view8[1] = tmp;

view16[0];						// 3340
```

سازنده‌های typed array چند امضای مختلف دارند. تا این‌جا فقط حالت پاس‌دادن buffer موجود را دیدیم. اما همان فرم دو پارامتر اضافه هم می‌گیرد: `byteOffset` و `length`. یعنی می‌توانید view typed array را از جایی غیر از `0` شروع کنید و الزاماً هم کل طول buffer را نپوشانید.

اگر buffer داده‌ی باینری شامل داده‌هایی با اندازه/جایگاه غیریکنواخت باشد، این تکنیک خیلی مفید است.

مثلاً buffer باینری‌ای را در نظر بگیرید که ابتدا یک عدد ۲ بایتی (یا "word") دارد، بعدش دو عدد ۱ بایتی، و بعد یک عدد شناور ۳۲ بیتی. این‌طور می‌توانید با چند view روی همان buffer، همراه offset و length، به داده‌ها دسترسی پیدا کنید:

```js
var first = new Uint16Array( buf, 0, 2 )[0],
	second = new Uint8Array( buf, 2, 1 )[0],
	third = new Uint8Array( buf, 3, 1 )[0],
	fourth = new Float32Array( buf, 4, 4 )[0];
```

### سازنده‌های TypedArray

علاوه بر فرم `(buffer,[offset, [length]])` که در بخش قبل دیدیم، سازنده‌های typed array از این فرم‌ها هم پشتیبانی می‌کنند:

* [constructor]`(length)`: یک view جدید روی یک buffer جدید با `length` بایت می‌سازد
* [constructor]`(typedArr)`: یک view و buffer جدید می‌سازد و محتوای view `typedArr` را کپی می‌کند
* [constructor]`(obj)`: یک view و buffer جدید می‌سازد و روی `obj` (آرایه‌مانند یا آبجکت) پیمایش می‌کند تا محتوا را کپی کند

سازنده‌های typed array زیر تا ES6 در دسترس هستند:

* `Int8Array` (اعداد صحیح علامت‌دار ۸ بیتی)، `Uint8Array` (اعداد صحیح بدون علامت ۸ بیتی)
	- `Uint8ClampedArray` (اعداد صحیح بدون علامت ۸ بیتی که هر مقدار هنگام set شدن به بازه‌ی `0` تا `255` clamp می‌شود)
* `Int16Array` (اعداد صحیح علامت‌دار ۱۶ بیتی)، `Uint16Array` (اعداد صحیح بدون علامت ۱۶ بیتی)
* `Int32Array` (اعداد صحیح علامت‌دار ۳۲ بیتی)، `Uint32Array` (اعداد صحیح بدون علامت ۳۲ بیتی)
* `Float32Array` (شناور ۳۲ بیتی، IEEE-754)
* `Float64Array` (شناور ۶۴ بیتی، IEEE-754)

نمونه‌های سازنده‌های typed array تقریباً شبیه آرایه‌های native معمولی هستند. بعضی تفاوت‌ها این است که طولشان ثابت است و همه‌ی مقدارها از یک «type» هستند.

با این حال، بیشتر متدهای `prototype` مشترک را دارند. بنابراین معمولاً می‌توانید بدون نیاز به تبدیل، مثل آرایه‌ی معمولی از آن‌ها استفاده کنید.

مثال:

```js
var a = new Int32Array( 3 );
a[0] = 10;
a[1] = 20;
a[2] = 30;

a.map( function(v){
	console.log( v );
} );
// 10 20 30

a.join( "-" );
// "10-20-30"
```

**هشدار:** بعضی متدهای `Array.prototype` که برای TypedArray معنا ندارند قابل استفاده نیستند؛ مثل متدهای تغییر‌دهنده (`splice(..)`، `push(..)` و ...) و `concat(..)`.

حواستان باشد عناصر TypedArray واقعاً به اندازه‌ی بیت اعلام‌شده محدود هستند. اگر `Uint8Array` داشته باشید و بخواهید مقداری بزرگ‌تر از ۸ بیت در یکی از عناصرش بگذارید، مقدار wrap می‌شود تا داخل همان طول بیت بماند.

این موضوع می‌تواند مشکل‌ساز شود؛ مثلاً اگر بخواهید همه‌ی مقادیر TypedArray را مربع کنید:

```js
var a = new Uint8Array( 3 );
a[0] = 10;
a[1] = 20;
a[2] = 30;

var b = a.map( function(v){
	return v * v;
} );

b;				// [100, 144, 132]
```

مقادیر `20` و `30` بعد از مربع شدن دچار سرریز بیت شدند. برای دور زدن این محدودیت می‌توانید از `TypedArray#from(..)` استفاده کنید:

```js
var a = new Uint8Array( 3 );
a[0] = 10;
a[1] = 20;
a[2] = 30;

var b = Uint16Array.from( a, function(v){
	return v * v;
} );

b;				// [100, 400, 900]
```

برای اطلاعات بیشتر درباره‌ی `Array.from(..)` که با TypedArray هم مشترک است، بخش «تابع ایستای `Array.from(..)`» در فصل ۶ را ببینید. به‌خصوص بخش «Mapping» که تابع نگاشتی آرگومان دوم را توضیح می‌دهد.

یک رفتار جالب این است که TypedArrayها هم مثل آرایه‌های معمولی متد `sort(..)` دارند، اما این یکی به‌صورت پیش‌فرض مقایسه‌ی عددی انجام می‌دهد، نه مقایسه‌ی واژگانی بر پایه‌ی رشته. مثال:

```js
var a = [ 10, 1, 2, ];
a.sort();								// [1,10,2]

var b = new Uint8Array( [ 10, 1, 2 ] );
b.sort();								// [1,2,10]
```

`TypedArray#sort(..)` هم مثل `Array#sort(..)` یک تابع مقایسه‌ی اختیاری می‌گیرد که دقیقاً همان‌طور کار می‌کند.
