# Feature Testing

feature test چیست؟ تستی است که اجرا می‌کنید تا بفهمید یک قابلیت وجود دارد یا نه. گاهی تست فقط برای وجود نیست، بلکه برای انطباق با رفتار مشخصات هم هست -- ممکن است قابلیت وجود داشته باشد ولی buggy باشد.

این یک تکنیک متاپروگرمینگ است: محیط اجرای برنامه را تست می‌کنید تا تصمیم بگیرید برنامه چطور باید رفتار کند.

رایج‌ترین استفاده‌ی feature test در JS بررسی وجود یک API است و اگر نبود، تعریف polyfill (فصل ۱). مثال:

```js
if (!Number.isNaN) {
	Number.isNaN = function(x) {
		return x !== x;
	};
}
```

دستور `if` در این مثال متاپروگرمینگ است: برنامه و محیط اجرای آن را probe می‌کنیم تا تعیین کنیم چطور ادامه بدهیم.

اما درباره‌ی قابلیت‌هایی که شامل syntax جدید هستند چه؟

ممکن است چیزی شبیه این امتحان کنید:

```js
try {
	a = () => {};
	ARROW_FUNCS_ENABLED = true;
}
catch (err) {
	ARROW_FUNCS_ENABLED = false;
}
```

متاسفانه این کار نمی‌کند، چون برنامه‌های JS کامپایل می‌شوند. اگر موتور از arrow function پشتیبانی نکند، روی سینتکس `() => {}` گیر می‌کند. خطای syntax باعث می‌شود برنامه اصلاً اجرا نشود و در نتیجه نتواند بعداً بر اساس وجود/عدم وجود قابلیت رفتار متفاوت نشان دهد.

برای feature test روی قابلیت‌های syntaxمحور، باید تست را از مرحله‌ی کامپایل اولیه‌ی برنامه ایزوله کنیم. مثلاً اگر کد تست را داخل رشته نگه داریم، موتور JS تا وقتی خودمان نخواهیم محتوای رشته را کامپایل نمی‌کند.

ذهن‌تان رفت سمت `eval(..)`؟

نه به این سرعت. در کتاب *Scope & Closures* می‌بینید چرا `eval(..)` ایده‌ی بدی است. گزینه‌ی کم‌هزینه‌تر داریم: سازنده‌ی `Function(..)`.

```js
try {
	new Function( "( () => {} )" );
	ARROW_FUNCS_ENABLED = true;
}
catch (err) {
	ARROW_FUNCS_ENABLED = false;
}
```

اینجا داریم متاپروگرمینگ می‌کنیم: تشخیص می‌دهیم قابلیتی مثل arrow function در موتور فعلی *قابل کامپایل* هست یا نه. سؤال بعدی این است که با این اطلاعات چه کنیم؟

در تست وجود API و polyfill fallback، مسیر عمل روشن است. اما وقتی `ARROW_FUNCS_ENABLED` `true/false` شد، کاربرد عملی‌اش چیست؟

چون اگر موتور از syntax پشتیبانی نکند، آن syntax نباید اصلاً داخل فایل باشد، نمی‌توانید به‌سادگی در همان فایل نسخه‌های مختلف تابع را تعریف کنید.

کاری که می‌شود کرد: با نتیجه‌ی تست تصمیم بگیرید کدام فایل JS بارگذاری شود. مثلاً اگر bootstrapper برنامه چند feature test داشته باشد، محیط را بررسی می‌کند تا تشخیص دهد آیا کد ES6 را مستقیم می‌توان لود/اجرا کرد یا باید نسخه‌ی transpiled (فصل ۱) را لود کرد.

به این تکنیک *split delivery* می‌گویند.

این تکنیک واقعیت را می‌پذیرد: برنامه‌ی ES6 شما گاهی در مرورگر ES6+ کاملاً «native» اجرا می‌شود، اما گاهی برای مرورگر pre-ES6 به transpilation نیاز دارد. اگر همیشه نسخه‌ی transpiled را لود کنید، حتی در محیط‌های ES6-سازگار هم بخشی از زمان کد زیر‌بهینه اجرا می‌کنید. این ایده‌آل نیست.

split delivery پیچیده‌تر و حرفه‌ای‌تر است، اما رویکرد بالغ‌تری برای پر کردن فاصله‌ی بین کدی که می‌نویسید و سطح پشتیبانی قابلیت‌ها در مرورگرهای مقصد است.

### FeatureTests.io

تعریف feature test برای تمام syntaxهای ES6+ و رفتارهای معنایی کاری سنگین است که احتمالاً دوست ندارید خودتان انجام دهید. چون این تست‌ها به کامپایل پویا (`new Function(..)`) نیاز دارند، هزینه‌ی کارایی ناخواسته هم دارند.

علاوه بر این، اجرای این تست‌ها در هر اجرای برنامه احتمالاً اتلاف است؛ چون مرورگر کاربر معمولاً هر چند هفته یک‌بار آپدیت می‌شود و حتی آن موقع هم لزوماً در هر نسخه قابلیت جدید اضافه نشده.

در نهایت، مدیریت فهرست feature testهای مرتبط با کدبیس خاص شما -- چون به‌ندرت برنامه‌ها تمام ES6 را استفاده می‌کنند -- دردسرساز و مستعد خطاست.

سرویس "https://featuretests.io" (feature-tests-as-a-service) برای این مشکلات راه‌حل ارائه می‌دهد.

می‌توانید کتابخانه‌ی سرویس را در صفحه لود کنید؛ آن آخرین تعریف تست‌ها را می‌گیرد و همه‌ی feature testها را اجرا می‌کند. اگر ممکن باشد با Web Worker در پس‌زمینه انجام می‌دهد تا هزینه‌ی کارایی کمتر شود. همچنین از LocalStorage استفاده می‌کند تا نتایج cache شوند و بین همه‌ی سایت‌هایی که از سرویس استفاده می‌کنند به اشتراک گذاشته شوند؛ در نتیجه دفعات اجرای تست در هر مرورگر به‌شدت کم می‌شود.

پس شما runtime feature test در مرورگر کاربران دارید و می‌توانید بر اساس نتیجه، برای هر کاربر مناسب‌ترین کد را (نه بیشتر، نه کمتر) ارسال کنید.

علاوه بر این، سرویس ابزار/API برای scan فایل‌ها و تشخیص قابلیت‌های مورد نیاز هم می‌دهد تا build process مربوط به split delivery را کاملاً خودکار کنید.

FeatureTests.io استفاده از feature test برای تمام بخش‌های ES6 و فراتر را عملی می‌کند تا مطمئن شوید برای هر محیط، بهترین کد ممکن بارگذاری و اجرا می‌شود.
