# مرور

متاپروگرمینگ یعنی منطق برنامه را معطوف به خود برنامه (یا محیط اجرای آن) کنیم؛ یا برای بازرسی ساختار خودش یا برای تغییر آن. ارزش اصلی متاپروگرمینگ این است که مکانیزم‌های معمول زبان را توسعه می‌دهد و قابلیت‌های اضافه می‌دهد.

قبل از ES6 هم JavaScript مقدار خوبی توان متاپروگرمینگ داشت، اما ES6 آن را با چند قابلیت جدید به‌طور چشم‌گیری تقویت کرد.

از استنتاج نام تابع برای تابع‌های بی‌نام تا meta propertyهایی که اطلاعاتی مثل نحوه‌ی فراخوانی سازنده را می‌دهند، حالا بیشتر از همیشه می‌شود ساختار برنامه را هنگام اجرا inspect کرد. Well-Known Symbolها اجازه‌ی override رفتارهای ذاتی را می‌دهند، مثل coercion آبجکت به primitive. Proxyها عملیات low-level مختلف روی آبجکت‌ها را intercept و سفارشی می‌کنند، و `Reflect` utilityهایی برای شبیه‌سازی همان عملیات می‌دهد.

Feature test حتی برای رفتارهای معنایی ظریف مثل Tail Call Optimization، تمرکز متاپروگرمینگ را از خود برنامه به قابلیت‌های موتور JS منتقل می‌کند. با دانستن بهترِ توان محیط، برنامه می‌تواند هنگام اجرا خودش را با بهترین حالت سازگار کند.

آیا باید متاپروگرمینگ کنید؟ توصیه‌ی من: اول روی فهم عمیق مکانیزم‌های هسته‌ای زبان تمرکز کنید. اما وقتی واقعاً فهمیدید JS خودش چه می‌تواند بکند، وقتش است از این قابلیت‌های قدرتمند متاپروگرمینگ برای جلو بردن زبان استفاده کنید.
