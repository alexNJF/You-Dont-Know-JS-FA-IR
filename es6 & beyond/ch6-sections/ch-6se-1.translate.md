# `Array`

یکی از قابلیت‌هایی که توسط کتابخانه‌های مختلف در JS زیاد توسعه داده شده، نوع `Array` است. بنابراین عجیب نیست که ES6 مجموعه‌ای از helperها را برای Array اضافه کرده؛ هم در سطح ایستا (static) و هم در سطح prototype (نمونه).

### تابع ایستای `Array.of(..)`

یک تله‌ی معروف در سازنده‌ی `Array(..)` این است که اگر فقط یک آرگومان بدهید و آن آرگومان عدد باشد، به‌جای این‌که آرایه‌ای با یک عنصرِ همان عدد بسازد، یک آرایه‌ی خالی با `length` برابر آن عدد می‌سازد. این رفتار همان «empty slot»های عجیب و بدنام آرایه‌های JS را ایجاد می‌کند.

`Array.of(..)` به‌عنوان شکل ترجیحیِ سازنده‌ی تابعی برای آرایه‌ها جای `Array(..)` را می‌گیرد، چون آن حالت خاص «یک آرگومانِ عددی» را ندارد. مثال:

```js
var a = Array( 3 );
a.length;						// 3
a[0];							// undefined

var b = Array.of( 3 );
b.length;						// 1
b[0];							// 3

var c = Array.of( 1, 2, 3 );
c.length;						// 3
c;								// [1,2,3]
```

چه زمانی `Array.of(..)` را به‌جای literal آرایه مثل `c = [1,2,3]` استفاده می‌کنیم؟ دو حالت ممکن است.

اگر callbackی دارید که باید آرگومان(ها)ی ورودی را داخل یک آرایه wrap کند، `Array.of(..)` دقیقاً مناسب است. خیلی رایج نیست، ولی گاهی به کار می‌آید.

سناریوی دیگر وقتی است که `Array` را subclass می‌کنید (بخش «Classes» در فصل ۳) و می‌خواهید نمونه‌ای از زیرکلاس خودتان را با عناصر اولیه بسازید:

```js
class MyCoolArray extends Array {
	sum() {
		return this.reduce( function reducer(acc,curr){
			return acc + curr;
		}, 0 );
	}
}

var x = new MyCoolArray( 3 );
x.length;						// 3 -- oops!
x.sum();						// 0 -- oops!

var y = [3];					// Array, not MyCoolArray
y.length;						// 1
y.sum();						// `sum` is not a function

var z = MyCoolArray.of( 3 );
z.length;						// 1
z.sum();						// 3
```

نمی‌توانید به سادگی سازنده‌ای برای `MyCoolArray` بنویسید که رفتار سازنده‌ی والد یعنی `Array` را override کند، چون همان سازنده برای ساخت آرایه‌ی درست‌رفتار (مقداردهی `this`) لازم است. متد ایستای inherited یعنی `of(..)` در زیرکلاس `MyCoolArray` راه‌حل تمیزی ارائه می‌دهد.

### تابع ایستای `Array.from(..)`

در JavaScript، «آبجکت شبه‌آرایه» آبجکتی است که ویژگی `length` دارد؛ به‌طور خاص با یک مقدار صحیحِ صفر یا بزرگ‌تر.

کار با این مقدارها در JS همیشه کمی آزاردهنده بوده است؛ معمولاً لازم می‌شد آن‌ها را به آرایه‌ی واقعی تبدیل کنیم تا متدهای `Array.prototype` (مثل `map(..)`، `indexOf(..)` و ...) رویشان قابل استفاده باشد. این کار معمولاً این‌طور انجام می‌شد:

```js
// array-like object
var arrLike = {
	length: 3,
	0: "foo",
	1: "bar"
};

var arr = Array.prototype.slice.call( arrLike );
```

کار رایج دیگر که `slice(..)` زیاد در آن استفاده می‌شود، کپی گرفتن از یک آرایه‌ی واقعی است:

```js
var arr2 = arr.slice();
```

در هر دو حالت، متد جدید ES6 یعنی `Array.from(..)` می‌تواند گزینه‌ای خواناتر و خوش‌دست‌تر باشد:

```js
var arr = Array.from( arrLike );

var arrCopy = Array.from( arr );
```

`Array.from(..)` اول بررسی می‌کند آرگومان اول iterable هست یا نه (بخش «Iteratorها» در فصل ۳). اگر iterable باشد، iterator آن برای تولید مقدارهایی که داخل آرایه‌ی خروجی «کپی» می‌شوند استفاده می‌شود. چون آرایه‌های واقعی iterator مقدار دارند، همان به‌صورت خودکار استفاده می‌شود.

اما اگر آرگومان اول یک آبجکت شبه‌آرایه باشد، رفتار `Array.from(..)` تقریباً مثل `slice()` بدون آرگومان یا `apply(..)` است؛ یعنی روی مقدار حلقه می‌زند و ویژگی‌های عددی از `0` تا مقدار `length` را می‌خواند.

مثال:

```js
var arrLike = {
	length: 4,
	2: "foo"
};

Array.from( arrLike );
// [ undefined, undefined, "foo", undefined ]
```

چون موقعیت‌های `0`، `1` و `3` در `arrLike` وجود نداشتند، خروجی برای این خانه‌ها `undefined` شد.

نتیجه‌ای مشابه را این‌طور هم می‌توانید بسازید:

```js
var emptySlotsArr = [];
emptySlotsArr.length = 4;
emptySlotsArr[2] = "foo";

Array.from( emptySlotsArr );
// [ undefined, undefined, "foo", undefined ]
```

#### پرهیز از Empty Slot

بین `emptySlotsArr` و خروجی `Array.from(..)` در مثال قبلی یک تفاوت ظریف ولی مهم وجود دارد: `Array.from(..)` هرگز empty slot تولید نمی‌کند.

قبل از ES6 اگر می‌خواستید آرایه‌ای با طول مشخص بسازید که واقعاً در هر خانه مقدار `undefined` داشته باشد (بدون empty slot)، باید کار اضافه می‌کردید:

```js
var a = Array( 4 );								// four empty slots!

var b = Array.apply( null, { length: 4 } );		// four `undefined` values
```

اما حالا `Array.from(..)` این کار را ساده کرده:

```js
var c = Array.from( { length: 4 } );			// four `undefined` values
```

**هشدار:** استفاده از آرایه‌ی دارای empty slot مثل `a` در مثال بالا ممکن است با بعضی توابع کار کند، اما بعضی دیگر (مثل `map(..)` و ...) آن‌ها را نادیده می‌گیرند. بهتر است عمداً با empty slot کار نکنید، چون احتمال زیادی دارد رفتار عجیب/غیرقابل‌پیش‌بینی در برنامه ایجاد کند.

#### Mapping

`Array.from(..)` یک قابلیت مفید دیگر هم دارد. آرگومان دوم (اگر داده شود) یک callback نگاشت است (تقریباً مشابه چیزی که `Array#map(..)` می‌خواهد) که هر مقدار منبع را به مقدار خروجی تبدیل می‌کند. مثال:

```js
var arrLike = {
	length: 4,
	2: "foo"
};

Array.from( arrLike, function mapper(val,idx){
	if (typeof val == "string") {
		return val.toUpperCase();
	}
	else {
		return idx;
	}
} );
// [ 0, 1, "FOO", 3 ]
```

**نکته:** مثل بقیه‌ی متدهای آرایه که callback می‌گیرند، `Array.from(..)` هم آرگومان سوم اختیاری دارد که اگر تنظیم شود، مقدار `this` برای callback آرگومان دوم را مشخص می‌کند. در غیر این صورت `this` برابر `undefined` است.

برای نمونه‌ای از استفاده‌ی `Array.from(..)` جهت تبدیل آرایه‌ای از مقادیر ۸ بیتی به آرایه‌ای از مقادیر ۱۶ بیتی، بخش «TypedArrayها» در فصل ۵ را ببینید.

### ساخت آرایه‌ها و زیرنوع‌ها

در دو بخش قبلی `Array.of(..)` و `Array.from(..)` را دیدیم که هر دو شبیه سازنده یک آرایه‌ی جدید می‌سازند. اما در زیرکلاس‌ها چه می‌شود؟ نمونه‌ی `Array` پایه ساخته می‌شود یا نمونه‌ی زیرکلاس مشتق؟

```js
class MyCoolArray extends Array {
	..
}

MyCoolArray.from( [1, 2] ) instanceof MyCoolArray;	// true

Array.from(
	MyCoolArray.from( [1, 2] )
) instanceof MyCoolArray;							// false
```

هر دو `of(..)` و `from(..)` از همان سازنده‌ای استفاده می‌کنند که از طریق آن فراخوانی شده‌اند. پس اگر `Array.of(..)` را استفاده کنید نمونه‌ی `Array` می‌گیرید، اما اگر `MyCoolArray.of(..)` را استفاده کنید نمونه‌ی `MyCoolArray` می‌گیرید.

در بخش «Classes» فصل ۳ گفتیم که کلاس‌های داخلی (مثل `Array`) تنظیم `@@species` دارند که متدهای prototype هنگام ساخت نمونه‌ی جدید از آن استفاده می‌کنند. `slice(..)` مثال خوبی است:

```js
var x = new MyCoolArray( 1, 2, 3 );

x.slice( 1 ) instanceof MyCoolArray;				// true
```

به‌طور کلی رفتار پیش‌فرض احتمالاً چیزی است که می‌خواهید، اما همان‌طور که در فصل ۳ گفتیم اگر بخواهید می‌توانید override کنید:

```js
class MyCoolArray extends Array {
	// force `species` to be parent constructor
	static get [Symbol.species]() { return Array; }
}

var x = new MyCoolArray( 1, 2, 3 );

x.slice( 1 ) instanceof MyCoolArray;				// false
x.slice( 1 ) instanceof Array;						// true
```

نکته‌ی مهم این است که تنظیم `@@species` فقط برای متدهای prototype مثل `slice(..)` استفاده می‌شود. برای `of(..)` و `from(..)` استفاده نمی‌شود؛ این دو فقط از `this` binding استفاده می‌کنند (هر سازنده‌ای که reference با آن ساخته شده). مثال:

```js
class MyCoolArray extends Array {
	// force `species` to be parent constructor
	static get [Symbol.species]() { return Array; }
}

var x = new MyCoolArray( 1, 2, 3 );

MyCoolArray.from( x ) instanceof MyCoolArray;		// true
MyCoolArray.of( [2, 3] ) instanceof MyCoolArray;	// true
```

### متد prototype به نام `copyWithin(..)`

`Array#copyWithin(..)` یک متد mutator جدید است که برای همه‌ی آرایه‌ها در دسترس است (از جمله TypedArrayها؛ فصل ۵). این متد بخشی از آرایه را به جای دیگری در همان آرایه کپی می‌کند و مقدار قبلی آن بخش را overwrite می‌کند.

آرگومان‌ها به‌ترتیب *target* (اندیس مقصد)، *start* (اندیس شروع کپی، شامل خودش) و *end* اختیاری (اندیس پایان کپی، بدون خودش) هستند. اگر هر آرگومان منفی باشد، نسبت به انتهای آرایه محاسبه می‌شود.

مثال:

```js
[1,2,3,4,5].copyWithin( 3, 0 );			// [1,2,3,1,2]

[1,2,3,4,5].copyWithin( 3, 0, 1 );		// [1,2,3,1,5]

[1,2,3,4,5].copyWithin( 0, -2 );		// [4,5,3,4,5]

[1,2,3,4,5].copyWithin( 0, -2, -1 );	// [4,2,3,4,5]
```

متد `copyWithin(..)` طول آرایه را افزایش نمی‌دهد؛ همان‌طور که در مثال اول دیدید. کپی‌کردن وقتی به انتهای آرایه برسد متوقف می‌شود.

برخلاف چیزی که ممکن است فکر کنید، کپی همیشه از چپ به راست (اندیس صعودی) انجام نمی‌شود. اگر بازه‌ی منبع و مقصد overlap داشته باشند، حرکت ساده‌ی چپ‌به‌راست می‌تواند باعث شود یک مقدارِ ازقبل‌کپی‌شده دوباره کپی شود که معمولاً مطلوب نیست.

برای همین الگوریتم داخلی در این حالت جهت را برعکس می‌کند تا از این مشکل جلوگیری شود. مثال:

```js
[1,2,3,4,5].copyWithin( 2, 1 );		// ???
```

اگر الگوریتم کاملاً چپ‌به‌راست بود، `2` روی `3` نوشته می‌شد، بعد همان `2` روی `4`، بعد همان `2` روی `5`، و خروجی `[1,2,2,2,2]` می‌شد.

اما الگوریتم واقعی جهت را برعکس می‌کند: اول `4` روی `5`، بعد `3` روی `4`، بعد `2` روی `3`، و نتیجه‌ی نهایی `[1,2,2,3,4]` می‌شود. از نظر انتظار رفتاری این معمولاً «درست‌تر» است، ولی اگر الگوریتم را ساده‌لوحانه چپ‌به‌راست تصور کنید ممکن است گیج‌کننده باشد.

### متد prototype به نام `fill(..)`

پر کردن کل آرایه (یا بخشی از آن) با یک مقدار مشخص، از ES6 به‌صورت بومی با `Array#fill(..)` پشتیبانی می‌شود:

```js
var a = Array( 4 ).fill( undefined );
a;
// [undefined,undefined,undefined,undefined]
```

`fill(..)` می‌تواند پارامترهای اختیاری *start* و *end* هم بگیرد تا فقط بخشی از آرایه پر شود:

```js
var a = [ null, null, null, null ].fill( 42, 1, 3 );

a;									// [null,42,42,null]
```

### متد prototype به نام `find(..)`

رایج‌ترین روش جست‌وجوی مقدار در آرایه معمولاً `indexOf(..)` بوده که اندیس مقدار را برمی‌گرداند، یا اگر پیدا نشود `-1`:

```js
var a = [1,2,3,4,5];

(a.indexOf( 3 ) != -1);				// true
(a.indexOf( 7 ) != -1);				// false

(a.indexOf( "2" ) != -1);			// false
```

مقایسه‌ی `indexOf(..)` نیازمند تطابق strict با `===` است؛ پس جست‌وجوی `"2"` مقدار `2` را پیدا نمی‌کند و برعکس. ضمن این‌که الگوریتم تطابق در `indexOf(..)` قابل override نیست. همچنین نیاز به مقایسه‌ی دستی با `-1` هم چندان خوش‌فرم نیست.

**نکته‌ی کاربردی:** در کتاب *Types & Grammar* این مجموعه یک ترفند جالب (و تا حدی بحث‌برانگیز) با عملگر `~` برای دور زدن زشتی `-1` مطرح شده است.

از ES5 به بعد، workaround رایج برای کنترل منطق تطبیق، متد `some(..)` بوده است. این متد برای هر عنصر callback را صدا می‌زند تا وقتی یکی از فراخوانی‌ها `true`/truthy برگرداند، سپس متوقف می‌شود. چون callback را خودتان می‌نویسید، کنترل کامل منطق match را دارید:

```js
var a = [1,2,3,4,5];

a.some( function matcher(v){
	return v == "2";
} );								// true

a.some( function matcher(v){
	return v == 7;
} );								// false
```

اما ضعف این روش این است که فقط `true/false` می‌گیرید و خودِ مقدار match‌شده را دریافت نمی‌کنید.

`find(..)` در ES6 همین مشکل را حل می‌کند. تقریباً مثل `some(..)` کار می‌کند، با این تفاوت که وقتی callback مقدار `true`/truthy برگرداند، خودِ مقدار آرایه برگردانده می‌شود:

```js
var a = [1,2,3,4,5];

a.find( function matcher(v){
	return v == "2";
} );								// 2

a.find( function matcher(v){
	return v == 7;					// undefined
});
```

استفاده از تابع `matcher(..)` سفارشی همچنین اجازه می‌دهد با مقادیر پیچیده مثل آبجکت‌ها match کنید:

```js
var points = [
	{ x: 10, y: 20 },
	{ x: 20, y: 30 },
	{ x: 30, y: 40 },
	{ x: 40, y: 50 },
	{ x: 50, y: 60 }
];

points.find( function matcher(point) {
	return (
		point.x % 3 == 0 &&
		point.y % 4 == 0
	);
} );								// { x: 30, y: 40 }
```

**نکته:** مثل بقیه‌ی متدهای آرایه که callback می‌گیرند، `find(..)` هم آرگومان دوم اختیاری دارد که اگر تنظیم شود، مقدار `this` برای callback آرگومان اول را تعیین می‌کند. در غیر این صورت `this` برابر `undefined` است.

### متد prototype به نام `findIndex(..)`

در بخش قبل دیدیم `some(..)` نتیجه‌ی بولی جست‌وجوی آرایه را می‌دهد و `find(..)` خودِ مقدار match‌شده را. اما گاهی لازم است اندیس موقعیت مقدار match‌شده را داشته باشیم.

`indexOf(..)` این کار را می‌کند، ولی منطق match آن قابل کنترل نیست و همیشه `===` strict را استفاده می‌کند. بنابراین پاسخ ES6 متد `findIndex(..)` است:

```js
var points = [
	{ x: 10, y: 20 },
	{ x: 20, y: 30 },
	{ x: 30, y: 40 },
	{ x: 40, y: 50 },
	{ x: 50, y: 60 }
];

points.findIndex( function matcher(point) {
	return (
		point.x % 3 == 0 &&
		point.y % 4 == 0
	);
} );								// 2

points.findIndex( function matcher(point) {
	return (
		point.x % 6 == 0 &&
		point.y % 7 == 0
	);
} );								// -1
```

برای گرفتن مقدار بولی جست‌وجو از `findIndex(..) != -1` استفاده نکنید (روش قدیمی با `indexOf(..)`)، چون `some(..)` همین `true/false` را مستقیم می‌دهد. و `a[ a.findIndex(..) ]` هم برای گرفتن مقدار match‌شده انجام ندهید، چون `find(..)` دقیقاً برای همین است. در نهایت: اگر اندیس تطبیق strict می‌خواهید `indexOf(..)`، و اگر اندیس تطبیق سفارشی می‌خواهید `findIndex(..)` را استفاده کنید.

**نکته:** مثل بقیه‌ی متدهای callback‌دار آرایه، `findIndex(..)` هم آرگومان دوم اختیاری برای تعیین `this` callback آرگومان اول می‌گیرد؛ در غیر این صورت `this` برابر `undefined` است.

### متدهای prototype: `entries()`، `values()`، `keys()`

در فصل ۳ دیدیم ساختارهای داده می‌توانند از طریق iterator، پیمایش آیتم‌به‌آیتمِ الگو‌مند روی مقدارهایشان ارائه دهند. بعد در فصل ۵ این موضوع را بسط دادیم و دیدیم کالکشن‌های جدید ES6 (مثل Map، Set و ...) چند متد برای تولید انواع مختلف پیمایش دارند.

هرچند `Array` جدیدِ ES6 نیست، معمولاً به‌صورت سنتی آن را «کالکشن» نمی‌بینند؛ ولی از این نظر کالکشن محسوب می‌شود که همین متدهای iterator را دارد: `entries()`، `values()` و `keys()`. مثال:

```js
var a = [1,2,3];

[...a.values()];					// [1,2,3]
[...a.keys()];						// [0,1,2]
[...a.entries()];					// [ [0,1], [1,2], [2,3] ]

[...a[Symbol.iterator]()];			// [1,2,3]
```

مثل `Set`، iterator پیش‌فرض `Array` همان چیزی است که `values()` برمی‌گرداند.

در بخش «پرهیز از Empty Slot» همین فصل دیدیم `Array.from(..)` با empty slotها طوری برخورد می‌کند که انگار خانه‌ی موجود با مقدار `undefined` هستند. دلیلش این است که iteratorهای آرایه زیر پوسته همین رفتار را دارند:

```js
var a = [];
a.length = 3;
a[1] = 2;

[...a.values()];		// [undefined,2,undefined]
[...a.keys()];			// [0,1,2]
[...a.entries()];		// [ [0,undefined], [1,2], [2,undefined] ]
```
