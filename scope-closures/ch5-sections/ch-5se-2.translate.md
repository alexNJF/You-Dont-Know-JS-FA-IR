# Hoisting: استعارهٔ دیگری

فصل ۲ پر از استعاره بود (برای ترسیم scope)، اما اینجا با استعارهٔ دیگری مواجهیم: خود hoisting. به‌جای اینکه hoisting یک مرحلهٔ اجرای مشخص باشد که موتور جاوااسکریپت انجام می‌دهد، مفیدتر است hoisting را به‌عنوان تجسمی از اقدامات مختلفی که جاوااسکریپت در تنظیم برنامه **قبل از اجرا** انجام می‌دهد در نظر بگیریم.

ادعای معمول معنای hoisting: *بلند کردن*—مثل بلند کردن وزنهٔ سنگین به سمت بالا—تمام شناسه‌ها تا بالای scope. توضیحی که اغلب ادعا می‌شود این است که موتور جاوااسکریپت در واقع آن برنامه را قبل از اجرا *بازنویسی* می‌کند، تا بیشتر شبیه این به نظر برسد:

```js
var greeting;           // hoisted declaration
greeting = "Hello!";    // the original line 1
console.log(greeting);  // Hello!
greeting = "Howdy!";    // `var` is gone!
```

hoisting (استعاره) پیشنهاد می‌کند که جاوااسکریپت برنامهٔ اصلی را پیش‌پردازش و کمی بازچینش می‌کند، تا تمام اعلان‌ها به بالای scopeهای مربوطه منتقل شده باشند، قبل از اجرا. علاوه بر این، استعارهٔ hoisting ادعا می‌کند که اعلان‌های `function` به‌طور کامل به بالای هر scope hoist می‌شوند. در نظر بگیرید:

```js
studentName = "Suzy";
greeting();
// Hello Suzy!

function greeting() {
    console.log(`Hello ${ studentName }!`);
}
var studentName;
```

«قانون» استعارهٔ hoisting این است که اعلان‌های تابع اول hoist می‌شوند، سپس متغیرها بلافاصله بعد از تمام توابع hoist می‌شوند. بنابراین، داستان hoisting پیشنهاد می‌کند که برنامه توسط موتور جاوااسکریپت *بازچینش* می‌شود تا شبیه این به نظر برسد:

```js
function greeting() {
    console.log(`Hello ${ studentName }!`);
}
var studentName;

studentName = "Suzy";
greeting();
// Hello Suzy!
```

این استعارهٔ hoisting راحت است. مزیتش اجازه دادن به ما برای hand wave روی پیش‌پردازش look-ahead جادویی لازم برای پیدا کردن تمام این اعلان‌های دفن‌شده در عمق scopeها و به نوعی جابه‌جایی (hoist) آن‌ها به بالا است؛ می‌توانیم فقط برنامه را طوری فکر کنیم انگار توسط موتور جاوااسکریپت در **یک گذر**، از بالا به پایین اجرا می‌شود.

Single-pass قطعاً ساده‌تر از ادعای فصل ۱ دربارهٔ پردازش دو فازی به نظر می‌رسد.

hoisting به‌عنوان مکانیزمی برای بازترتیب‌دهی کد ممکن است ساده‌سازی جذابی باشد، اما دقیق نیست. موتور جاوااسکریپت در واقع کد را بازچینش نمی‌کند. نمی‌تواند جادویی look ahead کند و اعلان‌ها را پیدا کند؛ تنها راه پیدا کردن دقیق آن‌ها، و همچنین تمام مرزهای scope در برنامه، parse کامل کد است.

حدس بزنید parsing چیست؟ فاز اول پردازش دو فازی! هیچ ژیمناستیک ذهنی جادویی نیست که از آن واقعیت جلوگیری کند.

پس اگر استعارهٔ hoisting (در بهترین حالت) نادقیق است، با این اصطلاح چه کنیم؟ فکر می‌کنم هنوز مفید است—در واقع، حتی اعضای TC39 همیشه از آن استفاده می‌کنند!—اما فکر نمی‌کنم باید ادعا کنیم بازچینش واقعی کد منبع است.

| WARNING: |
| :--- |
| مدل‌های ذهنی نادرست یا ناقص اغلب هنوز کافی به نظر می‌رسند چون گاهی می‌توانند منجر به پاسخ‌های تصادفی درست شوند. اما در بلندمدت سخت‌تر است اگر تفکرتان به‌طور خاص با نحوهٔ کار موتور جاوااسکریپت هم‌راستا نباشد نتایج را به‌درستی تحلیل و پیش‌بینی کنید. |

ادعا می‌کنم hoisting *باید* برای اشاره به **عملیات زمان کامپایل** تولید دستورالعمل‌های runtime برای ثبت خودکار متغیر در ابتدای scopeاش، هر بار که آن scope وارد می‌شود، استفاده شود.

این تغییر ظریف اما مهمی است، از hoisting به‌عنوان رفتار runtime به جای مناسبش در میان وظایف زمان کامپایل.
