# زبان کامپایلر

با آگاهی از پردازش دو فازی یک برنامهٔ جاوااسکریپت (کامپایل، سپس اجرا)، بیایید توجه خود را به نحوهٔ شناسایی متغیرها و تعیین scopeهای برنامه توسط موتور جاوااسکریپت در حین کامپایل معطوف کنیم.

اول، یک برنامهٔ سادهٔ جاوااسکریپت را برای تحلیل در چند فصل بعد بررسی کنیم:

```js
var students = [
    { id: 14, name: "Kyle" },
    { id: 73, name: "Suzy" },
    { id: 112, name: "Frank" },
    { id: 6, name: "Sarah" }
];

function getStudentName(studentID) {
    for (let student of students) {
        if (student.id == studentID) {
            return student.name;
        }
    }
}

var nextStudent = getStudentName(73);

console.log(nextStudent);
// Suzy
```

به‌جز اعلان‌ها، تمام رخدادهای متغیرها/شناسه‌ها در یک برنامه در یکی از دو «نقش» عمل می‌کنند: یا *هدف* یک انتساب هستند یا *منبع* یک مقدار.

(وقتی اولین بار نظریهٔ کامپایلر را هنگام گرفتن مدرک علوم کامپیوتر یاد گرفتم، اصطلاحات «LHS» (یعنی *هدف*) و «RHS» (یعنی *منبع*) را برای این نقش‌ها به ما آموختند. همانطور که از «L» و «R» حدس می‌زنید، این مخفف‌ها به معنای «سمت چپ» و «سمت راست» هستند، یعنی سمت چپ و راست عملگر انتساب `=`. با این حال، اهداف و منابع انتساب همیشه به‌طور تحت‌اللفظی در چپ یا راست `=` ظاهر نمی‌شوند، پس احتمالاً واضح‌تر است به‌جای چپ/راست به *هدف*/*منبع* فکر کنیم.)

چطور می‌فهمید یک متغیر *هدف* است؟ بررسی کنید آیا مقداری به آن انتساب می‌شود؛ اگر بله، *هدف* است. اگر نه، متغیر *منبع* است.

برای اینکه موتور جاوااسکریپت به‌درستی متغیرهای برنامه را مدیریت کند، باید ابتدا هر رخداد متغیر را به‌عنوان *هدف* یا *منبع* برچسب بزند. اکنون به چگونگی تعیین هر نقش می‌پردازیم.

### اهداف

چه چیزی یک متغیر را *هدف* می‌کند؟ در نظر بگیرید:

```js
students = [ // ..
```

این عبارت به‌وضوح یک عملیات انتساب است؛ به یاد داشته باشید، بخش `var students` به‌طور کامل به‌عنوان اعلان در زمان کامپایل مدیریت می‌شود، و بنابراین در حین اجرا نامربوط است؛ برای وضوح و تمرکز آن را حذف کردیم. همینطور با عبارت `nextStudent = getStudentName(73)`.

اما سه عملیات انتساب *هدف* دیگر در کد وجود دارد که شاید کمتر آشکار باشند. یکی از آن‌ها:

```js
for (let student of students) {
```

این عبارت برای هر تکرار حلقه مقداری به `student` انتساب می‌دهد. ارجاع *هدف* دیگر:

```js
getStudentName(73)
```

اما چطور این یک انتساب به *هدف* است؟ دقیق نگاه کنید: آرگومان `73` به پارامتر `studentID` انتساب داده می‌شود.

و یک ارجاع *هدف* آخر (ظریف) در برنامهٔ ما وجود دارد. می‌توانید آن را پیدا کنید؟

..

..

..

این یکی را شناسایی کردید؟

```js
function getStudentName(studentID) {
```

اعلان `function` حالت خاصی از ارجاع *هدف* است. می‌توانید آن را تقریباً مثل `var getStudentName = function(studentID)` در نظر بگیرید، اما دقیق نیست. یک شناسهٔ `getStudentName` (در زمان کامپایل) اعلان می‌شود، اما بخش `= function(studentID)` نیز در کامپایل مدیریت می‌شود؛ ارتباط بین `getStudentName` و تابع به‌طور خودکار در ابتدای scope تنظیم می‌شود به‌جای انتظار برای اجرای عبارت انتساب `=`.

| NOTE: |
| :--- |
| این ارتباط خودکار تابع و متغیر به «function hoisting» اشاره دارد، و در فصل ۵ با جزئیات پوشش داده می‌شود. |

### منابع

پس هر پنج ارجاع *هدف* را در برنامه شناسایی کردیم. ارجاع‌های متغیر دیگر باید پس *منبع* باشند (چون تنها گزینهٔ دیگر است!).

در `for (let student of students)`، گفتیم که `student` *هدف* است، اما `students` ارجاع *منبع* است. در عبارت `if (student.id == studentID)`، هر دو `student` و `studentID` ارجاع *منبع* هستند. `student` در `return student.name` نیز ارجاع *منبع* است.

در `getStudentName(73)`، `getStudentName` ارجاع *منبع* است (که امیدواریم به مقدار مرجع تابع resolve شود). در `console.log(nextStudent)`، `console` ارجاع *منبع* است، و `nextStudent` هم همینطور.

| NOTE: |
| :--- |
| در صورتی که کنجکاو بودید، `id`، `name` و `log` همگی property هستند، نه ارجاع متغیر. |

اهمیت عملی درک *اهداف* در مقابل *منابع* چیست؟ در فصل ۲، این موضوع را مرور می‌کنیم و نحوهٔ تأثیر نقش متغیر بر جستجوی آن را پوشش می‌دهیم (به‌طور خاص، اگر جستجو ناموفق باشد).
