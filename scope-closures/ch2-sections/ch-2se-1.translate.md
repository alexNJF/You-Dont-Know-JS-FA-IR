# تیله‌ها، سطل‌ها و حباب‌ها... وای!

یک استعارهٔ مؤثر که برای درک scope پیدا کرده‌ام، مرتب کردن تیله‌های رنگی در سطل‌های هم‌رنگ است.

تصور کنید به توده‌ای از تیله‌ها برخورد می‌کنید و متوجه می‌شوید همهٔ تیله‌ها قرمز، آبی یا سبز هستند. بیایید همهٔ تیله‌ها را مرتب کنیم، قرمزها را در سطل قرمز، سبزها را در سطل سبز و آبی‌ها را در سطل آبی بریزیم. بعد از مرتب‌سازی، وقتی بعداً به یک تیلهٔ سبز نیاز دارید، از قبل می‌دانید سطل سبز جایی است که باید بروید.

در این استعاره، تیله‌ها متغیرهای برنامهٔ ما هستند. سطل‌ها scopeها (توابع و بلوک‌ها) هستند، که فقط برای اهداف بحث رنگ‌های جداگانه به آن‌ها نسبت می‌دهیم. رنگ هر تیله بنابراین توسط scope *رنگی* که تیله در آن ایجاد شده تعیین می‌شود.

بیایید مثال برنامهٔ در حال اجرا از فصل ۱ را با برچسب‌های رنگی scope حاشیه‌نویسی کنیم:

```js
// outer/global scope: RED

var students = [
    { id: 14, name: "Kyle" },
    { id: 73, name: "Suzy" },
    { id: 112, name: "Frank" },
    { id: 6, name: "Sarah" }
];

function getStudentName(studentID) {
    // function scope: BLUE

    for (let student of students) {
        // loop scope: GREEN

        if (student.id == studentID) {
            return student.name;
        }
    }
}

var nextStudent = getStudentName(73);
console.log(nextStudent);   // Suzy
```

سه رنگ scope را با کامنت‌های کد مشخص کردیم: RED (scope سراسری بیرونی‌ترین)، BLUE (scope تابع `getStudentName(..)`) و GREEN (scope حلقهٔ `for`/داخل آن). اما هنوز ممکن است تشخیص مرزهای این سطل‌های scope هنگام نگاه به لیست کد دشوار باشد.

شکل ۲ مرزهای scopeها را با رسم حباب‌های رنگی (یعنی سطل‌ها) دور هر کدام تجسم می‌کند:

1. **حباب ۱** (RED) scope سراسری را در بر می‌گیرد، که سه شناسه/متغیر دارد: `students` (خط ۱)، `getStudentName` (خط ۸) و `nextStudent` (خط ۱۶).

2. **حباب ۲** (BLUE) scope تابع `getStudentName(..)` (خط ۸) را در بر می‌گیرد، که فقط یک شناسه/متغیر دارد: پارامتر `studentID` (خط ۸).

3. **حباب ۳** (GREEN) scope حلقهٔ `for` (خط ۹) را در بر می‌گیرد، که فقط یک شناسه/متغیر دارد: `student` (خط ۹).

| NOTE: |
| :--- |
| از نظر فنی، پارامتر `studentID` دقیقاً در scope BLUE(2) نیست. این سردرگمی را در «Implied Scopes» پیوست الف باز می‌کنیم. فعلاً برای برچسب زدن `studentID` به عنوان تیلهٔ BLUE(2) کافی است. |

حباب‌های scope در حین کامپایل بر اساس محل نوشته شدن توابع/بلوک‌های scope، تودرتویی داخل یکدیگر و غیره تعیین می‌شوند. هر حباب scope کاملاً درون حباب scope والدش قرار دارد—یک scope هرگز جزئی در دو scope بیرونی مختلف نیست.

هر تیله (متغیر/شناسه) بر اساس حباب (سطل) که در آن اعلان شده رنگ می‌گیرد، نه رنگ scope که ممکن است از آن دسترسی داشته باشد (مثلاً `students` در خط ۹ و `studentID` در خط ۱۰).

| NOTE: |
| :--- |
| به یاد داشته باشید در فصل ۱ ادعا کردیم که `id`، `name` و `log` همگی property هستند، نه متغیر؛ به عبارت دیگر، تیله در سطل نیستند، پس بر اساس قوانینی که در این کتاب بحث می‌کنیم رنگ نمی‌گیرند. برای فهم نحوهٔ برخورد با چنین دسترسی‌های property، کتاب سوم مجموعه، *اشیاء و کلاس‌ها* را ببینید. |

وقتی موتور جاوااسکریپت برنامه را پردازش می‌کند (در حین کامپایل) و اعلان متغیری پیدا می‌کند، اساساً می‌پرسد: «الان در scope *رنگی* (حباب یا سطل) کدام هستم؟» متغیر همان *رنگ* تعیین می‌شود، یعنی به آن سطل/حباب تعلق دارد.

سطل GREEN(3) کاملاً درون سطل BLUE(2) تو در تو است، و به همین ترتیب سطل BLUE(2) کاملاً درون سطل RED(1) تو در تو است. scopeها می‌توانند همانطور که نشان داده شد داخل یکدیگر تو در تو شوند، تا هر عمق تودرتویی که برنامه نیاز دارد.

ارجاع‌ها (غیر از اعلان‌ها) به متغیرها/شناسه‌ها مجاز هستند اگر اعلان مطابقی در scope فعلی یا هر scope بالاتر/بیرون از scope فعلی وجود داشته باشد، اما نه با اعلان‌های scopeهای پایین‌تر/تو در تو.

یک عبارت در سطل RED(1) فقط به تیله‌های RED(1) دسترسی دارد، **نه** BLUE(2) یا GREEN(3). یک عبارت در سطل BLUE(2) می‌تواند به تیله‌های BLUE(2) یا RED(1) ارجاع دهد، **نه** GREEN(3). و یک عبارت در سطل GREEN(3) به تیله‌های RED(1)، BLUE(2) و GREEN(3) دسترسی دارد.

می‌توانیم فرآیند تعیین این رنگ‌های تیلهٔ غیر-اعلانی در حین اجرا را به‌عنوان یک جستجو مفهوم‌سازی کنیم. چون ارجاع متغیر `students` در عبارت حلقهٔ `for` در خط ۹ اعلان نیست، رنگ ندارد. پس از سطل scope BLUE(2) فعلی می‌پرسیم آیا تیلهٔ مطابق آن نام دارد. چون ندارد، جستجو با scope بیرونی/محصورکنندهٔ بعدی ادامه می‌یابد: RED(1). سطل RED(1) تیله‌ای به نام `students` دارد، پس ارجاع متغیر `students` در عبارت حلقه به‌عنوان تیلهٔ RED(1) تعیین می‌شود.

عبارت `if (student.id == studentID)` در خط ۱۰ به همین ترتیب تعیین می‌شود که به تیلهٔ GREEN(3) به نام `student` و تیلهٔ BLUE(2) به نام `studentID` ارجاع می‌دهد.

| NOTE: |
| :--- |
| موتور جاوااسکریپت عموماً این رنگ‌های تیله را در زمان اجرا تعیین نمی‌کند؛ «جستجو» اینجا یک ابزار بلاغی برای کمک به درک مفاهیم است. در حین کامپایل، اکثر یا تمام ارجاع‌های متغیر با سطل‌های scope از قبل شناخته‌شده مطابقت خواهند داشت، پس رنگ آن‌ها از قبل تعیین و با هر ارجاع تیله ذخیره می‌شود تا از جستجوهای غیرضروری در حین اجرای برنامه جلوگیری شود. بیشتر دربارهٔ این ظرافت در فصل ۳. |

نکات کلیدی از تیله‌ها و سطل‌ها (و حباب‌ها!):

* متغیرها در scopeهای خاص اعلان می‌شوند، که می‌توان آن‌ها را به‌عنوان تیله‌های رنگی از سطل‌های هم‌رنگ در نظر گرفت.

* هر ارجاع متغیر که در scope اعلانش ظاهر می‌شود، یا در هر scope تو در توتر ظاهر می‌شود، با همان رنگ تیله برچسب می‌خورد—مگر اینکه scope میانی متغیر را «سایه» بیندازد؛ «Shadowing» را در فصل ۳ ببینید.

* تعیین سطل‌های رنگی و تیله‌هایی که شامل می‌شوند در حین کامپایل اتفاق می‌افتد. این اطلاعات برای «جستجوهای» متغیر (رنگ تیله) در حین اجرای کد استفاده می‌شود.
