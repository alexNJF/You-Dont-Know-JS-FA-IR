# گفتگویی میان دوستان

استعارهٔ مفید دیگر برای فرآیند تحلیل متغیرها و scopeهایی که از آن‌ها می‌آیند، تصور گفتگوهای مختلفی است که داخل موتور در حین پردازش و سپس اجرای کد اتفاق می‌افتد. می‌توانیم به این گفتگوها «گوش دهیم» تا بنیان مفهومی بهتری از نحوهٔ کار scopeها داشته باشیم.

اکنون اعضای موتور جاوااسکریپت را ملاقات کنیم که در حین پردازش برنامهٔ ما گفتگو خواهند داشت:

* *Engine*: مسئول کامپایل و اجرای برنامهٔ جاوااسکریپت ما از ابتدا تا انتها.

* *Compiler*: یکی از دوستان *Engine*؛ تمام کار کثیف parsing و code-generation را انجام می‌دهد (بخش قبل را ببینید).

* *Scope Manager*: دوست دیگر *Engine*؛ لیست جستجوی تمام متغیرها/شناسه‌های اعلان‌شده را جمع‌آوری و نگهداری می‌کند، و مجموعه‌ای از قوانین را دربارهٔ نحوهٔ دسترسی کد در حال اجرا به آن‌ها اعمال می‌کند.

برای *درک کامل* نحوهٔ کار جاوااسکریپت، باید شروع کنید *فکر* کنید مثل *Engine* (و دوستانش)، سوالاتی که می‌پرسند را بپرسید، و به سوالاتشان همانطور پاسخ دهید.

برای کاوش این گفتگوها، دوباره مثال برنامهٔ در حال اجرایمان را به یاد آورید:

```js
var students = [
    { id: 14, name: "Kyle" },
    { id: 73, name: "Suzy" },
    { id: 112, name: "Frank" },
    { id: 6, name: "Sarah" }
];

function getStudentName(studentID) {
    for (let student of students) {
        if (student.id == studentID) {
            return student.name;
        }
    }
}

var nextStudent = getStudentName(73);

console.log(nextStudent);
// Suzy
```

بیایید ببینیم جاوااسکریپت چطور این برنامه را پردازش می‌کند، به‌طور خاص با اولین عبارت شروع کنیم. آرایه و محتویاتش فقط literalهای مقدار پایهٔ جاوااسکریپت هستند (و بنابراین تحت تأثیر نگرانی‌های scope نیستند)، پس تمرکز ما اینجا روی بخش‌های اعلان و انتساب-مقداردهی اولیهٔ `var students = [ .. ]` خواهد بود.

معمولاً آن را یک عبارت واحد می‌دانیم، اما دوست ما *Engine* اینطور نمی‌بیند. در واقع، جاوااسکریپت این‌ها را دو عملیات مجزا تلقی می‌کند، یکی که *Compiler* در حین کامپایل مدیریت می‌کند، و دیگری که *Engine* در حین اجرا مدیریت می‌کند.

اولین کاری که *Compiler* با این برنامه انجام می‌دهد lexing برای شکستن آن به tokenها است، که سپس آن‌ها را به درخت (AST) parse می‌کند.

وقتی *Compiler* به code generation می‌رسد، جزئیات بیشتری برای در نظر گرفتن وجود دارد که شاید آشکار نباشد. فرض معقول این است که *Compiler* کدی برای اولین عبارت تولید کند مثل: «حافظه برای متغیر اختصاص بده، آن را `students` برچسب بزن، سپس مرجع آرایه را در آن متغیر قرار بده.» اما این کل داستان نیست.

مراحلی که *Compiler* برای مدیریت آن عبارت دنبال می‌کند:

1. با برخورد به `var students`، *Compiler* از *Scope Manager* می‌پرسد آیا متغیری به نام `students` از قبل برای آن سطل scope خاص وجود دارد. اگر بله، *Compiler* این اعلان را نادیده می‌گیرد و ادامه می‌دهد. در غیر این صورت، *Compiler* کدی تولید می‌کند که (در زمان اجرا) از *Scope Manager* می‌خواهد متغیر جدیدی به نام `students` در آن سطل scope ایجاد کند.

2. *Compiler* سپس کدی برای *Engine* برای اجرای بعدی تولید می‌کند، برای مدیریت انتساب `students = []`. کدی که *Engine* اجرا می‌کند ابتدا از *Scope Manager* می‌پرسد آیا متغیری به نام `students` در سطل scope فعلی قابل دسترسی است. اگر نه، *Engine* جای دیگر جستجو می‌کند («Nested Scope» را در زیر ببینید). وقتی *Engine* متغیر را پیدا کرد، مرجع آرایهٔ `[ .. ]` را به آن انتساب می‌دهد.

به شکل گفتگویی، فاز اول کامپایل برنامه ممکن است بین *Compiler* و *Scope Manager* اینطور پیش برود:

> ***Compiler***: هی، *Scope Manager* (scope سراسری)، اعلان رسمی برای شناسه‌ای به نام `students` پیدا کردم، قبلاً شنیده بودی؟

> ***(Global) Scope Manager***: نه، هرگز نشنیده بودم، پس الان برات ایجادش کردم.

> ***Compiler***: هی، *Scope Manager*، اعلان رسمی برای شناسه‌ای به نام `getStudentName` پیدا کردم، قبلاً شنیده بودی؟

> ***(Global) Scope Manager***: نه، اما الان برات ایجادش کردم.

> ***Compiler***: هی، *Scope Manager*، `getStudentName` به تابع اشاره می‌کند، پس به سطل scope جدید نیاز داریم.

> ***(Function) Scope Manager***: فهمیدم، سطل scope اینجاست.

> ***Compiler***: هی، *Scope Manager* (تابع)، اعلان پارامتر رسمی برای `studentID` پیدا کردم، قبلاً شنیده بودی؟

> ***(Function) Scope Manager***: نه، اما الان در این scope ایجاد شد.

> ***Compiler***: هی، *Scope Manager* (تابع)، حلقهٔ `for` پیدا کردم که به سطل scope خودش نیاز دارد.

> ...

گفتگو یک تبادل پرسش و پاسخ است، که **Compiler** از *Scope Manager* فعلی می‌پرسد آیا اعلان شناسهٔ برخوردشده قبلاً برخورد شده. اگر «نه»، *Scope Manager* آن متغیر را در آن scope ایجاد می‌کند. اگر پاسخ «بله» باشد، پس به‌طور مؤثر رد می‌شود چون کار دیگری برای آن *Scope Manager* نیست.

*Compiler* همچنین وقتی به توابع یا scopeهای بلوک برخورد می‌کند سیگنال می‌دهد، تا سطل scope جدید و *Scope Manager* بتوانند instantiate شوند.

بعداً، وقتی نوبت اجرای برنامه می‌رسد، گفتگو به *Engine* و *Scope Manager* منتقل می‌شود، و ممکن است اینطور پیش برود:

> ***Engine***: هی، *Scope Manager* (scope سراسری)، قبل از شروع، می‌توانی شناسهٔ `getStudentName` را جستجو کنی تا این تابع را به آن انتساب دهم؟

> ***(Global) Scope Manager***: بله، متغیر اینجاست.

> ***Engine***: هی، *Scope Manager*، ارجاع *هدف* برای `students` پیدا کردم، قبلاً شنیده بودی؟

> ***(Global) Scope Manager***: بله، برای این scope به‌طور رسمی اعلان شده بود، پس اینجاست.

> ***Engine***: ممنون، `students` را به `undefined` مقداردهی اولیه می‌کنم، پس آمادهٔ استفاده است.

> هی، *Scope Manager* (scope سراسری)، ارجاع *هدف* برای `nextStudent` پیدا کردم، قبلاً شنیده بودی؟

> ***(Global) Scope Manager***: بله، برای این scope به‌طور رسمی اعلان شده بود، پس اینجاست.

> ***Engine***: ممنون، `nextStudent` را به `undefined` مقداردهی اولیه می‌کنم، پس آمادهٔ استفاده است.

> هی، *Scope Manager* (scope سراسری)، ارجاع *منبع* برای `getStudentName` پیدا کردم، قبلاً شنیده بودی؟

> ***(Global) Scope Manager***: بله، برای این scope به‌طور رسمی اعلان شده بود. اینجاست.

> ***Engine***: عالی، مقدار در `getStudentName` یک تابع است، پس می‌خواهم آن را اجرا کنم.

> ***Engine***: هی، *Scope Manager*، الان باید scope تابع را instantiate کنیم.

> ...

این گفتگو تبادل پرسش و پاسخ دیگری است، که *Engine* ابتدا از *Scope Manager* فعلی می‌خواهد شناسهٔ hoisted شدهٔ `getStudentName` را جستجو کند، تا تابع را با آن مرتبط کند. *Engine* سپس از *Scope Manager* دربارهٔ ارجاع *هدف* برای `students` می‌پرسد، و غیره.

برای مرور و خلاصهٔ نحوهٔ پردازش عبارتی مثل `var students = [ .. ]` در دو مرحلهٔ مجزا:

1. *Compiler* اعلان متغیر scope را تنظیم می‌کند (چون قبلاً در scope فعلی اعلان نشده بود).

2. در حین اجرای *Engine*، برای پردازش بخش انتساب عبارت، *Engine* از *Scope Manager* می‌خواهد متغیر را جستجو کند، آن را به `undefined` مقداردهی اولیه می‌کند تا آمادهٔ استفاده باشد، و سپس مقدار آرایه را به آن انتساب می‌دهد.
