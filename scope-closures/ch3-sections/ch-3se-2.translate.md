# Shadowing (سایه‌اندازی)

«Shadowing» ممکن است مرموز و کمی مشکوک به نظر برسد. اما نگران نباشید، کاملاً قانونی است!

مثال در حال اجرای ما برای این فصل‌ها از نام‌های متغیر متفاوت در مرزهای scope استفاده می‌کند. چون همه نام‌های یکتا دارند، به نوعی مهم نبود اگر همه در یک سطل (مثل RED(1)) ذخیره می‌شدند.

جایی که داشتن سطل‌های lexical scope متفاوت اهمیت بیشتری پیدا می‌کند وقتی است که دو یا چند متغیر دارید، هر کدام در scopeهای مختلف، با نام‌های لغوی یکسان. یک scope نمی‌تواند دو یا چند متغیر با نام یکسان داشته باشد؛ چنین ارجاع‌های متعددی فقط به‌عنوان یک متغیر فرض می‌شوند.

پس اگر نیاز به نگهداری دو یا چند متغیر با نام یکسان دارید، باید از scopeهای جدا (اغلب تو در تو) استفاده کنید. و در آن مورد، نحوهٔ چیدمان سطل‌های scope متفاوت خیلی مرتبط است.

در نظر بگیرید:

```js
var studentName = "Suzy";

function printStudent(studentName) {
    studentName = studentName.toUpperCase();
    console.log(studentName);
}

printStudent("Frank");
// FRANK

printStudent(studentName);
// SUZY

console.log(studentName);
// Suzy
```

| TIP: |
| :--- |
| قبل از ادامه، وقت بگذارید این کد را با تکنیک‌ها/استعاره‌های مختلفی که در کتاب پوشش داده‌ایم تحلیل کنید. به‌طور خاص، حتماً رنگ‌های تیله/حباب را در این قطعه شناسایی کنید. تمرین خوبی است! |

متغیر `studentName` در خط ۱ (عبارت `var studentName = ..`) تیلهٔ RED(1) ایجاد می‌کند. همان متغیر نام‌گذاری‌شده به‌عنوان تیلهٔ BLUE(2) در خط ۳ اعلان می‌شود، پارامتر در تعریف تابع `printStudent(..)`.

تیلهٔ `studentName` در عبارت انتساب `studentName = studentName.toUpperCase()` و عبارت `console.log(studentName)` چه رنگی خواهد بود؟ هر سه ارجاع `studentName` BLUE(2) خواهند بود.

با مفهوم «جستجو»، ادعا کردیم که با scope فعلی شروع می‌کند و به سمت بیرون/بالا پیش می‌رود، به محض پیدا شدن متغیر مطابق متوقف می‌شود. تیلهٔ BLUE(2) `studentName` فوراً پیدا می‌شود. تیلهٔ RED(1) `studentName` اصلاً در نظر گرفته نمی‌شود.

این جنبهٔ کلیدی رفتار lexical scope است، به نام *shadowing*. متغیر BLUE(2) `studentName` (پارامتر) متغیر RED(1) `studentName` را سایه می‌اندازد. پس، پارامتر متغیر سراسری (سایه‌اندازی‌شده) را سایه می‌اندازد. آن جمله را چند بار برای خود تکرار کنید تا مطمئن شوید اصطلاحات را درست دارید!

به همین دلیل انتساب مجدد `studentName` فقط متغیر داخلی (پارامتر) را تحت تأثیر قرار می‌دهد: تیلهٔ BLUE(2) `studentName`، نه تیلهٔ سراسری RED(1) `studentName`.

وقتی انتخاب می‌کنید متغیری از scope بیرونی را سایه بیندازید، یک تأثیر مستقیم این است که از آن scope به سمت داخل/پایین (از طریق هر scope تو در تو) اکنون غیرممکن است هر تیله‌ای به رنگ متغیر سایه‌اندازی‌شده رنگ شود—(RED(1)، در این مورد). به عبارت دیگر، هر ارجاع شناسهٔ `studentName` با آن متغیر پارامتر مطابقت خواهد داشت، هرگز متغیر سراسری `studentName`. از نظر لغوی غیرممکن است به متغیر سراسری `studentName` در هر جای داخل تابع `printStudent(..)` (یا از هر scope تو در تو) ارجاع داد.

### ترفند Global Unshadowing

لطفاً آگاه باشید: استفاده از تکنیکی که می‌خواهم توصیف کنم تمرین خیلی خوبی نیست، چون محدود در کاربرد است، برای خوانندگان کدتان گیج‌کننده است، و احتمالاً باگ به برنامهٔ شما دعوت می‌کند. فقط به این دلیل پوشش می‌دهم که ممکن است به این رفتار در برنامه‌های موجود برخورد کنید، و فهمیدن آنچه اتفاق می‌افتد برای گیر نکردن حیاتی است.

*ممکن* است به متغیر سراسری از scopeی که آن متغیر سایه انداخته دسترسی یافت، اما نه از طریق ارجاع شناسهٔ لغوی معمولی.

در scope سراسری (RED(1))، اعلان‌های `var` و `function` همچنین خود را به‌عنوان property (با همان نام شناسه) روی *global object*—اساساً نمایش شیء scope سراسری—در معرض قرار می‌دهند. اگر جاوااسکریپت برای محیط مرورگر نوشته‌اید، احتمالاً global object را به‌عنوان `window` می‌شناسید. این *کاملاً* دقیق نیست، اما برای بحث ما کافی است. در فصل بعد، موضوع scope/شیء سراسری را بیشتر کاوش می‌کنیم.

این برنامه را در نظر بگیرید، به‌طور خاص به‌عنوان فایل .js مستقل در محیط مرورگر اجرا شده:

```js
var studentName = "Suzy";

function printStudent(studentName) {
    console.log(studentName);
    console.log(window.studentName);
}

printStudent("Frank");
// "Frank"
// "Suzy"
```

به ارجاع `window.studentName` توجه کردید؟ این عبارت به متغیر سراسری `studentName` به‌عنوان property روی `window` (که فعلاً فرض می‌کنیم مترادف با global object است) دسترسی می‌کند. این تنها راه دسترسی به متغیر سایه‌اندازی‌شده از داخل scopeی است که متغیر سایه‌انداز در آن حضور دارد.

`window.studentName` آینهٔ متغیر سراسری `studentName` است، نه کپی snapshot جداگانه. تغییرات یکی هنوز از دیگری دیده می‌شود، در هر دو جهت. می‌توانید `window.studentName` را به‌عنوان getter/setter که به متغیر واقعی `studentName` دسترسی می‌کند در نظر بگیرید. در واقع، حتی می‌توانید با ایجاد/تنظیم property روی global object متغیری به scope سراسری *اضافه* کنید.

| WARNING: |
| :--- |
| به یاد داشته باشید: فقط چون *می‌توانید* یعنی *باید*. متغیر سراسری که نیاز به دسترسی دارید را سایه نیندازید، و برعکس، از این ترفند برای دسترسی به متغیر سراسری که سایه انداخته‌اید اجتناب کنید. و قطعاً خوانندگان کدتان را با ایجاد متغیرهای سراسری به‌عنوان propertyهای `window` به‌جای اعلان‌های رسمی گیج نکنید! |

این «ترفند» کوچک فقط برای دسترسی به متغیر scope سراسری کار می‌کند (نه متغیر سایه‌اندازی‌شده از scope تو در تو)، و حتی آنگاه، فقط آن که با `var` یا `function` اعلان شده باشد.

اشکال دیگر اعلان scope سراسری propertyهای global object آینه‌ای ایجاد نمی‌کنند:

```js
var one = 1;
let notOne = 2;
const notTwo = 3;
class notThree {}

console.log(window.one);       // 1
console.log(window.notOne);    // undefined
console.log(window.notTwo);    // undefined
console.log(window.notThree);  // undefined
```

متغیرها (مهم نیست چطور اعلان شده‌اند!) که در هر scope دیگری غیر از scope سراسری وجود دارند از scopeی که سایه انداخته‌اند کاملاً غیرقابل دسترسی هستند:

```js
var special = 42;

function lookingFor(special) {
    // The identifier `special` (parameter) in this
    // scope is shadowed inside keepLooking(), and
    // is thus inaccessible from that scope.

    function keepLooking() {
        var special = 3.141592;
        console.log(special);
        console.log(window.special);
    }

    keepLooking();
}

lookingFor(112358132134);
// 3.141592
// 42
```

تیلهٔ سراسری RED(1) `special` توسط تیلهٔ BLUE(2) `special` (پارامتر) سایه انداخته می‌شود، و تیلهٔ BLUE(2) `special` خودش توسط تیلهٔ GREEN(3) `special` داخل `keepLooking()` سایه انداخته می‌شود. هنوز می‌توانیم با ارجاع غیرمستقیم `window.special` به تیلهٔ RED(1) `special` دسترسی یابیم. اما راهی برای `keepLooking()` برای دسترسی به تیلهٔ BLUE(2) `special` که عدد `112358132134` را نگه می‌دارد وجود ندارد.

### کپی کردن دسترسی نیست

این سوال «اما چه دربارهٔ...؟» را ده‌ها بار پرسیده‌اند. در نظر بگیرید:

```js
var special = 42;

function lookingFor(special) {
    var another = {
        special: special
    };

    function keepLooking() {
        var special = 3.141592;
        console.log(special);
        console.log(another.special);  // Ooo, tricky!
        console.log(window.special);
    }

    keepLooking();
}

lookingFor(112358132134);
// 3.141592
// 112358132134
// 42
```

اوه! پس آیا این تکنیک شیء `another` ادعای من را که پارامتر `special` از داخل `keepLooking()` «کاملاً غیرقابل دسترسی» است رد می‌کند؟ نه، ادعا هنوز درست است.

`special: special` مقدار متغیر پارامتر `special` را در ظرف دیگری (یک property با همان نام) کپی می‌کند. البته، اگر مقداری در ظرف دیگری بگذارید، shadowing دیگر اعمال نمی‌شود (مگر اینکه `another` هم سایه انداخته شود!). اما این یعنی ما به پارامتر `special` دسترسی نداریم؛ یعنی از طریق ظرف *دیگری* (property شیء) به کپی مقدار آن در آن لحظه دسترسی داریم. نمی‌توانیم پارامتر BLUE(2) `special` را از داخل `keepLooking()` به مقدار متفاوتی انتساب مجدد دهیم.

«اما...!؟» دیگری که ممکن است مطرح کنید: اگر به‌جای اعداد (`112358132134` و غیره) از شیءها یا آرایه‌ها به‌عنوان مقدار استفاده کرده بودم چه؟ آیا داشتن مرجع به شیءها به‌جای کپی مقادیر اولیه «غیرقابل دسترسی بودن» را «درست» می‌کرد؟

نه. تغییر محتویات مقدار شیء از طریق کپی مرجع **همان** دسترسی لغوی به خود متغیر نیست. هنوز نمی‌توانیم پارامتر BLUE(2) `special` را انتساب مجدد دهیم.

### Shadowing غیرقانونی

همهٔ ترکیب‌های shadowing اعلان مجاز نیستند. `let` می‌تواند `var` را سایه بیندازد، اما `var` نمی‌تواند `let` را سایه بیندازد:

```js
function something() {
    var special = "JavaScript";

    {
        let special = 42;   // totally fine shadowing

        // ..
    }
}

function another() {
    // ..

    {
        let special = "JavaScript";

        {
            var special = "JavaScript";
            // ^^^ Syntax Error

            // ..
        }
    }
}
```

توجه کنید در تابع `another()`، اعلان داخلی `var special` سعی می‌کند `special` در کل تابع را اعلان کند، که خودش خوب است (همانطور که تابع `something()` نشان می‌دهد).

توضیح خطای نحو در این مورد نشان می‌دهد که `special` از قبل تعریف شده، اما آن پیام خطا کمی گمراه‌کننده است—باز هم، چنین خطایی در `something()` اتفاق نمی‌افتد، چون shadowing عموماً کاملاً مجاز است.

دلیل واقعی پرتاب شدن به‌عنوان `SyntaxError` این است که `var` اساساً سعی می‌کند «از مرز» اعلان `let` با همان نام عبور کند (یا از روی آن بپرد)، که مجاز نیست.

ممنوعیت عبور از مرز به‌طور مؤثر در هر مرز تابع متوقف می‌شود، پس این variant هیچ استثنایی پرتاب نمی‌کند:

```js
function another() {
    // ..

    {
        let special = "JavaScript";

        ajax("https://some.url",function callback(){
            // totally fine shadowing
            var special = "JavaScript";

            // ..
        });
    }
}
```

خلاصه: `let` (در scope داخلی) همیشه می‌تواند `var` scope بیرونی را سایه بیندازد. `var` (در scope داخلی) فقط می‌تواند `let` scope بیرونی را سایه بیندازد اگر مرز تابعی بین آن‌ها باشد.
