# توابع پیکانی (Arrow Functions)

ES6 یک شکل `function` expression اضافی به زبان اضافه کرد، به نام «arrow functions»:

```js
var askQuestion = () => {
    // ..
};
```

تابع پیکانی `=>` کلمهٔ `function` برای تعریفش نیاز ندارد. همچنین، `( .. )` دور لیست پارامتر در برخی موارد ساده اختیاری است. به همین ترتیب، `{ .. }` دور بدنهٔ تابع در برخی موارد اختیاری است. و وقتی `{ .. }` حذف می‌شوند، مقدار برگشتی بدون استفاده از کلمهٔ کلیدی `return` ارسال می‌شود.

| NOTE: |
| :--- |
| جذابیت توابع پیکانی `=>` اغلب به‌عنوان «نحو کوتاه‌تر» فروخته می‌شود، و ادعا می‌شود که با کد عینی‌تر خوانا برابر است. این ادعا در بهترین حالت مشکوک است، و معتقدم کاملاً گمراه‌کننده است. در پیوست الف به «خوانایی» اشکال مختلف تابع می‌پردازیم. |

توابع پیکانی از نظر لغوی ناشناس هستند، یعنی شناسهٔ مستقیم مرتبطی که به تابع ارجاع دهد ندارند. انتساب به `askQuestion` یک نام استنتاج‌شدهٔ «askQuestion» ایجاد می‌کند، اما این **همان ناشناس نبودن نیست**:

```js
var askQuestion = () => {
    // ..
};

askQuestion.name;   // askQuestion
```

توابع پیکانی به بهای juggle ذهنی دسته‌ای از تغییرات برای اشکال/شرایط مختلف به اختصار نحوی می‌رسند. فقط چند نمونه:

```js
() => 42;

id => id.toUpperCase();

(id,name) => ({ id, name });

(...args) => {
    return args[args.length - 1];
};
```

دلیل واقعی مطرح کردن توابع پیکانی به خاطر ادعای رایج اما نادرست است که توابع پیکانی به نوعی با respect به lexical scope متفاوت از توابع `function` استاندارد رفتار می‌کنند.

این نادرست است.

به‌جز ناشناس بودن (و نداشتن شکل اعلانی)، توابع پیکانی `=>` همان قوانین lexical scope توابع `function` را دارند. یک تابع پیکانی، با یا بدون `{ .. }` دور بدنه‌اش، هنوز یک سطل scope داخلی تو در تو جدا ایجاد می‌کند. اعلان‌های متغیر داخل این سطل scope تو در تو همانند scope `function` رفتار می‌کنند.
