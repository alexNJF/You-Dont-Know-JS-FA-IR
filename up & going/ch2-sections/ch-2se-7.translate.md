# Prototypeها

مکانیزم prototype در جاوااسکریپت نسبتاً پیچیده است. اینجا فقط نگاهی گذرا به آن می‌اندازیم. می‌خواهید زمان زیادی را صرف مرور فصل‌های ۴ تا ۶ عنوان *this & Object Prototypes* این مجموعه برای تمام جزئیات کنید.

وقتی به ویژگی روی یک object ارجاع می‌دهید، اگر آن ویژگی وجود نداشته باشد، جاوااسکریپت به‌طور خودکار از reference داخلی prototype آن object برای یافتن object دیگری برای جستجوی ویژگی روی آن استفاده می‌کند. می‌توانید این را تقریباً مانند یک fallback در نظر بگیرید اگر ویژگی وجود نداشته باشد.

اتصال reference داخلی prototype از یک object به fallback آن در زمان ایجاد object رخ می‌دهد. ساده‌ترین راه تصویرسازی آن با یک ابزار داخلی به نام `Object.create(..)` است.

در نظر بگیرید:

```js
var foo = {
	a: 42
};

// create `bar` and link it to `foo`
var bar = Object.create( foo );

bar.b = "hello world";

bar.b;		// "hello world"
bar.a;		// 42 <-- delegated to `foo`
```

ویژگی `a` در واقع روی object `bar` وجود ندارد، اما چون `bar` به `foo` prototype-linked است، جاوااسکریپت به‌طور خودکار به جستجوی `a` روی object `foo` fallback می‌کند، جایی که یافت می‌شود.

این اتصال ممکن است ویژگی عجیبی از زبان به نظر برسد. رایج‌ترین نحوهٔ استفاده از این ویژگی — و من استدلال می‌کنم، سوءاستفاده — تلاش برای تقلید/جعل مکانیزم «class» با «inheritance» است.

اما روش طبیعی‌تر اعمال prototypeها الگویی به نام «behavior delegation» است، جایی که عمداً objectهای متصل خود را طراحی می‌کنید تا بتوانند برای بخش‌هایی از رفتار مورد نیاز از یکی به دیگری *delegate* کنند.

**Note:** برای اطلاعات بیشتر دربارهٔ prototypeها و behavior delegation، به فصل‌های ۴ تا ۶ عنوان *this & Object Prototypes* این مجموعه مراجعه کنید.
