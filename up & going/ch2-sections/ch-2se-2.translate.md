# متغیرها

در جاوااسکریپت، نام‌های متغیر (از جمله نام‌های function) باید *identifier*های معتبر باشند. قوانین دقیق و کامل برای کاراکترهای معتبر در identifierها وقتی کاراکترهای غیرسنتی مانند Unicode را در نظر می‌گیرید کمی پیچیده است. اگر فقط کاراکترهای الفبایی-عددی معمول ASCII را در نظر بگیرید، قوانین ساده هستند.

یک identifier باید با `a`-`z`، `A`-`Z`، `$` یا `_` شروع شود. سپس می‌تواند هر یک از آن کاراکترها به علاوهٔ ارقام `0`-`9` را شامل شود.

عموماً، همان قوانین برای نام ویژگی و برای identifier متغیر اعمال می‌شوند. با این حال، کلمات خاصی نمی‌توانند به‌عنوان متغیر استفاده شوند، اما به‌عنوان نام ویژگی درست هستند. این کلمات «reserved words» نامیده می‌شوند و شامل کلمات کلیدی JS (`for`، `in`، `if` و غیره) و همچنین `null`، `true` و `false` هستند.

**Note:** برای اطلاعات بیشتر دربارهٔ reserved words، به پیوست الف عنوان *Types & Grammar* این مجموعه مراجعه کنید.

### Function Scopes

از کلمهٔ کلیدی `var` برای اعلان متغیری استفاده می‌کنید که به scope تابع فعلی تعلق خواهد داشت، یا به scope سراسری اگر در سطح بالایی خارج از هر تابعی باشد.

#### Hoisting

هر جا که یک `var` در داخل یک scope ظاهر شود، آن اعلان به کل scope تعلق دارد و در سراسر آن در دسترس است.

از نظر استعاری، این رفتار *hoisting* نامیده می‌شود، زمانی که اعلان `var` به‌طور مفهومی به «بالای» scope محاط‌کنندهٔ خود «منتقل» می‌شود. از نظر فنی، این فرآیند با نحوهٔ کامپایل شدن کد دقیق‌تر توضیح داده می‌شود، اما می‌توانیم فعلاً از آن جزئیات عبور کنیم.

در نظر بگیرید:

```js
var a = 2;

foo();					// works because `foo()`
						// declaration is "hoisted"

function foo() {
	a = 3;

	console.log( a );	// 3

	var a;				// declaration is "hoisted"
						// to the top of `foo()`
}

console.log( a );	// 2
```

**Warning:** رایج یا ایدهٔ خوبی نیست که برای استفاده از متغیر زودتر از ظاهر شدن اعلان `var` آن در scope خود به *hoisting* متغیر تکیه کنید؛ می‌تواند بسیار گیج‌کننده باشد. رایج‌تر و پذیرفته‌تر استفاده از اعلان‌های function با *hoisting* است، همان‌طور که با فراخوانی `foo()` قبل از اعلان رسمی آن انجام می‌دهیم.

#### Nested Scopes

وقتی متغیری را اعلان می‌کنید، در هر جای آن scope و همچنین در هر scope پایین‌تر/داخلی در دسترس است. برای مثال:

```js
function foo() {
	var a = 1;

	function bar() {
		var b = 2;

		function baz() {
			var c = 3;

			console.log( a, b, c );	// 1 2 3
		}

		baz();
		console.log( a, b );		// 1 2
	}

	bar();
	console.log( a );				// 1
}

foo();
```

توجه کنید که `c` در داخل `bar()` در دسترس نیست، چون فقط در scope داخلی `baz()` اعلان شده است، و `b` به همین دلیل برای `foo()` در دسترس نیست.

اگر سعی کنید مقدار یک متغیر را در scopeای که در آن در دسترس نیست دسترسی کنید، یک `ReferenceError` پرتاب می‌شود. اگر سعی کنید متغیری را که اعلان نشده تنظیم کنید، یا متغیری در scope سراسری سطح بالا ایجاد می‌کنید (بد!) یا خطا می‌گیرید، بسته به «strict mode» (به «Strict Mode» مراجعه کنید). بیایید نگاهی بیندازیم:

```js
function foo() {
	a = 1;	// `a` not formally declared
}

foo();
a;			// 1 -- oops, auto global variable :(
```

این یک روش بسیار بد است. این کار را نکنید! همیشه متغیرهای خود را به‌طور رسمی اعلان کنید.

علاوه بر ایجاد اعلان‌ها برای متغیرها در سطح function، ES6 به شما اجازه می‌دهد با استفاده از کلمهٔ کلیدی `let` متغیرهایی را اعلان کنید که به بلوک‌های فردی (جفت‌های `{ .. }`) تعلق داشته باشند. علاوه بر برخی جزئیات ظریف، قوانین scoping تقریباً همان‌طور که با functionها دیدیم رفتار خواهند کرد:

```js
function foo() {
	var a = 1;

	if (a >= 1) {
		let b = 2;

		while (b < 5) {
			let c = b * 2;
			b++;

			console.log( a + c );
		}
	}
}

foo();
// 5 7 9
```

به‌خاطر استفاده از `let` به‌جای `var`، `b` فقط به دستور `if` تعلق خواهد داشت و بنابراین به scope کل تابع `foo()` تعلق نخواهد داشت. به‌طور مشابه، `c` فقط به حلقهٔ `while` تعلق دارد. block scoping برای مدیریت scopeهای متغیر شما به‌صورت ریزتر بسیار مفید است، که می‌تواند کد شما را در طول زمان بسیار ساده‌تر نگه‌داری کند.
