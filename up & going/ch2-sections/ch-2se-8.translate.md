# قدیمی و جدید

برخی از ویژگی‌های JS که قبلاً پوشش دادیم، و قطعاً بسیاری از ویژگی‌های پوشش‌داده‌شده در بقیهٔ این مجموعه، افزودنی‌های جدیدتری هستند و لزوماً در مرورگرهای قدیمی‌تر در دسترس نخواهند بود. در واقع، برخی از جدیدترین ویژگی‌های مشخصات حتی در هیچ مرورگر پایدار دیگری هنوز پیاده‌سازی نشده‌اند.

پس، با چیزهای جدید چه کار می‌کنید؟ آیا فقط باید سال‌ها یا دهه‌ها صبر کنید تا همهٔ مرورگرهای قدیمی به فراموشی سپرده شوند؟

این نحوهٔ فکر بسیاری از مردم دربارهٔ وضعیت است، اما واقعاً رویکرد سالمی به JS نیست.

دو تکنیک اصلی وجود دارد که می‌توانید برای «آوردن» چیزهای جدیدتر جاوااسکریپت به مرورگرهای قدیمی استفاده کنید: polyfilling و transpiling.

### Polyfilling

کلمهٔ «polyfill» یک اصطلاح ابداعی (توسط Remy Sharp) (https://remysharp.com/2010/10/08/what-is-a-polyfill) است که برای اشاره به گرفتن تعریف یک ویژگی جدیدتر و تولید قطعه‌ای کد که معادل رفتار است، اما قادر به اجرا در محیط‌های JS قدیمی‌تر است، استفاده می‌شود.

برای مثال، ES6 ابزاری به نام `Number.isNaN(..)` تعریف می‌کند تا بررسی دقیق و بدون باگ برای مقادیر `NaN` ارائه دهد، و ابزار اصلی `isNaN(..)` را منسوخ می‌کند. اما polyfill کردن آن ابزار آسان است تا بتوانید بدون توجه به اینکه کاربر نهایی در مرورگر ES6 است یا نه، استفاده از آن را در کد خود شروع کنید.

در نظر بگیرید:

```js
if (!Number.isNaN) {
	Number.isNaN = function isNaN(x) {
		return x !== x;
	};
}
```

دستور `if` در برابر اعمال تعریف polyfill در مرورگرهای ES6 که قبلاً وجود خواهد داشت محافظت می‌کند. اگر هنوز وجود نداشته باشد، `Number.isNaN(..)` را تعریف می‌کنیم.

**Note:** بررسی‌ای که اینجا انجام می‌دهیم از یک quirk با مقادیر `NaN` استفاده می‌کند، که این است که آن‌ها تنها مقداری در کل زبان هستند که با خودشان برابر نیستند. بنابراین مقدار `NaN` تنها مقداری است که `x !== x` را `true` می‌کند.

همهٔ ویژگی‌های جدید به‌طور کامل polyfillable نیستند. گاهی بیشتر رفتار را می‌توان polyfill کرد، اما هنوز انحرافات کوچکی وجود دارد. باید در پیاده‌سازی خود یک polyfill بسیار، بسیار محتاط باشید تا مطمئن شوید تا حد امکان به مشخصات پایبند هستید.

یا بهتر است، از مجموعه polyfillهای از پیش بررسی‌شده‌ای استفاده کنید که می‌توانید به آن‌ها اعتماد کنید، مانند آن‌هایی که توسط ES5-Shim (https://github.com/es-shims/es5-shim) و ES6-Shim (https://github.com/es-shims/es6-shim) ارائه می‌شوند.

### Transpiling

راهی برای polyfill کردن نحو جدیدی که به زبان اضافه شده وجود ندارد. نحو جدید در موتور JS قدیمی به‌عنوان نامعتبر/نامشخص خطا می‌دهد.

بنابراین گزینهٔ بهتر استفاده از ابزاری است که کد جدیدتر شما را به معادل‌های کد قدیمی تبدیل می‌کند. این فرآیند معمولاً «transpiling» نامیده می‌شود، اصطلاحی برای transforming + compiling.

اساساً، کد منبع شما به شکل نحو جدید نوشته می‌شود، اما آنچه به مرورگر deploy می‌کنید کد transpile‌شده به شکل نحو قدیمی است. معمولاً transpiler را در فرآیند build خود، مشابه linter یا minifier کد خود، قرار می‌دهید.

ممکن است تعجب کنید چرا زحمت نوشتن نحو جدید را می‌کشید فقط برای اینکه transpile شود به کد قدیمی — چرا مستقیماً کد قدیمی را ننویسید؟

چند دلیل مهم وجود دارد که باید به transpiling اهمیت دهید:

* نحو جدید اضافه‌شده به زبان برای خوانایی و نگه‌داری بیشتر کد شما طراحی شده است. معادل‌های قدیمی اغلب بسیار پیچیده‌تر هستند. باید نوشتن نحو جدیدتر و تمیزتر را ترجیح دهید، نه فقط برای خودتان بلکه برای همهٔ اعضای دیگر تیم توسعه.
* اگر فقط برای مرورگرهای قدیمی transpile کنید، اما نحو جدید را به جدیدترین مرورگرها serve کنید، می‌توانید از بهینه‌سازی‌های عملکرد مرورگر با نحو جدید بهره‌مند شوید. این همچنین به سازندگان مرورگر اجازه می‌دهد کد واقعی بیشتری برای تست پیاده‌سازی‌ها و بهینه‌سازی‌های خود داشته باشند.
* استفاده از نحو جدید زودتر اجازه می‌دهد در دنیای واقعی قوی‌تر تست شود، که بازخورد زودتری به کمیتهٔ جاوااسکریپت (TC39) ارائه می‌دهد. اگر مشکلات به اندازهٔ کافی زود یافت شوند، می‌توانند قبل از دائمی شدن آن اشتباهات طراحی زبان تغییر/اصلاح شوند.

در اینجا یک نمونهٔ سریع از transpiling آمده است. ES6 ویژگی‌ای به نام «default parameter values» اضافه می‌کند. به این شکل است:

```js
function foo(a = 2) {
	console.log( a );
}

foo();		// 2
foo( 42 );	// 42
```

ساده است، درست است؟ مفید هم هست! اما نحو جدیدی است که در موتورهای پیش از ES6 نامعتبر است. پس transpiler با آن کد چه می‌کند تا در محیط‌های قدیمی‌تر اجرا شود؟

```js
function foo() {
	var a = arguments[0] !== (void 0) ? arguments[0] : 2;
	console.log( a );
}
```

همان‌طور که می‌بینید، بررسی می‌کند که آیا مقدار `arguments[0]` برابر با `void 0` (یعنی `undefined`) است یا نه، و اگر چنین است مقدار پیش‌فرض `2` را ارائه می‌دهد؛ در غیر این صورت، هر چه پاس داده شده را اختصاص می‌دهد.

علاوه بر اینکه اکنون می‌توانید حتی در مرورگرهای قدیمی از نحو بهتر استفاده کنید، نگاه کردن به کد transpile‌شده در واقع رفتار مورد نظر را واضح‌تر توضیح می‌دهد.

ممکن است فقط از نگاه کردن به نسخهٔ ES6 متوجه نشده باشید که `undefined` تنها مقداری است که نمی‌توان صریحاً برای یک پارامتر default-value پاس داد، اما کد transpile‌شده آن را بسیار واضح‌تر می‌کند.

آخرین جزئیات مهم برای تأکید دربارهٔ transpilerها این است که اکنون باید آن‌ها را به‌عنوان بخش استاندارد اکوسیستم و فرآیند توسعهٔ JS در نظر بگیرید. JS به تکامل ادامه خواهد داد، بسیار سریع‌تر از قبل، بنابراین هر چند ماه نحو و ویژگی‌های جدیدی اضافه می‌شوند.

اگر به‌طور پیش‌فرض از transpiler استفاده کنید، همیشه می‌توانید هر زمان که مفید یافتید به نحو جدیدتر تغییر دهید، به‌جای اینکه همیشه سال‌ها منتظر بمانید تا مرورگرهای امروز حذف شوند.

transpilerهای بسیار خوبی برای انتخاب وجود دارند. در زمان نگارش این کتاب گزینه‌های خوبی وجود دارند:

* Babel (https://babeljs.io) (قبلاً 6to5): ES6+ را به ES5 transpile می‌کند
* Traceur (https://github.com/google/traceur-compiler): ES6، ES7 و فراتر را به ES5 transpile می‌کند
