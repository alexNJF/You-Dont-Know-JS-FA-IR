# حالت سخت‌گیرانه

ES5 یک «strict mode» به زبان اضافه کرد که قوانین رفتارهای خاص را سخت‌گیرانه‌تر می‌کند. عموماً، این محدودیت‌ها به‌عنوان نگه داشتن کد در مجموعه‌ای امن‌تر و مناسب‌تر از دستورالعمل‌ها دیده می‌شوند. همچنین، پایبندی به strict mode کد شما را عموماً برای موتور بهینه‌پذیرتر می‌کند. Strict mode یک دستاورد بزرگ برای کد است، و باید آن را برای همهٔ برنامه‌های خود استفاده کنید.

می‌توانید برای یک تابع منفرد، یا یک فایل کامل، بسته به جایی که pragma مربوط به strict mode را قرار می‌دهید، به strict mode opting in کنید:

```js
function foo() {
	"use strict";

	// this code is strict mode

	function bar() {
		// this code is strict mode
	}
}

// this code is not strict mode
```

آن را با این مقایسه کنید:

```js
"use strict";

function foo() {
	// this code is strict mode

	function bar() {
		// this code is strict mode
	}
}

// this code is strict mode
```

یک تفاوت کلیدی (بهبود!) با strict mode ممنوع کردن اعلان ضمنی متغیر سراسری خودکار از حذف `var` است:

```js
function foo() {
	"use strict";	// turn on strict mode
	a = 1;			// `var` missing, ReferenceError
}

foo();
```

اگر strict mode را در کد خود روشن کنید، و خطا بگیرید، یا کد شروع به رفتار باگ‌دار کند، ممکن است وسوسه شوید از strict mode اجتناب کنید. اما تسلیم شدن به آن غریزه ایدهٔ بدی است. اگر strict mode در برنامهٔ شما مشکلاتی ایجاد کند، تقریباً قطعاً نشانهٔ این است که چیزهایی در برنامه دارید که باید اصلاح کنید.

نه تنها strict mode کد شما را در مسیر امن‌تری نگه می‌دارد، و نه تنها کد شما را بهینه‌پذیرتر می‌کند، بلکه همچنین جهت آیندهٔ زبان را نمایندگی می‌کند. عادت کردن به strict mode الان برای شما آسان‌تر از به تعویق انداختن مداوم آن است — تبدیل کردن بعداً فقط سخت‌تر می‌شود!

**Note:** برای اطلاعات بیشتر دربارهٔ strict mode، به فصل ۵ عنوان *Types & Grammar* این مجموعه مراجعه کنید.
