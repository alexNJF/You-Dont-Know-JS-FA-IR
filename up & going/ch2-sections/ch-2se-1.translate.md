# مقادیر و انواع

همان‌طور که در فصل ۱ تأکید کردیم، جاوااسکریپت مقادیر دارای نوع دارد، نه متغیرهای دارای نوع. انواع داخلی زیر در دسترس هستند:

* `string`
* `number`
* `boolean`
* `null` و `undefined`
* `object`
* `symbol` (جدید در ES6)

جاوااسکریپت عملگر `typeof` را ارائه می‌دهد که می‌تواند یک مقدار را بررسی کند و به شما بگوید نوع آن چیست:

```js
var a;
typeof a;				// "undefined"

a = "hello world";
typeof a;				// "string"

a = 42;
typeof a;				// "number"

a = true;
typeof a;				// "boolean"

a = null;
typeof a;				// "object" -- weird, bug

a = undefined;
typeof a;				// "undefined"

a = { b: "c" };
typeof a;				// "object"
```

مقدار بازگشتی از عملگر `typeof` همیشه یکی از شش (هفت مورد از ES6 به بعد! — نوع «symbol») مقدار رشته است. یعنی `typeof "abc"` مقدار `"string"` برمی‌گرداند، نه `string`.

توجه کنید که در این قطعه کد، متغیر `a` هر نوع مقدار متفاوتی را نگه می‌دارد، و علیرغم ظاهر، `typeof a` «نوع `a`» را نمی‌پرسد، بلکه «نوع مقداری که اکنون در `a` است» را می‌پرسد. در جاوااسکریپت فقط مقادیر نوع دارند؛ متغیرها صرفاً ظروف ساده برای آن مقادیر هستند.

`typeof null` مورد جالبی است، زیرا به‌اشتباه `"object"` برمی‌گرداند، در حالی که انتظار می‌رود `"null"` برگرداند.

**Warning:** این یک باگ دیرینه در JS است، اما بعید است هرگز اصلاح شود. کدهای زیادی در وب به این باگ وابسته‌اند و بنابراین اصلاح آن باگ‌های بیشتری ایجاد می‌کند!

همچنین، به `a = undefined` توجه کنید. ما صریحاً `a` را به مقدار `undefined` تنظیم می‌کنیم، اما از نظر رفتاری تفاوتی با متغیری که هنوز مقداری برای آن تنظیم نشده ندارد، مانند خط `var a;` در بالای قطعه کد. یک متغیر می‌تواند از چند طریق مختلف به این حالت مقدار «undefined» برسد، از جمله توابعی که مقداری برنمی‌گردانند و استفاده از عملگر `void`.

### Objects

نوع `object` به مقداری مرکب اشاره دارد که می‌توانید در آن ویژگی‌ها (مکان‌های نام‌گذاری‌شده) تنظیم کنید که هر کدام مقادیر خود را از هر نوعی نگه می‌دارند. این شاید یکی از مفیدترین انواع مقدار در کل جاوااسکریپت باشد.

```js
var obj = {
	a: "hello world",
	b: 42,
	c: true
};

obj.a;		// "hello world"
obj.b;		// 42
obj.c;		// true

obj["a"];	// "hello world"
obj["b"];	// 42
obj["c"];	// true
```

ممکن است مفید باشد که این مقدار `obj` را به‌صورت بصری تصور کنید:

<img src="fig4.png">

ویژگی‌ها را می‌توان با *dot notation* (یعنی `obj.a`) یا *bracket notation* (یعنی `obj["a"]`) دسترسی کرد. dot notation کوتاه‌تر و عموماً خواناتر است و بنابراین در صورت امکان ترجیح داده می‌شود.

bracket notation زمانی مفید است که نام ویژگی کاراکترهای خاصی داشته باشد، مانند `obj["hello world!"]` — چنین ویژگی‌هایی هنگام دسترسی از طریق bracket notation اغلب *keys* نامیده می‌شوند. نماد `[ ]` به یک متغیر (که در ادامه توضیح داده می‌شود) یا یک *literal* رشته (که باید در `" .. "` یا `' .. '` قرار گیرد) نیاز دارد.

البته، bracket notation زمانی هم مفید است که بخواهید به یک ویژگی/key دسترسی پیدا کنید اما نام آن در متغیر دیگری ذخیره شده است، مانند:

```js
var obj = {
	a: "hello world",
	b: 42
};

var b = "a";

obj[b];			// "hello world"
obj["b"];		// 42
```

**Note:** برای اطلاعات بیشتر دربارهٔ `object`های جاوااسکریپت، به عنوان *this & Object Prototypes* این مجموعه مراجعه کنید، به‌ویژه فصل ۳.

چند نوع مقدار دیگر وجود دارد که معمولاً در برنامه‌های جاوااسکریپت با آن‌ها تعامل خواهید داشت: *array* و *function*. اما به‌جای اینکه انواع داخلی مناسب باشند، باید آن‌ها را بیشتر به‌عنوان زیرنوع‌ها — نسخه‌های تخصصی نوع `object` — در نظر بگیرید.

#### Arrays

یک array یک `object` است که مقادیر (از هر نوعی) را نه در ویژگی‌ها/کلیدهای نام‌گذاری‌شده، بلکه در موقعیت‌های اندیس‌دار عددی نگه می‌دارد. برای مثال:

```js
var arr = [
	"hello world",
	42,
	true
];

arr[0];			// "hello world"
arr[1];			// 42
arr[2];			// true
arr.length;		// 3

typeof arr;		// "object"
```

**Note:** زبان‌هایی که مانند JS از صفر شروع به شمارش می‌کنند، از `0` به‌عنوان اندیس اولین عنصر در array استفاده می‌کنند.

ممکن است مفید باشد که `arr` را به‌صورت بصری تصور کنید:

<img src="fig5.png">

چون arrayها objectهای خاصی هستند (همان‌طور که `typeof` نشان می‌دهد)، آن‌ها می‌توانند ویژگی‌هایی هم داشته باشند، از جمله ویژگی `length` که به‌طور خودکار به‌روزرسانی می‌شود.

از نظر تئوری می‌توانید از یک array به‌عنوان یک object معمولی با ویژگی‌های نام‌گذاری‌شدهٔ خودتان استفاده کنید، یا می‌توانید از یک `object` استفاده کنید اما فقط ویژگی‌های عددی (`0`، `1` و غیره) به آن بدهید، مشابه یک array. با این حال، این عموماً استفادهٔ نامناسب از انواع مربوطه تلقی می‌شود.

بهترین و طبیعی‌ترین رویکرد این است که از arrayها برای مقادیر با موقعیت عددی استفاده کنید و از `object`ها برای ویژگی‌های نام‌گذاری‌شده استفاده کنید.

#### Functions

زیرنوع دیگر `object` که در سراسر برنامه‌های JS خود استفاده خواهید کرد، function است:

```js
function foo() {
	return 42;
}

foo.bar = "hello world";

typeof foo;			// "function"
typeof foo();		// "number"
typeof foo.bar;		// "string"
```

باز هم، functionها زیرنوع `object`ها هستند — `typeof` مقدار `"function"` برمی‌گرداند، که دلالت بر این دارد که `function` یک نوع اصلی است — و بنابراین می‌توانند ویژگی داشته باشند، اما معمولاً فقط در موارد محدودی از ویژگی‌های function object (مانند `foo.bar`) استفاده خواهید کرد.

**Note:** برای اطلاعات بیشتر دربارهٔ مقادیر JS و انواع آن‌ها، به دو فصل اول عنوان *Types & Grammar* این مجموعه مراجعه کنید.

### Built-In Type Methods

انواع و زیرنوع‌های داخلی که تازه بحث کردیم، رفتارهایی دارند که به‌صورت ویژگی‌ها و متدها در معرض قرار گرفته‌اند و بسیار قدرتمند و مفید هستند.

برای مثال:

```js
var a = "hello world";
var b = 3.14159;

a.length;				// 11
a.toUpperCase();		// "HELLO WORLD"
b.toFixed(4);			// "3.1416"
```

«چگونگی» امکان فراخوانی `a.toUpperCase()` پیچیده‌تر از صرف وجود آن متد روی مقدار است.

به‌طور خلاصه، یک شکل object wrapper به نام `String` (با S بزرگ) وجود دارد که معمولاً «native» نامیده می‌شود و با نوع primitive `string` جفت می‌شود؛ این object wrapper است که متد `toUpperCase()` را روی prototype خود تعریف می‌کند.

وقتی از یک مقدار primitive مانند `"hello world"` به‌عنوان یک `object` با ارجاع به یک ویژگی یا متد استفاده می‌کنید (مثلاً `a.toUpperCase()` در قطعه قبلی)، JS به‌طور خودکار مقدار را به همتای object wrapper خود «box» می‌کند (در پشت صحنه پنهان).

یک مقدار `string` می‌تواند توسط یک object `String` wrap شود، یک `number` می‌تواند توسط یک object `Number` wrap شود، و یک `boolean` می‌تواند توسط یک object `Boolean` wrap شود. در بیشتر موارد، نیازی به نگرانی یا استفادهٔ مستقیم از این اشکال object wrapper مقادیر ندارید — در تقریباً همهٔ موارد شکل primitive مقدار را ترجیح دهید و جاوااسکریپت بقیه را برای شما انجام می‌دهد.

**Note:** برای اطلاعات بیشتر دربارهٔ nativeهای JS و «boxing»، به فصل ۳ عنوان *Types & Grammar* این مجموعه مراجعه کنید. برای درک بهتر prototype یک object، به فصل ۵ عنوان *this & Object Prototypes* این مجموعه مراجعه کنید.

### Comparing Values

دو نوع اصلی مقایسهٔ مقدار وجود دارد که در برنامه‌های JS خود باید انجام دهید: *equality* و *inequality*. نتیجهٔ هر مقایسه یک مقدار کاملاً `boolean` (`true` یا `false`) است، صرف‌نظر از اینکه چه نوع مقادیری مقایسه می‌شوند.

#### Coercion

در فصل ۱ به‌طور خلاصه دربارهٔ coercion صحبت کردیم، اما بیایید اینجا دوباره آن را مرور کنیم.

Coercion در جاوااسکریپت به دو شکل وجود دارد: *explicit* و *implicit*. coercion صریح به سادگی این است که می‌توانید به‌وضوح از کد ببینید که تبدیل از یک نوع به نوع دیگر رخ خواهد داد، در حالی که coercion ضمنی زمانی است که تبدیل نوع می‌تواند به‌عنوان یک اثر جانبی کمتر آشکار از عملیات دیگری رخ دهد.

احتمالاً گفته‌هایی مانند «coercion شیطانی است» شنیده‌اید که از این واقعیت ناشی می‌شود که مکان‌های مشخصی وجود دارند که coercion می‌تواند نتایج شگفت‌انگیزی تولید کند. شاید هیچ چیز بیشتر از زمانی که زبان آن‌ها را غافلگیر می‌کند، ناامیدی توسعه‌دهندگان را برنمی‌انگیزد.

Coercion شیطانی نیست، و لازم هم نیست شگفت‌انگیز باشد. در واقع، اکثر مواردی که می‌توانید با type coercion بسازید کاملاً منطقی و قابل‌فهم هستند، و حتی می‌توانند برای *بهبود* خوانایی کد شما استفاده شوند. اما بیشتر وارد آن بحث نمی‌شویم — فصل ۴ عنوان *Types & Grammar* این مجموعه همهٔ جنبه‌ها را پوشش می‌دهد.

در اینجا نمونه‌ای از coercion *explicit* آمده است:

```js
var a = "42";

var b = Number( a );

a;				// "42"
b;				// 42 -- the number!
```

و در اینجا نمونه‌ای از coercion *implicit* آمده است:

```js
var a = "42";

var b = a * 1;	// "42" implicitly coerced to 42 here

a;				// "42"
b;				// 42 -- the number!
```

#### Truthy & Falsy

در فصل ۱، به‌طور خلاصه به ماهیت «truthy» و «falsy» مقادیر اشاره کردیم: وقتی یک مقدار غیر از `boolean` به `boolean` تبدیل می‌شود، آیا به ترتیب `true` یا `false` می‌شود؟

فهرست مشخص مقادیر «falsy» در جاوااسکریپت به شرح زیر است:

* `""` (رشته خالی)
* `0`، `-0`، `NaN` (`number` نامعتبر)
* `null`، `undefined`
* `false`

هر مقداری که در این فهرست «falsy» نیست، «truthy» است. در اینجا نمونه‌هایی از آن‌ها آمده است:

* `"hello"`
* `42`
* `true`
* `[ ]`، `[ 1, "2", 3 ]` (arrayها)
* `{ }`، `{ a: 42 }` (objectها)
* `function foo() { .. }` (functionها)

مهم است به خاطر داشته باشید که یک مقدار غیر از `boolean` فقط در صورتی این coercion «truthy»/«falsy» را دنبال می‌کند که واقعاً به `boolean` تبدیل شود. گیج کردن خود با وضعیتی که به نظر می‌رسد مقدار را به `boolean` تبدیل می‌کند در حالی که نیست، چندان دشوار نیست.

#### Equality

چهار عملگر equality وجود دارد: `==`، `===`، `!=` و `!==`. اشکال `!` البته نسخه‌های متقارن «not equal» همتایان خود هستند؛ *non-equality* نباید با *inequality* اشتباه گرفته شود.

تفاوت بین `==` و `===` معمولاً این‌طور توصیف می‌شود که `==` برابری مقدار را بررسی می‌کند و `===` هم برابری مقدار و هم نوع را بررسی می‌کند. با این حال، این نادرست است. روش صحیح توصیف آن‌ها این است که `==` برابری مقدار را با اجازهٔ coercion بررسی می‌کند، و `===` برابری مقدار را بدون اجازهٔ coercion بررسی می‌کند؛ به همین دلیل `===` اغلب «strict equality» نامیده می‌شود.

coercion ضمنی مجاز در مقایسهٔ loose-equality با `==` و غیرمجاز با strict-equality با `===` را در نظر بگیرید:

```js
var a = "42";
var b = 42;

a == b;			// true
a === b;		// false
```

در مقایسهٔ `a == b`، JS متوجه می‌شود که انواع مطابقت ندارند، بنابراین مراحل منظمی را طی می‌کند تا یک یا هر دو مقدار را به نوعی متفاوت تبدیل کند تا انواع مطابقت کنند، جایی که سپس می‌توان برابری سادهٔ مقدار را بررسی کرد.

اگر به آن فکر کنید، دو راه ممکن وجود دارد که `a == b` می‌تواند از طریق coercion مقدار `true` بدهد. یا مقایسه می‌تواند به `42 == 42` ختم شود یا می‌تواند `"42" == "42"` باشد. پس کدام است؟

پاسخ: `"42"` به `42` تبدیل می‌شود تا مقایسه `42 == 42` شود. در چنین نمونهٔ ساده‌ای، واقعاً مهم به نظر نمی‌رسد که این فرآیند کدام مسیر را طی کند، چون نتیجهٔ نهایی یکسان است. موارد پیچیده‌تری وجود دارند که نه فقط نتیجهٔ نهایی مقایسه، بلکه *چگونگی* رسیدن به آن مهم است.

`a === b` مقدار `false` تولید می‌کند، چون coercion مجاز نیست، بنابراین مقایسهٔ سادهٔ مقدار آشکارا شکست می‌خورد. بسیاری از توسعه‌دهندگان احساس می‌کنند که `===` قابل‌پیش‌بینی‌تر است، بنابراین پیشنهاد می‌کنند همیشه از آن شکل استفاده شود و از `==` دوری شود. به نظر من این دیدگاه بسیار کوته‌بینانه است. معتقدم `==` ابزار قدرتمندی است که به برنامهٔ شما کمک می‌کند، *اگر زمانی را صرف یادگیری نحوهٔ کار آن کنید.*

ما جزئیات ریز نحوهٔ کار coercion در مقایسه‌های `==` را اینجا پوشش نمی‌دهیم. بیشتر آن کاملاً منطقی است، اما موارد گوشهٔ مهمی وجود دارند که باید مراقب آن‌ها باشید. می‌توانید بخش ۱۱.۹.۳ مشخصات ES5 (http://www.ecma-international.org/ecma-262/5.1/) را بخوانید تا قوانین دقیق را ببینید، و از سادگی این مکانیزم در مقایسه با تمام تبلیغات منفی پیرامون آن شگفت‌زده خواهید شد.

برای خلاصه کردن جزئیات زیاد به چند نکتهٔ ساده، و کمک به شما برای دانستن اینکه در موقعیت‌های مختلف از `==` یا `===` استفاده کنید، قوانین سادهٔ من این‌ها هستند:

* اگر هر یک از مقادیر (یعنی طرف) در یک مقایسه می‌تواند مقدار `true` یا `false` باشد، از `==` اجتناب کنید و از `===` استفاده کنید.
* اگر هر یک از مقادیر در یک مقایسه می‌تواند یکی از این مقادیر خاص باشد (`0`، `""` یا `[]` — array خالی)، از `==` اجتناب کنید و از `===` استفاده کنید.
* در *همهٔ* موارد دیگر، استفاده از `==` برای شما امن است. نه تنها امن است، بلکه در بسیاری از موارد کد شما را به گونه‌ای ساده می‌کند که خوانایی را بهبود می‌بخشد.

این قوانین به این خلاصه می‌شوند که باید دربارهٔ کد خود و انواع مقادیری که می‌توانند از طریق متغیرهایی که برای equality مقایسه می‌شوند بیایند، نقادانه فکر کنید. اگر می‌توانید از مقادیر مطمئن باشید و `==` امن است، از آن استفاده کنید! اگر نمی‌توانید از مقادیر مطمئن باشید، از `===` استفاده کنید. همین ساده است.

شکل non-equality یعنی `!=` با `==` جفت می‌شود، و شکل `!==` با `===` جفت می‌شود. تمام قوانین و مشاهداتی که تازه بحث کردیم به‌طور متقارن برای این مقایسه‌های non-equality اعمال می‌شوند.

اگر دو مقدار non-primitive مانند `object`ها (از جمله `function` و `array`) را مقایسه می‌کنید، باید به قوانین مقایسهٔ `==` و `===` توجه ویژه داشته باشید. چون آن مقادیر در واقع با reference نگه داشته می‌شوند، هر دو مقایسهٔ `==` و `===` صرفاً بررسی می‌کنند که آیا referenceها مطابقت دارند یا نه، نه چیزی دربارهٔ مقادیر زیربنایی.

برای مثال، `array`ها به‌طور پیش‌فرض با ساده‌ترین روش یعنی اتصال همهٔ مقادیر با کاما (`,`) در بین آن‌ها به `string`ها تبدیل می‌شوند. ممکن است فکر کنید دو `array` با محتوای یکسان `==` برابر باشند، اما نیستند:

```js
var a = [1,2,3];
var b = [1,2,3];
var c = "1,2,3";

a == c;		// true
b == c;		// true
a == b;		// false
```

**Note:** برای اطلاعات بیشتر دربارهٔ قوانین مقایسهٔ equality با `==`، به مشخصات ES5 (بخش ۱۱.۹.۳) مراجعه کنید و همچنین فصل ۴ عنوان *Types & Grammar* این مجموعه را مطالعه کنید؛ برای اطلاعات بیشتر دربارهٔ مقادیر در مقابل referenceها به فصل ۲ مراجعه کنید.

#### Inequality

عملگرهای `<`، `>`، `<=` و `>=` برای inequality استفاده می‌شوند، که در مشخصات «relational comparison» نامیده می‌شوند. معمولاً با مقادیر قابل مقایسهٔ ترتیبی مانند `number`ها استفاده می‌شوند. درک اینکه `3 < 4` آسان است.

اما مقادیر `string` جاوااسکریپت را نیز می‌توان برای inequality مقایسه کرد، با استفاده از قوانین الفبایی معمول (`"bar" < "foo"`).

در مورد coercion چطور؟ قوانین مشابه مقایسهٔ `==` (اگرچه دقیقاً یکسان نیست!) برای عملگرهای inequality اعمال می‌شوند. به‌طور قابل‌توجهی، عملگرهای «strict inequality» وجود ندارند که coercion را به همان روشی که `===` «strict equality» انجام می‌دهد ممنوع کنند.

در نظر بگیرید:

```js
var a = 41;
var b = "42";
var c = "43";

a < b;		// true
b < c;		// true
```

اینجا چه اتفاقی می‌افتد؟ در بخش ۱۱.۸.۵ مشخصات ES5 آمده است که اگر هر دو مقدار در مقایسهٔ `<` از نوع `string` باشند، همان‌طور که با `b < c` است، مقایسه به‌صورت lexicographically (یعنی الفبایی مانند فرهنگ لغت) انجام می‌شود. اما اگر یکی یا هر دو `string` نباشند، همان‌طور که با `a < b` است، آنگاه هر دو مقدار به `number` تبدیل می‌شوند و یک مقایسهٔ عددی معمولی رخ می‌دهد.

بزرگترین مشکل احتمالی که ممکن است اینجا با مقایسه‌های بین انواع مقدار بالقوه متفاوت با آن مواجه شوید — به خاطر داشته باشید، اشکال «strict inequality» برای استفاده وجود ندارند — زمانی است که یکی از مقادیر نمی‌تواند به یک عدد معتبر تبدیل شود، مانند:

```js
var a = 42;
var b = "foo";

a < b;		// false
a > b;		// false
a == b;		// false
```

صبر کنید، چطور هر سهٔ این مقایسه‌ها می‌توانند `false` باشند؟ چون مقدار `b` در مقایسه‌های `<` و `>` به مقدار «invalid number» یعنی `NaN` تبدیل می‌شود، و مشخصات می‌گوید که `NaN` نه بزرگ‌تر از و نه کوچک‌تر از هیچ مقدار دیگری است.

مقایسهٔ `==` به دلیلی متفاوت شکست می‌خورد. `a == b` می‌تواند شکست بخورد اگر به‌عنوان `42 == NaN` یا `"42" == "foo"` تفسیر شود — همان‌طور که قبلاً توضیح دادیم، مورد اول است.

**Note:** برای اطلاعات بیشتر دربارهٔ قوانین مقایسهٔ inequality، به بخش ۱۱.۸.۵ مشخصات ES5 مراجعه کنید و همچنین فصل ۴ عنوان *Types & Grammar* این مجموعه را مطالعه کنید.
