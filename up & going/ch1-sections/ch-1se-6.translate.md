# متغیرها

اکثر برنامه‌های مفید باید مقداری را هنگام تغییر در طول برنامه، با انجام عملیات مختلف مطابق وظایف مورد نظر برنامه، ردیابی کنند.

ساده‌ترین راه در برنامه انتساب مقدار به یک ظرف نمادین است، به نام *variable* — به این نام چون مقدار در این ظرف می‌تواند در طول زمان *تغییر* کند.

در برخی زبان‌های برنامه‌نویسی، متغیر (ظرف) را برای نگه‌داشتن نوع خاصی از مقدار اعلام می‌کنید، مثل `number` یا `string`. *Static typing*، که *type enforcement* هم نامیده می‌شود، معمولاً به‌عنوان مزیت برای صحت برنامه با جلوگیری از تبدیل‌های ناخواستهٔ مقدار ذکر می‌شود.

زبان‌های دیگر بر انواع مقادیر به‌جای متغیرها تأکید می‌کنند. *Weak typing*، که *dynamic typing* هم نامیده می‌شود، به متغیر اجازه می‌دهد هر نوع مقداری را در هر زمان نگه دارد. معمولاً به‌عنوان مزیت برای انعطاف برنامه با اجازه دادن به یک متغیر برای نمایش مقدار صرف‌نظر از شکل نوع آن در هر لحظهٔ جریان منطق برنامه ذکر می‌شود.

JavaScript از رویکرد دوم استفاده می‌کند، *dynamic typing*، یعنی متغیرها می‌توانند مقادیر هر *type* را بدون هیچ *type* enforcement نگه دارند.

همان‌طور که قبلاً گفتیم، با statement `var` متغیر اعلام می‌کنیم — توجه کنید هیچ اطلاعات *type* دیگری در اعلام نیست. این برنامهٔ ساده را در نظر بگیرید:

```js
var amount = 99.99;

amount = amount * 2;

console.log( amount );		// 199.98

// convert `amount` to a string, and
// add "$" on the beginning
amount = "$" + String( amount );

console.log( amount );		// "$199.98"
```

متغیر `amount` ابتدا number `99.99` را نگه می‌دارد، سپس نتیجهٔ `number` از `amount * 2` را نگه می‌دارد که `199.98` است.

دستور اول `console.log(..)` باید آن مقدار `number` را *implicitly* به `string` coerce کند تا چاپ کند.

سپس statement `amount = "$" + String(amount)` مقدار `199.98` را *explicitly* به `string` coerce می‌کند و کاراکتر `"$"` را به ابتدا اضافه می‌کند. در این نقطه، `amount` حالا مقدار `string` `"$199.98"` را نگه می‌دارد، پس statement دوم `console.log(..)` نیازی به coercion برای چاپ ندارد.

توسعه‌دهندگان JavaScript انعطاف استفاده از متغیر `amount` برای هر یک از مقادیر `99.99`، `199.98` و `"$199.98"` را متوجه می‌شوند. طرفداران static-typing ترجیح می‌دهند متغیر جداگانه‌ای مثل `amountStr` برای نگه‌داشتن نمایش نهایی `"$199.98"` داشته باشند، چون نوع متفاوتی است.

در هر صورت، متوجه می‌شوید `amount` مقدار در حال اجرایی را نگه می‌دارد که در طول برنامه تغییر می‌کند، که هدف اصلی متغیرها را نشان می‌دهد: مدیریت *state* برنامه.

به عبارت دیگر، *state* ردیابی تغییرات مقادیر هنگام اجرای برنامه است.

استفادهٔ رایج دیگر از متغیرها متمرکز کردن تنظیم مقدار است. وقتی متغیری با مقداری اعلام می‌کنید و قصد دارید آن مقدار در طول برنامه *تغییر نکند*، معمولاً *constants* نامیده می‌شود.

این *constants* را، اغلب در بالای برنامه، اعلام می‌کنید تا یک مکان برای تغییر مقدار در صورت نیاز داشته باشید. طبق قرارداد، متغیرهای JavaScript به‌عنوان constants معمولاً با حروف بزرگ و با underscore `_` بین کلمات چندتایی نوشته می‌شوند.

این یک مثال ساده است:

```js
var TAX_RATE = 0.08;	// 8% sales tax

var amount = 99.99;

amount = amount * 2;

amount = amount + (amount * TAX_RATE);

console.log( amount );				// 215.9784
console.log( amount.toFixed( 2 ) );	// "215.98"
```

**Note:** مشابه اینکه `console.log(..)` تابعی `log(..)` است که به‌عنوان property روی مقدار `console` دسترسی می‌یابد، `toFixed(..)` اینجا تابعی است که می‌توان روی مقادیر `number` دسترسی یافت. `number`های JavaScript به‌طور خودکار برای دلار قالب‌بندی نمی‌شوند — موتور نمی‌داند قصدتان چیست و نوعی برای ارز وجود ندارد. `toFixed(..)` به ما اجازه می‌دهد مشخص کنیم چند رقم اعشار می‌خواهیم `number` گرد شود، و در صورت نیاز `string` تولید می‌کند.

متغیر `TAX_RATE` فقط طبق قرارداد *constant* است — هیچ چیز ویژه‌ای در این برنامه نیست که از تغییرش جلوگیری کند. اما اگر شهر نرخ مالیات فروش را به ۹٪ افزایش دهد، هنوز می‌توانیم به‌راحتی برنامه را با تنظیم مقدار انتسابی `TAX_RATE` به `0.09` در یک مکان به‌روز کنیم، به‌جای پیدا کردن موارد زیاد مقدار `0.08` پراکنده در برنامه و به‌روزرسانی همهٔ آن‌ها.

جدیدترین نسخهٔ JavaScript در زمان نوشتن (معمولاً «ES6» نامیده می‌شود) روش جدیدی برای اعلام *constants* با استفاده از `const` به‌جای `var` دارد:

```js
// as of ES6:
const TAX_RATE = 0.08;

var amount = 99.99;

// ..
```

Constants مثل متغیرها با مقادیر تغییرنکرده مفیدند، با این تفاوت که constants همچنین از تغییر تصادفی مقدار جای دیگر بعد از تنظیم اولیه جلوگیری می‌کنند. اگر بخواهید بعد از آن اعلام اول هر مقدار متفاوتی به `TAX_RATE` انتساب دهید، برنامه تغییر را رد می‌کند (و در strict mode، با خطا شکست می‌خورد — ببینید «Strict Mode» در فصل ۲).

راستی، آن نوع «محافظت» در برابر اشتباهات مشابه type enforcement در static-typing است، پس می‌بینید چرا انواع static در زبان‌های دیگر جذاب‌اند!
