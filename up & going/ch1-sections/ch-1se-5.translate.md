# کامنت‌های کد

کارمند فروشگاه موبایل ممکن است یادداشت‌هایی دربارهٔ ویژگی‌های گوشی تازه‌منتشرشده یا طرح‌های جدید شرکتش بنویسد. این یادداشت‌ها فقط برای کارمند است — برای خواندن مشتریان نیست. با این حال، این یادداشت‌ها به کارمند کمک می‌کنند کارش را بهتر انجام دهد با مستند کردن چگونگی‌ها و چرایی‌های آنچه باید به مشتریان بگوید.

یکی از مهم‌ترین درس‌هایی که می‌توانید دربارهٔ نوشتن کد یاد بگیرید این است که فقط برای رایانه نیست. کد به همان اندازه، اگر نه بیشتر، برای توسعه‌دهنده است که برای compiler.

رایانهٔ شما فقط به کد ماشین اهمیت می‌دهد، رشته‌ای از ۰ و ۱ دودویی، که از *compilation* می‌آید. برنامه‌های تقریباً بی‌شماری می‌توانید بنویسید که همان رشتهٔ ۰ و ۱ را تولید کنند. انتخاب‌هایی که دربارهٔ نحوهٔ نوشتن برنامه می‌کنید مهم است — نه‌فقط برای شما، بلکه برای اعضای تیم و حتی خود آینده‌تان.

باید تلاش کنید نه‌فقط برنامه‌هایی بنویسید که درست کار می‌کنند، بلکه برنامه‌هایی که هنگام بررسی معقول به نظر می‌رسند. با انتخاب نام‌های خوب برای متغیرها (ببینید «Variables») و توابع (ببینید «Functions») راه زیادی می‌توانید بروید.

اما بخش مهم دیگر کامنت‌های کد است. این‌ها قطعات متنی در برنامه‌اند که صرفاً برای توضیح به انسان درج شده‌اند. interpreter/compiler همیشه این کامنت‌ها را نادیده می‌گیرد.

نظرات زیادی دربارهٔ کد خوب‌کامنت‌شده وجود دارد؛ نمی‌توانیم قوانین مطلق جهانی تعریف کنیم. اما برخی مشاهدات و راهنماها بسیار مفیدند:

* کد بدون کامنت بهینه نیست.
* کامنت زیاد (مثلاً یکی در هر خط) احتمالاً نشانهٔ کد ضعیف نوشته‌شده است.
* کامنت‌ها باید *چرا* را توضیح دهند، نه *چه*. می‌توانند در صورت گیج‌کننده بودن *چگونه* را هم توضیح دهند.

در JavaScript، دو نوع کامنت ممکن است: کامنت تک‌خطی و کامنت چندخطی.

در نظر بگیرید:

```js
// This is a single-line comment

/* But this is
       a multiline
             comment.
                      */
```

کامنت تک‌خطی `//` مناسب است اگر می‌خواهید کامنت را دقیقاً بالای یک statement بگذارید، یا حتی در انتهای خط. همهٔ چیز روی خط بعد از `//` به‌عنوان کامنت تلقی می‌شود (و بنابراین توسط compiler نادیده گرفته می‌شود)، تا انتهای خط. محدودیتی برای آنچه در کامنت تک‌خطی می‌تواند ظاهر شود وجود ندارد.

در نظر بگیرید:

```js
var a = 42;		// 42 is the meaning of life
```

کامنت چندخطی `/* .. */` مناسب است اگر چند خط توضیح در کامنت دارید.

این یک استفادهٔ رایج از کامنت‌های چندخطی است:

```js
/* The following value is used because
   it has been shown that it answers
   every question in the universe. */
var a = 42;
```

همچنین می‌تواند هر جای خط ظاهر شود، حتی وسط خط، چون `*/` آن را تمام می‌کند. مثلاً:

```js
var a = /* arbitrary value */ 42;

console.log( a );	// 42
```

تنها چیزی که نمی‌تواند داخل کامنت چندخطی ظاهر شود `*/` است، چون به پایان دادن کامنت تفسیر می‌شود.

قطعاً می‌خواهید یادگیری برنامه‌نویسی را با عادت کامنت‌گذاری کد شروع کنید. در بقیهٔ این فصل می‌بینید من از کامنت برای توضیح استفاده می‌کنم، پس در تمرین خودتان هم همین کار را بکنید. به من اعتماد کنید، هر کسی که کدتان را بخواند از شما تشکر می‌کند!
