# مقادیر و انواع

اگر از کارمندی در فروشگاه موبایل بپرسید یک گوشی خاص چقدر قیمت دارد و بگوید «نودونه، نودونه» (یعنی ۹۹.۹۹ دلار)، یک رقم عددی واقعی دلار به شما می‌دهد که نشان‌دهندهٔ آنچه برای خرید باید بپردازید (به‌اضافه مالیات) است. اگر دو تا از آن گوشی‌ها بخواهید، به‌راحتی می‌توانید ذهنی آن مقدار را دوبرابر کنید تا ۱۹۹.۹۸ دلار برای هزینهٔ پایه بگیرید.

اگر همان کارمند گوشی مشابه دیگری بردارد اما بگوید «رایگان» است (شاید با اشارهٔ هوایی)، عدد به شما نمی‌دهد، بلکه نوع دیگری از نمایش هزینهٔ مورد انتظارتان (۰.۰۰ دلار) — کلمهٔ «رایگان».

وقتی بعداً بپرسید آیا گوشی شارژر دارد، آن پاسخ فقط می‌توانست «بله» یا «خیر» باشد.

به‌طور مشابه، وقتی مقادیر را در برنامه بیان می‌کنید، بر اساس آنچه می‌خواهید با آن‌ها انجام دهید نمایش‌های متفاوتی انتخاب می‌کنید.

این نمایش‌های متفاوت برای مقادیر در اصطلاحات برنامه‌نویسی *types* نامیده می‌شوند. JavaScript انواع داخلی برای هر یک از این مقادیر به‌اصطلاح *primitive* دارد:

* وقتی می‌خواهید ریاضی انجام دهید، به `number` نیاز دارید.
* وقتی می‌خواهید مقداری روی صفحه چاپ کنید، به `string` نیاز دارید (یک یا چند کاراکتر، کلمه، جمله).
* وقتی می‌خواهید در برنامه تصمیم بگیرید، به `boolean` نیاز دارید (`true` یا `false`).

مقادیری که مستقیماً در کد منبع گنجانده شده‌اند *literals* نامیده می‌شوند. literalهای `string` با نقل‌قول دوتایی `"..."` یا تکی (`'...'`) احاطه می‌شوند — تنها تفاوت ترجیح سبکی است. literalهای `number` و `boolean` همان‌طور که هستند ارائه می‌شوند (مثل `42`، `true` و غیره).

در نظر بگیرید:

```js
"I am a string";
'I am also a string';

42;

true;
false;
```

فراتر از انواع مقدار `string`/`number`/`boolean`، معمول است که زبان‌های برنامه‌نویسی *arrays*، *objects*، *functions* و بیشتر ارائه دهند. در این فصل و بعدی دربارهٔ مقادیر و انواع بیشتر صحبت می‌کنیم.

### تبدیل بین انواع

اگر `number` دارید اما باید آن را روی صفحه چاپ کنید، باید مقدار را به `string` تبدیل کنید، و در JavaScript این تبدیل «coercion» نامیده می‌شود. به‌طور مشابه، اگر کسی رشته‌ای از کاراکترهای عددی در فرم صفحهٔ تجارت الکترونیک وارد کند، آن `string` است، اما اگر بخواهید آن مقدار را برای عملیات ریاضی استفاده کنید، باید آن را به `number` *coerce* کنید.

JavaScript چند ابزار مختلف برای coercion اجباری بین *types* ارائه می‌دهد. مثلاً:

```js
var a = "42";
var b = Number( a );

console.log( a );	// "42"
console.log( b );	// 42
```

استفاده از `Number(..)` (تابع داخلی) همان‌طور که نشان داده شد *explicit* coercion از هر نوع دیگر به نوع `number` است. باید کاملاً سرراست باشد.

اما موضوع بحث‌برانگیز وقتی است که می‌خواهید دو مقدار را که از همان نوع نیستند مقایسه کنید، که *implicit* coercion نیاز دارد.

وقتی string `"99.99"` را با number `99.99` مقایسه می‌کنید، اکثر مردم موافقند معادل‌اند. اما دقیقاً یکی نیستند، نه؟ همان مقدار در دو نمایش متفاوت، دو *type* متفاوت. می‌توانید بگویید «loosely equal» هستند، نه؟

برای کمک در این موقعیت‌های رایج، JavaScript گاهی وارد عمل می‌شود و مقادیر را *implicitly* به انواع مطابق coerce می‌کند.

پس اگر از عملگر loose equals `==` برای مقایسهٔ `"99.99" == 99.99` استفاده کنید، JavaScript سمت چپ `"99.99"` را به معادل `number` آن `99.99` تبدیل می‌کند. مقایسه می‌شود `99.99 == 99.99`، که البته `true` است.

اگرچه برای کمک طراحی شده، implicit coercion می‌تواند گیج‌کننده باشد اگر وقت نگذارید قوانین حاکم بر رفتارش را یاد بگیرید. اکثر توسعه‌دهندگان JS هرگز نگذاشته‌اند، پس احساس رایج این است که implicit coercion گیج‌کننده است و برنامه‌ها را با باگ‌های غیرمنتظره آسیب می‌زند و باید اجتناب شود. گاهی حتی نقص در طراحی زبان نامیده می‌شود.

با این حال، implicit coercion مکانیزمی است که *می‌توان یاد گرفت*، و علاوه بر آن *باید* توسط هر کسی که می‌خواهد برنامه‌نویسی JavaScript را جدی بگیرد یاد گرفته شود. نه‌تنها وقتی قوانین را یاد بگیرید گیج‌کننده نیست، بلکه می‌تواند برنامه‌هایتان را بهتر کند! تلاشش ارزشش را دارد.
